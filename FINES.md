# Отчёт: штрафы и затраты на Wildberries

> Отчётов три. Здесь — **штрафы и затраты** (сколько площадка забрала и за что).
> Наличие и упущенная выручка — [REPORTS.md](REPORTS.md);
> анализ ниши перед выходом — [NICHE.md](NICHE.md).

Продавец видит выручку, но не видит, **сколько у него забирает WB и за что**.
Отчёт раскладывает удержания на статьи, показывает долю каждой в выручке,
находит причины штрафов и товары, которые съедают прибыль.

Что показывает:

- **комиссия WB** (вместе с эквайрингом и вознаграждением ПВЗ);
- **логистика**, **хранение**, **платная приёмка**;
- **штрафы** — с разбивкой по причинам (`bonusTypeName`) и виновным товарам;
- **прочие удержания** и **доплаты** в пользу продавца;
- разрезы: по товарам (SKU), по отчётным неделям, по операциям;
- **сверку с контрольными суммами WB** — сходятся ли наши цифры с кабинетом.

## Источник данных и токен

Данные берутся из **WB Finance API** (раздел «Документы и бухгалтерия» →
«Финансовые отчёты»), это тот же документ, по которому WB считает выплату:

| Метод | Зачем |
|---|---|
| `POST /api/finance/v1/sales-reports/detailed` | построчная детализация за период |
| `POST /api/finance/v1/sales-reports/list` | контрольные суммы отчётов (сверка) |

Хост: `https://finance-api.wildberries.ru`. Нужен **токен категории «Финансы»**
(кабинет продавца → Профиль → Настройки → Доступ к API).

Токен ищется резолвером `lib/wbToken.js` в таком порядке:
`WB_API_TOKEN` → `Wildberries_API` (env) → те же ключи в `.env` в корне репо.
В GitHub Actions секрет прокидывается в workflow как `WB_API_TOKEN`.

> MPSTATS эти данные не отдаёт в принципе — штрафы и удержания видны только во
> внутренней финансовой отчётности кабинета. Поэтому здесь отдельный токен.

### Лимиты запросов WB — почему отчёт собирается медленно

Снимок официальной документации по лимитам лежит в ветке
`claude/losses-wildberries-p8dhw6` (`docs/wb-api/limits.md`), первоисточник —
<https://dev.wildberries.ru/docs/openapi/api-information>.

Базовый лимит зависит от типа токена (на аккаунт, период — 1 минута):

| Тип токена | Лимит | Интервал | Всплеск |
|---|---|---|---|
| Персональный / Сервисный | 300/мин | 200 мс | 20 |
| Базовый / Тестовый | 150/мин | 200 мс | 10 |

**Но у финансовых методов лимит жёстче: 1 запрос в минуту, всплеск 1**
(у Базового токена — 2 запроса в 24 часа). Поэтому:

- детализация выгружается страницами по 100 000 строк, и **каждая следующая
  страница ждёт минуту** — так задумано, это не зависание;
- клиент `lib/wbClient.js` держит **token bucket на каждый метод** и не доводит
  до 429; на 429 ждёт ровно `X-Ratelimit-Retry` секунд и повторяет;
- прочие 4xx **не повторяются** — повтор бесполезен и жжёт лимит;
- запускать отчёт нужно **по расписанию, а не в цикле**.

## Методология

Считается в `lib/finesReport.js`, воспроизводимо по строкам детализации:

1. **Знак строки.** Возвраты и сторно (`docTypeName = Возврат`,
   `sellerOperName` со словом «возврат»/«сторно продаж») уменьшают выручку и
   сумму к перечислению.
   `Выручка = Σ retailAmount × знак`, `К перечислению = Σ forPay × знак`.
2. **Комиссия WB = Выручка − К перечислению.** Это всё, что площадка удержала
   с продажи: комиссия + эквайринг + вознаграждение ПВЗ. Эквайринг
   (`acquiringFee`) показан отдельной **справочной** строкой — он уже внутри
   комиссии и второй раз не суммируется.
3. **Остальные статьи — отдельные колонки отчёта**, поэтому просто суммируются
   (двойного счёта нет): `deliveryService` (логистика), `paidStorage`
   (хранение), `paidAcceptance` (приёмка), `penalty` (штрафы),
   `deduction` (удержания, могут быть отрицательными = выплата продавцу),
   `additionalPayment` (доплаты продавцу).
4. **Итого затрат** = комиссия + логистика + хранение + приёмка + штрафы
   + удержания − доплаты.
   **Доля затрат** = Итого затрат / Выручка × 100 %.
5. **Разрезы**: причины штрафов (`bonusTypeName`), виды удержаний, операции,
   SKU, отчётные недели. Строки без артикула (общие удержания, хранение «на
   кабинет») собираются в псевдо-товар **«Без привязки к товару»** — чтобы
   сумма по SKU сходилась с итогом.
6. **Сверка.** Итоги сравниваются с суммами WB из списка отчётов
   (`penaltySum`, `paidStorageSum`, `deductionSum`…). Расхождение больше рубля
   → предупреждение в отчёте: скорее всего, детализация выгрузилась не вся.
   При фильтре по товарам сверка не проводится (она возможна только по
   кабинету целиком).

Пороги для выводов («много/мало») — константа `THRESHOLDS` в
`lib/finesReport.js`: доля затрат ≥ 45 %, логистика ≥ 20 %, хранение ≥ 5 %,
штрафы ≥ 1 % выручки, выкуп < 60 %.

## Переменные окружения

| Переменная | Обязательна | По умолчанию | Назначение |
|---|---|---|---|
| `WB_API_TOKEN` (или `Wildberries_API`) | да | — | Токен WB, категория «Финансы» |
| `WB_TOKEN_TYPE` | нет | `personal` | Тип токена: `personal`/`service`/`base`/`test` |
| `API_KEY` | да (для HTTP) | `supersecret` | Ключ доступа к эндпоинтам сервиса |
| `REPORT_DAYS` | нет | `30` | Длина периода по умолчанию, дней |
| `REPORT_GROUP` | нет | — | Группа товаров из `config/groups.json` |
| `REPORT_FILTER` | нет | — | Точечный фильтр (перебивает группу) |
| `FINES_PERIOD` | нет | `weekly` | Периодичность отчётов WB: `weekly`/`daily` |
| `FINES_CONTROL` | нет | `1` | `0` — не сверять с контрольными суммами WB |
| `WB_FINANCE_PAGE_LIMIT` | нет | `100000` | Строк в одном ответе (максимум WB) |
| `WB_FINANCE_MAX_PAGES` | нет | `30` | Страховка от бесконечной пагинации |
| `WB_TIMEOUT_MS` | нет | `120000` | Тайм-аут одного запроса |

## Запуск

### 1. Разово из командной строки

```bash
# период = последние REPORT_DAYS дней
WB_API_TOKEN=xxxxx npm run report:fines

# явный период
WB_API_TOKEN=xxxxx node report-fines.js 2026-07-01 2026-07-31

# только линейка РМП (правила выбора — как в отчёте по наличию)
WB_API_TOKEN=xxxxx REPORT_GROUP=РМП npm run report:fines
WB_API_TOKEN=xxxxx node report-fines.js "" "" "002_РМП_белый, 016 МС голубой"
```

Результат — `reports-output/`:

| Файл | Что внутри |
|---|---|
| `fines-<d1>_<d2>.csv` | строка на товар + ИТОГО |
| `fines-<d1>_<d2>-reasons.csv` | штрафы и удержания по причинам |
| `fines-<d1>_<d2>.json` | весь отчёт, включая разрезы и сверку |

CSV — UTF-8 с BOM, разделитель `;`, десятичная запятая: Excel открывает как есть.

> **Фильтр по товарам и штрафы.** Без фильтра отчёт строится по всему кабинету —
> так и надо: штрафы часто приходят строками **без артикула**, и по подмножеству
> SKU их просто не видно. Фильтр включайте, когда разбираете конкретную линейку.

### 2. По HTTP (сервис запущен)

```bash
# JSON — весь отчёт
curl -H "x-api-key: $API_KEY" \
  "http://localhost:8080/reports/fines?d1=2026-07-01&d2=2026-07-31"

# CSV по товарам
curl -H "x-api-key: $API_KEY" \
  "http://localhost:8080/reports/fines?format=csv" -o fines.csv

# CSV по причинам штрафов
curl -H "x-api-key: $API_KEY" \
  "http://localhost:8080/reports/fines?format=csv&sheet=reasons" -o fines-reasons.csv
```

Параметры: `d1`, `d2`, `format=json|csv`, `sheet=sku|reasons`,
`period=weekly|daily`, `filter`, `group`. Ответ может идти минуты — это лимит WB.

### 3. Регулярно

GitHub Actions: вкладка **Actions** → «Отчёт — штрафы и затраты WB» →
**Run workflow**. Нужен секрет `Wildberries_API` (Settings → Secrets and
variables → Actions). Готовые CSV/JSON прикладываются к запуску.

Системный cron:

```cron
0 7 * * 1  cd /path/to/wb-headless && WB_API_TOKEN=xxxxx node report-fines.js >> fines.log 2>&1
```

Понедельник — осмысленный день: WB формирует отчёты о реализации раз в неделю.

## Колонки отчёта по товарам (CSV/JSON)

| Поле | Описание |
|---|---|
| `seller` | Артикул продавца (`vendorCode`) |
| `sku` | Артикул WB (`nmId`), пусто у строк без привязки |
| `units` | Продано штук (нетто, за вычетом возвратов) |
| `revenue` | Выручка, ₽ |
| `commission` | Комиссия WB (с эквайрингом и ПВЗ), ₽ |
| `logistics` | Логистика, ₽ |
| `storage` | Хранение, ₽ |
| `acceptance` | Платная приёмка, ₽ |
| `penalty` | Штрафы, ₽ |
| `deduction` | Прочие удержания, ₽ |
| `additionalPayment` | Доплаты продавцу, ₽ |
| `totalCosts` | Итого затрат, ₽ |
| `costSharePct` | Доля затрат от выручки, % |
| `costsPerUnit` | Затрат на единицу, ₽ |
| `deliveries` / `returns` | Доставок / возвратов, шт |
| `buyoutPct` | Выкуп, % |
| `netPayout` | Остаётся продавцу, ₽ |

Строки отсортированы по убыванию `totalCosts` — сверху то, что дороже всего.

В JSON дополнительно: `fines` (причины штрафов с топ-товарами), `deductions`,
`operations`, `byWeek`, `control` (сверка с WB), `insights` (выводы на цифрах),
`warnings`.

## Что можно добавить дальше

У WB есть отдельные **отчёты об удержаниях** (токен категории «Аналитика»,
хост `seller-analytics-api.wildberries.ru`) — они объясняют штраф подробнее,
чем строка `bonusTypeName`:

| Метод | Про что |
|---|---|
| `/api/analytics/v1/measurement-penalties` | занижение габаритов упаковки |
| `/api/analytics/v1/warehouse-measurements` | замеры склада |
| `/api/analytics/v1/deductions` | подмены и неверные вложения |
| `/api/v1/analytics/antifraud-details` | самовыкупы |
| `/api/v1/analytics/goods-labeling` | маркировка товара |

Лимит у всех — 1 запрос в минуту. Подключать их имеет смысл, когда в отчёте
видно, что конкретная причина штрафов стала заметной статьёй затрат.
