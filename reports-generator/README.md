# Генератор PDF-отчётов по конкурентам и нишам (MPStats × Wildberries)

Набор скриптов, который по списку артикулов WB и поисковому запросу собирает
данные из **MPStats API** и рендерит **единый многостраничный PDF**:

```
стр. 1  — титульная сводка (ключевые выводы, содержание)
стр. 2… — карточка каждого артикула конкурента
последняя — анализ ниши по запросу
```

Каждая страница — компактный A4 с KPI-плитками, диаграммами остатков/складов,
позицией на рынке, ценовой структурой ниши и оценкой. Акцентные цвета разведены
по страницам через CSS-переменные, поэтому всё живёт в одном HTML-документе и
печатается одним вызовом Chromium — без внешних утилит склейки PDF.

## Что показывает

**По артикулу:** дата появления на ВБ, заказы и сумма за 30 дней, средняя цена,
процент выкупа, остатки по размерам и складам, упущенная выручка, доля рынка и
ранг в категории, видимость по ключевым запросам, авто-оценка состояния.

**По нише:** объём (₽/SKU/продажи), медианная цена и ценовой коридор, средний
выкуп, концентрация (ТОП-10/50/100, «длинный хвост»), число брендов/продавцов,
лидеры по брендам, ТОП-карточки, приток новинок, место ваших артикулов.

## Требования

- **Python 3.8+** (только стандартная библиотека — внешних пакетов нет).
- **Chromium/Chrome** для рендера PDF (`--print-to-pdf`).
- Переменная окружения **`MPSTATS_TOKEN`** (заголовок `X-Mpstats-TOKEN`).

Опционально:
- `MPSTATS_BASE_URL` — база API (по умолчанию `https://mpstats.io/api`).
- `CHROME` — путь к бинарю Chromium (иначе автопоиск: `/opt/pw-browsers/…`,
  `/usr/bin/chromium`, `google-chrome`).

## Использование

```bash
# 1) собрать данные из MPStats -> data.json
MPSTATS_TOKEN=xxxxx python3 reports-generator/collect.py \
  --sku 447156582 428365795 \
  --category "Мужчинам/Рубашки" \
  --query "рубашка мужская однотонная с длинным рукавом" \
  --out reports-output/data.json
# период по умолчанию — последние 30 дней; можно --days 60 или --d1/--d2

# 2) сверстать единый PDF (cover + карточки + ниша)
CHROME=/opt/pw-browsers/chromium-1194/chrome-linux/chrome \
python3 reports-generator/build.py reports-output/data.json \
  --html reports-output/combined.html \
  --pdf  reports-output/combined.pdf
```

Результат — `reports-output/combined.pdf` (эта папка в `.gitignore`).

## Файлы

| Файл | Назначение |
|---|---|
| `collect.py` | Тянет данные из MPStats API → `data.json` (артикулы + рынок + ниша). Качественные вердикты (`role`/`assessment`/`signals`) генерируются авто-эвристиками. |
| `build.py` | `data.json` → единый HTML со всеми страницами → PDF через Chromium. Общий CSS, акценты через CSS-переменные на каждой `.page`. |
| `README.md` | Этот файл. |

## Кастомизация

- **Тексты оценок.** `collect.py` пишет авто-вердикты; чтобы дать экспертный
  текст — отредактируйте в `data.json` поля `articles.<sku>.role /
  .assessment / .signals` и `niche.assessment` перед запуском `build.py`.
- **Цвета.** Палитры задаются в `collect.py` (`PALETTES`, `NICHE_PALETTE`) как
  `[accent, accent2, tint, soft]` и попадают в `data.json` → меняйте там же.
- **Фото товара.** `data.json` ожидает `articles.<sku>.image` как data-URI
  (base64). `collect.py` оставляет поле пустым; при необходимости подложите
  миниатюру (`thumb_middle` из ответа категории) сами.
- **Фильтр ниши.** Правила выделения подсегмента (однотонность/длинный рукав,
  исключения принтов/оверсайза) — в `collect.py`: `PAT`, `NONCLASSIC`, `SHORT`.

## Ограничения

- Доля «по запросу» считается на уровне выручки **категории** (сегмент по
  фильтру названий), т.к. SEO-модуль поисковой выдачи MPStats может быть
  недоступен на конкретном токене. По самим запросам приводится поисковая
  **позиция и тип трафика** из отчёта позиций артикула.
- Названия складов известны для основных ID; прочие показываются как `СЦ · ID`.
- «Сегодня» для периода по умолчанию берётся из системной даты; для
  воспроизводимости задавайте `--d1/--d2` явно.
