# Анализ ниши (категории Wildberries)

Отчёт оценивает нишу (категорию WB) перед выходом в неё по пяти измерениям и
выдаёт **сводный скоринг 0–100** с вердиктом «заходить / осторожно / не заходить»
и указанием узкого места. Данные берутся из MPSTATS (`POST /wb/get/category`
плюс срезы `category/trends|sellers|brands|price_segmentation`).

> Полная методика, источники и ограничения API — `docs/niche-analysis-methodology.md`.
> Оформлено также как навык `.claude/skills/wb-niche-analysis/` (пороги скоринга —
> в `references/scoring.md`).

## Что показывает

Пять измерений, каждое 0–20 баллов → сумма 0–100:

| Измерение | Что означает | Источник |
|---|---|---|
| **Ёмкость** | выручка/штуки ниши, ср. выручка на «живой» товар, упущенная выручка | `category` |
| **Сезонность** | зависимость от времени года, окно входа (нужен период 12+ мес) | `category/trends` |
| **Тренд** | куда движется ниша: Δ% 2-й половины периода vs 1-й + наклон регрессии | `category/trends` |
| **Конкуренция** | продавцы/бренды, монополизация (доля выручки топ-10), барьер по отзывам | `category`, `category/sellers|brands` |
| **Насыщенность** | доля товаров с продажами (мёртвые карточки = скрытая насыщенность) | `category` |

Плюс разрезы: **топ-продавцы** и **топ-бренды** ниши (выручка, число карточек, доля),
ценовые сегменты. JSON содержит весь анализ; CSV — таблицу товаров (сорт. по выручке ↓).

Ёмкость, насыщенность и упущенная выручка считаются **по всей нише** из `category/price_segmentation`
(сегменты не смещаются при усечении выгрузки); при недоступности сегментов — fallback на top-N.

**ТОП-выдача по уточняющим фразам (фаза 2).** Если передать `query`, добавляется блок из
`POST /analytics/v1/wb/search/items` — плотность топ-выдачи (выручка, % с продажами, монополизация
топ-10, упущенка). ⚠️ Эндпоинт отдаёт максимум ~100 карточек, поэтому это анализ верхушки, не всей
ниши. Метрика **«спрос:предложение»** (порог 10:1) считается только если переданы вручную частотность
и кол-во карточек — оба из Оракула Wildbox (в API MPStats их нет).

**Несколько фраз сразу.** `query` принимает список через «;», у каждой опц. `=частота:карточки` —
напр. `«тёплая=4569:4471; фланелевая=2086:2966»`. Тогда в сводке появляется сравнительная таблица
спрос:предложение по фразам. 5 измерений ниши (в т.ч. сезонность) при этом считаются на всю
категорию — по отдельной фразе сезонности в API нет.

**Автоотбор из Оракула (Wildbox).** Вместо ручного ввода — скормить выгрузку «Оракул запросов»
(xlsx/csv): `NICHE_ORACLE=файл`, `NICHE_PLUS="клетка,оверсайз,…"` (взять, если есть хотя бы один
ключ — по корню слова), `NICHE_MINUS="летняя,блузка,…"` (выкинуть). Частотность и кол-во карточек
подтянутся сами. Предпросмотр отбора без запросов к MPStats: `node scripts/oracle-phrases.mjs
файл.xlsx "плюс" "минус"`. Ридер xlsx/csv — свой, без сторонних зависимостей.

Пороги (согласованы с MarketGuru/Moneyplace/Wildbox): монополизация **0–15%** здоровая ·
**15–40%** умеренная · **40%+** высокая. Тренд восходящий = ок; нисходящий = насыщение.
Все пороги вынесены в **`config/niche-thresholds.json`** (калибруются; env `NICHE_THRESHOLDS`
задаёт свой путь).

## Методология (кратко)

1. Товары категории тянем постранично (`POST /wb/get/category`, сортировка по выручке ↓).
   Если ниша больше `NICHE_MAX_ROWS`, берём верх по выручке — самые значимые игроки.
2. **С продажами** = карточки, где штуки или выручка > 0.
3. **Монополизация** = выручка топ-10 товаров ÷ выручка ниши.
4. **Тренд** = год к году (последние 12 мес vs предыдущие 12, без сезонности); **сезонность** —
   помесячный индекс. Оба берутся из истории `trends` (~6 лет) и не зависят от периода запроса.
5. Каждое измерение → 0–20 баллов, сумма → вердикт; узкое место = блок с минимумом.

Полные формулы и калибровка порогов — в навыке (`references/scoring.md`).

## Переменные окружения

| Переменная | Обязательна | По умолчанию | Назначение |
|---|---|---|---|
| `MPSTATS_TOKEN` | да | — | Токен MPSTATS |
| `NICHE_PATH` | да* | — | Путь категории WB (`Женщинам/Одежда/Платья`). *Можно передать аргументом или `?path=` |
| `REPORT_DAYS` | нет | `30` | Длина периода по умолчанию (дней) |
| `NICHE_MAX_ROWS` | нет | `5000` | Сколько товаров максимум выгрузить |
| `NICHE_PAGE_SIZE` | нет | `500` | Размер страницы выгрузки |

## Запуск

### 1. Из командной строки

```bash
# период = последние REPORT_DAYS дней
MPSTATS_TOKEN=xxx NICHE_PATH="Женщинам/Одежда/Платья" npm run report:niche

# путь и явный период аргументами
MPSTATS_TOKEN=xxx node report-niche.js "Женщинам/Одежда/Платья" 2026-06-01 2026-06-30
```

Результат — `reports-output/niche-<категория>-<d1>_<d2>.csv` и `.json`
плюс сводка в консоль. CSV в UTF-8 с BOM и разделителем `;` — открывается
в Excel без плясок.

### 2. По HTTP (сервис запущен)

```bash
# JSON
curl -H "x-api-key: $API_KEY" \
  "http://localhost:8080/reports/niche?path=Женщинам/Одежда/Платья&d1=2026-06-01&d2=2026-06-30"

# CSV-файл
curl -H "x-api-key: $API_KEY" \
  "http://localhost:8080/reports/niche?path=Женщинам/Одежда/Платья&format=csv" -o niche.csv
```

Без `d1`/`d2` берётся период = последние `REPORT_DAYS` дней. Параметр
`path` обязателен.

### 3. Через GitHub Actions

Вкладка **Actions** → workflow «Анализ ниши (категории WB)» → **Run
workflow**. Заполните поле **path** (путь категории), при желании период
и `max_rows`. Готовый CSV+JSON приложится к запуску как артефакт
`niche-report`. Нужен секрет репозитория `MPSTATS_TOKEN`.
