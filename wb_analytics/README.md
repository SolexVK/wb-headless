# wb_analytics — единая аналитическая система WB × MPStats

Один **конфиг-управляемый** шаблон, который по описанию ниши/продавца собирает
данные из **MPStats API** и рендерит **единый многостраничный PDF-отчёт**. Подходит
под **любой тип товара и любую нишу** — всё задаётся JSON-конфигом, код и вёрстка не
меняются.

Раньше это были разрозненные навыки (анализ карточки конкурента, анализ ниши,
конкурентный анализ продавца, сборка PDF). Теперь они собраны в одну систему с
единым набором переиспользуемых секций.

```
конфиг.json ──▶ analyze.py ──▶ отчёт (dict/JSON) ──▶ render.py ──▶ единый PDF
                (MPStats API)                          (Chromium --print-to-pdf)
```

## Что внутри

| Модуль | Роль |
|---|---|
| `run.py` | Единая точка входа (CLI): читает конфиг → `analyze` → `render`. |
| `analyze.py` | Слой данных. `analyze(cfg) → report`: карточки, рынок ниши, сопоставимый сегмент, ТОП-конкуренты, **логистика складов** (продавец vs конкуренты), **потенциал + план распределения стока** (привязан к доле центрального спроса), авто-дорожная карта. |
| `render.py` | Слой рендера. Реестр секций `SECTIONS` + сборка HTML по манифесту `cfg['sections']`. |
| `theme.py` | Оформление: хелперы, кликабельные ссылки WB, справочник складов (`wh_label`), весь CSS, поиск Chromium и рендер HTML→PDF. |
| `reference/wb_warehouses.json` | Справочник складов WB (id → название, только WB-фулфилмент `isWb`). |
| `reference/wb_region_demand.json` | Оценочные доли спроса по макрорегионам (для расчёта потенциала; редактируемо). |
| `configs/*.example.json` | Примеры конфигов под разные ниши/типы товара. |

## Секции отчёта (манифест `sections`)

Порядок и состав страниц задаются списком в конфиге. Доступные секции:

| Ключ | Страница |
|---|---|
| `cover` | Титульная сводка: вердикт, главные выводы, таблица целевых артикулов. |
| `target_cards` | Детальный разбор каждой из первых `detailed` карточек (KPI, размеры, склады, запросы, оценка). |
| `competitors` | ТОП-конкуренты сегмента по выручке + сравнение «вы vs ТОП-10». |
| `warehouses` | Логистика: склады продавца vs конкурентов, покрытие центральных хабов. |
| `potential` | Сценарии потенциала + план распределения стока по хабам. |
| `niche` | Аналитика ниши: объём, цены, концентрация, бренды, позиция продавца. |
| `roadmap` | Авто-дорожная карта улучшений P1→P3. |

Например, чистый анализ ниши по артикулам без логистики/продавца:
`"sections": ["target_cards", "competitors", "niche"]`.

## Конфиг

```jsonc
{
  "category": "Дом/Детская/.../Постельное белье",   // путь категории MPStats
  "niche_name": "детское постельное бельё",           // заголовок ниши
  "segment_name": "комплекты",                        // короткая метка сопоставимого сегмента
  "segment_note": "исключены подушки/одеяла/простыни",// подпись под таблицей конкурентов
  "comparable": ["постельное бель", "кпб"],           // подстроки названия для сегмента; "a b" = обе
  "seller": { "id": 4289467, "name": "ИП Комиренко Т А" },
  "targets": [707011618, 529697243, ...],             // nmId целевых карточек
  "detailed": 3,                                       // сколько карточек разобрать детально
  "n_competitors": 12,
  "period": { "d1": "2026-06-08", "d2": "2026-07-07", "days": 30 }, // или просто { "days": 30 }
  "sections": ["cover","target_cards","competitors","warehouses","potential","niche","roadmap"],
  "capture": { "real": 0.5, "ambitious": 0.85 },       // доля отвоевания центр. спроса (потенциал)
  "content_factor": { "real": 1.5, "ambitious": 2.0 }  // фактор контента/отзывов (потенциал)
}
```

Почему `targets` задаются списком nmId: MPStats не отдаёт ассортимент продавца по
id/имени надёжно (бренд-сквоттинг, seller-by-id закрыт), а WB catalog/card API за
антиботом. По nmId же `item/*` и `category` работают стабильно.

## Требования

- **Python 3.8+** (только стандартная библиотека).
- **Chromium/Chrome** для PDF (`--print-to-pdf`). Путь из `$CHROME` или автопоиск.
- Переменная окружения **`MPSTATS_TOKEN`** (заголовок `X-Mpstats-TOKEN`).
- Опционально `MPSTATS_BASE_URL` (по умолчанию `https://mpstats.io/api`).

## Использование

```bash
# полный цикл: собрать из MPStats и сверстать PDF
MPSTATS_TOKEN=xxxxx python3 wb_analytics/run.py wb_analytics/configs/seller_bedding.example.json \
  --data reports-output/bedding.json --pdf reports-output/bedding.pdf

# только вёрстка из готового JSON (без обращения к сети)
python3 wb_analytics/run.py wb_analytics/configs/seller_bedding.example.json \
  --from-data reports-output/bedding.json --pdf reports-output/bedding.pdf
```

По умолчанию выходные пути — `reports-output/<имя-конфига>.json/.html` (папка в
`.gitignore`). PDF собирается только при `--pdf`.

## Кастомизация

- **Секции/порядок** — `sections` в конфиге.
- **Цвета** — `palettes` в конфиге: `{ "cover": [accent,accent2,tint,soft], "niche": [...], "cards": [[...],[...]] }`.
- **Тексты оценок** — правьте собранный `data.json` (`targets.<sku>.assess`-поля рассчитываются в `analyze`; экспертный текст можно вписать в JSON перед вёрсткой через `--from-data`).
- **Модель потенциала** — `capture` / `content_factor` в конфиге и веса в
  `reference/wb_region_demand.json` (доли спроса по макрорегионам).
- **Фильтр сегмента** — `comparable` (подстроки названия; `"a b"` = обе подстроки).

## Ограничения (важно — читать перед доработками)

- **Ассортимент продавца по id/имени/бренду в MPStats — НЕ работает надёжно.**
  `/wb/get/seller/{id}` → 405; `/wb/get/brand` отдаёт чужие карточки (бренд-сквоттинг).
  Обход: список nmId от пользователя.
- **Имя/бренд продавца:** WB `static-basket-01.wbbasket.ru/vol0/data/supplier-by-id/{id}.json`.
- **Справочник складов:** WB `.../stores-data.json` (`isWb` = фулфилмент WB). Внимание:
  WB-Тула = **Алексин (206348)**; «Склад продавца Тула» — это FBS, не фулфилмент.
- **`/wb/get/warehouses` → 500** — footprint складов считаем из `item/{sku}` `sizeandstores.s`.
- **Категорийный `purchase` (выкуп)** — величина уровня подкатегории, не по-товарная;
  в таблице конкурентов вместо неё — «возраст карточки».
- Доля «по запросу» считается на уровне выручки **сегмента категории** (SEO-модуль
  поисковой выдачи MPStats может быть недоступен на токене).
- Потенциал и план распределения — **оценочные** (допущения указаны в отчёте).
