# Остатки: формат выгрузки

Здесь лежит то, чего нет ни в одном API: **остатки в разрезе семи фулфилмент-складов**.
Сейчас эти данные живут в таблице логиста. Чтобы `replenishment` мог считать подсорт,
таблица должна выгружаться сюда в фиксированном формате.

## Файл `ff-stock-<ГГГГ-ММ-ДД>.csv`

Кодировка UTF-8, разделитель `;` — как в остальных выгрузках проекта.
Одна строка = **один баркод на одном складе**. Это принципиально: подсорт считается
до размера, поэтому агрегат по карточке не годится.

| Колонка | Обязательна | Что внутри |
| --- | --- | --- |
| `date` | да | Дата среза, ГГГГ-ММ-ДД |
| `warehouse` | да | Склад: `msk-1`, `msk-2`, `spb`, `krd`, `kzn`, `ekb`, `nsk` |
| `nmID` | да | Артикул WB |
| `barcode` | да | Баркод (размер). Если пока нет — оставить пустым и заполнить `techSize` |
| `techSize` | да | Размер: `S`, `M`, `48` и т. п. |
| `qty` | да | Остаток на складе, шт |
| `inTransit` | нет | В пути на этот склад, шт |
| `vendorCode` | нет | Артикул продавца, для чтения человеком |

Пример:

```csv
date;warehouse;nmID;barcode;techSize;qty;inTransit;vendorCode
2026-08-17;msk-1;535397255;2037000012345;46;12;40;001 РМК-твид бордовый
2026-08-17;ekb;535397255;2037000012345;46;3;0;001 РМК-твид бордовый
```

## Почему склады перечислены явно

Возвраты со всей страны приходят **только на московский фулфилмент** (F10), а расходуются
остатки на всех семи. Поэтому формула подсорта для Москвы обязана вычитать возвратный
приток, а для регионов — нет. Без разделения по складам эта поправка невозможна,
и получается ровно то, что происходит сейчас: Москва затаривается, регионы в дефиците.

## Файл `in-transit-<ГГГГ-ММ-ДД>.csv` (опционально)

Если карго-отправки удобнее вести отдельно:

| Колонка | Что внутри |
| --- | --- |
| `shippedAt` | Дата отправки из Бишкека |
| `etaAt` | Ожидаемая дата приёмки |
| `warehouse` | Склад назначения |
| `nmID`, `barcode`, `techSize`, `qty` | Что и сколько едет |

Фактические `shippedAt` и дата приёмки нужны не только для расчёта остатка: по ним
считается реальный срок карго, который идёт буфером в точку перезаказа. Обещанные
14–20 дней в формулу не годятся — нужен наблюдаемый разброс.

## Чего здесь быть не должно

Персональных данных покупателей, номеров заказов, ФИО. Только товар, склад, количество.
