## Что исправлено в этой корректировке

### Живой путь (Intent → Artifact) — работает сквозным прогоном
- Контракт log pipeline↔orchestrator: ключи шага доступны на верхнем уровне, история в `chain`.
- Явная маршрутизация фаза→трансформер (`set_routes`) вместо first-match: Category/Profile/Clarify больше не затеняются Dialogue.
- `DialogueAgent.parse` переписан под актуальный API `transform(graph, context)`.
- `LLMTransformer` возвращает свои proposals (L-001 «LLM Proposes, Kernel Decides» реален).
- Выбор модели на фазах 4–5 ведёт сразу к экспорту; `next_phase` принимает имена фаз.
- Fallback-парсер без LLM: сопоставление по ключевым словам вместо позиционного.
- Мост полей решений → ключи PromptExporter (`_map_export_fields`).
- SSOT: ProjectModel живёт в адаптере; оркестратор не подменяет его SemanticGraph-обёрткой.

### Kernel
- SnapshotManager переписан под реальный Edge/Node API (diff/trace/compare работают, 15/15 тестов).
- Снапшоты сохраняют и восстанавливают constraints/facts/identity/project_name/tags.
- Канон направлений рёбер зафиксирован в core.py (RelationType): Intent—SUPPORTS→Goal,
  Decision—SUPPORTS→Goal, Constraint—CONSTRAINS→Goal, Blueprint—SATISFIES→Decision,
  Blueprint—PRODUCES→Artifact. Адаптер и оба валидатора согласованы.
- `compile_blueprint` больше не теряет обновление ProjectModel.
- DecisionMaker: инварианты проверяются и для USER-предложений; без мутаций frozen-узлов.
- Artifact хранит полный промпт (обрезка [:200] удалена).

### Периферия
- 3 сломанных Domain Pack (youtube/infographic/fashion) приведены к интерфейсу base.py.
- Все 9 паков зарегистрированы в Orchestrator; render hints паков доходят до промпта.
- Knowledge Provider подключён к экспорту: пробелы заполняются фактами (source="knowledge"),
  приоритет: пользователь/профиль > знания > хинты пака. Доменная изоляция без fallback «всем».

  стиль/negative переопределяются данными (`style_defaults`/`negative`), а не хардкодом.
- llm_client: ключи из env (OPENROUTER_API_KEY/DEEPSEEK_API_KEY), модели через
  VCOS_LLM_MODEL/VCOS_LLM_FALLBACK, ошибки логируются.

## Известные ограничения (честный список)

1. **Персистентности нет**: Registry/снапшоты/память живут в RAM процесса (Фаза 6 плана).
2. Двойная система снапшотов в адаптере (`.snapshots` + `.snaps`) — объединить в Фазе 3.
3. Два Knowledge-протокола (`knowledge/provider.py` — канон, `transformers/knowledge_protocol.py` —
   используется KnowledgeTransformer'ом) — унифицировать.
4. Часть compliance-тестов остаётся структурными (has_module), а не поведенческими — Фаза 5 плана.
5. Спека CO-001 (6 сущностей) отстаёт от кода (8: + SOURCE, CONSTRAINT) — обновить спеку до v1.1.
6. `hermes/runtime/runtime.py` и SDK `fork()/diff()` не входили в этот проход — SDK fork
   по-прежнему делит Orchestrator между сессиями (известный дефект ревизии).
7. Rollback восстанавливает состояние прямым присваиванием (с bump версии) — заменить на
   event log в Фазе 3.
