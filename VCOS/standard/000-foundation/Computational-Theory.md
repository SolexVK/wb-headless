## 1. Introduction

Computational Theory описывает, как VCOS принимает решения, обрабатывает информацию и эволюционирует.

VCOS — это не нейросеть. Это **когнитивная архитектура**, в которой LLM является лишь одним из механизмов, предлагающих изменения семантического графа.

## 2. Когнитивный цикл

Фундаментальный вычислительный паттерн VCOS — **когнитивный цикл**:

```
1. Наблюдение (Observe)
   ↓
2. Оценка (Evaluate)
   ↓
3. Решение (Decide)
   ↓
4. Действие (Act)
   ↓
5. Запись (Record)
   ↓
(возврат к 1)
```

### 2.1 Observe
Агент (или оркестратор) читает текущее состояние Semantic Graph.  
Определяет, какая информация уже известна, какая отсутствует, какие решения не приняты.

*Вход:* Semantic Graph  
*Выход:* Cognitive Gap — множество неизвестных или неуверенных значений.

### 2.2 Evaluate
Агент оценивает, что можно сделать с текущим состоянием:
- Можно ли принять решение на основе имеющихся знаний?
- Нужно ли больше информации?
- Есть ли противоречия в графе?

*Вход:* Cognitive Gap + Knowledge  
*Выход:* Prioritised Actions — список возможных действий с приоритетами.

### 2.3 Decide
Агент выбирает одно действие и принимает решение.  
Decision фиксируется в Semantic Graph.

*Вход:* Prioritised Actions  
*Выход:* Decision Node в Semantic Graph.

### 2.4 Act
Агент выполняет действие:
- Задаёт вопрос пользователю (через Orchestrator)
- Запрашивает Knowledge из Domain Pack
- Запускает Visual Reasoner для генерации визуальных решений
- Вызывает Renderer для компиляции

*Вход:* Decision  
*Выход:* Изменение Semantic Graph (новые Node / Edge).

### 2.5 Record
Результат действия фиксируется в Semantic Graph.  
Knowledge обновляется. Граф эволюционирует.

## 3. Семантический граф как вычислительная модель

### 3.1 Определение

Semantic Graph — это направленный мультиграф, в котором:
- **Node** представляет сущность (Intent, Goal, Decision, Constraint, Fact, Blueprint, Artifact)
- **Edge** представляет отношение между узлами (depends_on, supports, contradicts, produces, references, contains)
- **Graph** представляет контейнер узлов и связей

### 3.2 Типы узлов (CO-001)

| Тип узла | Описание |
|----------|----------|
| Intent | Намерение пользователя (неизменяем) |
| Goal | Цель проектирования |
| Fact | Установленный факт |
| Decision | Принятое решение |
| Constraint | Ограничение |
| Blueprint | Проектная модель сцены |
| Artifact | Результат компиляции |

### 3.3 Типы связей

| Тип связи | Семантика |
|-----------|-----------|
| depends_on | A невозможно вычислить без B |
| supports | Knowledge обосновывает Decision |
| contradicts | A противоречит B |
| produces | Decision создаёт Artifact |
| references | Artifact ссылается на Decision |
| contains | Graph содержит Node |

## 4. Вычислительные операции

VCOS поддерживает следующие операции над графом:

### 4.1 Read
```python
read(graph, node_id) → Node
read(graph, node_type) → List[Node]
read(graph, edge_type) → List[Edge]
```
Чтение узлов и связей по идентификатору или типу.

### 4.2 Propose
```python
propose(graph, node: Node, edges: List[Edge]) → Proposal
```
LLM или агент предлагает новый узел со связями.

### 4.3 Validate
```python
validate(graph, proposal: Proposal) → ValidationResult
```
Проверка предложения на соответствие Core Ontology, инвариантам и текущему состоянию графа.

### 4.4 Apply
```python
apply(graph, proposal: Proposal) → Graph
```
Применение одобренного предложения к графу.

### 4.5 Reject
```python
reject(graph, proposal: Proposal) → Graph
```
Отклонение предложения. Узел не добавляется, но информация об отклонении может быть записана.

## 5. Управление уверенностью

Каждый узел и ребро в Semantic Graph имеют атрибут `confidence` (0.0–1.0).

- **1.0** — абсолютная уверенность (Intent, Fact от пользователя)
- **0.7–0.9** — высокая уверенность (подтверждённое Knowledge)
- **0.4–0.6** — средняя уверенность (вывод LLM)
- **0.1–0.3** — низкая уверенность (гипотеза, предположение)
- **0.0** — отсутствует

Оркестратор использует confidence для определения следующего шага:
- Если confidence всех критических узлов > 0.8 → можно компилировать
- Если confidence < 0.4 по ключевым параметрам → задать вопрос пользователю
- Если есть противоречия (contradicts) → запросить уточнение

## 6. Вычислительная сложность

- **Граф:** O(V + E) для полного обхода
- **Валидация предложения:** O(1) для проверки типов, O(E) для проверки связей
- **Когнитивный цикл:** O(V × E) для полной оценки графа
- **Поиск узлов по типу:** O(V) при отсутствии индекса, O(log V) с индексом

## 7. Модель эволюции

### 7.1 Состояния графа

```
Draft → Validated → Approved → Archived
                    ↘ Rejected
```

### 7.2 Переходы

- **Draft → Validated:** предложение LLM проверено и соответствует CO
- **Validated → Approved:** оркестратор принял решение включить узел
- **Approved → Archived:** проект завершён, узел больше не активен
- **Draft → Rejected:** предложение отклонено оркестратором

## 8. Модель памяти

VCOS использует два уровня памяти:

### 8.1 Проектная память (Semantic Graph)
Текущее состояние проекта. Живёт, пока активен проект.

### 8.2 Долгосрочная память (Knowledge Graph)
Накопленные знания между проектами.
- Успешные решения
- Проверенные паттерны
- Исторические оценки пользователей
