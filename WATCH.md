# Сторож удержаний WB: две проверки в день с отчётом в Telegram

> Отчётов теперь четыре. Здесь — **сторож**: он сам проверяет удержания дважды
> в день и пишет в Telegram. Разовые расследования — [FINES.md](FINES.md),
> наличие и упущенная выручка — [REPORTS.md](REPORTS.md), анализ ниши — [NICHE.md](NICHE.md).

Каждое утро и каждый вечер сторож выгружает свежую детализацию WB, разбирает
каждое удержание по причинам, расследует проблемные случаи и присылает итог:

- **проблем нет** → короткое «всё в порядке» со сводкой (чтобы молчание нельзя
  было спутать со сломанным сторожем);
- **проблемы есть** → список находок с суммами, причинами и первым действием
  по каждой, плюс PDF-расследования во вложении.

## Что он проверяет

| Правило | Когда срабатывает |
|---|---|
| Штрафы по каждой причине | сумма выше порога (по умолчанию 500) |
| Всплеск | сумма по причине втрое выше медианы обычного дня |
| **Незнакомая причина** | причины нет в каталоге — всегда сообщает |
| Прямая логистика | появилось удержание за доставку покупателю (при ИУ так быть не должно) |
| Массовый срыв заказов | 5+ отмен — с расследованием: склад ФФ, дата заданий, часы простоя |
| Возвраты в платной зоне | лежат на ПВЗ дольше 2 суток — плата уже идёт |
| Истёк срок хранения на ПВЗ | теряется сам товар, а не только плата |
| Хвост возвратной логистики | выданные, но ещё не оплаченные возвраты выше порога |
| Доля удержаний | вместе с комиссией выше 45% выручки |

Каталог причин — `lib/deductionCatalog.js` (20 типов: штрафы, логистика,
хранение, приёмка, реклама, сторно, компенсации). Пороги —
`config/watch-thresholds.json`. Правила — `lib/watchRules.js`.

## Настройка

### 1. Секреты репозитория

Settings → Secrets and variables → Actions → New repository secret:

| Секрет | Что это |
|---|---|
| `Wildberries_API` | токен WB с категориями Финансы, Аналитика, Статистика, Маркетплейс |
| `TELEGRAM_BOT_TOKEN` | токен бота от @BotFather (тот же, что у бота проекта) |
| `TELEGRAM_ALLOWED_CHAT` | chat id получателя; несколько — через запятую |

### 2. Расписание

`.github/workflows/wb-watch.yml`, cron `0 4,15 * * *` (UTC) —
**07:00 и 18:00 МСК**. GitHub может задержать запуск на несколько минут.

Кнопка «Run workflow» на вкладке Actions запускает проверку вручную; там же
переключатель `dry_run` — показать сообщение, ничего не отправляя.

### 3. Установка на Mac Mini (рекомендуемый способ)

Сторожу не нужны ни порт, ни Caddy, ни Tailscale Funnel — это задача по
расписанию, соседние сервисы она не задевает. Ставится одним скриптом:

```bash
git clone https://github.com/SolexVK/wb-headless.git ~/wb-headless
cd ~/wb-headless
git checkout claude/wildberries-branch-fines-costs-tn58of
bash scripts/mac-mini-install.sh
```

Скрипт идемпотентный (можно запускать повторно): проверит node, поставит
зависимости, создаст пустой `.env` с правами 600 и загрузит LaunchAgent
`com.wbheadless.finewatch` на 07:00 и 18:00 по времени машины. Чужие агенты
он не трогает.

**Куда вписывать секреты.** Только в `~/wb-headless/.env` на самой машине:

```bash
nano ~/wb-headless/.env
```

```
Wildberries_API=<токен WB: Финансы, Аналитика, Статистика, Маркетплейс>
TELEGRAM_BOT_TOKEN=<токен от @BotFather>
TELEGRAM_ALLOWED_CHAT=<ваш chat id>
```

Файл лежит вне git (`.gitignore`), права 600 — читает только владелец.
**Ни в чат, ни в команды терминала, ни в репозиторий секреты вставлять не нужно:**
всё, что видит сторож и его проверки, — это маска вида `eyJh…Gi2g (len 424)`.
Если токен всё же где-то засветился — отзовите его в кабинете WB / у @BotFather
и выпустите новый; правка только в `.env`, код менять не придётся.

**Проверка после установки** (по возрастанию последствий):

```bash
cd ~/wb-headless
node scripts/wb-watch-selftest.mjs          # ничего не отправляет
node scripts/wb-watch-selftest.mjs --send   # одно тестовое сообщение в чат
node agent-wb-watch.mjs --dry-run           # полный анализ, без отправки
./scripts/run-watch.sh                      # боевой прогон, как по расписанию
```

Self-test проверяет: права на `.env`, срок и категории токена WB, живой ответ
API, доступность бота (`getMe`) и список получателей. Секреты при этом
маскируются.

**Управление:**

```bash
tail -f ~/wb-headless/logs/wb-watch.log             # что делал сторож
launchctl list | grep finewatch                     # загружен ли агент
launchctl bootout gui/$UID/com.wbheadless.finewatch # выключить
launchctl bootstrap gui/$UID ~/Library/LaunchAgents/com.wbheadless.finewatch.plist
```

Часы можно изменить: `WATCH_HOUR_MORNING=8 WATCH_HOUR_EVENING=20 bash scripts/mac-mini-install.sh`.
Время — по часовому поясу машины; если он не МСК, скрипт об этом предупредит.

Обычный cron (если launchd не нужен):

```cron
0 7,18 * * *  cd /path/to/wb-headless && ./scripts/run-watch.sh
```

## Как читать сообщения

Проблемы отсортированы по важности: 🔴 критично → 🟠 серьёзно → 🟡 внимание.
Пометка «(новое)» означает, что об этой находке ещё не сообщали — сторож помнит
историю в `state/wb-watch-state.json` (workflow коммитит файл обратно в репозиторий),
поэтому вечерняя проверка не выдаёт утренние проблемы за свежие.

К сообщению прикладываются PDF: расследование по штрафам и по логистике —
те же, что делает `report-forensics.mjs`.

## Переменные окружения

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `WB_API_TOKEN` / `Wildberries_API` | — | токен WB |
| `TELEGRAM_BOT_TOKEN` | — | токен бота |
| `TELEGRAM_ALLOWED_CHAT` (или `…CHATS`) | — | получатели |
| `WATCH_WINDOW_DAYS` | `3` | окно проверки, дней |
| `WATCH_BASELINE_DAYS` | `30` | база сравнения для всплесков |
| `WATCH_STATE_FILE` | `state/wb-watch-state.json` | файл состояния |
| `CHROME_PATH` / `CHROMIUM_PATH` | автопоиск | браузер для PDF |

## Если что-то не так

| Симптом | Причина и лечение |
|---|---|
| «Telegram не настроен» | нет `TELEGRAM_BOT_TOKEN` или `TELEGRAM_ALLOWED_CHAT` |
| «Не найден токен WB» | нет `WB_API_TOKEN` / `Wildberries_API` |
| Сообщение пришло, PDF нет | не нашёлся Chromium — задайте `CHROME_PATH`; текст всё равно отправляется |
| Запуск идёт минутами | так и задумано: у финансовых методов WB лимит 1 запрос в минуту |
| Пустая детализация | WB ещё не закрыл отчёт за день; сторож сообщит об этом в сводке |
| Сторож молчит | проверьте вкладку Actions: workflow мог не запуститься или упасть на секретах |

## Ограничения

- Сторож видит только то, что WB уже провёл в отчёте. Списание за возврат
  приходит в день выдачи возврата, иногда через 1–2 недели после самого события.
- Отчёт за текущий день закрывается не сразу: утренняя проверка обычно видит
  данные по вчерашний день включительно.
- Оспаривание штрафов сторож не автоматизирует — он показывает, что и на каких
  основаниях оспаривать.
