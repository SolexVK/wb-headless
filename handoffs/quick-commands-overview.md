# Handoff: quick-commands-overview
_Обновлено: 2026-07-05 · ветка: claude/quick-commands-overview-ou4w33_

## Цель
Разобраться с быстрыми (слэш-)командами Claude Code и выстроить для пользователя
удобный рабочий процесс передачи состояния между сессиями/чатами. Итог —
собственные команды `/handoff` (сохранить состояние задачи в файл) и `/resume`
(возобновить работу из файла) с поддержкой параллельных задач через slug.

## Текущее состояние
Готово и работает. Команды созданы, закоммичены, запушены и уже подхвачены
средой (видны в списке доступных скиллов). Это первый пробный запуск `/handoff`
по самой этой сессии.

## Файлы, над которыми работали
- `.claude/skills/handoff/SKILL.md` — скилл `/handoff` (основной формат, с frontmatter)
- `.claude/skills/resume/SKILL.md` — скилл `/resume` (основной формат)
- `.claude/commands/handoff.md` — команда `/handoff` (запасной формат)
- `.claude/commands/resume.md` — команда `/resume` (запасной формат)
- `handoffs/quick-commands-overview.md` — этот файл (первый handoff)

## Что изменилось
- Введён рабочий процесс handoff: не один `handoff.md` в корне, а папка
  `handoffs/` с файлом на каждую задачу — `handoffs/<slug>.md`.
- Slug определяется так: явный аргумент команды, иначе — выводится из имени
  git-ветки (префикс `claude/` и хвост-хэш отбрасываются). Это защищает
  параллельные задачи от затирания.
- В `/handoff` встроены коммит и пуш — чтобы файл пережил эфемерный контейнер.
- В `/resume` встроена проверка: сначала ищет handoff по текущей ветке, при
  отсутствии — показывает список всех и спрашивает; прогоняет команды проверки;
  задаёт открытые вопросы прежде чем писать код.
- Структура handoff расширена относительно исходной идеи пользователя: добавлены
  разделы «Команды для проверки» и «Открытые вопросы».

## Что пробовали и НЕ сработало
- **Единый `handoff.md` в корне репо** — отвергнут: при параллельной работе в
  нескольких чатах файлы затирают друг друга. Заменён на папку `handoffs/` с
  slug'ами.
- Ничего технически не «ломалось» — сессия в основном объяснительная. Главный
  тупик был концептуальный (один файл vs папка), и он решён на этапе дизайна.

## Открытые вопросы (нужно решение пользователя)
1. **Стратегия видимости handoff-файлов.** Сейчас команды пишут в ТЕКУЩУЮ ветку
   (подход №1: возобновлять на той же ветке). Обсуждали альтернативу — складывать
   все handoff в `main`, чтобы любой новый чат видел все задачи разом (подход №2,
   требует slug'ов для изоляции). Пользователь пока не выбрал окончательно —
   оставили подход №1 как более безопасный. Ждёт реального опыта эксплуатации.
2. **Нужен ли PR** для этой ветки. Пока НЕ создавали (по умолчанию — только пуш
   в ветку). Создавать PR только по явной просьбе.

## Следующий шаг
Пользователю — опробовать цикл на практике: в новой сессии на этой же ветке
набрать `/resume` и убедиться, что состояние подхватывается корректно. При
параллельной задаче — проверить `/handoff <slug>` с явным именем. По итогам
опыта вернуться к открытому вопросу №1 (видимость через `main` или нет).
