# Доступ к planner: Telegram-вход, роли и приглашения

Кто и что видит в планировщике. Инструмент работает на VPS за Caddy
(`https://planner.aidemiko.ru/`), секреты живут только в `planner/data/.env`
на сервере — этот файл в репозиторий не попадает.

## Модель доступа коротко

| Роль | Как получают | Что видит | Что может менять |
|---|---|---|---|
| **Владелец** (админ) | `OWNER_TELEGRAM_ID` в `.env` | всё | всё, плюс `/admin` |
| **Сотрудник** (`staff`) | состоит в рабочей группе Telegram | Гант, План по размерам, Ранг сезонности, Отчёты, Юнит-экономика | ничего в общей базе; юнит-экономика — личный черновик |
| **Гость** (`guest`) | просто открыл адрес демо-стенда | Гант, План по размерам, Ранг сезонности, Отчёты | ничего |

Главное правило: **незнакомый Telegram-аккаунт сам себя зарегистрировать не может.**
Условие доступа одно — членство в рабочей группе. Завести новый аккаунт в Telegram
бессмысленно: в группе его нет, значит отказ.

Права проверяет сервер, а не интерфейс. Даже если подделать запрос в обход
страницы, запись отрежется: сервер берёт свою версию состояния и накладывает
только те секции, которые роли разрешены (`lib/permissions.js`).

## 1. Бот и владелец

1. **@BotFather** → `/newbot` → имя и username бота. Токен — секрет.
2. Там же `/setdomain` → выбрать бота → `planner.aidemiko.ru` (без `https://`).
   Без этого шага кнопка входа Telegram не работает.
3. Написать боту `/start` — иначе он не сможет прислать вам уведомление.
4. Свой числовой ID — у **@userinfobot**. Это не секрет.

## 2. Переменные в `planner/data/.env`

```bash
TELEGRAM_BOT_TOKEN=123456789:AA_токен_из_BotFather
TELEGRAM_BOT_USERNAME=aidemiko_planner_bot
OWNER_TELEGRAM_ID=882257781
STAFF_CHAT_ID=-1001234567890          # id рабочей группы: кто в ней — тот сотрудник
# INVITE_STAFF_CODE=<запасной путь, если группу не используем>
# PLANNER_LOGIN_CODE=<резервный вход владельцем, если виджет Telegram не грузится>
```

Коды генерировать случайными, не короче 8 символов (короче — сервер их не примет):

```bash
openssl rand -hex 12
```

После правки: `sudo systemctl restart planner`. В логе
(`journalctl -u planner -n 20`) должно быть
`[planner] Telegram-авторизация ВКЛЮЧЕНА (бот @…, владелец …)`.

С этого момента прежний пароль (`PLANNER_PASSWORD`) больше не спрашивается —
его место занял Telegram-вход. Переменную можно оставить: она снова заработает,
если убрать токен бота.

## 3. Как пускать сотрудников

Никаких ссылок с кодами. Условие — членство в рабочей группе Telegram.

**Настройка (один раз):**
1. Создайте рабочую группу (или возьмите существующую) и добавьте в неё бота.
2. Узнайте id группы: отправьте в неё любое сообщение, затем на сервере
   ```bash
   source /opt/planner/planner/data/.env
   curl -s "https://api.telegram.org/bot$TELEGRAM_BOT_TOKEN/getUpdates" | grep -o '"chat":{"id":-[0-9]*' | head -1
   ```
   Id группы — отрицательное число вида `-1001234567890`.
3. Впишите его в `.env` как `STAFF_CHAT_ID=` и перезапустите службу.

**Дальше всё само.** Сотрудник открывает `https://planner.aidemiko.ru/`, жмёт вход
через Telegram — бот сверяет членство и выдаёт права сотрудника. Вам приходит
уведомление, кто подключился. Подтверждать ничего не нужно.

**Отзыв доступа — убрать человека из группы.** При следующем входе его не пустят,
а активная сессия закроется при ближайшей фоновой проверке (раз в час на человека);
владельцу придёт уведомление. Нужно немедленно — `/admin` → «Заблокировать»,
это рвёт сессию сразу.

Если группы почему-то нет, остаётся запасной путь — ссылка с кодом
(`INVITE_STAFF_CODE` в `.env`, адрес вида `/login?i=КОД`). По умолчанию он выключен
и нужен только как страховка.

## 4. Юнит-экономика: личный черновик

У сотрудника вкладка «Юнит-экономика» открыта на просмотр, но калькулятор
рабочий: он вводит свою себестоимость, цены, ДРР — всё считается, ничего не
уходит в общую базу. Черновик хранится в его браузере и переживает перезагрузку
страницы; кнопка «Сбросить черновик» возвращает общие цифры.

Так сделано намеренно: данные `unit` — общие для всех, и правка сотрудника
меняла бы цифры и у владельца. На другие расчёты юнит-экономика не влияет:
её читает только собственный экран, ни планирование, ни Гант, ни план по
размерам к ней не обращаются.

## 5. Ручное управление доступом (`/admin`)

Нужно, только если хочется отойти от пресета роли:

- выдать доступ по Telegram-ID вручную (без приглашения);
- расширить права конкретному человеку — например, разрешить ему **строить**
  отчёты сезонности (`Ранг сезонности` → «правка»). По умолчанию сотрудник видит
  только уже построенные: построение тратит лимит запросов MPStats;
- поставить срок доступа (пусто = бессрочно), заблокировать, удалить.

Одна активная сессия на аккаунт: новый вход вытесняет предыдущий, «поделиться»
доступом не получится.

## 6. Что где лежит

- Пользователи и права — таблица `users` в `planner/data/planner.db`.
- Секреты — `planner/data/.env` (0600, владелец `planner`).
- Секрет подписи сессий — `SESSION_SECRET` или автоген в `meta.session_secret`.
  Смена секрета разлогинивает всех.
