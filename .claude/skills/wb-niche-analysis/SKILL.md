# WB Niche Analysis — стоит ли заходить в нишу

Навык оценивает нишу Wildberries **от категории** (путь WB) по данным MPStats и выдаёт
решение «заходить / заходить осторожно / не заходить» с указанием узкого места.

Пять измерений (каждое 0–20 → сводный скоринг 0–100):

1. **Ёмкость рынка** — выручка/штуки ниши, ср. выручка на «живой» товар, упущенная выручка.
2. **Сезонность** — зависимость от времени года, пик/спад, окно входа (из истории за ~6 лет).
3. **Тренды** — куда движется ниша: **год к году** (последние 12 мес vs предыдущие 12, без сезонности).
4. **Уровень конкуренции** — продавцы/бренды, монополизация (доля выручки топ-10), барьер по отзывам.
5. **Насыщенность** — доля товаров с продажами (мёртвые карточки = скрытая насыщенность).

Плюс блоки для точного решения: **реализация остатка** (метод Овчинникова: продажи ÷ средний
остаток, на месяц), **экономика единицы** (маржа/безубыток/коридор по себестоимости), **процент
выкупа**, **возраст карточек в топе**, **перспективный ценовой сегмент**, **планка входа**
(реклама+контент топа), **риск-флаги** (жёсткие стопы) и **заключение с рекомендацией**.
Отчёт — консоль + CSV + JSON + **компактный PDF** с цветными графиками.

Методы/поля MPStats — [`references/mpstats.md`](references/mpstats.md).
Формулы, пороги и калибровка скоринга — [`references/scoring.md`](references/scoring.md).
Глубокая методика (источники, ограничения API, план) — `docs/niche-analysis-methodology.md` в корне.

## Воркфлоу (интейк → прогон)
При запросе на анализ ниши собери вводные (можно одним сообщением), затем прогони:
1. **Ниша** — категория словами или путь. Путь резолвь через
   `node scripts/wb-category.mjs <слова>` (печатает пути дерева; выбери лист-категорию).
2. **Плюс-ключи** и **минус-ключи** (для отбора уточняющих фраз из Оракула). Минус может включать
   спец-токен **`@цвета`** — раскрывается в список цветовых корней (бел/чёрн/син/…).
3. **Период** — недавний завершённый месяц для «живого» спроса (длинный период раздувает
   насыщенность; реализация нормируется на месяц). Сезонность/тренд период не трогает.
4. **Себестоимость** — для блока экономики.
5. **Файл Оракула** (xlsx/csv) — для частотности и разбивки по фразам. Без него отчёт по всей
   категории (сузить до атрибута, напр. «в клетку», API не даёт).
Перед прогоном покажи отобранные фразы на сверку (`scripts/oracle-phrases.mjs`).

## Когда использовать
Любой запрос про оценку/выбор ниши или категории WB: «анализ ниши», «ёмкость рынка»,
«стоит ли заходить», «насыщенность/конкуренция в категории», «тренд ниши», «сезонность».
Триггеры: Wildberries, WB, ниша, категория, ёмкость, насыщенность, монополизация, тренд, сезонность.

> Отличие от `wb-competitor-analysis`: тот навык разбирает конкурентов и готовит **план доработки
> своей карточки**. Этот — оценивает **саму нишу** (решение о входе). Часто используются вместе:
> сначала оценить нишу (этот навык), затем — план карточки (competitor-analysis).

## Предпосылки (проверить один раз)
1. `MPSTATS_TOKEN` в `.env` в корне репозитория (или в env). Токен НЕ хардкодить.
2. Домен `mpstats.io` разрешён сетевой политикой окружения.
3. У токена **дневной лимит запросов** MPStats. При 429/«лимит запросов» — сказать пользователю
   подождать/поднять тариф, а не «нет данных».

## Разбор запроса пользователя → вход
- **Путь категории WB** (обязателен) — напр. `Женщинам/Одежда/Платья`. Если пользователь назвал
  нишу словами («женские платья»), собери путь: пол-корень (`Женщинам`/`Мужчинам`/`Детям`) + предмет.
  Если путь неоднозначен — уточни или предложи варианты.
- **Себестоимость** (опц.) — `NICHE_COST` / 7-й аргумент. Включает блок экономики: точку
  безубыточности, маржинальный коридор и вердикт по марже при медианной цене ниши.
- **Период** — по умолчанию последние 30 дней (`REPORT_DAYS`). Период влияет **только** на ёмкость,
  насыщенность и конкуренцию — бери недавние 30 дней (длинный период раздувает кумулятивы и гонит
  % с продажами к 100%). **Сезонность и тренд длинный период НЕ требуют**: `category/trends` отдаёт
  помесячную историю за ~6 лет независимо от `d1/d2`, поэтому считаются на любом прогоне.
- **Поисковые (уточняющие) фразы** (опц., фаза 2) — `NICHE_QUERY` / 4-й аргумент. Одна фраза или
  несколько через «;». Для каждой — анализ ТОП-выдачи (выручка, % с продажами, монополизация топ-10)
  и, при наличии чисел, спрос:предложение; при нескольких фразах — сравнительная таблица.
- **Частотность и кол-во карточек** (опц.) — для метрики «спрос:предложение» (частотность ÷ карточки,
  порог 10:1). Оба числа — из **Оракула Wildbox** (в API MPStats их нет). Способы передать:
  - одиночная фраза: 5-й и 6-й аргументы (`… "фраза" <частота> <карточки>`) или `NICHE_FREQ`/`NICHE_SUPPLY`;
  - несколько фраз: в самой спецификации — `«фраза=частота:карточки; фраза2=частота:карточки»`.
  Без чисел блок покажет метрики ТОП-выдачи и примечание.

> ⚠️ 5 измерений ниши (в т.ч. **сезонность**) считаются на **всю категорию** пути — по конкретной
> уточняющей фразе сезонности в API нет. Фразы дают срез спроса/предложения и ТОП-выдачи, но их
> собственную сезонность не покажут (напр. «тёплая рубашка» сезонит осенью, а категория рубашек в
> целом — летом).

## Запуск
```bash
cd <repo root с .env>

# период = последние 30 дней (сезонность/тренд подтянутся из истории сами)
NICHE_PATH="Женщинам/Блузки и рубашки/Рубашка" node report-niche.js

# явный недавний период для ёмкости/насыщенности
node report-niche.js "Женщинам/Блузки и рубашки/Рубашка" 2026-06-12 2026-07-11

# + одна фраза (фаза 2); freq+supply — для «спрос:предложение» (из Оракула Wildbox)
node report-niche.js "Женщинам/Блузки и рубашки/Рубашка" 2026-06-12 2026-07-11 "рубашка в клетку" 30000 2500

# + несколько уточняющих фраз (сравнение спрос:предложение)
node report-niche.js "Женщинам/Блузки и рубашки/Рубашка" 2026-06-12 2026-07-11 \
  "рубашка в клетку тёплая=4569:4471; рубашка в клетку фланелевая=2086:2966"

# 0) резолв пути категории по словам
node scripts/wb-category.mjs женские рубашки

# ПОЛНЫЙ прогон: Оракул + плюс/минус-ключи (@цвета) + себестоимость
NICHE_ORACLE=oracle.xlsx \
NICHE_PLUS="клетка,оверсайз,демисезон,осень,фланель,длинный рукав" \
NICHE_MINUS="летняя,лен,муслин,мужская,детская,блузка,капюшон,джинс,@цвета" \
NICHE_COST=536 \
  node report-niche.js "Женщинам/Блузки и рубашки/Рубашка" 2025-08-01 2026-03-31
```

### Отбор фраз из Оракула (плюс/минус-ключи)
Вместо ручного ввода фраз можно скормить **выгрузку «Оракул запросов»** (xlsx или csv) — тогда
частотность и кол-во карточек подтянутся автоматически, а фразы отфильтруются по ключам:
- `NICHE_ORACLE` — путь к файлу выгрузки;
- `NICHE_PLUS` — плюс-ключи через запятую: фраза берётся, если есть **хотя бы один** (совпадение по
  корню слова: «клетка»→«в клетку», «фланель»→«фланелевая», «осень»→«осенняя»);
- `NICHE_MINUS` — минус-ключи: фраза с любым из них **выкидывается**. Спец-токен **`@цвета`**
  раскрывается в список цветовых корней (исключить любые упоминания цвета).

Предпросмотр отбора **без запросов к MPStats** (сверить список и получить спецификацию):
```bash
node scripts/oracle-phrases.mjs oracle.xlsx "клетка,оверсайз,фланель" "летняя,блузка,@цвета"
```
Через HTTP (сервис запущен): `GET /reports/niche?path=<категория>&d1=&d2=&query=<фраза>&freq=<частотность>&format=json|csv`
с заголовком `x-api-key`.

Результат: сводка в консоль (скоринг + 5 блоков + цифры + топ-продавцы + примечания),
`reports-output/niche-<категория>-<d1>_<d2>.csv` (товары) и `.json` (весь анализ).

Результат: консоль-сводка + заключение, `reports-output/niche-<категория>-<d1>_<d2>.{pdf,html,csv,json}`.
**PDF** — компактный отчёт с цветными графиками (собирается, если найден Chromium; `NICHE_PDF=0` отключает).

### Необязательные переменные
`NICHE_COST` — себестоимость (блок экономики). `NICHE_MAX_ROWS` (5000) — предел выгрузки товаров.
`NICHE_PAGE_SIZE` (500) — размер страницы. `REPORT_DAYS` (30) — период по умолчанию.
`NICHE_THRESHOLDS` — свой файл порогов (`config/niche-thresholds.json`). `CHROMIUM_PATH` — путь к Chromium.

### Калибровка скоринга
Пороги вердикта — в `config/niche-thresholds.json` (монополизация, демпинг-аналоги, ёмкость,
насыщенность, спрос:предложение). Правь под свои ниши; подробности — `references/scoring.md`.

## Как читать результат
- **Заключение о входе** (верх PDF) — буллеты на цифрах + риск-флаги + рекомендация. Главный вывод.
- **Вердикт + узкое место** — блок с минимальным баллом «валит» нишу. Жёсткие стопы (монополизация
  ≥40%, затоварка, барьер отзывов, убыточность) понижают вердикт «Заходить» → «Осторожно».
- **5 измерений** — рядом с баллом 0–20 показаны РЕАЛЬНЫЕ цифры (ёмкость ₽/мес, размах сезонности,
  тренд % г/г, монополизация/продавцы, % с продажами) — балл не абстрактный.
- **Реализация остатка по месяцам** — временнáя диаграмма за весь период: зелёные столбцы со
  стрелкой ↑ (реализация >1.0) — окна, где спрос обгонял предложение (когда выгоднее продавать).
  Метод Овчинникова: продажи ÷ средний остаток. Итог за период + оборот (дней).
- **Экономика** — точка безубыточности, коридор маржи 25–30%, маржа при медианной цене ниши, плюс
  **достижимый объём при целевой марже 30%**: сколько шт/мес, выручки и прибыли на карточку в
  целевом ценовом сегменте.
- **Ёмкость** — смотри «на живой товар» (мёртвые занижают). **Насыщенность** — % с продажами.
- **Тренд** — год к году (без сезонности) + «последние 3 мес г/г». **Сезонность** — пик/спад/окно
  входа + рекомендация по торговле **вне сезона** (товар продаётся круглый год).
- **Перспективные сегменты** — два лучших: высокая выручка на карточку при меньшей конкуренции
  (приоритет дорогим сегментам — массовость не нужна).
- **Топ-продавцы** — выручка ₽/мес + доля %, бренд и ссылка на витрину продавца на WB.
- **Планка входа** — экспресс-ориентиры для будущей карточки: цель по объёму продаж, доля топа в
  рекламе, медиана фото/видео, барьер отзывов, размерный ряд и длина описания — что нужно перебить.
- **Уточняющие фразы** — ранжированы по реализации остатка (мини-бар); в «спрос:предл.» стрелка
  ↑ (зелёная) — спрос выше предложения, ↓ (красная) — предложение выше спроса.

## Что навык НЕ закрывает (по методике — вручную/Wildbox)
- «Оракул запросов», рейтинг ниши по 15+ показателям, сезонность за 3 года с ML — UI Wildbox/MPStats.
- **Частотность** поискового запроса — эндпоинт `/wb/get/keywords` в API есть (запросы категории),
  но формат фильтра публично не документирован (отвечает «Не корректные условия фильтра»). Пока
  частотность и кол-во карточек берём из выгрузки Оракула. Основной сигнал спрос/предложение —
  **реализация остатка** (продажи ÷ остаток), частотность не требует.
- Принадлежность % признаков, конверсии по слайдам, полки — не оцифровывается MPStats.

> ⚠️ Данные MPStats **оценочные** (восстановление по остаткам/выкупам) — для сравнения и ранжирования,
> не как бухгалтерия.
