# Скоринг ниши: формулы, пороги, калибровка

Движок — `lib/nicheAnalysis.js` (функция `buildNicheAnalysis`). Каждое из 5 измерений даёт
0–20 баллов → сумма 0–100. Пороги вынесены в `DEFAULT_THRESHOLDS` (там же) и калибруются.
Денежные пороги заданы **на 30 дней** — движок нормирует период к месяцу (`k = 30/дней`).

## Вердикт по сумме
| Сумма | Вердикт |
|---|---|
| ≥ 70 | 🟢 Заходить |
| 45–69 | 🟡 Заходить осторожно |
| < 45 | 🔴 Не заходить |

**Узкое место** = блок с минимальным баллом (что «валит» нишу).

## 1. Ёмкость (0–20)
Два подсигнала по 10:
- `выручка/мес` (нормированная): шкала `revLowMonth` (3 млн) → `revHighMonth` (30 млн) → 0…10.
- `выручка/мес на «живой» товар`: шкала `perActiveLowMonth` (30 тыс) → `perActiveHighMonth` (150 тыс) → 0…10.

Дополнительно в отчёте: упущенная выручка `Σ lost_profit` (неудовлетворённый спрос = место для входа),
медианная цена.

> **Источник данных (`dataBasis`).** Выручка/штуки/упущенка/насыщенность берутся из
> `category/price_segmentation` — сегменты покрывают **всю нишу**, поэтому не смещаются при
> усечении выгрузки (`NICHE_MAX_ROWS`). Если сегменты недоступны — fallback на сумму по
> выгруженным top-N (тогда `dataBasis='analyzed'`, и % с продажами может быть завышен → есть note).
> Проверено живым токеном: `Σ items` сегментов ≈ `total` категории.

## 2. Сезонность (0–20)
`category/trends` отдаёт **помесячную историю за ~6 лет и игнорирует `d1/d2`** (проверено живым
токеном) — поэтому сезонность доступна **всегда**, даже на 30-дневном прогоне. Нужно ≥12 месяцев
истории, иначе **10 (нейтрально)**.
- Помесячный индекс = средняя выручка календарного месяца / средняя по месяцам (усреднение по годам).
- `strength` = (max − min) / средний индекс.
- `low` (≤0.15) → **16**, `moderate` (0.15–0.4) → **12**, `high` (≥0.4) → **8**.
- Пик-месяц, спад-месяц и **окно входа** (за 1 мес до пика — успеть накопить отзывы/органику).

## 3. Тренд (0–20)
Из той же помесячной истории. Так как ряд — за ~6 лет, «половина vs половина» была бы 6-летним
ростом; поэтому считаем **год к году** (без сезонности):
- `growthPct` = (Σ выручки последних 12 мес − предыдущих 12) / предыдущие 12 × 100.
- Дополнительно `recentYoyPct` — последние 3 мес vs те же 3 мес год назад (свежая динамика).
- Шкала: `downPct` (−10) → `upPct` (+10) → 0…20. Направление: `up` ≥ +10% · `flat` · `down` ≤ −10%.
- Штраф −3, если товаров с продажами растёт быстрее выручки на >30 п.п. г/г (ниша забивается).
- При короткой истории (<24 мес) — fallback на «половина vs половина» (`basis='half'`).

## 4. Конкуренция (0–20)
- **Монополизация** = доля выручки топ-10 товаров (`top10RevenueSharePct`).
  Шкала обратная: ≤ `monopolyHealthy` (15%) → 20; ≥ `monopolyHigh` (40%) → 0; линейно между.
- Штраф −3, если продавцов < `thinSellers` (10) — тонкая/монопольная ниша.
- Штраф −4, если медиана отзывов у топ-20 > `reviewsBarrier` (3000) — высокий барьер соц-доказательства.
- Счётчики продавцов/брендов берутся из спец-эндпоинтов `category/sellers|brands` (авторитетно,
  не урезано лимитом выгрузки); при их недоступности — из выборки товаров.

Ярлыки: ≤15% «здоровая» · 15–40% «умеренная монополизация» · ≥40% «высокая монополизация».
(Пороги согласуются с MarketGuru/Moneyplace/Wildbox.)

## 5. Насыщенность (0–20)
- `% товаров с продажами` = `Σ items_with_sells / Σ items` по ценовым сегментам (**вся ниша**,
  не смещено усечением). Шкала `withSalesBad` (30%) → `withSalesGood` (60%) → 0…20. Низкий % =
  много мёртвых карточек = скрытая насыщенность. Без сегментов — по выгруженным top-N (смещение).

## ТОП-выдача по запросу (фаза 2, блок `queryDemand`, не входит в 0–100)
Если задан `query` — отдельный блок из `POST /analytics/v1/wb/search/items`.
**Важно (проверено живым токеном): эндпоинт отдаёт максимум ~100 карточек** (топ выдачи), поэтому
это анализ ВЕРХУШКИ, а не всей ниши по запросу:
- Выручка топа, ср. на карточку и на «живую», % с продажами, монополизация топ-10, упущенная
  выручка, медиана цены продажи (`topCapped=true`, если выдача упёрлась в 100).
- **Спрос:предложение** = частотность ÷ кол-во карточек — считается ТОЛЬКО если переданы ОБА числа
  (`frequency` + `supplyCards`), т.к. в API MPStats их нет (источник — Оракул Wildbox). Пороги
  `ratioHigh` (10) / `ratioMid` (3): ≥10:1 «спрос превышает предложение», 3–10 «умеренный»,
  <3 «предложение насыщено».

> Блок `queryDemand` **не меняет** core-скоринг 0–100 (тот стабильно от категории) — обогащает вывод.

## Калибровка
Пороги лежат в **`config/niche-thresholds.json`** — правь их там (файл перекрывает встроенные
дефолты по ключам; недостающие берутся из дефолтов, лишние игнорируются; битый файл → дефолты).
Другой путь можно задать через env `NICHE_THRESHOLDS=/path/to.json`. Программно — передать
`thresholds` в `buildNicheAnalysis(...)`. Денежные пороги (`*Month`) — под средний чек своих ниш:
для дорогих категорий подними `perActive*`, для массовых дешёвых — опусти.
