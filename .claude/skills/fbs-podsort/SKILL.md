# /fbs-podsort — расчёт подсорта FBS

Готовит рекомендацию к пополнению по каждому нашему FF-складу и пробный завоз
новинок/докладок. Это финальная согласованная логика — основа будущего
веб-инструмента.

## Что считает (финальная логика)

- **Только FF-склады (FBS).** FBO не учитываем (распродаём, не завозим).
- **По КАЖДОМУ складу отдельно.** Скорость продаж и остаток — по конкретному
  складу (`warehouseId|nmID`), не суммарно по сети.
- **Лид-тайм заложен в заказ.** Горизонт = `leadMax + cover` дн. Статус
  «разрыв до поставки» = закончится раньше `leadMin` (подсорт не успеет доехать),
  «риск разрыва» = может не дожить до `leadMax`.
- **Ассортимент в работе — белый список** номеров артикулов (`articles`). Весь
  отчёт (и подсорт, и завоз) считается ТОЛЬКО по ним; сезонные вне списка — нет.
- **Пробный завоз (seed):** для (склад × артикул), где товара на складе ещё не
  было, — `seedMin` шт **на каждый размер**. Тип: «новинка» (не была ни на одном
  FF) / «докладка» (продаётся на других складах, но на этом не было).
- Сортировка: артикул № → цвет → количество.

## Настройки — `config/replenishment.json`

Единый источник параметров (и бэкенд будущей формы веб-инструмента):

```json
{
  "articles": ["002","003","023","028","029","030","036"],
  "seedMin": 10, "velocityDays": 28, "leadMax": 18, "leadMin": 12, "cover": 28
}
```

Меняем список/параметры здесь — пересчёт подхватит. Любой параметр можно
переопределить аргументом: `npm run fbs:replenish -- --articles 002,003 --cover 21`.

## Как запустить (повторный расчёт — одна команда)

```bash
npm run fbs:podsort
```

Выполняет по шагам (нужен токен WB, ~1–2 мин):
1. `fbs:stock`         — остатки FBS → `reports-output/fbs-stock.json`
2. `fbs:replenish`     — расчёт подсорта → `reports-output/fbs-replenishment.json`
3. `fbs:replenish:dash`— HTML-дашборд → `reports-output/fbs-replenishment-dashboard.html` (+ `.artifact.html`)
4. `fbs:xlsx`          — Excel → `reports-output/fbs-podsort.xlsx`

Отдельные шаги при необходимости: `npm run fbs:replenish -- <args>` затем
`npm run fbs:replenish:dash` / `npm run fbs:xlsx`.

## Что отдать пользователю

- Опубликовать `reports-output/fbs-replenishment-dashboard.artifact.html`
  инструментом **Artifact** (favicon 📦) и прислать ссылку.
- Прислать `reports-output/fbs-podsort.xlsx` через **SendUserFile** (attach) и
  `…dashboard.html` (render).
- Коротко: подсорт всего (шт), строк в риске, пробный завоз (позиций/шт) —
  из `reports-output/fbs-replenishment.json` → `totals`.

## Файлы (переиспользуются HTML-сервисом)

- `scripts/fbs-stock.mjs` — остатки FBS (cards→штрихкоды→/api/v3/stocks/{id}).
- `scripts/fbs-replenishment.mjs` — движок подсорта (вся логика выше). JSON-снимок
  на stdout (`--json`) — готовый вход для веб-сервиса.
- `scripts/fbs-replenishment-dashboard.mjs` — рендер дашборда из снимка.
- `scripts/fbs-xlsx.py` — Excel из снимка (openpyxl).
- `config/replenishment.json` — настройки.

## Заметки

- Скорость склада, где сейчас 0, берётся из продаж ранее в окне, когда остаток
  был; склад, который никогда не продавал артикул, — не прогнозируем (уходит в
  пробный завоз как «докладка»/«новинка»).
- Данные живые: остатки/склады меняются между прогонами.
- `reports-output/` в `.gitignore` — коммитятся только генераторы.
- Excel собирается со значениями (не формулами): LibreOffice-пересчёт в этом
  окружении не укладывается в тайм-аут, а значения — уже результат движка.
