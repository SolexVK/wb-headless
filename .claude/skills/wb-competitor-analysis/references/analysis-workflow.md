# Полный воркфлоу конкурентного анализа → план доработки карточки

Инструмент состоит из **двух слоёв**:

- **Слой A — оцифрованный (движок `wb_analyze.py` по MPStats).** Автоматически: ёмкость ниши,
  ТОП-конкуренты, ценовой коридор и «привлекательная цена», цвет-принадлежность (прокси),
  контент-бенчмарк, сезонность, гэп-анализ своей карточки.
- **Слой B — ручной (по методике из базы знаний).** То, что MPStats не отдаёт: принадлежность %
  признаков (Wildbox), смыслы/листинг (скриншоты + Gem), конверсии по запросам, полки/инфографика.

Итог для пользователя = **план доработки карточки**, где слой A даёт цифры-цели, а слой B —
качественные правки. Ниже — как их соединить.

---

## Шаг 0. Собрать вводные

- Ниша: пол + предмет + принт, или явный `--path`, или фраза `--query`.
- **Свой артикул** (`--my-sku`) — если есть: включает гэп-анализ (блок G) и адресный план.
- Период (`--days`, по умолчанию 30). ⚠️ За **будущие** даты MPStats пусто — если срез пустой,
  проверь период (сегодняшняя дата контейнера может опережать горизонт данных MPStats).

## Шаг 1. Прогнать движок (слой A)

```bash
cd <repo с .env>
python3 .claude/skills/wb-competitor-analysis/wb_analyze.py \
  --gender women --item рубашка --pattern полоска \
  --my-sku <ваш_артикул> --top 10 --days 30 \
  --json-out /tmp/wb.json
```

Проверить в `stderr` выбранный `[path]` и альтернативы; если срез не тот — перезапустить с `--path`.
Разделы отчёта A–H — см. docstring движка. Из блоков берём **цели**:

- **C** → цена-цель (зона привлекательной цены).
- **E** → контент-цели (фото ≥ медианы, видео, рейтинг ≥ медианы, SEO-слов).
- **D** → доминирующие цвета (принадлежность-прокси).
- **G/H** → готовые гэпы своей карточки.

## Шаг 2. Принадлежность % (слой B — Wildbox)

MPStats даёт цвет-прокси; полный порог входа — только Wildbox (главы 13, 18, 19).

1. Wildbox → SEO → **«Запросы у топов поиска»** (глубина топ-100) → главный запрос → «Сформировать».
2. Разложить свой товар на **сегменты/подсегменты** (материал, назначение, стиль, ЦА, цена, тренд,
   размер, функциональность, конструктив, цвет) — можно через ChatGPT: фото + структура сегментов.
3. По каждому признаку — **% присутствия** в топе.
4. **Правило порога:** признак < ~30% → вход в этот запрос закрыт; высокий % → **обязателен**,
   выносить на первое фото (пример: мембрана 86% — «кричать» на 1-м слайде).

→ В план: список запросов, куда карточка проходит по принадлежности, и признаки-«обязательны».

## Шаг 3. Отбор 5 карточек и таблица листинга (слой B — глава 04)

1. Взять из блока **F** отчёта (карточки под разбор) + при наличии свою → **5 уникальных**.
2. Скриншоты **каждого слайда** 5 карточек → таблица-линейка (Google-таблица / Miro).
3. Искать **закономерности**: у топов листинг схож; что усилено на первых слайдах.
4. Фиксировать листинги топов; через **1–2 недели** пересравнить — что поменяли (копировать удачное).

## Шаг 4. Смыслы и конверсии по запросам (слой B — глава 04)

- Теги смыслов: из **хвостов запросов** выписывать только уникальные слова-триггеры (осень, 104–110,
  «набор», «для лица»). Частотные — **выше** в листинге, менее частотные — ниже.
- **Gem → Competition** (до 5 карточек, ≈140 ₽/сравнение) или **Keywords** (Wildbox, без Gem):
  где конкурент **сильнее в корзину/заказ** по запросу → зайти в его листинг → понять **почему** →
  повторить/усилить. Разрыв «корзина высокая / заказ низкий» = что-то отталкивает на решении.
- Разметку смыслов по ~10 поставщикам можно доверить ChatGPT (кластеры смыслов; красный фон = низкие
  метрики, зелёный = хорошие конверсии).

## Шаг 5. Полки и инфографика (слой B — глава 18)

- Метод доски/бота: кто **чаще в полках** = топ = лучшая клиентоориентированная инфографика.
- Скопировать **видимые характеристики топов 1-в-1** (свои реальные значения — только где физически
  отличаешься: люмены, мА·ч, состав). Заполнить характеристики по максимуму категорий.
- Проверить парность/допы (2 шт vs 1), сезонность, размерный ряд (каждый размер — отдельная выдача).

## Шаг 6. Собрать план доработки

Свести слой A (цифры) и слой B (качество) в единый чек-лист. Шаблон ниже.

---

## Шаблон плана доработки карточки

```
КАРТОЧКА: <артикул / название>            НИША: <путь> · период <d1–d2>

1. ЦЕНА (блок C/G)
   [ ] Текущая: ____ ₽ → цель (привлекательная цена): ____–____ ₽; шагами 3–5%, держать 7–14 дней

2. ПРИНАДЛЕЖНОСТЬ (шаг 2, глава 13)
   [ ] Запросы, куда проходим по %: ____________
   [ ] Обязательные признаки (высокий %): ____________  → вынести на 1-е фото
   [ ] Цвет: наш ____ vs доминирующие ____ → правка оттенка/названия?

3. КОНТЕНТ / ЛИСТИНГ (блоки E/F, шаги 3–5)
   [ ] Фото: ____ → цель ≥ ____ ;  видео: ____ ;  3D: ____
   [ ] Первые 5–6 слайдов: смыслы-триггеры в порядке частоты: ____________
   [ ] Инфографика по топам полок: что скопировать ____________

4. ХАРАКТЕРИСТИКИ (шаг 5, главы 13/18)
   [ ] Видимые как у топа (состав/конструктив/мощность): ____________
   [ ] Заполнить по максимуму категорий

5. КОНВЕРСИИ / ЗАПРОСЫ (шаг 4, глава 04)
   [ ] Где конкурент сильнее в корзину/заказ и почему: ____________
   [ ] SEO-ядро: наш охват слов ____ vs медиана ____ → добрать ____________

6. ОТЗЫВЫ / РЕЙТИНГ (блок E/G, глава 06)
   [ ] Рейтинг ____ → цель ≥ ____ ;  отзывов ____ → набирать; негатив ____%

7. РЕКЛАМА (после доработки базы — главы 16/17/19)
   [ ] Запуск по релевантным запросам (принадлежность), Шторм-цикл
```

> ⚠️ Данные MPStats **оценочные** (восстановление по остаткам/выкупам) — для сравнения/ранжирования,
> не как бухгалтерия. Конверсии по слайду, «покупают также», принадлежность % — **не** из MPStats.
