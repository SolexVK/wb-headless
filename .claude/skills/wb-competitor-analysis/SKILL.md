# WB Competitor Analysis → план доработки карточки

Навык проводит конкурентный анализ ниши Wildberries по методике из базы знаний и выдаёт
**план доработки собственной карточки**. Работает в два слоя:

- **Слой A (авто, `wb_analyze.py` по MPStats):** ёмкость ниши, ТОП-конкуренты, ценовой коридор и
  «привлекательная цена», цвет-принадлежность (прокси), контент/качество-бенчмарк, сезонность,
  гэп-анализ своей карточки (`--my-sku`).
- **Слой B (ручной, по методике):** принадлежность % (Wildbox), смыслы/листинг (скриншоты + Gem),
  конверсии по запросам, полки/инфографика. Движок эти пункты **размечает как задачи**, а ты
  дополняешь их, опираясь на базу знаний.

Полная пошаговая процедура и шаблон плана — в [`references/analysis-workflow.md`](references/analysis-workflow.md).
Методы/поля MPStats — в [`references/mpstats.md`](references/mpstats.md). Первоисточник методики —
главы базы знаний **04, 13, 18, 05, 19** (`knowledge-base/`).

## Когда использовать
Любой запрос про конкурентов/нишу/лидеров WB или про улучшение своей карточки: «конкурентный анализ»,
«разбери нишу», «топ-N продавцов/брендов», «что улучшить в карточке/артикуле». Триггеры: Wildberries,
WB, ниша, конкуренты, ТОП, продавцы, бренды, доработка карточки, артикул.

## Предпосылки (проверить один раз)
1. `MPSTATS_TOKEN` в `.env` в корне репозитория (или в env). Токен НЕ хардкодить.
2. Домен `mpstats.io` разрешён сетевой политикой окружения.
3. У токена есть **дневной лимит запросов**. Движок при исчерпании выводит понятную ошибку
   (`429 … лимит запросов`) — тогда сказать пользователю подождать/поднять тариф, а не «нет данных».

## Разбор запроса пользователя → аргументы движка
- **пол** → `--gender`: женск→`women`, мужск→`men`, детск→`kids` (по умолчанию `women`; уточни, если неоднозначно).
- **предмет** → `--item`: рубашка, платье, отпариватель… (именительный, ед. ч.).
- **принт/паттерн** → `--pattern`: полоска, клетка… (опционально).
- **свой артикул** → `--my-sku <id>`: включает гэп-анализ (блок G) и адресный план доработки. **Всегда
  спрашивай его**, если пользователь хочет улучшить карточку, а артикул не назвал.
- **СЕБЕСТОИМОСТЬ** → `--cost <руб>`: **ОБЯЗАТЕЛЬНО спрашивай перед каждым запуском** (она разная у
  каждого товара; ~536 ₽ в среднем, landed до склада WB). Без неё блок C считает только «зону объёма»
  без маржи. С ней — считает выгодный ценовой коридор по марже. Остальные параметры юнит-экономики
  зашиты дефолтами (см. ниже) и общие для всех товаров.
- **глубина** → `--top` (10), **период** → `--days` (30), **срез** → `--by seller|brand`.
- фраза ниши целиком → `--query "…"` (для шапки отчёта).

### Юнит-экономика (дефолты — подтверждены пользователем, общие для всех товаров)
Комиссия ВБ до СПП **35,7%** · СПП **4%** · эквайринг **4,7%** · налог **2%** (от цены с СПП) ·
ДРР запуск/выход **30%/8%** · брак **2,5%** (от себестоимости) · выкуп **36%** (для оценки объёма) ·
логистика/хранение **0** · целевая маржа **25–30%**. Флаги для переопределения: `--commission-pct`,
`--spp-pct`, `--acquiring-pct`, `--tax-pct`, `--drr-launch-pct`, `--drr-steady-pct`, `--defect-pct`,
`--redemption-pct`, `--logistics`, `--storage`, `--target-margin-min/max`.
**Модель:** маржа считается от цены **без СПП** `S = P/(1−СПП)`; комиссия — от `S`; эквайринг/налог/ДРР
— от цены с СПП `P` (как в MPStats); брак — от себестоимости. Маржа % = операц. прибыль / `S`.
Полностью — в [`references/analysis-workflow.md`](references/analysis-workflow.md#юнит-экономика).

## Запуск
```bash
cd <repo root с .env>
python3 .claude/skills/wb-competitor-analysis/wb_analyze.py \
  --gender women --item рубашка --pattern полоска \
  --my-sku 123456789 --cost 536 --top 10 --days 30 --by seller \
  --html-out /tmp/wb_report.html --json-out /tmp/wb_report.json
```
Движок печатает markdown-отчёт (разделы A–H) в stdout и (опц.) сохраняет HTML/JSON.

Полезные флаги: `--path "Явный/Путь"` (если авто-подбор промахнулся — проверь `[path]` в stderr),
`--html-out FILE` (кликабельный HTML-отчёт: таблицы, ссылки на карточки WB, интерактивный чек-лист
плана с сохранением галочек в localStorage, тёмная/светлая тема), `--bench N` (топ-SKU в
контент-бенчмарк, 20), `--cards N` (карточек под ручной разбор, 6), `--selftest [--html-out F]`
(прогон сборки на синтетике без сети — проверить, что движок цел / посмотреть вид HTML).

**HTML-отчёт для пользователя.** Если пользователь хочет наглядный отчёт — прогони с `--html-out`,
затем покажи файл (SendUserFile с `display:"render"` или опубликуй Artifact-ом: для Artifact нужна
embed-версия — вызови `build_html(..., embed=True)`, чтобы не было двойного `<html>`).

**PDF-отчёт (кликабельный).** `--pdf-out FILE` рендерит standalone HTML в PDF через headless
Chromium; ссылки на карточки WB остаются **кликабельными**. Нужен Chromium (ищется по env
`CHROMIUM_BIN`, затем `/opt/pw-browsers/chromium`, `chromium`, `google-chrome`). Можно вместе с
`--html-out` (HTML собирается один раз). Отдай пользователю через SendUserFile (`display:"attach"`).

## Что делает движок (разделы отчёта)
- **A.** Ёмкость/концентрация + сезонность (тренд 2-й половины периода к 1-й).
- **B.** ТОП-N конкурентов: выручка, доля, продажи, ср. цена, SKU, рейтинг, упущенная выручка.
- **C.** Цена × **юнит-экономика** (при `--cost`): выгодный ценовой коридор по марже, точка
  безубыточности, маржа в фазе запуска, таблица ценовых сегментов × наша маржа/прибыль/прогноз, вердикт
  (куда целиться). «Зона объёма» показана отдельно как справка — НЕ цель. Без `--cost` — только зона объёма.
- **D.** Принадлежность-прокси: доминирующие цвета топа по доле выручки.
- **E.** Контент-бенчмарк: фото/видео/3D/описание/рейтинг/отзывы/негатив/SEO-слов — медиана и лидер.
- **F.** Карточки под ручной разбор (прямые ссылки на WB).
- **G.** Своя карточка против ниши (если `--my-sku`) — конкретные гэпы.
- **H.** План доработки: авто-гэпы + цели по цене/контенту + **чек-лист ручного слоя**.

## Как подавать результат пользователю
1. Кратко: ниша, путь, период; **ёмкость + концентрация + тренд** (блок A).
2. **Таблица ТОП-N** (блок B) и 2–4 вывода: лидер и его модель, точка перехвата (упущенная выручка),
   ценовой коридор.
3. **Выгодный ценовой коридор по марже** и **вердикт** (блок C) — главное для ценообразования: где
   у пользователя маржа 25–30% И есть спрос. Явно отделяй от «зоны объёма» (там деньги, но не маржа).
   Плюс **контент-бенчмарк** (блок E) — как цели.
4. Если задан `--my-sku` — **гэпы карточки** (блок G) и **план доработки** (блок H) первым планом.
5. **Дополни ручной слой** (блок H, шаги 2–5 воркфлоу) содержательно из базы знаний: принадлежность %
   (Wildbox), смыслы/листинг (Gem/скриншоты), полки (глава 18). Не выдавай ручные пункты как
   «сделано» — это задачи для пользователя с конкретикой из отчёта.
6. Всегда указывай ограничения: данные MPStats **оценочные**; конверсии по слайду / «покупают также» /
   принадлежность % — не из MPStats; какой путь категории выбран.

## Ограничения (честно закладывать)
- MPStats восстанавливает продажи по остаткам/выкупам — для сравнения/ранжирования, не как бухгалтерию.
- Принадлежность % (порог входа в запрос), конверсии в корзину/заказ по запросу, анализ инфографики —
  **Wildbox/Gem/визуально**. Движок даёт по ним цвет-прокси и размечает задачи, но не заменяет их.
- Фильтр по названию (`--pattern`) может упустить карточки, где принт указан только на фото.
