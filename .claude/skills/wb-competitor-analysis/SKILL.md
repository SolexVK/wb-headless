# WB Competitor Analysis → план доработки карточки

Навык проводит конкурентный анализ ниши Wildberries по методике из базы знаний и выдаёт
**план доработки собственной карточки**. Работает в два слоя:

- **Слой A (авто, `wb_analyze.py` по MPStats + публичный `card.json`):** ёмкость ниши, ТОП-конкуренты,
  цена × юнит-экономика, доминирующие цвета, контент-бенчмарк, смыслы/характеристики/листинг топов,
  **принадлежность признаков (F3, ≥30% = обязателен)**, сезонность, гэп-анализ карточки (`--my-sku`).
- **Слой B (ручной, по методике):** конверсии в корзину/заказ по запросам, анализ инфографики/полок —
  Wildbox/Gem/визуально. Движок эти пункты **размечает как задачи**, а ты дополняешь их из базы знаний.

Полная пошаговая процедура и шаблон плана — в [`references/analysis-workflow.md`](references/analysis-workflow.md).
Методы/поля MPStats — в [`references/mpstats.md`](references/mpstats.md). Первоисточник методики —
главы базы знаний **04, 13, 18, 05, 19** (`knowledge-base/`).

## Когда использовать
Любой запрос про конкурентов/нишу/лидеров WB или про улучшение своей карточки: «конкурентный анализ»,
«разбери нишу», «топ-N продавцов/брендов», «что улучшить в карточке/артикуле». Триггеры: Wildberries,
WB, ниша, конкуренты, ТОП, продавцы, бренды, доработка карточки, артикул.

## Предпосылки (проверить один раз)
1. `MPSTATS_TOKEN` в `.env` в корне репозитория (или в env). Токен НЕ хардкодить.
2. Домен `mpstats.io` разрешён сетевой политикой окружения.
3. У токена есть **дневной лимит запросов**. Движок при исчерпании выводит понятную ошибку
   (`429 … лимит запросов`) — тогда сказать пользователю подождать/поднять тариф, а не «нет данных».

## Разбор запроса пользователя → аргументы движка
- **пол** → `--gender`: женск→`women`, мужск→`men`, детск→`kids` (по умолчанию `women`; уточни, если неоднозначно).
- **предмет** → `--item`: рубашка, платье, отпариватель… (именительный, ед. ч.).
- **принт/паттерн** → `--pattern`: полоска, клетка… (опционально).
- **свой артикул** → `--my-sku <id>`: включает гэп-анализ (блок G) и адресный план доработки. **Всегда
  спрашивай его**, если пользователь хочет улучшить карточку, а артикул не назвал.
- **СЕБЕСТОИМОСТЬ** → `--cost <руб>`: **ОБЯЗАТЕЛЬНО спрашивай перед каждым запуском** (она разная у
  каждого товара; ~536 ₽ в среднем, landed до склада WB). Без неё блок C считает только «зону объёма»
  без маржи. С ней — считает выгодный ценовой коридор по марже. Остальные параметры юнит-экономики
  зашиты дефолтами (см. ниже) и общие для всех товаров.
- **глубина** → `--top` (10), **период** → `--days` (30), **срез** → `--by seller|brand`.
- фраза ниши целиком → `--query "…"` (для шапки отчёта).

### Юнит-экономика (дефолты — подтверждены пользователем, общие для всех товаров)
Комиссия ВБ до СПП **35,7%** · СПП **4%** · эквайринг **4,7%** · налог **2%** (от цены с СПП) ·
ДРР запуск/выход **30%/8%** · брак **2,5%** (от себестоимости) · выкуп **36%** (для оценки объёма) ·
логистика/хранение **0** · целевая маржа **25–30%**. Флаги для переопределения: `--commission-pct`,
`--spp-pct`, `--acquiring-pct`, `--tax-pct`, `--drr-launch-pct`, `--drr-steady-pct`, `--defect-pct`,
`--redemption-pct`, `--logistics`, `--storage`, `--target-margin-min/max`.
**Модель:** маржа считается от цены **без СПП** `S = P/(1−СПП)`; комиссия — от `S`; эквайринг/налог/ДРР
— от цены с СПП `P` (как в MPStats); брак — от себестоимости. Маржа % = операц. прибыль / `S`.
Полностью — в [`references/analysis-workflow.md`](references/analysis-workflow.md#юнит-экономика).

## Запуск
```bash
cd <repo root с .env>
python3 .claude/skills/wb-competitor-analysis/wb_analyze.py \
  --gender women --item рубашка --pattern полоска \
  --my-sku 123456789 --cost 536 --top 10 --days 30 --by seller \
  --keywords "рубашка в полоску оверсайз, рубашка льняная" \
  --html-out /tmp/wb_report.html --pdf-out /tmp/wb_report.pdf --json-out /tmp/wb_report.json
```
`--no-wb` отключает обращения к публичному API WB (блоки F2/B2), если нужна скорость/офлайн.
Движок печатает markdown-отчёт (разделы A–H) в stdout и (опц.) сохраняет HTML/JSON.

Выше — **категорийный режим** (ниша тянется из MPStats по пути категории). Ниже — **каскадный
режим**, встроенный в конвейер `[1] ТОП по фразе → [2] Сравнение карточек → [3] этот анализ`.

## Каскадный режим ([1]→[2]→[3]) — работа в конвейере

Вместо MPStats-категории ниша приходит из инструмента **[1]** (ТОП по фразе), а воронка нашей
карточки — из **[2]** (Сравнение карточек). Флаги движка:

- `--items-json <top-rivals.json>` — отчёт [1]: топ-ниша (nmId/бренд/цена/выручка/цвет/рейтинг).
  Заменяет категорийный сбор; `--gender/--item/--path` в этом режиме не нужны. Срез — по брендам.
  Контент (фото/видео/описание/слайды/характеристики) движок **добирает по nmId** из card.json WB.
- `--funnel-json <cards-compare.json>` — отчёт [2]: воронка наш vs конкуренты. Даёт блок G
  («Ваша карточка»), новый блок **«Сравнение карточек — воронка»** перед планом и **вороночные цели**
  (CTR/корзина/заказ/показы) в план «Гэпы карточки». Наш артикул берётся из воронки автоматически.
- `--foreign` — **анализируемый артикул чужой** (нет в вашем кабинете). Инструмент [2] «Сравнение
  карточек» невозможен (нет доступа к чужому кабинету), поэтому воронка [2] пропускается: блок
  **«Сравнение карточек — воронка» и вороночные цели не выводятся**. Блоки карточки остаются и
  считаются по публичным источникам (срез MPStats + `card.json` по nmId — фото/видео/описание/
  характеристики/цена/рейтинг), но помечаются нейтрально: «**Анализируемая карточка против ниши**»
  вместо «Ваша», колонка «**Артикул**» вместо «Ваше». Наш артикул задаётся явно (`--my-sku`/`--our`).
  Ниша/топ (A,B,C,D,E-медианы,F2,F3,листинг) — не задеты. При `--foreign` любой `--funnel-json`
  игнорируется.
- `--seasonality-delta <Δ%>` — сезонность (2-я половина периода к 1-й) для блока A. Считается
  оркестратором из ряда MPStats (два агрегата [1] по половинам периода) и/или лежит в
  `top-rivals.json → _meta.seasonality`; движок читает её оттуда, если флаг не задан.
- `--cost <руб>` — как обычно, включает блок C (юнит-экономика + **заработок за период в целевом
  сегменте**). Спрашивай себестоимость.

**Проще всего — через оркестратор** `scripts/wb-pipeline.mjs` (две фазы, ручной выбор конкурентов):

```bash
# Фаза 1 — найти конкурентов и показать таблицу-пикер (+ сохранить top-rivals.json, посчитать сезонность):
npm run pipeline -- --query "рубашка женская в полоску" --period 30 --top 20 \
  --group "крой=оверс,прям" --exclude "притал,стойк,волан" --price-min 1800

# → выбираешь 2–4 nmId, спрашиваешь наш артикул и себестоимость, затем Фаза 2:
npm run pipeline -- --run-id <из фазы 1> --our 841324733 \
  --rivals 297675127,494807116,435980977,342248350 --cost 536 --submit
# (--submit тратит 1 из лимита [2]; --export-existing — переиспользовать готовое сравнение бесплатно)

# Анализ ЧУЖОГО артикула (нет в твоём кабинете) — [2] пропускается, --submit/--export-existing не нужны:
npm run pipeline -- --run-id <из фазы 1> --our 297675127 \
  --rivals 494807118,435980977,342248350 --cost 536 --foreign
```

Оркестратор кладёт всё в `reports-output/<run-id>/`: `top-rivals.json`, `cards-compare.*`,
`analysis.md/html/pdf/json`. Прямой вызов движка в каскаде (если JSON-ы уже есть):

```bash
python3 .claude/skills/wb-competitor-analysis/wb_analyze.py \
  --items-json reports-output/<id>/top-rivals.json \
  --funnel-json reports-output/<id>/cards-compare.json \
  --cost 536 --seasonality-delta 12 --top 20 \
  --html-out r.html --pdf-out r.pdf --json-out r.json
```

**Подбор конкурентов по запросам (Фаза 4).** `--keywords "запрос1, запрос2"` — по каждому запросу берёт
выдачу WB (search.wb.ru, публичный API, **не тратит квоту MPStats**) и добавляет блок B2 с конкурентами
из поиска; помечает 🆕 тех продавцов, которых нет в ТОП категории (их «вниз по категории» не видно).
`--kw-limit N` — сколько карточек на запрос (8). Спрашивай у пользователя ключевые запросы ниши.

Полезные флаги: `--path "Явный/Путь"` (если авто-подбор промахнулся — проверь `[path]` в stderr),
`--html-out FILE` (кликабельный HTML-отчёт: таблицы, ссылки на карточки WB, интерактивный чек-лист
плана с сохранением галочек в localStorage, тёмная/светлая тема), `--bench N` (топ-SKU в
контент-бенчмарк, 20), `--cards N` (размер пула топ-карточек для листинга/характеристик/принадлежности
F/F2/F3, 6), `--foreign` (чужой артикул — без воронки [2]), `--selftest [--html-out F]`
(прогон сборки на синтетике без сети — проверить, что движок цел / посмотреть вид HTML).

**HTML-отчёт для пользователя.** Если пользователь хочет наглядный отчёт — прогони с `--html-out`,
затем покажи файл (SendUserFile с `display:"render"` или опубликуй Artifact-ом: для Artifact нужна
embed-версия — вызови `build_html(..., embed=True)`, чтобы не было двойного `<html>`).

**PDF-отчёт (кликабельный).** `--pdf-out FILE` рендерит standalone HTML в PDF через headless
Chromium; ссылки на карточки WB остаются **кликабельными**. Нужен Chromium (ищется по env
`CHROMIUM_BIN`, затем `/opt/pw-browsers/chromium`, `chromium`, `google-chrome`). Можно вместе с
`--html-out` (HTML собирается один раз). Отдай пользователю через SendUserFile (`display:"attach"`).

## Что делает движок (разделы отчёта)
- **A.** Ёмкость/концентрация + сезонность (тренд 2-й половины периода к 1-й).
- **B.** ТОП-N конкурентов: выручка, доля, продажи, ср. цена, SKU, рейтинг, упущенная выручка.
- **B2.** (при `--keywords`) конкуренты из выдачи WB по запросам, с 🆕-меткой тех, кого нет в ТОП категории.
- **C.** Цена × **юнит-экономика** (при `--cost`): выгодный ценовой коридор по марже, точка
  безубыточности, маржа в фазе запуска, таблица ценовых сегментов × наша маржа/прибыль/прогноз, вердикт
  (куда целиться) + **потенциальный заработок за период в целевом сегменте**. «Зона объёма» — справка,
  НЕ цель. Без `--cost` — только зона объёма.
- **D.** Доминирующие цвета (базовые): по всей базе MPStats — доля выручки, число артикулов, сумма
  заказов ₽ (до 10 цветов). В PDF — с новой страницы.
- **E.** Контент-бенчмарк топа: фото/видео/3D/описание/характеристики/длина названия/рейтинг/отзывы/
  заказы/выручка — медиана топа + лидер + колонка карточки (при `--my-sku`); смыслы для названия.
- **F.** Листинг топов (слайды): первые 10 слайдов каждого топа с подписью-номером (в HTML/PDF —
  миниатюры; в PDF картинки вшиты в файл).
- **F2.** Готовые данные по топам из публичного API WB (авто, если не `--no-wb`): **смыслы** — теги из
  хвостов запросов топов; **характеристики** — сравнительная таблица топов с доминантой (что заполнить у себя).
- **F3.** Принадлежность признаков топа (авто, по `card.json`): у какой доли топа встречается значение
  характеристики; **≥30% = обязателен** (порог входа в запрос, гл. 13). Прокси к Wildbox, без кабинета.
- **G.** Своя карточка против ниши (если `--my-sku` или `--funnel-json`) — конкретные гэпы.
  При `--foreign` — «**Анализируемая** карточка против ниши» (чужой артикул, по публичным данным).
- **G2.** (каскад, при `--funnel-json`) **Сравнение карточек — воронка**: наш vs конкуренты по
  показам/CTR/корзине/заказу/выкупу + планка (медиана конкурентов). Перед планом.
  **Пропускается при `--foreign`** (нет доступа к чужому кабинету → воронки нет).
- **H.** План доработки: гэпы карточки (метрики ниши + **вороночные цели** CTR/корзина/заказ/показы
  из [2], если не `--foreign`) + цели по цене/контенту + **ручные задачи**. Пункты с уже посчитанными
  авто-данными (смыслы/листинг, характеристики, принадлежность %) помечены кликабельными ✅-якорями
  к блокам F2/F3/листинг (в HTML). «Полки/доска» и «конверсии по запросам (ДЖЕМ)» из плана убраны.

## Как подавать результат пользователю
1. Кратко: ниша, путь, период; **ёмкость + концентрация + тренд** (блок A).
2. **Таблица ТОП-N** (блок B) и 2–4 вывода: лидер и его модель, точка перехвата (упущенная выручка),
   ценовой коридор.
3. **Выгодный ценовой коридор по марже** и **вердикт** (блок C) — главное для ценообразования: где
   у пользователя маржа 25–30% И есть спрос. Явно отделяй от «зоны объёма» (там деньги, но не маржа).
   Плюс **контент-бенчмарк** (блок E) — как цели.
4. Если задан `--my-sku` — **гэпы карточки** (блок G) и **план доработки** (блок H) первым планом.
5. **Ручные задачи** (блок H): смыслы/листинг, характеристики, принадлежность % движок уже посчитал
   автоматически (блоки F2/F3/листинг) — задача пользователя проставить их у себя. Не выдавай ручные
   пункты как «сделано» — это задачи с конкретикой из отчёта.
6. Всегда указывай ограничения: данные MPStats **оценочные**; конверсии по слайду / «покупают также» —
   не из MPStats; принадлежность % (F3) — авто по `card.json`, прокси к Wildbox; какой путь категории выбран.

## Ограничения (честно закладывать)
- MPStats восстанавливает продажи по остаткам/выкупам — для сравнения/ранжирования, не как бухгалтерию.
- Принадлежность % (порог входа в запрос) движок считает **авто** (блок F3, по `card.json` — прокси к
  Wildbox); конверсии в корзину/заказ по запросу и анализ инфографики — **Wildbox/Gem/визуально**,
  движок их размечает задачами, но не заменяет.
- Фильтр по названию (`--pattern`) может упустить карточки, где принт указан только на фото.
