# WB Competitor Analysis (через MPStats)

Навык превращает запрос-словами в готовый конкурентный отчёт по нише Wildberries.
Данные берутся из MPStats API движком `wb_analyze.py` (HTTP через curl, токен из `.env`).

## Когда использовать
Любой запрос про конкурентов/нишу/лидеров на WB: «проведи конкурентный анализ», «топ-N
продавцов/брендов», «кто лидеры в нише», «разбери нишу …». Триггеры: Wildberries, WB,
ниша, конкуренты, ТОП, продавцы, бренды.

## Предпосылки (проверить один раз)
1. `MPSTATS_TOKEN` должен быть в `.env` в корне репозитория (или в env). Токен НЕ хардкодить.
2. Домен `mpstats.io` должен быть разрешён сетевой политикой окружения. Если curl вернёт
   `403 CONNECT` / `connect_rejected` — сеть закрыта: сказать пользователю добавить
   `mpstats.io` в **Network access → Allowed domains** окружения на claude.ai/code.

## Как разобрать запрос пользователя → аргументы движка
Из фразы вытащи:
- **пол** → `--gender`: женск→`women`, мужск→`men`, детск→`kids`, не указан→`women` (спроси, если неоднозначно).
- **предмет** → `--item`: рубашка, платье, футболка, джинсы… (именительный падеж, ед. ч.).
- **принт/паттерн** → `--pattern`: полоска, клетка, однотон, цветочн… Опционально; если в
  запросе несколько (полоска/клетка) — запусти по каждому отдельно и сравни.
- **глубина** → `--top`: «ТОП-10» → `10` (по умолчанию 10).
- **период** → `--days`: «за месяц»→30, «за неделю»→7, «за квартал»→90 (по умолчанию 30).
- **срез конкурентов** → `--by`: продавцы→`seller` (по умолчанию), бренды→`brand`.
  Если пользователь не уточнил, а это важно — быстро уточни (продавец vs бренд).

## Запуск
```bash
cd <repo root с .env>
python3 .claude/skills/wb-competitor-analysis/wb_analyze.py \
  --gender women --item рубашка --pattern полоска \
  --top 10 --days 30 --by seller \
  --json-out /tmp/wb_report.json
```
Движок печатает markdown-отчёт в stdout и (опц.) сохраняет JSON с агрегатами.

Полезные флаги:
- `--path "Явный/Путь/Категории"` — если авто-подбор категории промахнулся (движок печатает,
  какой путь выбран; проверь его в шапке отчёта и переопредели при необходимости).
- Несколько принтов/полов — несколько запусков; затем сведи сравнение в один ответ.

## Что делает движок (кратко)
1. Резолвит путь категории MPStats по полу+предмету (кэш категорий в /tmp).
2. Тянет товары категории за период (`wb/get/category`), при паттерне — серверный фильтр по
   названию (contains). Пагинирует до полного объёма.
3. Агрегирует по продавцу/бренду: выручка, доля, продажи, ср. цена (выручка/продажи), SKU,
   взвеш. рейтинг, упущенная выручка (`lost_profit`), остатки; топ-хит игрока.
4. Собирает отчёт: ёмкость, концентрация (доля ТОП-N), таблица ТОП-N, выводы.

## Как подавать результат пользователю
- Покажи шапку (ниша, путь, период, срез) и **таблицу ТОП-N**.
- Дай 2–4 вывода: лидер и его модель (хиты vs ассортимент), кто теряет на остатках
  (точка перехвата), ценовой коридор.
- Всегда указывай ограничения: данные MPStats оценочные; фильтр по названию мог упустить
  часть карточек; какой путь категории выбран.
- Предложи следующий шаг: другой срез (бренды vs продавцы), соседний принт, расширить
  категорию, добавить ценовую сегментацию, выгрузить в CSV/HTML.

## Расширение
Движок можно дополнить срезами (ценовая сегментация `wb/get/category/price_segmentation`,
тренды `wb/get/category/trends`, SEO по ключам). Поля товара и методы MPStats — в
`references/mpstats.md`.
