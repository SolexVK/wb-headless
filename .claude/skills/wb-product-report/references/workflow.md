# Пошаговый воркфлоу построения товарного отчёта WB

Проверено на кейсах: мужские рубашки в полоску, мужские однотонные рубашки, женские нарядные
блузки с жабо (гипюр/шёлк/хлопок).

## 0. Вход и постановка
- Пользователь даёт: артикулы/ссылки WB, или ссылку на image-search, или описание модели.
- Из ссылки достать SKU: `catalog/(\d+)` (см. `lib/skuReport.js:parseSku`).
- Определить: пол+предмет, сегмент (нарядная/базовая/офисная), отличительный элемент (жабо, рюши,
  клетка, полоска), ткань, длина рукава. Что не ясно — спросить.
- **Уточнить у пользователя ключевые фразы** (обычно 3–4): категорийная («блузка женская»),
  сегмент («блузка женская нарядная»), отличительный элемент 1–2 формулировки («с жабо», «с рюшами»).
- Уточнить период (по умолч. для отчёта — последний год; для поиска модели — 3 мес.).
- Уточнить, нужны ли РАЗНЫЕ бренды в топ-N.

## 1. Сбор кандидатов
```bash
MPSTATS_TOKEN=xxx MERGE_D1=2026-05-22 MERGE_D2=2026-08-21 \
  node report-search-merge.js "блузка женская" "блузка женская нарядная" "блузка женская с жабо" "блузка женская с рюшами"
# → reports-output/search-merge-<d1>_<d2>.json : {items[], byPhrase[], uniqueCount}
```
- Каждая фраза даёт ~100 карточек (WB-выдача ограничена сотней), поля богатые (revenue, sales, price,
  lost_profit, thumb, url, color, size_count, purchase, rating…).
- В `items[]` у каждой карточки: `phrases[]` (в каких фразах встретилась), `phraseHits`, `bestPos`,
  `rank`. Сортировка по `phraseHits`→`revenue`.

## 2. Отбор артикулов (топ-N по выручке)
Скрипт-фильтр по сохранённому JSON (пример — жабо, однотонные, с рукавами, разные бренды):
```js
const a = require('./reports-output/search-merge-…json');
const minus = ['коротк','тепл','фланел','клетк','полос','без рукав','безрукав','девочк'];
const cand = a.items
  .filter(it => { const n=it.name.toLowerCase(); return n.includes('жабо') && !minus.some(r=>n.includes(r)); })
  .sort((x,y)=>y.revenue-x.revenue);
// топ-N разных брендов:
const seen=new Set(), top=[];
for (const it of cand){ const b=(it.brand||'').toLowerCase(); if(seen.has(b))continue; seen.add(b); top.push(it); if(top.length===3)break; }
```
**Внимание:** имя часто не содержит ни ткань, ни длину рукава. Для точного отбора:
1. Тянуть `card.json` кандидатов (Состав/описание) — `lib/wbPublic.js:fetchCardJson`.
2. **ВИЗУАЛЬНО проверить фото** (см. §3) — обязательный шаг, текст не заменяет.

## 3. Визуальная проверка фото (обязательно)
Скачать первые фото кандидатов и посмотреть монтажом:
```js
// для каждого sku: fetchItemFull → photo.list[0].f (big) → скачать webp в scratchpad
// собрать HTML-грид <img> с подписями (бренд, выручка, арт) → chromium --screenshot → прочитать PNG
```
Пример монтажа: HTML `display:grid;grid-template-columns:repeat(3,240px)` c `<img width=220 height=293>` +
подпись, затем `chromium --headless --screenshot=out.png file://…`. Смотреть глазами:
- жабо/рюши/воланы есть? (а не бант/вырез/гладкая планка)
- рукав длинный? (не короткий/безрукавный/фонарик до локтя)
- однотонная? (не принт/горох/клетка/полоска/разводы)
- та ткань? (кружево/гипюр vs атлас-блеск vs матовый хлопок)
- это блузка? (не боди, не туника-пляж, не топ, не футболка, не детское)
Отсеять неподходящие, добрать следующих по выручке. При нехватке — целевой доп.поиск
(`mergePhrases(['блузка кружевная нарядная', …])`).

## 4. Единый отчёт
```bash
MPSTATS_TOKEN=xxx \
SHIRTS_CATEGORY="Женщинам/Блузки и рубашки/Блузка" \
SHIRTS_NICHE_QUERIES="блузка кружевная нарядная|блузка женская гипюровая|блузка нарядная с жабо кружево" \
SHIRTS_SIZES_QUERY="блузка женская с жабо" \
SHIRTS_MINUS="коротк,тепл,тёпл,фланел,клетк,полос,без рукав,безрукав" \
SHIRTS_REFINE='{"longSleeve":true,"include":"гипюр|кружев","exclude":"летн|девочк|детск|пляж","scan":130}' \
SHIRTS_TITLE="Гипюровые нарядные блузки с жабо — рынок, топ и разбор 3 артикулов" \
SHIRTS_NICHE_DESC="Ниша: гипюровые/кружевные нарядные блузки, длинный рукав (исключены …)" \
node report-shirts.js <арт1> <арт2> <арт3>
# → reports-output/shirts-analysis-<skus>-<d1>_<d2>.{pdf, html, -book.html, json}
```
Что собирается внутри (`lib/shirtsData.js`):
- **Артикул** ×3: `fetchItemFull` (period_stats: revenue/lost_profit/purchase/sales; brand; photo;
  link) → деньги (выручка, заработал=×выкуп, упущено, ср.цена=выручка/штуки); `fetchItemDailySales`
  → помесячно выручка (продажи×цена) + средний остаток; `fetchCardJson` → характеристики + ключевые
  запросы; `fetchReviews`+`classifyReviews` → рейтинг/звёзды/темы/проблемы/что доработать; `scanArticle`
  → диагональное сканирование.
- **Ниша** (`buildShirtsMarket`): пул из `nicheQueries` (объединённый поиск) ИЛИ категории; `refine`
  по card.json чистит топ; рынок (₽/год, упущено, доля), топ-10 (фото/бренд/ссылка), расцветки
  (топ-300), размерные ряды, преобладающие размеры (`fetchDominantSizes` из search.wb.ru).

## 5. Проверка результата
- `node -e` по JSON: фото 3/3 и 10/10 (`hasImg`), `dominantSizes` не пуст, топ-10 без короткого рукава/
  не той ткани, ср.цены разумные.
- Рендер книжного HTML в PNG (`chromium --window-size=720,N --screenshot`) и просмотр: заголовок,
  деньги, средняя цена, график выручка+остаток, отзывы, диаг.сканирование, расцветки/размеры.
- Отдать PDF (attach) + при желании HTML (render, интерактив: фото ×3, клики).

## 6. Итерации по фидбэку (типичные)
- «Маленькая выручка» → отбирать топ по выручке из ШИРОКОЙ ниши, не из узкого литерального ключа.
- «Короткий рукав в топе» → `refine.longSleeve` + `exclude:"летн"`; для строгости `requireLong`
  (но он режет лидеров без слова «рукав» — применять точечно).
- «Попали не той ткани/гипюр в хлопок» → нишу брать из фраз нужной ткани + `refine.exclude` чужой.
- «Пустые размеры» → это 429 от search.wb.ru; ретрай с backoff уже встроен, перезапустить.
- «Нет средней цены» → она в блоке артикула («Средняя цена продажи»); = выручка/штуки за период.
