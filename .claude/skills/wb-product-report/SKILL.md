# WB Product Report — отчёты по конкретным товарам

Навык строит отчёты **от товара/модели** (в отличие от `wb-niche-analysis`, который оценивает
категорию целиком). Три готовых типа отчёта + переиспользуемые кубики данных.

## Когда использовать
- Пользователь дал **артикулы или ссылки** WB и просит разобрать их (выручка, заработок, упущенная
  выручка, остатки по месяцам, отзывы, конкуренты).
- Пользователь описал **модель** («нарядная блузка с жабо», «рубашка в полоску») и просит найти
  топ похожих товаров и разобрать их.
- Просит **сравнить сегменты** (по ткани/цвету/цене/размерам), собрать топ-3/топ-10 по выручке.
- Триггеры: артикул, ссылка WB, «топ по выручке», «разбери товар/конкурентов», «отзывы разложи»,
  «по тканям/цветам/размерам», «диагональное сканирование».

## Предпосылки (проверить один раз)
1. `MPSTATS_TOKEN` в env (заголовок `X-Mpstats-TOKEN`). НЕ хардкодить.
2. Домены разрешены сетевой политикой: `mpstats.io`, `*.wbbasket.ru` (фото/card.json),
   `feedbacks1/2.wb.ru` (отзывы), `search.wb.ru` (выдача/размеры).
3. У MPStats **суточный лимит** запросов (429 → «Превышен лимит… за ДАТУ»): сказать подождать/поднять
   тариф, не «нет данных». У `search.wb.ru` — **поминутный rate-limit** (429): лечится ретраем с backoff.
4. Chromium для PDF (`lib/renderPdf.js` находит сам; в этом окружении `/opt/pw-browsers/chromium`).

## Готовые отчёты (CLI)
- **`report-shirts.js`** — ГЛАВНЫЙ единый отчёт: рынок ниши + топ-10 за год + разбор 3 артикулов
  (деньги, характеристики, ключевые запросы, отзывы+классификация, диагональное сканирование,
  график выручка+остаток по месяцам) + расцветки/размеры. Книжный (портретный A4) PDF + HTML.
  Обобщён под ЛЮБУЮ нишу через env (см. ниже). Несмотря на имя «shirts» — работает для блузок и пр.
- **`report-sku.js <арт…>`** — годовая аналитика по конкретным артикулам: выручка / заработал
  (=выручка×выкуп%) / упущенная выручка / помесячная выручка, фото ×3, кликабельные арт/бренд.
- **`report-top.js "<Путь/Категории>" [d1 d2]`** — топ-N товаров категории по выручке
  (env `TOP_PLUS/TOP_MINUS/TOP_N`), с фото/остатками/динамикой/доп.колонками.
- **`report-search-merge.js "фраза1" "фраза2" …`** — собрать топ-100 по каждой фразе через MPStats,
  объединить, дедуп по SKU (+ в скольких фразах встретилась), сохранить JSON для дальнейшего отбора.

Полная пошаговая процедура — в [`references/workflow.md`](references/workflow.md).
Карта источников и полей — в [`references/data-sources.md`](references/data-sources.md).

## Алгоритм (как собирались данные и строился отчёт)

**Шаг 0. Понять модель.** Из ссылки/описания/картинки выделить: пол+предмет (блузка женская),
нарядность, отличительный элемент (жабо/рюши), ткань. Спросить у пользователя ключевые фразы, если
не дал (обычно 3–4: категорийная + сегмент + отличительный элемент 1–2 формулировки).

**Шаг 1. Сбор кандидатов (MPStats search).** По каждой фразе — `report-search-merge.js` /
`lib/searchPhrases.js:mergePhrases`: топ-100 по фразе (`/analytics/v1/wb/search/items`), объединение,
**дедуп по SKU** с подсчётом, в скольких фразах встретилась (сигнал релевантности) и лучшей позиции.
Период — по запросу (для поиска модели брали 3 мес.; для аналитики — год).

**Шаг 2. Отбор артикулов (по выручке + фильтры + ВИЗУАЛЬНАЯ проверка).**
- Сортировка по выручке (или по релевантности→выручке).
- Фильтр по названию: `minus` (короткий рукав, тёплые, клетка, полоска, без рукава, детск/девочк…),
  при необходимости `plus`/ткань.
- **card.json**: длину рукава и ткань в названии часто НЕ пишут → тянуть `card.json` (Состав/описание)
  и детектить по тексту+составу (см. gotchas).
- **ВИЗУАЛЬНАЯ проверка (обязательна!)**: скачать первые фото кандидатов и посмотреть монтажом
  (HTML-грид → chromium screenshot). Так подтверждается жабо, длинный рукав, однотонность, ткань —
  текстовые фильтры это надёжно не ловят. Отсеять принты, безрукавные, боди, туники, детское.
- Разные бренды — если просили.

**Шаг 3. Единый отчёт (`report-shirts.js`).** Для 3 отобранных артикулов + ниша:
- По каждому артикулу: `item/full` (деньги: revenue, lost_profit, purchase=выкуп, units; бренд;
  фото; ссылка), `item/{sku}/sales` (помесячно: выручка=продажи×цена, средний остаток),
  `card.json` (характеристики+ключевые запросы), `feedbacks` (отзывы → классификация), диагональное
  сканирование (`search.wb.ru` → реальные конкуренты + гэпы).
- Ниша: из объединённой выдачи поиска (`nicheQueries`) — точнее, чем name-filter категории, когда
  отличительный элемент редко в названии; **`refine` по card.json** чистит топ-10 (рукав/жабо/ткань).
- Рынок (₽/год, упущенная выручка, доля), топ-10, расцветки (топ-300), размерные ряды, преобладающие
  размеры (`search.wb.ru` фасет), средняя цена продажи.
- Рендер: книжный портретный A4 (плотная упаковка, без наложений) — см. `book:true`.

## Env-параметры `report-shirts.js` (обобщение под нишу)
```bash
MPSTATS_TOKEN=xxx \
SHIRTS_CATEGORY="Женщинам/Блузки и рубашки/Блузка"   # путь категории (для контекста/резолва)
SHIRTS_NICHE_QUERIES="фраза1|фраза2|фраза3"          # ниша из поиска (| — разделитель)
SHIRTS_SIZES_QUERY="блузка женская с жабо"           # запрос для фасета преобладающих размеров
SHIRTS_MINUS="коротк,тепл,тёпл,фланел,клетк,полос,без рукав,безрукав"  # исключить по названию
SHIRTS_PLUS=""                                       # требовать в названии (напр. жабо), опц.
SHIRTS_REFINE='{"longSleeve":true,"jabot":true,"include":"хлоп","exclude":"гипюр|кружев|летн|девочк","scan":140}'
SHIRTS_TITLE="Заголовок отчёта"
SHIRTS_NICHE_DESC="Ниша: … (что исключено)"
SHIRTS_D1=2025-08-22 SHIRTS_D2=2026-08-21            # период (по умолч. ~год)
node report-shirts.js <арт1> <арт2> <арт3>
```
`refine` (чистка топ-10/распределений по card.json): `longSleeve` (убрать короткий/безрукавные),
`requireLong` (требовать ЯВНЫЙ длинный рукав — СТРОГО, режет лидеров без слова «рукав», применять
осторожно), `jabot` (требовать жабо/рюши/воланы), `include`/`exclude` (regex по названию+описанию+
составу — ткань и т.п.), `scan` (сколько топ-кандидатов проверять, 70–180).

## Готовые рецепты (проверены на нарядных блузках с жабо)
- **Гипюр**: `NICHE_QUERIES="блузка кружевная нарядная|блузка женская гипюровая|блузка нарядная с жабо кружево"`,
  `REFINE={"longSleeve":true,"include":"гипюр|кружев","exclude":"летн|девочк|детск|пляж","scan":130}`.
- **Шёлк/атлас**: `NICHE_QUERIES="блузка атласная нарядная|блузка шелковая нарядная|блузка нарядная с жабо атлас"`,
  `REFINE={"longSleeve":true,"include":"атлас|шёлк|шелк|сатин","exclude":"летн|девочк|детск","scan":130}`.
- **Хлопок**: `NICHE_QUERIES="блузка хлопковая нарядная|блузка офисная хлопковая нарядная|блузка нарядная с жабо хлопок"`,
  `REFINE={"longSleeve":true,"jabot":true,"exclude":"гипюр|кружев|летн|девочк|детск|футбол","scan":120}`.
  (Для хлопка нишу берём из «хлопковых» фраз и НЕ требуем `include:хлоп` через card.json — иначе при
  сбое card.json высоковыручные без «хлоп» в названии выпадают.)

Рецепты по крою (проверены на рубашках-блузках на запах/асимметричных, тренд 2026):
- **На запах, однотонные**: `NICHE_QUERIES="рубашка на запах|блузка на запах|рубашка на завязке женская|рубашка с запахом женская"`,
  `MINUS="…,полоск,асимметр,ассиметр"`, `REFINE={"longSleeve":true,"exclude":"полоск|асимметр|ассиметр|летн|пляж|детск|школьн","scan":150}`.
- **На запах, в полоску**: `NICHE_QUERIES="рубашка на запах в полоску|рубашка в полоску на завязке|блузка на запах в полоску|рубашка в полоску приталенная"`,
  `REFINE={"longSleeve":true,"include":"полоск","exclude":"летн|пляж|детск|школьн","excludeBrand":"mixers|oh my man|man!","scan":140}`.
  (Фраза «рубашка в полоску» тащит мужские/школьные — их снимает gender-фильтр + `excludeBrand` + `MINUS=школьн,мужск`.)
- **Асимметричные**: `NICHE_QUERIES="рубашка асимметричная|асимметричная рубашка женская|блузка асимметричная|рубашка с асимметрией"`,
  `REFINE={"longSleeve":true,"include":"асимметр|ассиметр","exclude":"летн|пляж|детск|школьн|футбол","scan":150}`.
  (Лидеры часто «больших размеров» без слова «асимметр» в названии — ловятся через описание в card.json; рукав бывает 3/4 — это ок, режем только короткий/без рукава.)

Отбор топ-3 артикулов **из ГОДОВОГО топ-10 ниши**, а не из 3-месячной выдачи: 3-мес. лидер может
проседать за год (и наоборот). Практика: собрать модель за 3 мес. → построить отчёт → взять из
`data.market.top10` реальных годовых лидеров → ВИЗУАЛЬНО их проверить (монтаж) → пересобрать отчёт с
топ-3 разных брендов. Так выполняется требование «высокая выручка + разные бренды + подтверждено фото».

## Важные грабли (не повторять)
- **Ткань/рукав редко в названии.** У блузок в `card.json` часто НЕТ поля «Длина рукава». Рукав
  детектить из названия+описания (`коротк рукав|без рукав|безрукав` → короткий; `длин…рукав|
  рукавами|с рукавом` → длинный) + косвенно `летняя` (обычно короткая) → в `exclude`.
- **Жабо текстом ненадёжно.** Многие визуально-жабо блузки не пишут «жабо». Для ТОП-10 ниши жабо НЕ
  требовать (только рукав+ткань), а для ОТБИРАЕМЫХ артикулов — подтверждать ВИЗУАЛЬНО по фото.
- **card.json ломок под нагрузкой.** Если `include:ткань` завязан на Состав, а card.json флапнул —
  товар без ткани в названии выпадет. Решение: нишу брать из фразы нужной ткани, а не перепроверять
  Состав. Все сетевые вызовы — с ретраями (фото, card.json, feedbacks, search).
- **search.wb.ru 429 (поминутный).** Диагональное сканирование + фасет размеров бьют один хост →
  429 → пустые «преобладающие размеры». Лечится терпеливым ретраем с backoff (в `shirtsMarket.js`
  до 12 попыток) + card.json-чистка даёт хосту передышку перед запросом размеров.
- **Мужские/детские/школьные в женской нише.** Категорийные фразы («рубашка в полоску») тащат мужские
  и школьные карточки. `buildShirtsMarket` отсекает их по полю `gender` (Мужской/Мальчики/Девочки) из
  выдачи поиска; бренды-помехи — через `refine.excludeBrand` (регэксп по бренду, напр. `mixers|oh my man`).
  Дополнительно `MINUS=школьн,мужск`. Без этого мужские премиум-рубашки попадают в топ-10.
- **«Дубайский шёлк»/«шёлк армани»** — это полиэстер-атлас (не натуральный шёлк). Для сегмента
  «шёлк» это норм (шёлк-лук), но помнить при трактовке Состава.
- **Заработал = выручка × выкуп%**; выкуп MPStats даёт оценочно на уровне КАТЕГОРИИ (у разных
  артикулов бывает одинаковый ~42%) → «заработал» это ориентир, не бухгалтерия. Указывать в сноске.
- **Период отбора vs анализа.** Модель ищем за короткий период (3 мес.), но сам отчёт — за год
  (как единый анализ). Годовая выручка может отличаться от 3-месячной.
- **Книжный PDF.** `report-shirts.js` пишет и широкий интерактивный `.html`, и `-book.html`, и PDF
  из книжной вёрстки (портретный A4, плотная упаковка). Фото ×3 hover и клики — в HTML.

## Стек (кубики данных)
`lib/mpstats.js` (fetchSearchResults, fetchCategory, fetchItemFull, fetchItemDailySales),
`lib/searchPhrases.js` (mergePhrases), `lib/wbPublic.js` (card.json, feedbacks, ключевые запросы),
`lib/reviewsClassify.js` (классификация отзывов), `lib/diagonalScan.js` (конкуренты+гэпы),
`lib/shirtsMarket.js` (рынок/топ-10/цвета/размеры + refine), `lib/shirtsData.js` (оркестратор),
`lib/shirtsReportHtml.js` (вёрстка + книжный режим), `lib/renderPdf.js` (PDF).
