# /fbs-dashboards — сборка дашбордов FBS

Готовит три дашборда по нашим складам-фулфилментам FBS на живых данных WB API:

1. **Передано в доставку по дням** — `reports-output/fbs-delivery-dashboard.html`
   (плитки по дням: сегодня — план, прошедшие — факт передачи в доставку; матрица «фулфилмент × день»).
2. **Принято на фулфилмент + баланс** — `reports-output/fbs-accepted-dashboard.html`
   (принято = новые задания в работу по дням; панель «Разница: передано − принято»; матрица принято).
3. **Остатки по артикулам и цветам** — `reports-output/fbs-stock-articles.html`
   (остаток на каждом складе, строка = карточка nmID = артикул+цвет, размеры объединены).

Всё считается методами Маркетплейса (`/api/v3/orders`, `/api/v3/supplies`,
`/api/v3/stocks/{id}`) и Content (`content/v2/get/cards/list`) с соблюдением
лимитов (`lib/wbClient.js`). Прогон занимает ~1–2 минуты и требует токена WB.

## Предпосылки (проверить один раз)

- Токен WB виден: `npm run token:check` → «найден ДА». Если нет — задать
  `WB_API_TOKEN`/`Wildberries_API` (env или `.env`); без токена шаги упадут 401.
- Для рендера скриншотов/PDF нужен Chromium (в этом окружении предустановлен,
  `PLAYWRIGHT_BROWSERS_PATH`). Для дашбордов-HTML браузер не нужен.

## Шаги

### 1. Обновить данные и собрать все три дашборда — одной командой

```bash
npm run fbs:dashboards
```

Это последовательно выполнит:
`fbs:stock` → `fbs:delivery` → `fbs:delivery:dash` → `fbs:accepted:dash` → `fbs:stock:articles`.

**Период** для дашбордов #1/#2 по умолчанию — сегодня + 7 полных прошедших дней
(МСК). Чтобы задать другой период, обнови данные вручную с аргументами, затем
пересобери дашборды:

```bash
npm run fbs:delivery -- --days 14           # или --day 2026-08-09, --from .. --to ..
npm run fbs:delivery:dash && npm run fbs:accepted:dash
```

Остатки (дашборд #3) — всегда срез «на текущий момент» (историю остатков WB API
не отдаёт).

### 2. Опубликовать артефактами и прислать файлы

Для каждого из трёх `*.artifact.html` вызвать инструмент **Artifact** (favicon:
🚚 для #1, 📥 для #2, 🎨 для #3), затем прислать соответствующие `*.html`
пользователю через **SendUserFile** (`display: render`). Файлы:

- `reports-output/fbs-delivery-dashboard.html` (+ `.artifact.html`)
- `reports-output/fbs-accepted-dashboard.html` (+ `.artifact.html`)
- `reports-output/fbs-stock-articles.html` (+ `.artifact.html`)

Если дашборд с таким путём уже публиковался в этой сессии — повторная публикация
того же пути сохранит ту же ссылку.

### 3. Коротко отчитаться

Дать сводку ключевых чисел из снимков `reports-output/fbs-delivery-daily.json`
и `reports-output/fbs-stock.json`: за период передано/принято/разница; общий
остаток и число артикул+цвет. Ссылки на артефакты — пользователю.

## Заметки

- `reports-output/` в `.gitignore` — сами дашборды/снимки в git не коммитятся,
  коммитятся только генераторы (`scripts/fbs-*.mjs`).
- «Принято на фулфилмент» = новые сборочные задания, поступившие в работу
  (создано за день). Физических поступлений на склад продавца WB API не отдаёт
  (`supplier/incomes` — это FBW-приёмка на склады WB, другая модель).
- Нужен единый операционный отчёт (остатки + ретроспектива заказов) или PDF —
  это отдельные команды: `npm run fbs:report` (HTML), `npm run fbs:pdf`
  (единый PDF), `npm run fbs:stock:pdf` (PDF остатков к заказу).
- **Расчёт подсорта** (заказ на пополнение по складам + пробный завоз новинок) —
  это отдельный скилл **`/fbs-podsort`** (`npm run fbs:podsort` → дашборд + Excel;
  настройки в `config/replenishment.json`). Для «что дозаказать» используем его.
