# Расследование удержаний Wildberries

Отвечает на вопрос «за что WB снял деньги и что с этим делать» — не общими
словами, а по конкретным строкам отчёта, с привязкой к заказу, складу, ПВЗ и дате.

## Когда применять

- «Почему удержали за логистику», «что за штраф», «за что списали X»
- «Разбери финансовый отчёт WB», «проверь удержания за неделю»
- Пришло уведомление сторожа в Telegram и нужно разобраться глубже
- Нужно настроить или починить сторожа (расписание, Telegram, пороги)

## Главное правило

**Причина удержания лежит в поле `bonusTypeName`** строки детализации. Название
операции (`sellerOperName`) говорит только вид — «Штраф», «Логистика»,
«Удержание». Без `bonusTypeName` расследования нет: именно оно отличает
«возврат брака» от «возврата по МП» и «штраф за отмену» от «хранения на ПВЗ».

Второе правило: **суммы в валюте отчёта** (`currency` в строке). У этого
продавца — KGS, не рубли. Никогда не подписывай суммы «₽», не проверив поле.

## Порядок работы

1. **Выгрузить детализацию** за нужный период:
   `node report-forensics.mjs --collect ГГГГ-ММ-ДД ГГГГ-ММ-ДД`
   Это соберёт финансовые строки, возвраты, заказы, сборочные задания и склады
   в `reports-output/forensics-cache.json` и построит два PDF-расследования.
   Повторный рендер без обращений к API — та же команда без `--collect`.
2. **Классифицировать** каждую причину по каталогу `lib/deductionCatalog.js`.
   Незнакомую причину не игнорировать: разобрать вручную и **дописать в каталог**.
3. **Связать строки с фактами** — таблица связок в `references/method.md`.
4. **Проверить итоги** по контрольным суммам WB (`/sales-reports/list`):
   расхождение больше единицы валюты означает, что детализация выгрузилась не вся.
5. **Дать вывод и меры** — что именно сделать, а не «оптимизировать процессы».

## Сторож (ежедневные проверки)

```bash
node agent-wb-watch.mjs --dry-run      # показать сообщение, ничего не отправляя
node agent-wb-watch.mjs                # проверить и отправить в Telegram
node agent-wb-watch.mjs --cache        # пересчитать из локального кэша, без API
```

Расписание — `.github/workflows/wb-watch.yml` (04:00 и 15:00 UTC = 07:00 и 18:00 МСК).
Пороги — `config/watch-thresholds.json`. Состояние (что уже сообщали) —
`state/wb-watch-state.json`. Подробности: `WATCH.md`.

## Чего не делать

- Не считать «штрафы = penalty» и на этом останавливаться: удержания сидят ещё
  в `deduction`, `deliveryService`, `paidStorage`, `paidAcceptance`.
- Не запрашивать финансовые методы чаще раза в минуту — прилетит 429 и лимит
  пойдёт по кругу. Клиент `lib/wbClient.js` уже держит паузы, не обходи его.
- Не считать нулевую логистику в дневном отчёте отсутствием логистики:
  списания приходят **пакетами** в день выдачи возврата.
- Не подписывать суммы валютой, не заглянув в поле `currency`.
