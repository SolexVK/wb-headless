# /wb-cards-compare — отчёт «Сравнение карточек» (кабинет WB)

Функция кабинета (Джем), **не API**. Работаем headless-браузером с сессией
пользователя (куки + токен из localStorage). Инструменты:
`lib/wbCardsCompare.js` (логика) и `scripts/wb-cards-compare.mjs` (CLI).

Страница: `https://seller.wildberries.ru/platform-analytics/cards-comparison`
(Аналитика развития бизнеса → Сравнение карточек).

## Обязательный порядок действий

1. **Спроси у пользователя НАШ артикул** (`nmID`) — его всегда даёт пользователь.
   Никогда не подставляй наш артикул сам.
2. **Конкуренты (0–4 шт.):** либо пользователь даёт их явно, либо приходят из
   инструмента [1] «ТОП по ключевой фразе» через РУЧНОЙ выбор (см. ниже «Откуда
   берём конкурентов»). Всего в сравнении 2–5 карточек.
3. **Проверь сессию:** `npm run cabinet:check`. Если «протухла» — см. раздел
   «Обновление кред» ниже (спроси у пользователя свежие).
4. **DRY-RUN (без траты лимита):** добавь артикулы и покажи пользователю скрин
   `.secrets/cmp-filled.png` со счётчиком «N из 5». Лимит НЕ тратится.
5. **После подтверждения** — запусти с `--submit`: сравнение выполнится
   (тратит 1 сравнение из лимита; тариф «Продвинутый» ≈ 20) и выгрузит XLSX.

## Запуск

```bash
# DRY-RUN: добавить и показать «N из 5», лимит не тратится
npm run cards:compare -- --our 758196168 --rivals 176252338,168333315,297675127,757262495

# Реальный запуск + автоматическая выгрузка XLSX (тратит 1 из лимита)
npm run cards:compare -- --our 758196168 --rivals 176252338,168333315 --submit --out reports-output/cmp.xlsx

# Пере-скачать УЖЕ готовое сравнение (в пределах 72 ч — БЕСПЛАТНО, лимит не тратится)
npm run cards:compare -- --our 758196168 --export-existing --out reports-output/cmp.xlsx

# Конкуренты из файла (вывод другого инструмента) или из stdin
npm run cards:compare -- --our 758196168 --rivals-file rivals.json --submit
getRivals | npm run cards:compare -- --our 758196168 --submit
```

Выгрузка выполняется автоматически: «Создать Excel» → имя → «Сформировать» →
панель «Загрузки» → скачать → развернуть ZIP (WB отдаёт .xlsx внутри ZIP) →
чистый `.xlsx` в `--out`. Готовое сравнение живёт 72 ч и пере-скачивается бесплатно.

## Откуда берём конкурентов (связка [1]→[2], ручной выбор)

Основной источник конкурентов — инструмент **[1]** «ТОП по ключевой фразе»
(`wb-top-keywords`). Стык **ручной**, человек в цикле:

1. Прогони [1] с `--pick`: `node scripts/wb-top-keywords.mjs --query "…" --top 20 --pick`
   — печатает нумерованную таблицу `# · nmId · бренд · название · ср.цена · выручка · тип`.
2. Покажи таблицу пользователю → он называет 2–4 конкурента (номера строк или nmId).
   Сам не выбираешь; можешь предложить кандидатов по выручке, решает пользователь.
3. Спроси НАШ артикул (`--our`).
4. Передай выбранные сюда: `--rivals <nmId,nmId,…>` (DRY-RUN → подтверждение → `--submit`).

Авто-топ-K без выбора (`… --nmids-only | wb-cards-compare --our N`) — запасной путь
для явных «просто топ-N»; по умолчанию используем ручной выбор.

## Интеграция с другими инструментами (артикулы конкурентов)

Логика вынесена в функцию — другой инструмент может передать конкурентов напрямую:

```js
import { runCardsComparison } from './lib/wbCardsCompare.js';
const rivals = await topByKeywords(query);      // напр. ТОП-10 по запросу → [nmId,...]
await runCardsComparison({ our: 167477208, rivals: rivals.slice(0, 4), submit: true });
```

`resolveRivals({rivals, rivalsFile})` собирает список из csv-строки/массива/файла
(JSON `[...]` / `{rivals:[...]}` / по строкам). Дубли и пустые отсеиваются, наш
артикул добавляется первым, всего максимум 5.

## Где лежит сессия и как обновить креды (когда протухнут)

Сессия берётся из (в порядке приоритета), см. `lib/wbCabinet.js`:
- **куки:** аргумент → env `WB_COOKIES` → файл `.secrets/wb-cookies.json`;
- **localStorage-токен:** аргумент → env `WB_LOCALSTORAGE` → файл `.secrets/wb-localstorage.txt`.

⚠️ Токен WB лежит в **localStorage** (`wb-eu-passport-v2.access-token`), а НЕ в
куках. Нужны ОБА набора. Файлы `.secrets/*` — gitignored, значения не логируем.

**Если сессия протухла** (`npm run cabinet:check` → «НЕ авторизованы», или CLI
вернул `SESSION_EXPIRED`): останови работу и **попроси пользователя дать свежие
креды** — он логинится в кабинет и присылает:
1. экспорт кук (Cookie-Editor → Export → JSON, домен `wildberries.ru`);
2. записи localStorage кабинета (минимум `wb-eu-passport-v2.access-token`,
   можно все `wb-eu-*`), формат «имя значение» по строке.

Ты сохраняешь их в `.secrets/wb-cookies.json` и `.secrets/wb-localstorage.txt`
(или пользователь кладёт в env `WB_COOKIES` / `WB_LOCALSTORAGE`) и повторяешь.

## Лимит и безопасность

- Каждый `--submit` тратит 1 сравнение; DRY-RUN — бесплатно. Остаток виден в форме
  («Доступно: N сравнений») и в `.secrets/cmp-filled.png`.
- XLSX-отчёты — в `reports-output/` (gitignored). Скрины — в `.secrets/`.

## Как получить инструмент в другой ветке

Файлы (`lib/wbCabinet.js`, `lib/wbCardsCompare.js`, `scripts/wb-*`, этот скилл) —
это файлы репозитория. Чтобы пользоваться в другой ветке, влей туда эту ветку
(или в `main`): `git merge claude/wildberries-api-docs-bfnvun`. После слияния
навык виден везде, а `.secrets/` с кредами остаётся локальным (в git его нет).
