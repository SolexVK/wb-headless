# Telegram-бот: ставим задачи по проекту из чата

Бот-мост позволяет писать задачи прямо в Telegram — они уходят в **Claude Agent
SDK** (тот же движок, что и Claude Code: с доступом к файлам репозитория, git и
командам), а результат приходит обратно в чат. По сути — «Claude Code, которым
управляешь из Telegram».

## Что нужно один раз настроить

### 1. Создать бота и получить токен
1. Откройте в Telegram диалог с **@BotFather**.
2. Отправьте `/newbot`, придумайте имя и username.
3. BotFather пришлёт **токен** вида `123456:ABC-DEF...` — это `TELEGRAM_BOT_TOKEN`.

### 2. Получить ключ Claude API
1. Зайдите в консоль Claude (platform.claude.com) → **API Keys**.
2. Создайте ключ — это `ANTHROPIC_API_KEY`.

### 3. Узнать свой chat id
Нужен, чтобы **никто, кроме вас, не мог писать боту**.
1. Впишите пока только `TELEGRAM_BOT_TOKEN` и `ANTHROPIC_API_KEY` в `.env`,
   поле `TELEGRAM_ALLOWED_CHAT` оставьте пустым — временно.
2. Запустите бота (`npm run bot`) и напишите ему любое сообщение.
3. Бот ответит: `Доступ запрещён. Ваш chat id: 123456789`.
4. Впишите этот id в `TELEGRAM_ALLOWED_CHAT` и перезапустите бота.

### 4. Заполнить .env и запустить
```bash
cp .env.example .env      # впишите TELEGRAM_BOT_TOKEN, TELEGRAM_ALLOWED_CHAT, ANTHROPIC_API_KEY
npm install               # ставит @anthropic-ai/claude-agent-sdk
npm run bot
```
Увидите: `Бот @your_bot запущен (long polling).` — можно писать задачи.

## Команды в чате
- Любой текст — задача: бот выполнит её в репозитории и пришлёт результат.
- `/status` — что происходит: занят/очередь, модель, режим, проект, сессия, расходы.
- `/stop` — остановить текущую задачу и очистить очередь.
- `/reset` — начать новый диалог (сбросить контекст сессии).
- `/model [id]` — показать или сменить модель.
- `/mode [default|acceptEdits|bypassPermissions|plan]` — показать или сменить режим прав.
- `/project [name]` — показать или сменить проект (папку агента).
- `/diff` — показать `git diff`.
- `/commit [сообщение]` — закоммитить (без сообщения агент придумает сам).
- `/push` — `git push`.
- `/send <путь>` — прислать файл из рабочей папки в чат.
- `/help` — справка.

Также можно **прислать файл** (сохраню в проект) или **голосовое** (распознаю
текст, если настроен STT) — голос обрабатывается как обычная текстовая задача.

## Подтверждение опасных действий (режим `default`)
В режиме прав `default` перед выполнением инструментов, требующих подтверждения,
бот присылает сообщение с кнопками **✅ Разрешить / ⛔ Запретить**. В `acceptEdits`
правки файлов проходят автоматически, в `bypassPermissions` — всё без вопросов.

Диалог **сохраняет контекст**: агент помнит предыдущие сообщения в рамках сессии,
пока вы не отправите `/reset` или не перезапустите бота.

Во время работы бот присылает **строки прогресса** (`🔧 Edit: server.js`,
`🔧 Bash: npm test`) — видно, что делает агент. Ответы форматируются (код,
жирный) с откатом в простой текст, если форматирование не проходит.

## Переменные окружения
| Переменная | Обязательна | По умолчанию | Назначение |
|---|---|---|---|
| `TELEGRAM_BOT_TOKEN` | да | — | Токен бота от @BotFather |
| `TELEGRAM_ALLOWED_CHAT` | да | — | Ваш chat id; только он может писать боту |
| `ANTHROPIC_API_KEY` | да | — | Ключ Claude API для движка агента |
| `CLAUDE_MODEL` | нет | `claude-opus-4-8` | Модель агента |
| `CLAUDE_PERMISSION_MODE` | нет | `acceptEdits` | Режим прав агента (`acceptEdits`, `bypassPermissions`, `default`) |
| `BOT_WORKDIR` | нет | папка проекта | Рабочая папка агента |
| `AGENT_TIMEOUT_MS` | нет | `600000` | Таймаут одной задачи, мс (по истечении — прерывание) |
| `DAILY_COST_LIMIT` | нет | `0` | Дневной лимит расходов в $ (0 = без лимита) |
| `TELEGRAM_ALLOWED_CHATS` | нет | — | Список chat id через запятую (перебивает одиночный) |
| `BOT_PROJECTS` | нет | — | Проекты `имя:/путь` через запятую (для `/project`) |
| `STT_API_URL` | нет | — | OpenAI-совместимый STT-эндпоинт для голосовых |
| `STT_API_KEY` | нет | — | Ключ STT-сервиса |
| `STT_MODEL` | нет | `whisper-1` | Модель распознавания речи |
| `BOT_STATE_FILE` | нет | `.bot-state.json` | Файл состояния (сессии/настройки/расходы) |

Несколько пользователей: `TELEGRAM_ALLOWED_CHATS=111,222`. У каждого чата
**своя сессия** (контексты не смешиваются). Проект и модель — общие для бота.

`.env` бот загружает сам (встроенный парсер, без зависимостей) — достаточно
положить файл рядом с `telegram-bot.js`. Реальные переменные окружения имеют
приоритет над `.env`.

## Как это устроено (надёжность)
- **Опрос и выполнение расцеплены.** Пока агент работает над задачей, бот
  продолжает принимать сообщения; новые задачи становятся в **очередь**
  (бот сообщает, сколько впереди).
- **Таймаут.** Задача дольше `AGENT_TIMEOUT_MS` прерывается, чтобы не блокировать бота.
- **Сессия переживает рестарт.** id сессии хранится в `BOT_STATE_FILE`; после
  перезапуска диалог продолжается (сбросить — `/reset`).
- **Аккуратная остановка.** По `Ctrl+C` / `SIGTERM` бот прерывает текущую задачу,
  сохраняет состояние и выходит.
- **Защита от двойного запуска.** Если Telegram вернёт 409 (запущен второй
  экземпляр или активен webhook) — бот сообщит и остановится.

## Развёртывание (always-on)
Бот должен работать постоянно. Три варианта:

**systemd** (готовый юнит — `deploy/wb-telegram-bot.service`):
```bash
sudo cp deploy/wb-telegram-bot.service /etc/systemd/system/
# поправьте WorkingDirectory и User в файле
sudo systemctl daemon-reload
sudo systemctl enable --now wb-telegram-bot
journalctl -u wb-telegram-bot -f   # логи
```

**Docker** (`deploy/Dockerfile`):
```bash
docker build -f deploy/Dockerfile -t wb-telegram-bot .
docker run -d --restart=always --env-file .env --name wb-bot wb-telegram-bot
```

**pm2**:
```bash
pm2 start telegram-bot.js --name wb-bot && pm2 save && pm2 startup
```

Логи можно писать в файл: `BOT_LOG_FILE=/var/log/wb-telegram-bot.log`
(ротация по размеру `BOT_LOG_MAX`).

## Webhook вместо polling
По умолчанию бот работает в режиме **polling**. Для сервера с доменом можно
включить **webhook** (`BOT_MODE=webhook`) — нужен публичный HTTPS-URL:
```bash
BOT_MODE=webhook BOT_WEBHOOK_URL=https://ваш-домен/telegram/webhook \
BOT_WEBHOOK_SECRET=секрет BOT_WEBHOOK_PORT=8081 npm run bot
```
Или встроить приём в существующий `server.js` (тот же порт, что и API):
```bash
TELEGRAM_WEBHOOK_IN_SERVER=1 BOT_WEBHOOK_URL=https://ваш-домен/telegram/webhook \
BOT_WEBHOOK_SECRET=секрет npm start
```
Секрет проверяется по заголовку `X-Telegram-Bot-Api-Secret-Token`.

## Long polling vs Webhook — в чём разница

Бот использует **long polling** — сам опрашивает Telegram методом `getUpdates`.

- **Long polling («сам хожу за почтой»)** — программа в цикле спрашивает Telegram:
  «есть новые сообщения?». **Публичный адрес не нужен**, работает с любого сервера
  или ноутбука. Запустил `npm run bot` — работает. Именно этот режим здесь.
- **Webhook («почту приносят сами»)** — вы говорите Telegram слать сообщения
  POST-запросом на ваш URL (`https://…/telegram/webhook`). Экономнее и мгновенно,
  но нужен **публичный HTTPS-адрес с валидным сертификатом** (домен/деплой/туннель).
  Имеет смысл, когда бот живёт на сервере с доменом; тогда приём можно встроить в
  существующий `server.js` как ещё один маршрут.

Для «пишу задачи из Telegram» long polling — самый простой и надёжный старт.

## Безопасность
- Боту может писать **только** `TELEGRAM_ALLOWED_CHAT`. Остальным — отказ.
- Агент по умолчанию работает в режиме `acceptEdits` (может править файлы в
  `BOT_WORKDIR`). Для полной автономии поставьте `bypassPermissions`, но помните:
  агент сможет выполнять команды в проекте — держите бота приватным.
- `.env` в git не попадает (см. `.gitignore`) — токены остаются локально.
