# Демо-стенд planner

Публичная витрина инструмента на `https://demo.aidemiko.ru/` — вход по одной ссылке,
без Telegram и без регистрации. Живёт отдельно от боевого экземпляра.

## Почему отдельный экземпляр, а не роль

Демо-гость — посторонний человек. Если пустить его в боевую базу, он увидит настоящие
артикулы, объёмы производства и сроки: права спрячут вкладки, но данные останутся в
одной базе, и любая будущая ошибка в правах станет утечкой. Поэтому у демо своя копия
базы, из которой всё чувствительное **удалено физически** — показывать там просто нечего.

| | Боевой | Демо |
|---|---|---|
| Адрес | `planner.aidemiko.ru` | `demo.aidemiko.ru` |
| Порт | `127.0.0.1:9100` | `127.0.0.1:9101` |
| Служба | `planner.service` | `planner-demo.service` |
| Каталог | `/opt/planner` | `/opt/planner-demo` |
| Пользователь | `planner` | `plannerdemo` |
| Вход | Telegram + приглашение | ссылка `/guest?c=КОД` |
| Данные | настоящие | обезличенная копия |
| Токены MPStats/WB | есть | **нет** — во внешние API не ходит |

## Что делает обезличивание

Скрипт `planner/tools/anonymize-db.mjs` (ветка `claude/production-plan-twv8ki`)
работает по копии и отказывается запускаться, если в пути нет слова `demo`.

**Удаляет:** пользователей и их права, ответственных, журнал производственных событий,
снимки состояния, архив отчётов, историю поисков сезонности, все токены
(MPStats, Google, Anthropic, секрет сессий) и выгрузку продаж.

**Обезличивает:** артикулы → «Модель N», поставщиков → «Поставщик N», цеха → «Цех N»,
контакты и заметки стирает, коды WB и привязки к карточкам убирает, себестоимость и
цены искажает случайным множителем (±30%, с округлением), количества умножает на один
общий коэффициент — пропорции плана сохраняются, реальные объёмы не читаются.

**Оставляет:** рыночные данные WB и MPStats (тарифы, карточки, ключевые фразы, выдача) —
они публичные и делают демо живым; бренд и артикул продавца в карточках затираются.

## Развернуть

```bash
sudo bash /opt/wb-headless/deploy/vps/41-deploy-planner-demo.sh
sudo nano /opt/planner-demo/planner/data/.env   # вписать токен бота и OWNER_TELEGRAM_ID
sudo systemctl restart planner-demo
sudo bash /opt/wb-headless/deploy/vps/add-site.sh demo.aidemiko.ru 9101
```

Гостевая ссылка печатается при первом запуске и лежит в `GUEST_LINK_CODE`:

```
https://demo.aidemiko.ru/guest?c=<GUEST_LINK_CODE>
```

Сменить ссылку (старая мгновенно перестаёт работать): новое значение
`GUEST_LINK_CODE` в `.env` → `sudo systemctl restart planner-demo`.

## Обновить данные демо

Демо-база не обновляется сама — это осознанно: показываем срез, а не оперативные данные.
Когда захочется освежить:

```bash
sudo REFRESH_DB=1 bash /opt/wb-headless/deploy/vps/41-deploy-planner-demo.sh
```

Снимок боевой базы снимается через `VACUUM INTO` — так забирается и WAL-журнал;
обычный `cp` живой базы даёт неполную копию (проверено: таблицы «терялись»).
Если обезличивание упадёт — скрипт остановится и не опубликует базу.

## Уведомления о заходах

При первом за полчаса заходе с одного адреса владельцу приходит сообщение в Telegram:
время и IP. Дедупликация — чтобы одна демонстрация не превращалась в очередь сообщений.
Работает, если в `.env` демо заданы `TELEGRAM_BOT_TOKEN` и `OWNER_TELEGRAM_ID`.

## Что видит гость

Диаграмма Ганта, План по размерам, Ранг сезонности, Отчёты — только просмотр, с выгрузкой
файлов. Юнит-экономику сервер вырезает из ответа (в демо она всё равно искажена).
Все гости работают под одним аккаунтом и не выбивают друг друга из системы.
