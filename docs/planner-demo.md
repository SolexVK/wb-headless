# Демо-стенд planner

Публичная витрина инструмента на `https://demo.aidemiko.ru/` — вход по одной ссылке,
без Telegram и без регистрации. Живёт отдельно от боевого экземпляра.

## Почему отдельный экземпляр с придуманными данными

Демо-гость — посторонний человек, а ссылку раздают кому угодно. Две развилки решены так:

**Не роль внутри боевого экземпляра.** Права спрятали бы вкладки, но данные остались бы
в одной базе — любая будущая ошибка в правах становится утечкой.

**И не обезличенная копия боевой базы.** Первую версию я сделал именно так — с заменой
названий и искажением цен — и это была ошибка. Копия с чужими подписями остаётся
настоящим производственным планом: те же сроки, та же структура партий, те же размерные
раскладки, то же число моделей. Плюс каждая правка обезличивателя — новый шанс что-то
забыть. Сейчас данные демо **генерируются** из сида репозитория (`lib/model.js`:
вымышленная фабрика, шесть цехов, пять моделей рубашек, сезон целиком). Этот сид открыт
в публичном репозитории — показывать его безопасно по определению, а боевых данных на
стенде нет физически.

| | Боевой | Демо |
|---|---|---|
| Адрес | `planner.aidemiko.ru` | `demo.aidemiko.ru` |
| Порт | `127.0.0.1:9100` | `127.0.0.1:9101` |
| Служба | `planner.service` | `planner-demo.service` |
| Каталог | `/opt/planner` | `/opt/planner-demo` |
| Пользователь | `planner` | `plannerdemo` |
| Вход | Telegram + рабочая группа | открыл адрес — уже внутри |
| Данные | настоящие | придуманные (сид репозитория) |
| Токены MPStats/WB | есть | **нет** — во внешние API не ходит |

## Что лежит в демо-базе

`planner/tools/seed-demo.mjs` (ветка `claude/production-plan-twv8ki`) очищает базу
полностью — пользователей, снимки, архив отчётов, журнал событий, все токены и кэши
рыночных данных — и записывает состояние из сида: пять моделей рубашек, шесть цехов,
двух поставщиков «А» и «Б», двадцать партий на сезон. Скрипт отказывается работать,
если в пути к базе нет слова `demo`.

Отчёты на стенде строятся сами: они считаются в браузере из тех же демо-данных,
поэтому гость нажимает «Получить отчёт» и видит результат, а Excel и PDF скачиваются.
Внешние API (MPStats, WB) стенду недоступны — токенов там нет, и раздел «Ранг
сезонности» показывает только то, что уже есть в данных.

## Развернуть

```bash
sudo bash /opt/wb-headless/deploy/vps/41-deploy-planner-demo.sh
sudo nano /opt/planner-demo/planner/data/.env   # вписать токен бота и OWNER_TELEGRAM_ID
sudo systemctl restart planner-demo
sudo bash /opt/wb-headless/deploy/vps/add-site.sh demo.aidemiko.ru 9101
```

Гостям даётся просто **https://demo.aidemiko.ru/** — открыл и смотришь, без входа
и без кода в адресе. Это включает `GUEST_AUTO=1` в `.env` стенда.

Закрыть витрину: убрать `GUEST_AUTO=1` и перезапустить службу — тогда остаётся
запасной вход по ссылке `/guest?c=<GUEST_LINK_CODE>`. Совсем убрать из сети —
`sudo systemctl disable --now planner-demo`.

## Пересоздать данные демо

Если на стенде что-то наковыряли (гости ничего не пишут, но владелец может зайти и
править) — вернуть исходный вид:

```bash
sudo REFRESH_DB=1 bash /opt/wb-headless/deploy/vps/41-deploy-planner-demo.sh
```

Без `REFRESH_DB=1` существующая база не трогается.

## Уведомления о заходах

При первом за полчаса заходе с одного адреса владельцу приходит сообщение в Telegram:
время и IP. Дедупликация — чтобы одна демонстрация не превращалась в очередь сообщений.
Работает, если в `.env` демо заданы `TELEGRAM_BOT_TOKEN` и `OWNER_TELEGRAM_ID`.

## Что видит гость

Все гости работают под одним общим аккаунтом. Видят: Диаграмма Ганта, План по
размерам, Ранг сезонности, Отчёты — только просмотр, но с рабочими выгрузками: построить отчёт, скачать Excel и PDF можно, изменить данные нельзя.
Юнит-экономику сервер вырезает из ответа. Все гости работают под одним аккаунтом и не
выбивают друг друга из системы.
