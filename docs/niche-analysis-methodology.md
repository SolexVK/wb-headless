## 1. Источники данных: что MPStats отдаёт под каждое измерение

База: `https://mpstats.io/api` · заголовок `X-Mpstats-TOKEN`.

| Эндпоинт | Метод | Что даёт |
|---|---|---|
| `wb/get/categories` | GET | дерево категорий (`{url,name,path}`) — резолвинг пути ниши |
| `wb/get/category` | POST | товары ниши с метриками (постранично, AG-Grid) |
| `wb/get/category/trends` | GET | динамика ниши по датам → **тренд + сезонность** |
| `wb/get/category/sellers` | GET | продавцы ниши → **конкуренция** |
| `wb/get/category/brands` | GET | бренды ниши → **конкуренция** |
| `wb/get/category/price_segmentation` | GET | распределение по ценовым сегментам |
| `wb/get/search` | POST | выдача по поисковой фразе (метод «от спроса») |
| `wb/get/item/{sku}/sales` | GET | дневной ряд карточки |

## 2. Пять измерений: определение → формула → порог → вердикт

### 2.1. Ёмкость рынка (capacity)
**Что:** сколько денег и штук ниша генерит за период — верхняя граница возможной выручки.

- `Выручка ниши = Σ revenue` по всем товарам категории.
- `Продажи ниши = Σ sales` (шт).
- `Ср. выручка на товар = Выручка / кол-во товаров`.
- `Ср. выручка на «живой» товар = Выручка / кол-во товаров с продажами` — честнее (не размывается мёртвыми карточками).
- `Упущенная выручка = Σ lost_profit` — **неудовлетворённый спрос** (дефицит у конкурентов = место для входа).
- `Медианная выручка на товар` — устойчивее среднего к монстрам-хитам.

**Вердикт:** высокая ёмкость + высокая ср. выручка на живой товар = есть на чём зарабатывать.
Ёмкость сама по себе ничего не решает без насыщенности и конкуренции (см. ниже).

### 2.2. Тренды (trend)
**Что:** куда движется ниша — растёт, стоит, падает.

Из `wb/get/category/trends` (ряд выручки/продаж/товаров-с-продажами по датам):
- `Δ% = (2-я половина периода − 1-я половина) / 1-я половина × 100` (готово в `seasonality()`).
- Наклон линейной регрессии по ряду выручки (устойчивее к шуму, чем деление пополам).
- Отдельно тренд по **числу товаров с продажами** — если растёт быстрее выручки, ниша забивается игроками (спрос делится на большее число карточек).

**Порог (по MPStats):** восходящий тренд = «на верном пути»; горизонтальный/нисходящий =
сигнал насыщения, новых игроков ниша уже не вмещает.

### 2.3. Сезонность (seasonality)
**Что:** насколько продажи зависят от времени года/праздников и когда окно входа.

- Запросить `trends` за **12–24 мес** → разложить по месяцам → индекс сезонности каждого месяца
  (`выручка месяца / средняя по месяцам`).
- Определить пик и «окно входа» (за 1–1,5 мес до пика — успеть накопить отзывы/органику).
- **Коэффициент демпинга** (из KB): 0–15% нет · 15–30% умеренный · **>30% высокий (не заходить)**.
  В сезон демпинг должен падать; если растёт — ниша нездоровая.

**Ограничение API:** полноценная сезонность за 3 года и ML-декомпозиция — это UI MPStats/Wildbox.
Через API приближаем по длинному ряду `trends` (12–24 мес). Это фиксируем как допущение.

### 2.4. Уровень конкуренции (competition)
**Что:** сколько игроков, насколько монополизировано, каков барьер входа.

- `Продавцов` и `брендов` в нише (уникальные) — из `category/sellers`, `category/brands`.
- **Монопольность = доля выручки топ-игроков.** Считаем несколько срезов:
  - доля выручки **топ-10 товаров** (готово в `/reports/niche`);
  - доля выручки **топ-продавца** и **топ-3 продавцов**;
  - индекс Херфиндаля-Хиршмана (HHI) по долям продавцов (опц., строгая мера).
- **Барьер по отзывам:** медиана `comments` у топ-20 по выручке. Мало отзывов у топа = молодая
  ниша, вход реален; 10 000+ = высокий барьер (нужно долго набирать соц-доказательство).
- **Барьер по цене входа:** «привлекательный» ценовой коридор из `price_zone` / `price_segmentation`.

**Порог монопольности (сводно по источникам):**
`0–15%` — здоровая конкуренция · `15–40%` — умеренная монополизация · `40%+` — нужен большой
бюджет / заходить рискованно.

### 2.5. Насыщенность (saturation)
**Что:** хватает ли спроса на всех — или предложение уже переросло спрос.

- **% товаров с продажами** = товары с ≥1 продажей / всего товаров. Низкий % = много «мёртвых»
  карточек, спрос не на всех → высокая скрытая насыщенность.
- **Спрос : предложение** = частотность запроса / кол-во карточек (метод «от спроса»,
  из `wb/get/search` + Оракул). Порог **10:1 и выше** = спрос явно превышает предложение (хорошо).
- **% новинок в топе** (карточки моложе 14 дней по `sku_first_date`): много новинок в топе =
  тренд зарождается, свежий игрок может пробиться; ноль новинок = топ «забетонирован».
- `Товары с продажами` растут быстрее выручки (из trends) = ниша забивается (насыщается).

**Фаза 2 (реализовано).** ТОП-выдача «от спроса» по поисковому запросу через
`POST /analytics/v1/wb/search/items` (эндпоинт залочен живым токеном). ⚠️ Проверено на живых
данных: эндпоинт отдаёт **максимум ~100 карточек** (топ), `total` тоже упирается в 100 — это НЕ
полное предложение ниши. Блок считает плотность/живость топ-выдачи (выручка, % с продажами,
монополизация топ-10, упущенка). **Спрос:предложение** (порог 10:1) считается только при переданных
вручную частотности И кол-ве карточек (оба — из Оракула Wildbox, в API нет). Не меняет скоринг 0–100.

## 6. Проверено живым прогоном (2026-07)

Прогон на `Женщинам/Платья и сарафаны` (39 183 товара) подтвердил и поправил:
- **Ёмкость/насыщенность/упущенка берутся из `category/price_segmentation`** — сегменты покрывают
  всю нишу (`Σ items` ≈ `total`), поэтому корректны даже при усечении выгрузки. По top-N (3000) они
  смещались: выручка занижалась на «хвост» (11 → 19,6 млрд ₽), а % с продажами ложно давал 100%
  (реально 82,6%). `dataBasis='niche'|'analyzed'` фиксирует источник.
- Поле «товары с продажами» в `trends` — `items_with_sells` (двойная L).
- Поля `search/items` (id, revenue, sales, final_price, final_price_average, lost_profit,
  comments, sku_first_date) совпали с нормализацией.
- Путь категории **надо резолвить из `wb/get/categories`** (напр. `Женщинам/Платья и сарафаны`);
  произвольный путь даёт `total=0`.

## 7. Проверено прогоном сезонности (14 мес → пересмотр тренда/сезонности)

Прогон на `Женщинам/Блузки и рубашки/Рубашка` вскрыл поведение `category/trends`:
- **`trends` ИГНОРИРУЕТ `d1/d2`** и всегда отдаёт **помесячную историю за ~6 лет** (2020→). Значит:
  - **Сезонность доступна на любом прогоне** (даже 30-дневном) — гейт «нужен длинный период» убран;
    индекс считается по календарным месяцам, усреднённым по годам (пик август, спад декабрь для рубашек).
  - **Тренд пересчитан на year-over-year** (последние 12 мес vs предыдущие 12) — «половина vs
    половина» давала 6-летний рост (604%!). YoY убирает сезонность: реальный рост ниши рубашек ≈ 23% г/г,
    последние 3 мес −2% г/г. Плюс `search/items` `items_with_sells` учтён.
- **Период запроса влияет только на ёмкость/насыщенность/конкуренцию** (их отдают `category` и
  `price_segmentation`, они `d1/d2` уважают). Рекомендация: брать **недавние 30 дней** — на длинном
  периоде кумулятивы раздуваются, а % с продажами стремится к 100%. Сезонность/тренд период не трогает.

## 11. Устранённые недочёты и добавленные блоки (по итогам аудита)

- **Реализация остатка по СРЕДНЕМУ остатку периода** (`stocks_graph`), а не по снимку `balance` —
  убрано смещение на исторических периодах.
- **Экономика единицы** (`NICHE_COST`): точка безубыточности и маржинальный коридор 25–30% по
  подтверждённой модели (комиссия 35,7%/СПП 4%/эквайринг 4,7%/налог 2%/ДРР/брак 2,5%); вердикт по
  марже при медианной цене ниши. Сверено с эталоном (себест. 536 → безубыт. 1051, коридор 2094–2613).
- **Процент выкупа** (`purchase`) — медиана по нише, риск возвратов.
- **Возраст карточек в топе** (`sku_first_date`) — доля топа моложе 90/180 дней (проходимость новичка).
- **Перспективные ценовые сегменты** — два лучших по выручке на карточку/мес при конкуренции ≤ медианы
  (приоритет дорогим сегментам). Плюс **достижимый объём при марже 30%**: шт/мес, выручка и прибыль
  на карточку в целевом сегменте (не только «цена безубытка»).
- **Планка входа** — экспресс-ориентиры топ-50 для будущей карточки: цель по объёму продаж, доля в
  рекламе, медианы фото/видео/отзывов, размерный ряд, длина описания (CPM и «негатив-медиана» убраны).
- **Топ-продавцы** — выручка ₽/мес + доля, бренд и ссылка на витрину продавца (`supplier_id`).
- **Помесячная реализация остатка** — временнáя диаграмма за период: когда спрос обгонял предложение.
- **Торговля вне сезона** — рекомендация держать ассортимент круглый год, работать на органике в спад.
- **Жёсткие риск-флаги** — монополизация ≥40%, затоварка (<0,8×), барьер отзывов, низкий выкуп,
  убыточность — понижают вердикт «Заходить» → «Осторожно» и выводятся отдельно.
- Терминология в отчёте — русская (без англицизмов), без дублирующих блоков.

## 9. Sell-through (метод Овчинникова) — корректный сигнал спрос/предложение

«Частотность ÷ карточки» описывает интерес к запросу, но НЕ говорит, выгодно ли продавать
**сейчас**. Правильнее — **соотношение продаж и остатков в периоде** (метод Овчинникова):
- `sell-through = Σ продано(шт) / Σ остаток(шт)` по нише за период. **>1.5×** — распродают быстрее,
  чем лежит на складе → спрос не покрыт → выгодный, «дефицитный» период. **<0.8×** — склады
  переполнены → невыгодно.
- Дополнительно **оборачиваемость** `turnover_days` (медиана) — за сколько дней распродаётся остаток.
- Данные — из `wb/get/category` (поля `sales`, `balance`, `turnover_days`) и из поисковой выдачи по
  фразе (те же поля) → sell-through считается и по нише, и по каждой уточняющей фразе, **без Wildbox**.
- Проверено живьём: рубашки (авг-2025) — sell-through **2.10×**, медиана оборота **12 дней** (быстро).

Фразы теперь ранжируются по sell-through (реальные продажи/остатки), а частотность/карточки из
Оракула — опциональное дополнение.

## 10. Частотность из API MPStats — статус

Эндпоинт `GET/POST /wb/get/keywords` (запросы категории с частотностью) в API **существует**
(требует `path`=категория), но его формат фильтра не описан в публичной интеграционной доке и
на пробах стабильно отвечает «Не корректные условия фильтра». Вывод: **частотность в API MPStats
доступна в принципе** (данные и эндпоинт есть), но нужен точный контракт запроса (из полной
API-доки MPStats за логином). До этого частотность берём из выгрузки Оракула (ручной ввод), а
основной сигнал спрос/предложение — sell-through (не требует частотности вовсе).

## 8. Валидация «спрос:предложение» по Оракулу Wildbox

Прогон запроса «рубашка женская в клетку … с длинным рукавом» с числами из выгрузки Оракула
(частотность 2088, товаров в выдаче 7355) дал `ratio = 2088/7355 = 0.3:1` → «предложение
насыщено». Совпало с колонкой Оракула «Отношение частотности к количеству артикулов» (R = 0.3) —
формула и пороги подтверждены живыми данными. Оба числа берутся из Оракула (в API MPStats их нет):
частотность → `frequency`/`NICHE_FREQ`, кол-во товаров в выдаче → `supplyCards`/`NICHE_SUPPLY`.

## 3. Сводный вердикт (скоринг ниши)

Свести 5 измерений в интегральную оценку (по образцу «рейтинга качества ниши» Wildbox — 15+ метрик).
Черновой скоринг 0–100, каждый блок 0–20:

| Блок | Хорошо (20) | Плохо (0) |
|---|---|---|
| Ёмкость | высокая выручка + ср. на живой товар | мало денег в нише |
| Тренд | восходящий | нисходящий |
| Сезонность | стабильно / вход перед пиком, демпинг <15% | демпинг >30% / пик прошёл |
| Конкуренция | монопольность <15%, отзывы у топа низкие | >40%, отзывы 10k+ |
| Насыщенность | % с продажами высокий, спрос 10:1+, новинки в топе | много мёртвых, топ забетонирован |

→ Итог: **«заходить / заходить осторожно / не заходить»** + узкое место (что именно мешает).

## 4. Чего MPStats API не отдаёт (закрывать вручную / Wildbox)

- «Оракул запросов» и рейтинг качества ниши по 15+ показателям — Wildbox (UI).
- Полная сезонность за 3 года с ML-декомпозицией — UI MPStats/Wildbox (через API приближаем).
- Принадлежность % признаков, конверсии по слайдам, полки — не оцифровывается MPStats.
- Частотность поисковых запросов для «спрос:предложение» — `wb/get/search`/Wildbox, не `category`.
