# FBS-сервис — архитектура и план

Опорный документ по мульти-тенант веб-сервису вокруг движков подсорта/дашбордов.
Наглядная версия: `docs/service/plan.html` (открыть в браузере) / артефакт.

## Согласованные решения
- БД: **SQLite** (Mac Mini) → **PostgreSQL** (VPS, позже) через тонкий слой доступа.
- Восстановление пароля: **админ-сброс** на MVP; email по ссылке — Фаза 4.
- Код: папка **`service/`** в этом репо; движки `scripts/fbs-*.mjs` переиспользуем через `--json`.
- Обновление данных — **по кнопке** (кэш снимка на кабинет).

## Модель доступа (решение нюанса «несколько менеджеров — один кабинет»)
`Пользователь` (свой логин/сессия) → `memberships` (роль owner/admin/member) →
`Организация` → `Кабинет` (WB-токен, шифрован, вводится один раз) → `Отчёты`.
- Токен вводит admin один раз; все участники организации видят её кабинеты без повторного ввода.
- У каждого свой аккаунт/сессия → нет накладок при параллельной работе.
- Снимок кэшируется на кабинет; одновременный «Обновить» схлопывается single-flight-замком; отчёты — только чтение.

## Модель данных
users · organizations · memberships(role) · cabinets(wb_token_enc AES-256-GCM, token_meta) ·
invitations · snapshot_cache(cabinet_id × report × params_hash → json, refreshed_at).

## Безопасность
- Токены WB — AES-256-GCM в БД, ключ в env/Keychain, не в логах/на фронте.
- Пароли — bcrypt; сессии httpOnly+Secure; CSRF; rate-limit на авторизацию.
- WB-токен: **Базовый, «Только чтение»**, категории **Контент + Статистика + Маркетплейс**.
- Проверка прав до запроса: JWT-маска `s` (Контент=1, Аналитика=2, Маркетплейс=4, Статистика=5, read-only=30) + `/ping`.
- Изоляция данных строго по (user → org → cabinet).

## Дорожная карта
- **Ф0** каркас + авторизация (Express в `service/`, SQLite, регистрация/логин/сессии/логи).
- **Ф1** организации, кабинеты, токены (валидация /ping + разбор прав JWT, шифрование, выбор кабинета).
- **Ф2** оболочка отчётов + кнопка «Обновить» + кэш; первым — Подсорт с формой + Excel; затем Остатки.
- **Ф3** остальные готовые отчёты (передано/принято/ретро) + скачивание PDF/Excel.
- **Ф4** email-восстановление, невстроенные отчёты (выкупы/SLA/баклог/FBO), переезд на VPS+Postgres.

## Деплой на Mac Mini — ПЕРЕД деплоем читать
Памятка: `docs/china-fbs/deploy/MAC-MINI-RULES.md` (соседняя ветка, PR #13).
Кратко: свой сервис на loopback `127.0.0.1:91xx` + свой LaunchAgent (уникальный label);
публикация только через **Caddy** (path на 443 + `caddy reload`); **не трогать** Tailscale
funnel/serve, порт 443, чужие launchd и занятые порты (8477/8787/8899/7837/8090/9000/8443/10000/2019).
Дизайн-следствие: сервис слушает настраиваемый `127.0.0.1:91xx` (env `PORT`), без привязок к 443/Funnel.
