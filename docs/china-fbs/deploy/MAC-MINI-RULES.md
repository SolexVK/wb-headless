# ⚠️ Mac Mini — правила деплоя (ПРОЧИТАЙ ПЕРЕД ТЕМ КАК ЧТО-ТО ЗАПУСКАТЬ)

Записка самому себе. На `Mac-mini-Vital` уже крутится несколько чужих и наших сервисов за общим
Tailscale Funnel. Конфиг Funnel **глобальный и общий** — одной неаккуратной командой можно уронить
соседей. Один раз уже ломали `/calc`. Ниже — что можно, что нельзя, и как добавить сервис правильно.

Сначала обязательно прочти: `deploy/CADDY.md` (архитектура прокси) и `deploy/RUNBOOK.md` (полное состояние).

## 🚫 НЕЛЬЗЯ (сломает соседей)
- **`tailscale serve reset`** — снесёт ВСЕ Funnel (443/8443/10000). Никогда.
- **Голый `tailscale funnel <порт>`** или `tailscale funnel --https=443 …` без ясной цели —
  перезапишет маршрут `/` на 443. 443 уже занят под Caddy — руками его не трогай.
- **Не занимай порты** 8477, 8787, 8899, 7837, 8090, 9000, 8443, 10000, 2019 (Caddy admin) — заняты.
- **Не включай `com.tandem.funnel`** обратно.
- **Не трогай чужие launchd** (`com.tandemtrace.*`, `com.getcourse.*`, `com.wbheadless.planner`) —
  не выгружай, не перезапускай, plist не редактируй.
- **Не коммить секреты**: `users.json`, `.auth-secret`, пароли, tailnet-токены. Они в `.gitignore`.
  Пароль сервиса — только в `EnvironmentVariables` plist (chmod 600) или env, не в репо.
- **Не меняй публичный вход соседей** (их пути/порты/URL) без явной просьбы.

## ✅ МОЖНО / РЕКОМЕНДОВАНО
- **`brew install <x>`** — аддитивно, безопасно.
- **Свой сервис — на СВОБОДНОМ порту, слушать только `127.0.0.1`** (например `127.0.0.1:9100`).
- **Автозапуск — свой LaunchAgent** с уникальным label (`com.<твоё-имя>.<сервис>`), не пересекаясь
  с чужими. Пример-шаблон — `deploy/install-launchd.sh` (наш калькулятор).
- **Публиковать новый сервис — ТОЛЬКО через Caddy на 443**, добавив path-маршрут (см. ниже).
  Funnel при этом не трогаем вообще.
- **Всегда тестируй локально ДО публикации**, в т.ч. «внешний» кейс с реальным Host:
  ```bash
  curl -s -H 'Host: mac-mini-vital.tail13d29e.ts.net' http://127.0.0.1:9000/<путь>
  ```
- `git pull` в папке нашего калькулятора + перезапуск только НАШЕЙ службы — ок.

## Как правильно добавить новый публичный сервис (на 443, через Caddy)
1. Подними сервис на свободном loopback-порту, напр. `127.0.0.1:9100`.
2. Отредактируй `/opt/homebrew/etc/Caddyfile` — добавь блок ВЫШЕ дефолтного `handle`:
   ```
   @myapp path /myapp /myapp/*
   handle @myapp {
       reverse_proxy 127.0.0.1:9100
   }
   ```
   - `handle` берёт ОДИН путь-аргумент → несколько путей только через именованный матчер `@…`.
   - Если приложение живёт на КОРНЕ и внешний префикс надо срезать — `handle_path` вместо `handle`.
     Если живёт прямо на `/myapp` (как tandemtrace) — `handle` (путь сохраняется).
   - Порядок важен: специфичные пути — раньше дефолтного `handle`.
3. Применить без даунтайма:
   ```bash
   /opt/homebrew/bin/caddy validate --config /opt/homebrew/etc/Caddyfile && \
   /opt/homebrew/bin/caddy reload --config /opt/homebrew/etc/Caddyfile
   ```
4. Синхронизируй канонич. копию в репо: `docs/china-fbs/deploy/Caddyfile` (чтобы не потерять при
   пересборке и для переноса на VPS).
5. **Funnel НЕ трогаем** — 443 уже указывает на Caddy.

## Грабли, на которые уже наступали (не повторять)
- **zsh на этом Mac: интерактивные комментарии ВЫКЛючены** → строки, начинающиеся с `#`,
  выполняются как команды (`command not found: #`). В командах для терминала не пиши `#`-строки
  (внутри heredoc — можно, они уходят в файл). Для пояснений — `echo`.
- **Caddy: адрес сайта `:9000` + `bind 127.0.0.1`, а НЕ `http://127.0.0.1:9000`.** Второе навешивает
  фильтр по `Host=127.0.0.1`; запросы от Funnel идут с реальным именем хоста и не матчатся → порт
  «не открывается» публично (при рабочем локальном curl). Проверяй через `-H 'Host: <домен>'`.
- **Tailscale `--set-path` префикс НЕ срезает** — бэкенд получает полный путь.
- **Обращение к своему же funnel-адресу с самого Mac часто не проходит (hairpin-NAT)** — это не
  поломка. Публичную доступность проверяй с телефона на мобильном интернете или через `-H Host:`.

## Если всё-таки что-то уронил
```bash
tailscale funnel status                 # что сейчас с маршрутами
brew services list | grep caddy         # жив ли прокси
launchctl list | grep -Ei 'tandem|wbcalc|getcourse|planner|caddy|wb\.unit'
```
Восстановить наш вход 443→Caddy (если слетел):
```bash
tailscale funnel --bg --https=443 127.0.0.1:9000
```
Дальше сверяйся с `deploy/CADDY.md` — там рабочая конфигурация целиком.
