# Работа с документацией и API Wildberries

Здесь зафиксировано, **как читать документацию WB**, **как соблюдать лимиты
запросов** и как всё это поддерживать в актуальном состоянии.

Официальная документация: <https://dev.wildberries.ru/docs/openapi/api-information>

---

## 1. Как мы читаем документацию (метод обхода блокировок)

Страницы `dev.wildberries.ru` **нельзя** прочитать обычным `curl`/`fetch`: они
закрыты антибот-челленджем и отрисовываются на клиенте (SPA). Нужен настоящий
браузер. Инструмент — [`scripts/fetch-wb-docs.mjs`](../../scripts/fetch-wb-docs.mjs).

Две преграды и как они сняты (чтобы не искать заново):

1. **Антибот** (`__wbaas/challenges/antibot`). Отдаёт страницу-заглушку с
   JS-задачкой; настоящий браузер её решает сам и получает cookie-пропуск.
   Помогают «стелс»-мелочи: реальный User-Agent, локаль `ru-RU`, скрытый
   `navigator.webdriver`, небольшие паузы и движения мышью.
2. **MITM-прокси окружения** (когда задан `HTTPS_PROXY`). Он **рвёт TLS 1.3**
   хендшейк Chrome из-за расширения **ECH (Encrypted Client Hello)** —
   диагностировано по `net-log` (туннель `200 Connection Established`, затем
   `ECONNRESET` на рукопожатии). Лечится опусканием потолка до **TLS 1.2**
   (`--ssl-version-max=tls1.2`) + игнором MITM-сертификата. `curl` работал
   именно потому, что ECH не использует. Без прокси (обычная сеть, CI) ничего
   этого не нужно — фетчер включает воркэраунд только при наличии `HTTPS_PROXY`.

### Как пользоваться

```bash
# любую страницу доки → в stdout
npm run docs:fetch -- https://dev.wildberries.ru/docs/openapi/analytics

# страница «общая информация + лимиты» → снимок в файл
npm run docs:limits            # = docs/wb-api/limits.md
```

Требуется браузер Chromium. В этом окружении он предустановлен
(`PLAYWRIGHT_BROWSERS_PATH`); в CI ставится командой
`npx playwright install --with-deps chromium`.

## 2. Лимиты запросов — коротко (первоисточник в `limits.md`)

WB считает лимиты по алгоритму **token bucket**. Полный снимок официальной
страницы — [`limits.md`](./limits.md). Ключевое:

**Базовые лимиты по типу токена (на аккаунт, период = 1 минута):**

| Тип токена | Лимит | Интервал | Всплеск (burst) |
|---|---|---|---|
| Персональный | 300/мин | 200 мс | 20 |
| Сервисный | 300/мин | 200 мс | 20 |
| Базовый | 150/мин | 200 мс | 10 |
| Тестовый | 150/мин | 200 мс | 10 |

- **Интервал** = период / лимит. Запросы надо **размазывать**, а не слать залпом.
- **Всплеск (burst)** — сколько можно разом; текущий остаток сервер отдаёт в
  заголовке `X-Ratelimit-Remaining` (во всех ответах, кроме 429).
- **429** приходит, если `X-Ratelimit-Remaining = 0` и запрос ушёл без паузы.
  Сколько ждать — в заголовках ответа: `X-Ratelimit-Retry` (через сколько
  секунд повторять), `X-Ratelimit-Reset` (когда восстановится всплеск),
  `X-Ratelimit-Limit` (макс. всплеск).
- **4xx в категории «Маркетплейс» = 10 запросов.** Ошибочный запрос жжёт лимит
  в 10 раз быстрее — поэтому 4xx **не повторяем**.
- **У отдельных методов лимиты жёстче базовых** — их читаем на странице метода
  (см. правило ниже) и задаём точечно через `methodLimit`.

Эти правила реализованы в клиенте [`lib/wbClient.js`](../../lib/wbClient.js):
token-bucket на каждую категорию, чтение `X-Ratelimit-*`, ожидание по
`X-Ratelimit-Retry` на 429, запрет ретраев на прочие 4xx, бэкофф на 5xx/сеть.

## 3. Обязательное правило при работе с методами

Перед использованием любого нового метода WB API **точечно и внимательно**
читаем страницу этого метода и берём его собственный лимит (он часто строже
базового). Затем передаём его в клиент:

```js
import { WbClient } from '../lib/wbClient.js';
const wb = new WbClient({ token: process.env.WB_API_TOKEN, tokenType: 'base' });

// пример: у метода лимит «X запросов за Y секунд» — фиксируем его явно
const { data } = await wb.get('statistics', '/api/v1/supplier/stocks', {
  query: { dateFrom: '2024-01-01' },
  methodLimit: { limit: 1, periodSec: 60, burst: 1 }, // ← из доки метода!
});
```

Прочитать страницу метода можно тем же фетчером:
`npm run docs:fetch -- <URL-метода>`.

## 4. Регулярное обновление (раз в неделю)

Лимиты и список методов у WB меняются. Снимок обновляется:

- **автоматически** — GitHub Actions
  [`.github/workflows/wb-docs-refresh.yml`](../../.github/workflows/wb-docs-refresh.yml)
  раз в неделю перечитывает страницы и коммитит изменения (если они есть).
  Git-diff покажет, что именно поменялось в лимитах/методах;
- **вручную** — `npm run docs:limits` и посмотреть `git diff docs/wb-api/`.

Список обновляемых страниц задаётся в `docs/wb-api/pages.json`.
