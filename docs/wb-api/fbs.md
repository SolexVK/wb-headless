# FBS (Fulfillment by Seller) — методы, склады и лимиты

Практический справочник по продажам **со склада продавца (FBS)** в WB API:
какие у нас склады, какими запросами управлять заказами и какие у методов
**лимиты**, чтобы не ловить `429` и временную блокировку.

- Полный снимок официальной страницы методов: [`orders-fbs.md`](./orders-fbs.md)
- Общие правила лимитов (token bucket, заголовки `X-Ratelimit-*`): [`limits.md`](./limits.md) и [`README.md`](./README.md)
- Клиент, который соблюдает лимиты автоматически: [`lib/wbClient.js`](../../lib/wbClient.js)

Категория токена для всех методов ниже — **Маркетплейс**.
Хост: `https://marketplace-api.wildberries.ru` (песочница —
`https://marketplace-api-sandbox.wildberries.ru`).

**Поля ответа и их значения:**

- `id` — идентификатор нашего склада (`warehouseId`). Используется в методах
  остатков, поставок и при работе со сборочными заданиями.
- `officeId` — идентификатор офиса/ПВЗ/СЦ WB, куда физически отгружаются товары.
- `deliveryType` — тип логистики склада:
  - `1` — обычная доставка (стандартная FBS-логистика силами WB) ← у всех наших;
  - `2` — доставка силами продавца (DBS);
  - `3` — экспресс-доставка.
- `cargoType` — габарит:
  - `1` — обычный (СГТ) ← у всех наших;
  - `2` — крупногабаритный (КГТ);
  - `3` — сверхгабаритный.
- `isDeleting` / `isProcessing` — служебные флаги (склад в процессе
  удаления / обработки). У всех наших складов `false`.

Смежные методы «Складов продавца» (для управления складами и остатками):

## 2. Лимиты FBS-методов (главное, чтобы не поймать бан)

WB считает лимиты по **token bucket** на аккаунт продавца. Ключевое:

- **`4XX` в Маркетплейсе = 10 обычных запросов** — ошибочный запрос жжёт лимит
  в 10 раз быстрее. Поэтому 4xx **не повторяем**.
- Остаток «всплеска» — в заголовке `X-Ratelimit-Remaining` (во всех ответах,
  кроме 429). На `429` ждём `X-Ratelimit-Retry` секунд.
- Значения ниже — для **персонального/сервисного** токена. У базового без
  секрета лимиты вдвое ниже (см. [`limits.md`](./limits.md)).

Все FBS-методы делятся на **три лимитные группы** (проверено по снимку
[`orders-fbs.md`](./orders-fbs.md)):

| Группа методов | Лимит | Интервал | Всплеск |
|---|---|---|---|
| Сборочные задания, поставки, пропуска, автовозврат, стикеры | **300 / мин** | 200 мс | 20 |
| Получение / удаление идентификаторов маркировки | **300 / мин** | 200 мс | 20 |
| **Закрепление** идентификаторов маркировки (`meta/*`) | **1000 / мин** | 60 мс | 20 |
| ⚠️ Отмена сборочного задания — **строже всех** | **100 / мин** | 600 мс | 20 |

## 3b. Ретроспектива заказов по фулфилменту (сколько, кем, за какое время)

Задача: за период (напр. неделю) увидеть по **каждому нашему складу**
(фулфилменту), сколько заказов сделано и обработано, за какое время и были ли
критически долгие. Инструмент: [`scripts/fbs-orders-retro.mjs`](../../scripts/fbs-orders-retro.mjs)
(`npm run fbs:retro`).

**Правильные методы (атрибуция по нашему складу + точное время обработки):**

| Что берём | Метод | Ключевые поля |
|---|---|---|
| Сборочные задания за период | `GET /api/v3/orders` (`dateFrom`/`dateTo` unix-сек, пагинация `next`; макс 30 дн) | `id`, `createdAt`, **`warehouseId`** (наш склад), `supplyId`, `article`, `nmId` |
| Поставки (момент отгрузки) | `GET /api/v3/supplies` (пагинация `next`) + `GET /api/v3/supplies/{supplyId}` для добора | `id`, `createdAt`, **`closedAt`** (передана в доставку), `done` |
| Текущий статус задания | `POST /api/v3/orders/status` | `supplierStatus`: new/confirm/complete/cancel |

**Время обработки заказа = `supply.closedAt − order.createdAt`** (join по
`supplyId`). Заказ считается «обработанным», когда его поставка закрыта
(`done`/`closedAt`); иначе — «в работе / не отгружен».

**Важные подводные камни (проверено на практике):**

- ⚠️ Статистический `GET /api/v1/supplier/orders` для FBS кладёт заказ на
  **приёмку/СЦ WB** (`warehouseName` вроде «СЦ Чебоксары», «Подольск МП»),
  а поле `warehouseType` = `«Склад продавца»`. Наш склад-фулфилмент там
  **не виден** — для атрибуции «по нашему складу» берём `warehouseId` из
  `/api/v3/orders`. Статистику используем для спроса/географии, не для
  времени сборки.
- ⚠️ `POST /api/v3/orders/status/history` — **только трансграничные**
  поставки; как источник времени обычного FBS не годится.
- `GET /api/v3/orders` возвращает задания **без актуального статуса** — статус
  добираем отдельно через `/api/v3/orders/status`.

## 4. Как обращаться к FBS-методам безопасно

Используйте общий клиент — он держит token bucket на категорию `marketplace`,
читает `X-Ratelimit-*`, ждёт по `X-Ratelimit-Retry` на 429 и **не повторяет**
прочие 4xx:

```js
import { WbClient } from '../lib/wbClient.js';
const wb = new WbClient({ tokenType: 'personal' }); // токен из env/.env

// Новые сборочные задания FBS
const { data } = await wb.get('marketplace', '/api/v3/orders/new');

// Метод со СВОИМ, более строгим лимитом — задаём его точечно:
await wb.request('marketplace', `/api/v3/orders/${orderId}/cancel`, {
  method: 'PATCH',
  methodLimit: { limit: 100, periodSec: 60, burst: 20 }, // ← из таблицы выше
});
```

**Правило:** перед первым использованием нового метода сверяйтесь с его
лимитом в таблицах выше или в снимке [`orders-fbs.md`](./orders-fbs.md) и
передавайте `methodLimit`, если он строже базового (отмена задания;
закрепление маркировки — там мягче по интервалу, но выше потолок).
