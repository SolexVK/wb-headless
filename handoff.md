# Handoff — ABC-анализ товарной матрицы + поправка на наличие (WB API)

_Ветка: `claude/abc-product-matrix-vu12kj`. Обновлено по итогам сессии._

## Цель
Сделать качественный ABC-анализ ассортимента продавца WB (бренд AIDEMIKO) и на
его основе принимать решения по матрице товаров: что **оставить** (в т.ч.
выделить ядро — **Супер А**), что **доработать**, кому **дать шанс**, что
**сливать**. Ключевое требование пользователя — учитывать **наличие остатков**
на складе WB: товар в классе C может быть не «плохим», а просто отсутствовавшим
в продаже (out-of-stock), и такие нельзя выводить.

## Текущее состояние
- **Аналитика для пользователя — сделана и отдана файлами** (XLSX + PDF v4 с
  ярусами Супер А / Оставить / Дать шанс / Доработать / Сливать, поправкой на
  наличие и комментариями). Итог: Супер А 16 · Оставить 71 · Дать шанс 28 ·
  Доработать 32 · Сливать 40.

  scratchpad (эфемерный каталог сессии — **потеряется**). В git закоммичен

- **WB API — проверен вживую и работает.** Токен из env `Wildberries_API`
  действителен (до 2027-01-03), категории Аналитика+Статистика, read-only.
  Полный цикл истории остатков (создать→статус→скачать ZIP→распарсить) прошёл
  end-to-end на живом API.
- Открытых «красных» тестов нет; формальных тестов в проекте нет (см. ниже).

## Что изменилось
- Разобрал методологию пользователя из Excel: **мультикритериальный ABC** —
  3 буквы = ABC независимо по [Прибыль операционная, Сумма реализации,
  Количество], пороги накопленной доли **A≤80% / B≤95% / C>95%**; плюс
  **миграция класса по месяцам** (янв–июн) и экономика остатка.
- Вердикты строил на полных месяцах (**опора апрель–май**, июнь неполный — срез
  на 12.06). Добавил сезон (осень-зима/лето из справочника-картинки),
  **сезонную поблажку** недавним ОЗ-новичкам, флаг **«сливать»** (жёсткий).
- **Поправка на наличие (главный результат):** через WB API вытащил дневные
  остатки за апр–июн (`STOCK_HISTORY_DAILY_CSV`) и спрос за 6 мес (воронка
  `DETAIL_HISTORY_REPORT`, openCardCount). **18 артикулов подняты из «сливать» в
  «дать шанс»** — их топил дефицит склада, а не спрос (линейки
  `033_ржм_*_вс`, `032_ржм_*_ов`, `034_рмж_*_пк`: наличие апр/май ≈0%, но
  1,64 млн просмотров и 25k заказов за полгода).
- Ввёл ярус **Супер А** (16 флагманов): Оставить + класс A май + ОП мая ≥130к +
  маржа ≥27% + в наличии. Ядро — линейка `014 муслин`.

## Что пробовали и НЕ сработало (важное — чтобы не повторять)
- **Документация WB `dev.wildberries.ru` недоступна WebFetch** — отдаёт HTTP 498
  (бот-защита). Обход: брал OpenAPI из GitHub `eslazarev/wildberries-sdk`
  (`api.github.com/repos/.../git/trees/main?recursive=1` → файл
  `clients/go/analytics/api/openapi.yaml`).
- **Сначала угадал пути WB-отчёта неверно** (`/api/v1/analytics/report/generate`
  и т.п.) — их НЕ существует. **Реальные:** `POST /api/v2/nm-report/downloads`
  (создать), `GET /api/v2/nm-report/downloads?filter[downloadIds]=<id>` (статус),
  `GET /api/v2/nm-report/downloads/file/<id>` (скачать). Хост
  `seller-analytics-api.wildberries.ru`.
- **`DETAIL_HISTORY_REPORT` НЕ содержит остатков** — это воронка продаж по дням
  (openCard/addToCart/orders/buyouts/конверсии). Тупик для «6-месячной истории
  склада». Вывод: **дневного остатка глубже 3 месяцев в WB API нет**;
  `STOCK_HISTORY_DAILY_CSV` = максимум 3 месяца (но это ровно апр–июн — нужное окно).
- **Тело create валидируется строго:** `STOCK_HISTORY_DAILY_CSV` требует
  обязательный `params.stockType` (пусто = склады WB; иначе HTTP 400).
  `DETAIL_HISTORY_REPORT` требует `params.startDate`/`endDate` (а НЕ
  `currentPeriod`). Значения полей ловятся по тексту ошибки 400 — удобно.
- **Скачивание отдаёт ZIP**, не сырой CSV; сам CSV — в **«широком» формате**
  (колонки-даты `DD.MM.YYYY`, строка = nmID×размер×склад), а не длинном.
  Первый парсер (длинный формат) не подошёл — переписал под широкий.
- **В Node нет встроенного ZIP** (есть только gzip). Решение: своя минимальная
  распаковка через центральный каталог + `zlib.inflateRawSync` (без внешних
  зависимостей) — см. `unzipFirst` в `lib/wbStocks.js`.
- **«Обновлённый» Excel пользователя оказался байт-в-байт идентичен прежнему** —
  мусорные артикулы остались в расчётных блоках (значения вписаны **жёстко, не
  формулами**, чистка не пропагировалась). Обошёл: сам выкинул 2 технических
  («неопознанный товар», «Нераспределённое»), остальное пометил.
- **Баг в самом Excel:** в столбце «ОП 05» диапазон VLOOKUP обрезан
  `$AX$4:$BC$82` (надо `…$195`) — обнулял ОП мая у ~100 артикулов. Считал не по
  этим лукапам, а напрямую из майского блока.
- **Инструменты харнесса иногда падали** с «permission stream closed»
  (`AskUserQuestion`, `Artifact` publish) — помогал повтор / текстовый обход.
- **playwright не импортится обычно** — нужен абсолютный путь
  `/opt/node22/lib/node_modules/playwright/index.js` и **CommonJS `require`**
  (не ESM `import`). PDF рендерил через `chromium` из этого пути.

## Команды для проверки
```bash
# синтаксис ключевых модулей (должно молча пройти)
node --check lib/wbApi.js && node --check lib/wbStocks.js && node --check report-wb-stocks.js \
  && node --check lib/abcReport.js && node --check report-abc.js && node --check server.js

# WB API вживую (токен в env Wildberries_API; лимиты соблюдаются автоматически)
WB_TOKEN="$Wildberries_API" node report-wb-stocks.js --current              # снимок остатков
WB_TOKEN="$Wildberries_API" node report-wb-stocks.js 2026-06-15 2026-07-05   # дневная история

# ABC-отчёт из MPStats (нужен MPSTATS_TOKEN)
MPSTATS_TOKEN="$MPSTATS_TOKEN" npm run report:abc
```

живой прогон `report-wb-stocks.js` возвращает данные (в прошлый раз: 206 товаров,
12 в дефиците, файл в `reports-output/`).
