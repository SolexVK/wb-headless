# Handoff — planner / Этап 3 (Остатки и поставки, WB-остатки, неттинг)

Ветка: `claude/production-plan-twv8ki` · репо `solexvk/wb-headless` · приложение в `planner/`.
Билд на конец сессии: **`supply-net-export-2026-08-21n`** (APP_BUILD в `public/app.js`, BACKEND_BUILD в `server.js`).

## Цель
Лист «Остатки и поставки»: собрать реальные остатки товара (WB FBW + FBS, в пути, склад
производства, в производстве), вычесть их из плана продаж (неттинг), и в производство (Excel для
цеха + Гант) закладывать только то, чего не хватает — не шить лишнего. Всё увязано с планом из
«Ранг сезонности», разложено по цехам и показано на диаграмме Ганта.

## Текущее состояние
Работает и подтверждено пользователем:
- Подтяжка остатков WB **FBW + FBS** по nmID. FBW идёт через Seller Analytics `warehouse_remains`
  (отчёт: создать→дождаться→скачать), FBS — через marketplace `/api/v3/warehouses` +
  `/api/v3/stocks/{whId}` по штрихкодам. Оба суммируются в одно предложение по цвету×размеру.
- Привязка артикул↔nmID: загрузка **таблицы номенклатур ВБ** (колонки «Артикул продавца» +
  «Артикул WB») — nmID проставляются автоматически по ведущему номеру (`022 МР…` → артикул `022`).
- Неттинг живой (в планировщике): полностью покрытые партии не шьются, частично — уменьшаются,
  нетто раскладывается по цехам, Гант строится на нетто (+ метки прихода поставок).
- **Выгрузка «План по размерам → Excel для цеха» идёт на НЕТТО** (за вычетом остатков) — это была
  последняя правка сессии, ключевая для корректной передачи в производство.

Пользователь выбрал: экран «План по размерам» оставить как есть (эталон спроса, живой слой) —
меняется только то, что уходит в цех (Excel + Гант).

Не тестируется в этом контейнере (нет WB-токена/сети) — проверка только на Mac mini пользователя.

## Что изменилось (по сути)
1. FBW-остатки перестали быть нулевыми: раньше join шёл по «nmID|размер-карточки», а у карточек
   Content API `techSize` часто пустой → ни одна строка отчёта не находилась. Теперь FBW индексируется
   по nmID, размер берётся из строки отчёта.
2. FBS заработал: причина нулей — кэш карточек в БД (`wb_cards`) хранил только габариты и терял
   штрихкоды. Добавлен `payload`-JSON; плюс авто-перечитка свежих карточек, если в кэше нет skus.
3. Привязка по nmID из таблицы номенклатур (одной загрузкой, по ведущему номеру).
4. Лист почищен от легаси-привязки по префиксам.
5. Экспорт плана в Excel для цеха — на нетто (главное для «не шить лишнего» на выходе в производство).

## Что пробовали и НЕ сработало (грабли — читать внимательно)
- **Старый `/api/v1/supplier/stocks` (statistics) — 404 «deprecated».** Не воскрешать. Правильный путь
  для FBW — Seller Analytics `warehouse_remains` (асинхронный отчёт, ~до 2 минут генерации, кэш 1ч).
- **FBW join по размеру карточки давал 0.** У Content API `sizes[].techSize` часто пустой (размер в
  `wbSize`). Нельзя джойнить остатки по размеру из карточки — размер берём из строки отчёта, а карточку
  находим по nmID. (См. `aggregateStocks` → индекс по nmID.)
- **FBS всегда 0 при «штрихкодов запрошено — 0».** Ловушка: таблица `wb_cards` в SQLite сохраняла
  только габариты и **молча теряла skus/sizes/color** при кэш-раунд-трипе. Даже свежая выборка карточек
  писалась в БД без штрихкодов, а следующая (не-force) подтяжка читала их обратно уже без skus. Лечится
  колонкой `wb_cards.payload`. Диагностика «штрихкодов запрошено 0» = верный индикатор этой болезни.
- **Ручные ключи с ошибками написания** (`003_РМП` vs WB `023_рвп`, «016» с кучей написаний) — тупик
  для привязки по префиксу. Ушли на nmID из номенклатуры (точная привязка карточки).
- **Разбиение цветового сегмента по дефису** ломало составные цвета (`светло-коричневый`). `vcSegments`
  режет по `[_\s]+`, НЕ по дефису.
- **«Неттинг не пересчитывается»** — это не баг: неттинг живой, остатки могут покрыть план лишь частично
  (приходят позже последнего довоза → излишек). Прояснено колонками Покрыто/Излишек.
- Экран «План по размерам» **намеренно НЕ переписываем** нетто — иначе при обновлении остатков план
  «съедался» бы и повторный неттинг ломался. Нетто уходит только в Excel-выгрузку и Гант.

и сети к WB). Последний коммит запушен: `6b8cb1f` (нетто-выгрузка).
