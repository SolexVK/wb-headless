# Handoff — анализ конкурентов и ниши WB через MPStats + PDF-отчёты

## Цель
Провести анализ карточек конкурента на Wildberries по данным **MPStats API** и оформить результат в
**красивые PDF-отчёты**. По ходу выросло в переиспользуемый инструмент: по списку артикулов и
поисковому запросу собрать данные и сгенерировать единый многостраничный PDF (обложка-сводка +
карточка каждого артикула + анализ ниши).

## Текущее состояние
Работает end-to-end. В репозиторий закоммичен переиспользуемый пайплайн `reports-generator/`
(`collect.py` → `build.py`), проверен «с нуля»: `collect.py` тянет ~10 987 SKU категории, оба
артикула и нишу; `build.py` рендерит корректный **4-страничный PDF**. В финальной версии добавлены
кликабельные ссылки на WB (артикулы/бренды), внутренние переходы по оглавлению, фото товаров на
обложке и в ТОП-конкурентах ниши, жирное выделение значимых цифр. Всё запушено в ветку
`claude/wildberries-competitor-analysis-u4ftu1` (последний коммит `a85d4b2`). PR **не создавался**.

Анализировались артикулы **447156582** (классическая, среднего хвоста, ранг 2051) и **428365795**
(приталенная, флагман, ранг 43 / ТОП-100). Ниша: «рубашка мужская однотонная с длинным рукавом».

## Файлы, над которыми работали
- `reports-generator/collect.py` — сборщик: MPStats API → `data.json` (артикулы, рынок, ниша, авто-вердикты, base64-фото).
- `reports-generator/build.py` — рендер: `data.json` → единый HTML (CSS-переменные на страницу) → PDF через Chromium; ссылки/фото/жирный.
- `reports-generator/README.md` — как запускать, требования, кастомизация, ограничения.
- `.gitignore` — добавлены `__pycache__/`, `*.pyc` (ранее уже был `reports-output/`).
- `reports-output/` (в .gitignore) — рабочие выходы: `data.json`, `combined.html`, `combined.pdf`.
- Скретчпад (эфемерный, НЕ в git): `/tmp/rep/*` (сырые JSON, фото, промежуточные PDF) и
  `/tmp/gen_*.py`, `/tmp/collect.py`, `/tmp/niche.py` — одноразовые прото-скрипты, из которых вырос
  `reports-generator/`. При новой сессии контейнер чистый — этих файлов уже не будет.

## Что изменилось
- Клиент к MPStats на stdlib (`urllib`), заголовок `X-Mpstats-TOKEN`, ретраи с бэкоффом.
- Рынок считается по **полной выгрузке категории** (постранично) — сумма выручки всех SKU, ранги и
  доли артикулов. Ниша выделяется **фильтром по названию/цвету** (однотонность + длинный рукав,
  исключены принты/короткий рукав/оверсайз/пляжные).
- PDF собирается **одним документом** (обложка + карточки + ниша) и печатается одним вызовом
  Chromium `--print-to-pdf`. Акценты трёх отчётов разведены через CSS-переменные
  (`--accent/--accent2/--tint/--soft`) на каждой `.page`, чтобы не конфликтовали в общем `<style>`.
- Кликабельность: артикулы → `wildberries.ru/catalog/{nmId}/detail.aspx`; бренды → поиск WB
  `search.aspx?search=<бренд>`; оглавление → внутренние якоря `#p2/#p3/#p4`. Всё подтверждено в PDF
  (аннотации `/URI` и `/Dest`).

## Что пробовали и НЕ сработало (важно — читать перед доработками)
- **SEO/поисковая выдача MPStats закрыта на этом токене.** Долго искали эндпоинт «продажи по
  запросу»:
  - `GET/POST /wb/get/search?path=<запрос>` → **HTTP 200, но пустое тело `text/html`** (роут-заглушка).
  - `/wb/get/keywords/keyword`, `/keywords/results`, `/keywords/expanding` → **405 «Must be one of:
    OPTIONS»** (только preflight — модуль недоступен).
  - `/wb/get/in_search`, `/wb/get/search_results`, `/wb/get/word` → существуют, но на любой body
    отвечают **`500 «Не корректные условия фильтра»`** (ждут категорийный `path`, не свободный запрос).
  - Вывод: «долю в продажах по запросу vs ТОП-100» напрямую взять НЕЛЬЗЯ. Обходной путь — доля по
    выручке **категории** + позиция артикула по запросу из `/wb/get/item/{sku}/by_keywords`
    (там есть `avg_pos`, `avg_organic_pos`, `total`/частотность). Нишу выделяем фильтром названий.
- **`percent_from_revenue` в ответе категории всегда 0** — доля per-row не приходит. Поэтому рынок
  считаем сами: суммируем выручку всех строк. `endRow=11000` → **500**; рабочий предел страницы
  `endRow=5000`; хвост добираем чанками `startRow=5000/8000` (одним куском `startRow=5000..10987`
  тоже падает 500 — только меньшими диапазонами).
- **Нет утилит склейки PDF** (`pdfunite/qpdf/gs/pdftk`, python `pypdf/PyPDF2` — все отсутствуют).
  Поэтому не склеиваем 4 PDF, а рендерим один HTML с `break-after:page`. Проверено: Chromium
  `--print-to-pdf` сохраняет и внешние (`/URI`), и внутренние (`/Dest`) ссылки.
- **Метод-квирки MPStats:** `by_warehouse/by_region`, `item/{sku}/card` → 405; карточка берётся
  через `GET /wb/get/item/{sku}` (поле `first_date`, `sizeandstores`). Остатки по складам — из
  `sizeandstores[*].s` (ключи — ID складов; названия известны лишь для основных, прочие как `СЦ · ID`).
- **Дважды ловили переполнение страницы** (контент вылезал за A4, `overflow:hidden` его срезал) после
  укрупнения шрифтов и после добавления фото в таблицу лидеров — лечили уменьшением отступов/шрифтов/
  миниатюр и укорачиванием имён. Проверять скриншотом под A4 (794×1123 @ 96dpi).
- Мелочи-грабли: `sizeandstores[*].s` иногда **list (пустой), а не dict** — падало `.values()`;
  `%,d` в Python-`%`-форматировании **не работает** (только `{:,}`); у брендов **нет стабильного
  публичного URL страницы** → ведём на поиск WB.

## Команды для проверки
Требуется `MPSTATS_TOKEN` в окружении и Chromium (`$CHROME` или автопоиск `/opt/pw-browsers/...`).
```bash
# синтаксис/импорт (без сети)
python3 -c "import sys; sys.path.insert(0,'reports-generator'); import build, collect; print('OK')"

# полный прогон: собрать данные и собрать PDF
MPSTATS_TOKEN=*** python3 reports-generator/collect.py \
  --sku 447156582 428365795 --category "Мужчинам/Рубашки" \
  --query "рубашка мужская однотонная с длинным рукавом" \
  --d1 2026-06-08 --d2 2026-07-07 --out reports-output/data.json

CHROME=/opt/pw-browsers/chromium-1194/chrome-linux/chrome \
python3 reports-generator/build.py reports-output/data.json \
  --html reports-output/combined.html --pdf reports-output/combined.pdf

# проверить результат
file -b reports-output/combined.pdf                                  # ожидаем "PDF ... 4 page(s)"
strings reports-output/combined.pdf | grep -c 'detail.aspx'          # ссылки на карточки (>0)
strings reports-output/combined.pdf | grep -c '/Dest /p'             # внутренние переходы (=3)
```
**Ожидаемое состояние (зелёное):** формальных тестов в проекте нет. «Зелёно» = `import` печатает OK;
`collect.py` завершается с кодом 0 и пишет `data.json` (~10 987 SKU); `build.py` выдаёт **4-страничный**
PDF; счётчики ссылок > 0 (item ≈ 36, brand ≈ 16, dest = 3). «Красное», если: пусто в ответах MPStats
(проверь токен/лимит 429), 500 на выгрузке категории (уменьши `--days`/страницу), либо Chromium не
найден (задай `$CHROME`). На момент хендоффа всё зелёное; последний собранный PDF доставлен пользователю.
