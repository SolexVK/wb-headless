# Handoff — Юнит-калькулятор WB Китай (FBS)

## Цель
Сделать инструмент предварительного расчёта юнит-экономики для трансграничной модели
**Китай → РФ (FBS)** на Wildberries: продавец из КНР, товар едет со склада в Китае, WB везёт
покупателю в РФ. Пользователь пока **без кабинета продавца** (только планирует регистрацию),
поэтому нужен предварительный расчёт по открытым данным и оферте. Изначально просили Excel,
затем осознанно ушли в **веб-приложение** (HTML/JS) — удобнее и расширяемее.

## Текущее состояние
Рабочее веб-приложение готово и задеплоено. Всё считается корректно, JS без ошибок в консоли,
обе темы (светлая/тёмная) читаемы, проверено скриншотами через Playgright.

- **Живой артефакт (та же ссылка при обновлениях):** https://claude.ai/code/artifact/17c33362-dd1f-43c7-b1e8-f0fa3dae2cba
- **Ветка:** `claude/china-fbs-branch-fuhjhb` (запушена).
- Логистика переведена на **реальный весовой тариф WB для Китая** (скачан официальный PDF).
- Комиссии — ориентир China POP (~10%), т.к. точный каталог только в кабинете (за авторизацией).
- Excel-версия (`wb_china_unit_calc.xlsx`) осталась в репо как артефакт ранней итерации, НЕ основная.

## Что изменилось
- **Валюта/цены:** расчёты в юанях (¥, валюта договора). Цепочка цен показана в ₽:
  базовая → скидка продавца → **Рц (цена продажи без скидки WB)** → СПП → цена покупателю.
  Рц — база для комиссии и выплаты (оферта 5.1.1/5.4). Прибыль и себестоимость — в ¥ и ₽.
- **Два курса:** Курс ВБ (ЦБ + надбавка ≤10%) — для витрины; курс ЦБ — для реальной ₽-стоимости
  прибыли. Онлайн-подтяжка курса ЦБ с cbr-xml-daily.ru (в песочнице артефакта fetch блокируется CSP —
  fallback на ручной ввод).
- **Логистика — по ВЕСУ** (реальный тариф WB China): `ставка_кг × вес(округл.100г) + фикс_за_заказ`.
  Два весовых диапазона (0,1–0,3 / 0,4–20 кг). Выбор способа доставки (Standard/Plus/Express/Гонконг)
  с настоящими ставками. Объём для Китая НЕ участвует (это РФ-модель).
- **Убран двойной счёт:** отдельные «хранение» и «обратная логистика» удалены — по оферте 13.1.11.2
  весовой тариф уже включает возврат на ФФ в РФ и хранение. Возвраты учтены через % выкупа
  (логистика на единицу = тариф ÷ выкуп).
- **Комиссии** пересчитаны под China POP (~10%, ориентир), автоподстановка по категории.
- **Налоги:** НДС РФ выключен по умолчанию (продавец из КНР обычно не плательщик, оферта 6.8);
  добавлен «налог продавца, % от прибыли».
- **Чувствительность:** выкуп 10–100% × ДРР.
- **Тултипы** переписаны простым языком (без ссылок на пункты оферты).
- Добавлена справка об условиях входа China POP (входной взнос ≈10 000 ¥, баллы, выплаты в юанях).

## Что пробовали и НЕ сработало
- **LibreOffice recalc для xlsx постоянно падал по таймауту.** `scripts/recalc.py` (макрос
  calculateAll+store) висел >139 c. Причина — среда очень медленная на первом запуске + профиль.
  `--convert-to` вообще выдавал «source file could not be loaded» за 1 c. Обход: поставил
  `cffi` заново (был сломан `_cffi_backend` → падал `pdfplumber`/`cryptography`), а формулы
  проверил и закешировал значения **через пакет `formulas`** (чистый Python, без LibreOffice) +
  ручной патч XML (`<v>` кэш + `fullCalcOnLoad`). ВАЖНО: если снова понадобится xlsx —
  НЕ полагаться на recalc.py, использовать `formulas`.
- **Пакет `formulas` поймал реальный баг:** ячейка-подпись начиналась с `=` → Excel считал её
  формулой (`#NAME?`). Урок: в xlsx текст не должен начинаться с `=`.
- **openpyxl/pandas/playwright не были предустановлены** — ставил через `pip install` (openpyxl,
  pdfplumber, formulas, playwright). Node playwright отсутствует — использовал **python-playwright**
  с `executable_path` на `/opt/pw-browsers/chromium-*/chrome-linux/chrome`.
- **Не удалось достать точный каталог комиссий по категориям** для китайских продавцов — он за
  авторизацией в кабинете (`seller.wildberries.ru/dynamic-product-categories`). Открытые агрегаторы
  (wb-calculator.ru) конкретные % по категориям в тексте не отдают; e-kontur даёт 403. Вывод:
  каталог кВВ достоверно берётся только из кабинета — оставлен ориентир + правка вручную.
- **Расхождение оферты и практики по возвратной логистике:** оферта 13.1.11.2 говорит «тариф
  включает возврат+хранение», а 13.1.14 — «возврат = 1×/2× стоимости доставки». Для РФ-продавцов
  (не наш случай) возврат = фикс 50 ₽ + коэффициент при выкупе <75%. Точку поставит реальный отчёт
  из кабинета — которого пока нет. НЕ финализировать формулу возврата без подтверждения.
- **Node `eval(src)` в strict-режиме** не пробрасывает `const` во внешнюю область — тесты модели
  гонял через временный файл (конкатенация source+тест), а не `eval`.
