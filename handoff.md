# Handoff — FBS / Fulfillment

## Цель
Построить в ветке `claude/fbs-fullfilment-branch-cfvgir` инструментарий для работы с продажами
Wildberries по схеме **FBS (Fulfillment by Seller)**: поднять документацию WB API (с акцентом на
лимиты, чтобы не ловить 429/бан), находить наши склады-фулфилменты, собирать остатки и ретроспективу
обработки заказов по каждому складу, и выдавать это **дашбордом (HTML)** и **PDF-отчётом**. В финале —
упаковать всё в скилл, чтобы получать отчёт одной командой.

## Текущее состояние
Работает end-to-end конвейер: **stock → retro → report(HTML/артефакт) → pdf**. Все скрипты гоняются
на живом WB API (токен есть в окружении), лимиты соблюдаются клиентом `lib/wbClient.js`.
- Найдены наши **8 складов FBS** (`GET /api/v3/warehouses`), снимок в `config/warehouses.json`.
- Остатки по складам считаются (`fbs:stock`), дашборд остатков и единый дашборд публикуются артефактом.
- Ретроспектива заказов по фулфилменту работает (`fbs:retro`): количество/обработано/статусы/время
  обработки/критически долгие. Поддерживает период: `--days N`, `--day YYYY-MM-DD` (по умолч. МСК),
  `--from/--to`.
- PDF-отчёт (`fbs:pdf`) — A4 альбомная, вёрстка проверена скриншотами: столбцы не налезают.
- Последние прогоны: неделя — 2351 заказ, обработано 78%, медиана 19.2 ч, крит>48ч — 135;
  вчера (09.08.2026) — 284 заказа, обработано 94%, медиана 14.7 ч, крит — 0.
- **Скилл ещё НЕ создан** — ждём согласования формата (см. открытые вопросы).
- `reports-output/` в `.gitignore` — в git идут только генераторы, не сами отчёты/снимки.

## Файлы, над которыми работали
- `lib/wbClient.js` — клиент WB API с token-bucket и обработкой `X-Ratelimit-*` (принесён из ветки доков).
- `lib/wbToken.js` — резолвер токена WB (env `WB_API_TOKEN`/`Wildberries_API` или `.env`).
- `docs/wb-api/README.md` — навигация по докам + краткая сводка лимитов.
- `docs/wb-api/limits.md`, `analytics.md`, `reports-statistics.md` — снимки офиц. страниц WB.
- `docs/wb-api/orders-fbs.md` — снимок страницы методов «Заказы FBS» (фетч через антибот).
- `docs/wb-api/fbs.md` — рукописный справочник: наши склады, все FBS-методы с лимитами, §3b — методика ретроспективы.
- `docs/wb-api/pages.json` — список страниц для еженедельного авто-рефреша (добавлена orders-fbs).
- `scripts/fetch-wb-docs.mjs`, `refresh-wb-docs.mjs`, `wb-token-check.mjs` — фетчер доков и проверка токена.
- `scripts/wb-warehouses.mjs` — `fbs?`: тянет `GET /api/v3/warehouses` → `config/warehouses.json`.
- `scripts/fbs-stock.mjs` — остатки FBS по складам (`content cards` → штрихкоды → `POST /api/v3/stocks/{id}`).
- `scripts/fbs-orders-retro.mjs` — ретроспектива заказов по фулфилменту (+статусы, +корзины времени, +период).
- `scripts/fbs-report.mjs` — единый HTML-дашборд (остатки+заказы) и `.artifact.html`.
- `scripts/fbs-pdf.mjs` — PDF-отчёт A4 альбомная (рендер print-HTML через Playwright/Chromium).
- `scripts/fbs-dashboard.mjs` — первый дашборд ТОЛЬКО по остаткам (оставлен, но заменён единым `fbs-report`).
- `package.json` — добавлены скрипты `wb:warehouses`, `fbs:stock`, `fbs:dashboard`, `fbs:retro`, `fbs:report`, `fbs:pdf`; devDependency `playwright`.
- `config/warehouses.json` — снимок наших складов FBS (закоммичен).

## Что изменилось
- Ветка FBS получила инфраструктуру доков WB API + клиент с соблюдением лимитов.
- Реализована атрибуция заказов **по нашему складу** через `warehouseId` из `/api/v3/orders`, а время
  обработки — join с `/api/v3/supplies` по `supplyId`: `closedAt − createdAt`.
- Добавлен разбор по `supplierStatus` (new/confirm/complete/cancel) и распределение времени по корзинам.
- Единый дашборд и PDF: секции KPI → остатки → заказы по фулфилменту → статусы → время → критические → топ-позиции.
- Инструмент ретро научился работать за конкретный день/диапазон (`periodLabel` пробрасывается в отчёты).

## Что пробовали и НЕ сработало
- **Статистика `GET /api/v1/supplier/orders` для атрибуции по нашему складу — НЕ подходит.** Для FBS она
  относит заказ к **приёмке/СЦ WB** (`warehouseName` вроде «СЦ Чебоксары», «Подольск МП»); поле
  `warehouseType`=«Склад продавца», но наш склад-фулфилмент там не виден. Её `date`→`lastChangeDate`
  тоже плохой прокси времени сборки (медиана ~0.1 ч). Обход: берём `warehouseId` из маркетплейсного
  `/api/v3/orders`, а время — из `/api/v3/supplies.closedAt`. Статистику оставили только как источник
  спроса/географии.
- **`POST /api/v3/orders/status/history` — только трансграничные поставки** (прямо написано в доке); как
  источник времени обычного FBS не годится. Тайминг берём из поставок.
- **Метод остатков FBS `POST /api/v3/stocks/{warehouseId}` принимает ШТРИХКОДЫ, а не `nmID`.** Пришлось
  сначала строить карту `штрихкод→nmID` из Content API (`content/v2/get/cards/list`, пагинация по
  cursor updatedAt+nmID), затем опрашивать склады чанками по 1000.
- **Фетч страниц `dev.wildberries.ru` обычным curl/fetch не работает** — антибот + SPA. Решение уже
  зафиксировано в `scripts/fetch-wb-docs.mjs`: реальный Chromium (Playwright) + «стелс»-настройки; при
  `HTTPS_PROXY` опускать TLS до 1.2 (`--ssl-version-max=tls1.2`) из-за ECH. Подбор slug'ов страниц
  дорогой (каждый фетч ~40–90 с из-за челленджа) — `work-with-warehouses` дал 404, не тратить время на брутфорс.
- **Playwright не был установлен**, Chromium предустановлен в `/opt/pw-browsers`. Ставили `npm i playwright`;
  запускать с `executablePath` из `PLAYWRIGHT_BROWSERS_PATH`, `PLAYWRIGHT_SKIP_BROWSER_DOWNLOAD=1`.
- **Скрипты из scratchpad не видят `playwright`** (node_modules только в репо) — вспомогательные скрипты
  клали временно в корень репо (`_shot.mjs`) и удаляли после.
- **`pdftoppm` в окружении нет** — проверяли вёрстку PDF скриншотами print-HTML через Playwright (по `.page`).
- Для PDF, чтобы столбцы не налезали: `table-layout:fixed` + явные `<colgroup>`-ширины, `page-break-inside:avoid`.

## Команды для проверки
```bash
# синтаксис всех наших скриптов
for f in scripts/fbs-*.mjs scripts/wb-*.mjs lib/wb*.js; do node --check "$f" && echo "ok $f"; done

# токен виден?
npm run token:check           # ожид.: найден ДА, источник env:Wildberries_API

# конвейер (нужен живой WB API; каждый шаг пишет снимок в reports-output/)
npm run wb:warehouses         # → config/warehouses.json (8 складов)
npm run fbs:stock             # → reports-output/fbs-stock.json
npm run fbs:retro -- --day 2026-08-09 --crit 48   # → reports-output/fbs-orders-retro.json
npm run fbs:report            # → reports-output/fbs-report.html (+ .artifact.html)
npm run fbs:pdf               # → reports-output/fbs-report.pdf (A4 landscape)
```
Формальных тестов нет; «зелёным» считается: `node --check` по всем скриптам проходит; при наличии
токена `token:check` = найден; конвейер отрабатывает без ошибок и пишет непустые снимки в
`reports-output/`. **Ожидаемое состояние сейчас:** всё зелёное на живом API (последний прогон —
за 09.08.2026: 284 заказа, 94% обработано, 0 крит). Если конвейер падает 401/пусто — проверить токен
(`WB_API_TOKEN`/`Wildberries_API`); это «сломалось за ночь», а не наш код.

## Открытые вопросы (нужно решение пользователя)
- **Упаковка в скилл — ЖДУ ОТВЕТА.** Пользователь просил в финале сделать скилл (напр. `/fbs-report [день|период]`),
  который одной командой обновит данные и выдаст PDF+дашборд. Формат отчёта согласован на примере за день;
  осталось подтвердить «делаем скилл» и его параметры (период по умолчанию, порог критичности, что
  включать — HTML/PDF/оба).
- **Часовой пояс «дня»:** сейчас `--day` считается по МСК (UTC+3). Рекомендация — оставить МСК по
  умолчанию, `--tz` для переопределения. Подтвердить, если нужен UTC.
- **Остатки в отчёте за прошлый день** — всегда срез «на сейчас» (историю остатков WB API не отдаёт).
  Рекомендация: оставить как есть с пометкой в отчёте. Альтернатива на будущее — завести ежедневный
  снап остатков, чтобы иметь историю.
