# Handoff — FBS / Fulfillment → веб-сервис

## Цель
Ветка `claude/fbs-fullfilment-branch-cfvgir`. Инструменты аналитики FBS для
Wildberries: остатки, движение товара, ретроспектива заказов и — главное —
**подсорт** (заказ на пополнение) по каждому фулфилмент-складу и размеру.
Дальше — упаковать всё в **мульти-тенант веб-сервис** (регистрация, кабинеты,
токены, выбор отчётов) на Mac Mini (потом VPS), публичный доступ через Tailscale.

## Текущее состояние
Набор рабочих инструментов на живом WB API (токен env `Wildberries_API`, лимиты
держит `lib/wbClient.js`). Всё строго FBS. Готово и проверено:
- **Подсорт (главное, size-level)** — `npm run fbs:podsort`: скорость и остаток
  по (склад × артикул × цвет × **размер**), лид-тайм (горизонт 46 дн), дни до
  нуля, статусы; пробный завоз новинок/докладок 10 шт/размер по белому списку
  артикулов; сводная (арт×цвет×размер × склады). Отдаёт HTML-дашборд + **Excel**
  (листы «Сводка», «Сводная», «Подсорт», «Пробный завоз»). Настройки —
  `config/replenishment.json`.
- **Остатки** — `fbs:stock:articles` (дашборд по артикул+цвету), `fbs:stock:pdf`.
- **Движение по дням** — `fbs:delivery:dash` (передано в доставку), `fbs:accepted:dash`
  (принято на фулфилмент + баланс передано−принято).
- **Ретроспектива заказов** — `fbs:retro`, единый `fbs:report` (HTML) / `fbs:pdf`.
- **Скиллы**: `/fbs-podsort`, `/fbs-dashboards`, `/wb-docs`, `/handoff`, `/resume`.
- Форматы: HTML-дашборд (артефакт), PDF (A4 альбомная), Excel (openpyxl, значения).

**Веб-сервис ещё НЕ начат** — на этапе согласования архитектуры (см. открытые
вопросы). Последняя сессия закончилась сводкой возможностей и планом сервиса.

## Файлы, над которыми работали (движки подсорта — финал сессии)
- `scripts/fbs-replenishment.mjs` — движок подсорта, переписан на **size-level**
  (склад × штрихкод=размер; спрос из orders.skus; techSize из cards). Выдаёт
  snapshot с `warehouses[].rows` (по размерам), `seedGrid` (завоз по размерам),
  `pivot` (сводная арт×цвет×размер×склад). Читает `config/replenishment.json`.
- `scripts/fbs-replenishment-dashboard.mjs` — дашборд size-level: колонка «Размер»
  в таблицах складов и завоза + секция «Сводная: подсорт по размерам × склад».
- `scripts/fbs-xlsx.py` — Excel: листы «Сводка», «Сводная» (Арт|Цвет|Размер|склады|
  Итого), «Подсорт» (детально), «Пробный завоз» (по размерам).
- `config/replenishment.json` — настройки (articles=белый список, seedMin,
  velocityDays, leadMax/leadMin, cover). Бэкенд будущей формы веб-сервиса.
- `.claude/skills/fbs-podsort/SKILL.md` — скилл подсорта; `fbs-dashboards` — ссылка на него.
- `package.json` — команды `fbs:podsort`, `fbs:xlsx` и др.
- Прочее (прошлые сессии): `lib/wbClient.js`, `lib/wbToken.js`, `scripts/fbs-*.mjs`,
  `docs/wb-api/*`, `config/warehouses.json`.

## Что изменилось (эта сессия)
- Подсорт доведён до **уровня размера** во всех результатах (дашборд + Excel +
  сводная), сортировка артикул→цвет→размер (S<M<L<XL<XXL<3XL…).
- Зафиксирован конвейер подсорта (`fbs:podsort`) и скилл `/fbs-podsort` как основа
  веб-сервиса; движок отдаёт готовый JSON (`--json`) — вход для сервиса.
- Сверился с докой WB по **токену для сервиса** (см. ниже) — ответ для формы
  подключения кабинета.

## Что пробовали и НЕ сработало
- **LibreOffice recalc в этом окружении НЕ работает** (таймаут 25/89/179 с). Поэтому
  Excel собираем **значениями** (не формулами) — числа уже посчитаны движком,
  файл открывается корректно везде. Логику сверяли отдельно (0 расхождений).
  `openpyxl`/`markitdown` не предустановлены — ставили `pip install openpyxl`.
- **Подсорт «склад×артикул» шумит** (остаток «переезжает» между складами) — считаем
  per-warehouse по факту продаж; склад без истории не прогнозируем (уходит в завоз).
- **Скрипты из scratchpad не видят node_modules** — временный `_shot.mjs` кладём в
  корень репо и удаляем. `pdftoppm` нет — вёрстку проверяем скриншотами print-HTML.
- **WB API нюансы (важно для сервиса):** персональный токен ЗАПРЕЩЁН в облачных
  сервисах; сервисный — только для Каталога WB. Для нашего публичного сервиса
  пользователь даёт **Базовый** токен read-only. Категории под наши методы:
  **Контент** (cards) + **Статистика** (statistics/orders,sales) + **Маркетплейс**
  (warehouses/stocks/orders/supplies). Уровень «Только чтение». Токен — JWT, права
  в битовой маске `s` (Контент=1, Аналитика=2, Маркетплейс=4, Статистика=5,
  read-only=30) — форма подключения сможет проверить наличие категорий до запроса.
- `statistics/incomes` даёт 404 / это FBW-приёмка; физпоступлений на склад продавца
  WB не отдаёт. Выкупы — через join `orders.rid ↔ sales.srid` (не встроено).

## Команды для проверки
```bash
for f in scripts/fbs-*.mjs scripts/wb-*.mjs lib/wb*.js; do node --check "$f" && echo "ok $f"; done
python3 -c "import ast; ast.parse(open('scripts/fbs-xlsx.py').read()); print('py ok')"
npm run token:check           # ожид.: найден ДА, источник env:Wildberries_API

# полный конвейер подсорта (нужен токен; ~1–2 мин)
npm run fbs:podsort           # stock → replenish → dashboard → xlsx
# → reports-output/fbs-replenishment-dashboard.html (+ .artifact.html), fbs-podsort.xlsx
```
Формальных тестов нет. «Зелёное»: `node --check` по всем скриптам проходит;
`token:check` = найден; `fbs:podsort` отрабатывает без ошибок и пишет непустые
снимки; в Excel сумма листа «Подсорт» = сумме «Итого» листа «Сводная».
**Ожидаемое сейчас:** всё зелёное. Последний снимок: подсорт ~1641 шт, сводная
122 строки, пробный завоз 450 строк (~33050 шт). Excel: openpyxl нужно
`pip install openpyxl` (не предустановлен). ВНИМАНИЕ: данные ЖИВЫЕ — числа/склады
меняются между прогонами (это не баг).
