# Handoff — Этап 3: Ранг сезонности → План по размерам (этапы → поставки)

Ветка: `claude/production-plan-twv8ki`. Приложение: `planner/` (Node + Express + SQLite, SPA на ванильном JS-модуле). Работает на Mac mini у пользователя (`openclaw@Mac-mini-Vital`), публично через Tailscale Funnel. **Планировщик запущен на порту 8477** (не 8090 — 8090 занят посторонним Python-приложением).

## Цель
Связать «Ранг сезонности» (прогноз спроса) с производственным «Планом по размерам». Прогноз → матрица цвет×размер → **серия партий-поставок** (приход на WB частями), с заменой устаревших «4 этапов» на динамические поставки, распределением по цехам по мощностям, и реалистичным стартом плана продаж с учётом времени на запуск. Архитектура сопоставления цветов — «C+».

## Что изменилось (суть)
Партия перестала быть `(артикул × этап)` — теперь `(артикул × поставка)` со своим сроком WB. «Применить» в Ранге создаёт серию партий-поставок (доли по времени × полный цветной тираж, Хэмилтон — каждый цвет×размер в каждой партии). «План по размерам» показывает их без оси этапов, распределяет по цехам по мощностям (свой первый, 2-3-й только под срок). Прогноз строится не от «сегодня», а от реалистичного старта продаж (сегодня + срок запуска), с автосдвигом сезона, если не успеваем.

## Что пробовали и НЕ сработало / грабли (важно!)
- **ГЛАВНАЯ ловушка сессии: старый backend в памяти.** Пользователь `git pull` + hard-reload → браузер брал новый `app.js` (статика с диска), но **работающий Node-процесс держал старый `model.js` в памяти** (Node не перечитывает модули). Старый фильтр удалял партии-поставки без этапа → «Применить» молча создавал 0 партий (Гант «0 циклов», «нет партий»). Ушло МНОГО времени на отладку (сервер/модель/HTTP/RBAC/даты — всё чисто в изоляции). **Диагностика-победитель:** `console.log('[apply] после сохранения: партий = N')` показал «создано 3, выжило 0». **Причина:** процесс не перезапущен. **Лечение:** обязательно рестарт Node-процесса после pull. Добавлен `backendBuild` в `/api/health` + красный баннер во фронте, чтобы рассинхрон был виден сразу.
- **Порты на Mac mini:** планировщик на **8477** (env `PLANNER_PORT=8477`), а `npm start` по умолчанию лезет на 8090 (занят посторонним Python → `EADDRINUSE`). Рестарт: `lsof -ti tcp:8477 | xargs kill -9`, затем `PLANNER_PORT=8477 nohup node --experimental-sqlite server.js > ~/planner.log 2>&1 &`.
- **Даты ISO со временем:** ранний фильтр `model.js` валидировал `deadline` строгим `^\d{4}-\d{2}-\d{2}$` — не проходили даты вида `2027-04-15T00:00:00Z`. Починено: `validDeadline` режет строку до 10 символов. (В реальном плане даты были чистые, но защита нужна.)
- **`df()` — локальная в другой функции**, не глобальная → ReferenceError при повторном использовании. В каждой функции свой форматтер даты.
- **`git push` иногда молча «Everything up-to-date»** после commit в той же compound-команде. Всегда проверять `git rev-list --left-right --count origin/<branch>...HEAD` → `0 0`.
- **Планы в SQLite (не в файлах):** перезапись `data/plans/004.json` НЕ меняет то, что отдаёт сервер. Для теста плана — `savePlan()` через node пишет в БД. Старые планы (004/026) без `colorAnalysis` → блок 🧩 для них «недоступно».
- **Playwright:** `/opt/node22/lib/node_modules/playwright`, CommonJS: `import pkg from '.../index.js'; const {chromium}=pkg;`, `chromium.launch({executablePath:'/opt/pw-browsers/chromium'})`. Кнопки внутри свёрнутого `<details>` кликать через `pg.evaluate(()=>document.getElementById(id).click())` (иначе «element not visible»). Готовые скрипты в scratchpad.
- **Распределение по цветам уже работает:** `splitMatrixByShares` (per-cell Хэмилтон) кладёт КАЖДЫЙ цвет×размер в КАЖДУЮ партию (проверено: 11 цветов × 8 размеров = 88 ячеек в каждой из 3 партий, даже в П1 на 5%). Пересобирать не нужно.
