# Handoff — Telegram-бот WB-скиллов

Ветка: **`claude/telegram-bot-skills-81540d`**. Разработка бота идёт здесь.

## Цель
Telegram-бот, который по требованию подтягивает нужный WB-скилл, через диалог/кнопки
собирает входные данные, выполняет скилл и возвращает готовый отчёт в чат. Скиллы
добавляются манифестами (добавить скилл = добавить манифест). Есть кэш дорогих вытяжек,
гейт «наш/не наш» для кабинетных операций, каскад [1]→[2]→[3].

## Текущее состояние
Работает, бот живой (@solexvk_wb_tools_bot). Четыре скилла в проде:
- **🔍 Конкуренты по запросу** (top-keywords) — ТОП выдачи WB по фразе + фильтры-фасеты.
- **📊 Сравнение карточек** (cards-compare) — воронка из кабинета WB (браузер).
- **🧭 Конкурентный анализ ниши** (competitor-analysis) — Python-движок, PDF/HTML.
- **💰 Наши продажи по запросам** (brand-sales) — выкупы наших брендов, PDF.

**Меню Telegram (setMyCommands):** `/cascade` (единый вход каскада [1]→[2]→[3]),
`/sales` (самостоятельный), `/skills`, `/cancel`. Стадии каскада [2]/[3] скрыты из меню
(работают через кнопки после каждого шага; команды /compare, /analysis остаются
вводимыми вручную).

**Каскад [1]→[2]→[3]** связан кнопками: конкуренты → пикер (фото + тумблеры) → «📊
Сравнить» (гейт наш/не наш → подтверждение → submit → XLSX) → «🧭 Анализ ниши»
(спрашивает себестоимость → движок на items-json[1]+funnel-json[2]).

Готово также: фильтры-фасеты (выбор значения признака → остальные авто-минус),
воронка отсева в сводке, кэш выдачи MPStats (эфемерный), файловый кэш карточек,
проверка «наш ли артикул» через Content API.

**НЕ сделано:** пресеты пользователя (бренды/фразы для /sales), инженерный режим
(правка скиллов через Claude по коду), переезд на persistent volume (VPS).

**Среда нестабильна:** контейнер часто перезапускается → фоновый бот падает.
Перезапуск: `npm run bot`.

## Файлы, над которыми работали
- `bot/index.js` — ядро бота (grammY): меню, FSM, очередь, все runner-ы (cli/
  cardsCompare/competitorAnalysis/brandSales), каскад cc2/ca2, фото-пикер,
  форматы, setMyCommands.
- `bot/core/registry.js` — загрузка/валидация манифестов; menuItems сворачивает
  каскад в один пункт, прячет промежуточные стадии.
- `bot/core/fsm.js`, `keyboards.js`, `queue.js`, `executor.js`, `session-store.js` — диалог, клавиатуры, очередь с дорожками, spawn CLI, персист сессий.
- `bot/render/` — рендер top-keywords в HTML/PDF/XLSX.
- `bot/skills/*.manifest.js` — 4 манифеста (метки cascade/cascadeEntry/command).
- `lib/db.js` — SQLite слой (миграции v1–v3), кэш/файлы/склейка/прогоны/сессии.
- `lib/wbCard.js` — добор card.json (характеристики) + классификатор рисунка.
- `lib/wbFacets.js` — справочник признаков-фасетов + вердикт (stems И regex).
- `lib/wbOwnCards.js` — множество наших nmID (Content API) для гейта.
- `lib/wbTopKeywords.js` — фильтр по фасетам/характеристикам + воронка + кэш выдачи.
- `scripts/wb-top-keywords.mjs` — CLI: --facet, --pattern, кэш выдачи, лог воронки.
- `.claude/skills/wb-competitor-analysis/wb_analyze.py` — ретрай/пагинация curl,
  потолок items, фикс вёрстки таблицы «Доминанта» в PDF.

## Что изменилось
- Собран бот на grammY поверх слоя БД (перенесён из ветки claude/database-branch
  аддитивно — истории несвязаны). Реестр манифестов → форма → очередь → выдача.
- 4 скилла; каскад [1]→[2]→[3] с передачей данных между блоками через БД.
- Фильтры-фасеты вместо ручных groups/exclude; авто-исключение остальных значений.
- Гейт «наш/не наш» (Content API) перед тратой лимита сравнений.
- Cards-compare переведён на одну браузер-сессию (было двухфазно — падало).
- Единое меню: каскад одним пунктом, самостоятельные — отдельно.

## Что пробовали и НЕ сработало
- **git merge ветки БД — НЕЛЬЗЯ** (несвязанные истории, merge-base пуст). Перенесли
  файлы слоя БД аддитивно; package.json/.gitignore/.env.example патчили руками.
- **Cards-compare двухфазно (DRY-RUN отдельным браузером → submit другим) — падало**
  (#7 «5 из 5» таймаут, #14 «Target page closed»). Причина — черновик сравнения
  живёт между двумя браузерами на стороне WB. Оба раза ЛИМИТ НЕ тратился (падение
  до клика «Сравнить»). Решение: одна сессия add+submit + авто-восстановление через
  exportExisting; + clearDraft (кнопка «Удалить все карточки») делает прогон идемпотентным.
- **Фасеты контекстных признаков жёсткими подстроками («длинн рукав») — НЕ работало**
  на морфологии («с длинным рукавом» не матчилось). Перешли на regex `\S*\s+`; при
  противоречии (и плюс, и минус найдены) → uncertain (🟡), не ложный keep.
- **wb_analyze.py на большой нише — падал «curl (18) transfer closed»/обрезанный JSON**
  (агент-прокси режет большой поток, страница 5000 строк ≈10МБ). Фикс: ретрай
  транзиентных ошибок И обрезанного JSON, --http1.1, страница 1500, потолок items 6000.
- **Столбец «Доминанта» (position:sticky) налезал в PDF** — в печати sticky кривой.
  Фикс: @media print → position:static. table-layout:fixed НЕ брать (переполнял
  колонку длинным словом заголовка).
- **Живой бот пачкал закоммиченную data/wb.db** сессиями → стоп-хук. Обошли:
  DB_PATH=data/wb-runtime.db (gitignored).
- **pgrep -f "bot/index.js" даёт ложное «жив»** (матчит строку в самой команде).
  Проверять `ps aux | grep -F bot/index.js | grep -v grep`.
- **Наложение экземпляров бота при частых рестартах** → падение при старте. Всегда
  сначала pkill, потом один старт в фоне.
- **Telegram не берёт webp с CDN WB по URL** («failed to get HTTP URL content»), но
  принимает БАЙТАМИ → фото-пикер качает миниатюру и шлёт InputFile.
- **withDefaults пред-заполнял обязательные поля** → диалог их проскакивал. Дефолты
  теперь только для необязательных.
