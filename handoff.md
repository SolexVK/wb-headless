# Handoff — потери Wildberries от пожаров на складах

Ветка: `claude/losses-wildberries-p8dhw6` (всё запушено в origin).
Дата снимка данных: 2026-08-13.

## Цель
Оценить убытки продавца от утраты товара на складах Wildberries, сгоревших/
повреждённых при атаках БПЛА (18.07–07.08.2026), и наглядно это подать.
Метод: количество утраченного товара = остатки на атакованных складах (WB API
`warehouse_remains`, детализация по артикулам) × средняя себестоимость 620 ₽.
Плюс: зафиксировать документацию по WB API и лимиты запросов (чтобы не ловить бан).

## Текущее состояние
Работает и прогнано на живом аккаунте (токен есть в env `Wildberries_API`):
- `report:fire` тянет остатки и считает потери. Последний результат:
  **158 артикулов · 27 790 ед. · 17 229 800 ₽** по 18 складам.
- `pdf:fire` собирает цветную A4-инфографику в PDF (проверено скриншотом — вёрстка ок).
- Промпт для карты сгоревших складов готов (`docs/fire-map-prompt.md`).
- Документация WB API + лимиты влиты из ветки доков; заметка про потери написана.
Не сделано: живой снимок официальной страницы `reportDetailByPeriod` (антибот
портала WB блокирует IP окружения, см. «что не сработало»). Карта-картинка не
генерилась — отдан только промпт.

## Файлы, над которыми работали
- `report-fire-losses.mjs` — раннер: warehouse_remains (async task) → фильтр по
  сгоревшим складам → сумма по артикулам × 620 ₽. Печатает все встреченные склады.
- `config/fire-warehouses.json` — список сгоревших складов (18 паттернов) +
  себестоимость + `uncertain` (Казань/Зеленодольск) + хроника атак по датам.
- `scripts/build-fire-pdf.mjs` — генератор PDF-инфографики из свежего JSON (Chromium).
- `docs/fire-map-prompt.md` — RU/EN промпт для карты + таблица «город→ед→₽».
- `docs/wb-api/losses-burned-warehouse.md` — как получать данные о потерях/компенсациях.
- `docs/wb-api/pages.json` — добавлена страница финотчётов для снапшота.
- `package.json` — скрипты `report:fire`, `pdf:fire` (+ ранее docs:*).
- `.claude/skills/wb-docs/SKILL.md` — ссылка на заметку о потерях.
- (из merge) `docs/wb-api/*`, `scripts/fetch-wb-docs.mjs`, `lib/wbClient.js`,
  `lib/wbToken.js` — основа доков/клиента WB с соблюдением лимитов.

## Что пробовали и НЕ сработало
- **Живой фетч документации WB (`scripts/fetch-wb-docs.mjs`).** Портал
  `dev.wildberries.ru` отдаёт HTTP 498 «Подозрительная активность» — антибот
  жёстко блокирует IP этого окружения. Пробовали разные слаги (`financial-reports`,
  `api-information`, `reports`) и таймауты до 240с (`WB_DOCS_TIMEOUT`) — «челлендж
  пройден: НЕТ» стабильно, даже на заведомо рабочей странице. Вывод: это не тот
  слаг, а среда/IP. Обход: официальный снимок `reportDetailByPeriod` НЕ втянут;
  страница добавлена в `pages.json`, подтянется еженедельным workflow или ручным
  `npm run docs:fetch` из окружения без блокировки. Слаг `financial-reports` не
  подтверждён — проверить живьём.
- **Первый список складов был неполным (7 шт).** Одна пара новостных запросов дала
  только первую волну атак. Полный список (18–19 объектов) нашёлся только после
  прицельных запросов + WebFetch на Meduza «список» и MP Manager «полный разбор».
  Урок: по таким событиям сразу тянуть агрегирующие статьи-списки.
- **`require('reports-output/...json')` в `node -e`** падает (MODULE_NOT_FOUND):
  нужен абсолютный путь или `./`. Использовали `$PWD/...`.
- **`file://relative.html` в Playwright** → `ERR_INVALID_URL`. Нужен абсолютный
  `file://` путь.
- **Методическая ловушка (важно, не потеряй!):** `warehouse_remains` — снимок «на
  сейчас». После списания сгоревшего товара WB остатки обнулятся, и оценка
  ЗАНИЗИТСЯ. Сейчас (3 недели после атак) товар ещё числится — цифра осмысленна, но
  снимок надо фиксировать датой (раннер это делает) и в идеале иметь снимок ДО пожара.
- **Казань/Зеленодролск** намеренно НЕ включена (в `uncertain`): в новостях бит
  Зеленодольск, не факт что это склад, который API зовёт «Казань». +361 ед. /
  +223 820 ₽ при включении.

## Команды для проверки
```bash
# синтаксис
node --check report-fire-losses.mjs
node --check scripts/build-fire-pdf.mjs

# JSON-конфиги валидны
node -e "JSON.parse(require('fs').readFileSync('config/fire-warehouses.json','utf8'));JSON.parse(require('fs').readFileSync('docs/wb-api/pages.json','utf8'));console.log('JSON OK')"

# раннер без сети (проверка резолва токена/конфига)
node report-fire-losses.mjs --dry-run

# ПОЛНЫЙ прогон (нужен env Wildberries_API; бьёт живой WB API, read-only, лимиты соблюдаются)
npm run report:fire        # → reports-output/fire-losses-<ts>.{json,csv}
npm run pdf:fire           # → reports-output/fire-losses-infographic-<ts>.pdf
```
Ожидаемое состояние: `node --check` и JSON-проверка — ЗЕЛЁНЫЕ. `--dry-run` печатает
токен `env:Wildberries_API` и выходит. Полный `report:fire` — ЗЕЛЁНЫЙ (последний
прогон: 27 790 ед. / 17 229 800 ₽; цифры плавают по мере изменения остатков/списаний).
Формальных unit-тестов в проекте нет — «зелёное» = скрипты отрабатывают без ошибок и
дают непустой отчёт. Красных проверок нет; единственный заблокированный пункт —
живой фетч доков WB (антибот, см. выше), это не регресс.
