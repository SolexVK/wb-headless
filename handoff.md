# Handoff — конкурентный анализ WB через MPStats + PDF-отчёты

## Цель
Проводить конкурентный анализ товаров/продавцов на Wildberries по данным **MPStats API** и оформлять
результат в **красивые многостраничные PDF** (сводка + разбор карточек + конкуренты + ниша + дорожная
карта). Есть переиспользуемый пайплайн в репозитории; конкретные разборы делаются в скретчпаде.

## Текущее состояние
- **Закоммичено и работает:** `reports-generator/` (`collect.py` → `build.py`) — универсальный генератор
  PDF (обложка + карточки артикулов + ниша) с кликабельными ссылками, фото, жирными акцентами.
  Ветка `claude/wildberries-competitor-analysis-u4ftu1`, последний коммит `bb1499d`, открыт **PR #11**
  (https://github.com/SolexVK/wb-headless/pull/11).
- **Сделано в этой сессии (НЕ в git, скретчпад `/tmp` — эфемерно):** полный конкурентный анализ
  продавца **4289467 = ИП Комиренко Т А**, ниша **детское постельное бельё**, 12 целевых артикулов.
  Итог — 8-страничный PDF доставлен пользователю. Скрипты `/tmp/collect_bed.py`, `/tmp/build_bed.py`,
  `/tmp/recon.py`, `/tmp/wh_analysis.py`; данные `/tmp/rep2/bedding_data.json`, `/tmp/rep2/stores.json`.
  При новой сессии контейнер чистый — этих файлов не будет, отчёт придётся пересобирать.

### Ключевые выводы по разбору (детское постельное, ИП Комиренко)
- 12 SKU, ~508–531 продаж/30д, ~1,35 млн ₽, средняя цена **2 697 ₽** (это ВЫШЕ медианы комплектов
  1 726 ₽ и p75 2 615 ₽ — продавец НЕ дешёвый). Отзывов в среднем 27 против ≈1 363 у ТОП-10.
- **Корневая причина низких продаж (подтверждена данными по запросу пользователя): география складов.**
  Товар только на РЕГИОНАЛЬНЫХ складах (Рязань 322, Волгоград 222, Самара, Свердловск…), **0% стока на
  центральных хабах**. Нет ни одного из Коледино / Электросталь / Тула(Алексин) / Казань / СПб /
  Екатеринбург. У ТОП-12 конкурентов в среднем 3 центральных хаба, 44% стока на центре
  (Электросталь — у 9/12, Тула/Алексин — 8/12, Коледино и Казань — по 5/12). Лидеры «Наследник»,
  «HLOPBERRY» — 100% стока на центральных хабах.
- Прочие причины: тонкий слой отзывов (×50), 12 почти одинаковых карточек дробят трафик, пустое поле
  бренда. Приоритет причин: склады → отзывы → дробление → нет бренда → контент/SEO.

## Что изменилось
- Добавлен разбор «продавец + его артикулы + конкуренты по нише + логистика складов + дорожная карта».
- Ниша выделяется из «замусоренной» подкатегории фильтром на **комплекты (КПБ)**: name содержит
  «постельное бель» / «кпб» / «комплект»+«бель» (иначе подушки/одеяла/простыни искажают медиану цены).
- Логистический анализ: остатки по складам из `item/{sku}` (`sizeandstores.s` = {склад_id: кол-во}) +
  официальный справочник складов WB, классификация «центральный хаб vs регион».

## Что пробовали и НЕ сработало (важно — читать перед доработками)
- **Идентификация ассортимента продавца по id/имени — НЕ работает надёжно.**
  - `/wb/get/seller?path=<имя>` (и 5 вариантов написания «ИП Комиренко Т. А.») → `total: 0`.
  - `/wb/get/seller/{id}` и `/{id}/sales` → 405 (OPTIONS-only, gated).
  - `/wb/get/brand?path=<бренд>` для торговой марки продавца → вернул карточки ДРУГИХ продавцов
    (бренд-«сквоттинг»: под одним названием торгуют разные ИП). Нельзя вычленить нужного продавца.
  - WB catalog/card API (`catalog.wb.ru/sellers/...`, `card.wb.ru/cards/...`) → **429/404 + антибот
    (WBAAS challenge)** через прокси. Список товаров продавца оттуда не забрать.
  - **Обход:** попросили у пользователя список nmId. По nmId `item/*` и `category` работают идеально.
- **Имя продавца и бренд:** берутся из WB `supplier-by-id`:
  `https://static-basket-01.wbbasket.ru/vol0/data/supplier-by-id/{id}.json` (supplierName + trademark).
- **Справочник складов WB:** `https://static-basket-01.wbbasket.ru/vol0/data/stores-data.json` (~14.5 МБ,
  77k складов, поля id/name/isWb). **Внимание:** старый хардкод `WH_NAMES` в
  `reports-generator/build.py` СОДЕРЖИТ ОШИБКИ (130744 там «Тула» — на деле **Краснодар**; 206348 там
  «СПб Уткина Заводь» — на деле **Алексин** = тульский хаб). Для складов использовать stores-data.json,
  не старый map. (В bedding-сборке уже переопределено через `WMAP`.)
- **`/wb/get/warehouses?path=<ниша>`** → `500 «Не корректные условия фильтра»`. Распределения продаж по
  складам для категории через API нет — считали footprint из `sizeandstores` по каждой карточке.
- **Категорийный `purchase` (выкуп)** в ответе `category` — величина уровня ПОДКАТЕГОРИИ (одинакова для
  всех SKU, тут 81%), НЕ по-товарная. В таблице конкурентов её убрали (заменили на «возраст карточки»).
- **Дерево категорий:** `/wb/get/categories` (GET, ~12 МБ, 45k путей) — тут искали точный путь ниши
  `Дом/Детская/Постельные принадлежности/Для детей/Постельное белье` (8 704 SKU).
- **Пагинация категории:** `endRow=5000` — рабочий предел страницы; total 8 704 → 2 страницы.
- **Транзиентные пустые ответы** от `/wb/get/category` (изредка ALL пустой → ZeroDivision) — лечится
  повторным запуском `collect_bed.py`.
- **Грабли Python:** `sizeandstores[*].s` бывает пустым list (не dict) — обрабатывать; кириллица в
  редактируемых строках — случайно вставился иероглиф «但» вместо «но».

## Команды для проверки
Требуется `MPSTATS_TOKEN` в окружении и Chromium (`/opt/pw-browsers/chromium-1194/chrome-linux/chrome`).
```bash
# 1) закоммиченный пайплайн (синтаксис/импорт, без сети)
python3 -c "import sys; sys.path.insert(0,'reports-generator'); import build, collect; print('OK')"

# 2) пересобрать РАЗБОР по постельному (эфемерные скрипты — только в текущем контейнере!)
python3 /tmp/recon.py                 # разведка 12 SKU
python3 /tmp/collect_bed.py           # → /tmp/rep2/bedding_data.json (тянет ни- 8704 SKU, ~1–2 мин)
python3 /tmp/wh_analysis.py           # склады продавца vs конкуренты (нужен /tmp/rep2/stores.json)
CHROME=/opt/pw-browsers/chromium-1194/chrome-linux/chrome python3 /tmp/build_bed.py  # → /tmp/rep2/bedding.pdf (8 стр.)

# проверить результат
python3 -c "d=open('/tmp/rep2/bedding.pdf','rb').read();print('pages',d.count(b'/Type /Page')-d.count(b'/Type /Pages'))"  # ожидаем 8
strings /tmp/rep2/bedding.pdf | grep -c detail.aspx   # ссылки на карточки (>0, ~55)
```
**Ожидаемое состояние (зелёное):** формальных тестов нет. `import` печатает OK; `collect_bed.py`
завершается с кодом 0 и пишет `bedding_data.json` (ниша 8 704 SKU, сегмент КПБ ~5 735); `build_bed.py`
даёт **8-страничный** PDF; счётчик ссылок >0. КРАСНОЕ, если: пусто в ответах MPStats (токен/лимит 429),
`/wb/get/category` вернул пусто (перезапустить), либо в НОВОЙ сессии `/tmp/*` уже нет (скрипты нужно
воссоздать — логика в этом хендоффе). На момент хендоффа всё зелёное, отчёт v2 доставлен.
