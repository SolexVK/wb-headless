# Handoff — инструменты для Wildberries

Ветка: **`claude/wildberries-tools`** (каноническая). Продолжаем разработку здесь.
Веб-сессия может стартовать на авто-ветке `claude/resume-*` — скилл `/resume` (шаг 0)
сам переключает на каноническую. Если оказался на авто-ветке — перенеси работу в
`claude/wildberries-tools` fast-forward’ом и продолжай в ней.

## Цель
Каскад инструментов для WB: **[1] ТОП по фразе → [2] Сравнение карточек → [3] Конкурентный
анализ**. Сцепляются общим JSON-контрактом (ключ `nmId`). Правило: наш артикул ВСЕГДА
спрашиваем у пользователя; конкурентов даёт [1] или пользователь вручную. Итог [3] —
многоблочный отчёт (A–H + воронка + авто-принадлежность F3) + план доработки карточки.
Архитектура и контракты — `docs/pipeline/README.md`.

## Текущее состояние
- **[1] ТОП по фразе (MPStats) — ГОТОВ, СКИЛЛ, обкатан.** `.claude/skills/wb-top-keywords/`,
  `lib/wbTopKeywords.js` (+ `formatPickTable`, эмитит `allItems` — вся база до deep-фильтров),
  `scripts/wb-top-keywords.mjs`. Двухуровневый фильтр, HTML-отчёт, `--pick` (пикер для [2]).
- **[2] Сравнение карточек — ГОТОВ.** `lib/wbCardsCompare.js` + скилл `wb-cards-compare`.
  DRY-RUN / `--submit` (тратит 1 лимит) / `--export-existing` (бесплатно). Контракт
  воронки — `cards-compare.json`.
- **[4] Юнит-калькулятор — ГОТОВ, СКИЛЛ.** `lib/wbUnitCalc.js` + `scripts/wb-unit-calc.mjs`
  (`npm run unit:calc`) + скилл `wb-unit-calc`. Вынесенное ядро юнит-экономики (та же модель,
  что в блоке C движка [3], подтверждена пользователем): раскладка на единицу, ценовой коридор
  под маржу, точка безубыточности, обратный расчёт (цена под маржу/прибыль), таблицы
  чувствительности (цена/ДРР), прогноз за период. Вход: `--cost` (обязат.) + `--price`/
  `--seller-price`/`--nm` (цена по артикулу из MPStats). Вывод текст/JSON/HTML/PDF. Эталон:
  `--cost 536 --price 2400` → прибыль 705 ₽, маржа 28%, коридор 2094–2613 ₽, безубыт. 1051 ₽.
- **[3] Конкурентный анализ — РАБОТАЕТ в каскаде; отчёт по структуре ПРОЙДЕН ПОЛНОСТЬЮ (A–H).**
  Python-движок `.claude/skills/wb-competitor-analysis/wb_analyze.py` (~1950 строк). Собирает
  markdown+HTML+PDF+JSON. Каскадный режим: `--items-json` (ниша из [1]) + `--funnel-json`
  (воронка из [2]) + `--seasonality-delta` + `--cost` + `--niche`/`--period-label`.
- **Оркестратор `scripts/wb-pipeline.mjs` — ГОТОВ, двухфазный.** Фаза 1 (discovery): [1] +
  сезонность (2 агрегата MPStats по половинам периода) + пикер. Фаза 2 (analysis): [2] → [3].
- **База WB API:** `lib/wbClient.js`, `lib/wbToken.js`, `lib/mpstats.js`, `lib/wbCabinet.js`
  (headless-браузер), снимки доки `docs/wb-api/*`.
- **Токены (env этой сессии):** `MPSTATS_TOKEN` (заголовок `X-Mpstats-TOKEN`), `Wildberries_API`,
  `WB_COOKIES` + `WB_LOCALSTORAGE` (сессия кабинета для [2]).

**Структура отчёта [3] (все блоки доведены и согласованы поблочно):**
- **A. Ёмкость** — шапка: имя ниши (`derive_niche`) + ключевая фраза; период человекочитаемо
  (`derive_period_label`); KPI-строка; «Динамика спроса (2я/1я) — сезонный тренд».
- **B. ТОП-10** — расчёты по всему срезу, в таблицу ТОП-10; первые столбцы = фото + артикул(ссылка);
  строка «Медиана ТОП-10»; hover-зум фото ×4 (floating JS-превью).
- **C. Юнит-экономика** — коридор маржи/ДРР зелёным+жирным; сегменты по цене продажи
  (`sale_price_of`), топ-100, равные по числу артикулов; безубыточность с рекламой; «продажи»=заказы,
  выкупы=заказы×36%. Колонки: цена продажи / медиан.цена / артикулов / доля выручки / выкупов-SKU /
  рейтинг / маржинальность / опер.прибыль-SKU / прогноз опер.прибыль-SKU.
- **D. Доминирующие цвета (базовые)** — по всей базе MPStats (`allItems`), схлопывание к базовому
  цвету (`base_color`/`BASE_COLOR_RULES`); ряд: [цвет | диаграмма 50% | метрики 30%: доля·артикулы·
  сумма заказов ₽]. **С новой страницы в PDF** (класс `pgbreak`).
- **E. Контент-бенчмарк** (по 20 SKU) — медиана топа + лидер (только значение) + «Ваше»; метрики
  фото/видео/описание/характеристики/длина названия/рейтинг/отзывы/заказы/выручка; смыслы для названия.
- **Листинг топов (слайды)** — по 10 слайдов на карточку с подписью-номером; шапка 2 строки
  (бренд-ссылка·ср.цена·рейтинг·выручка / название). id-якорь `blk-listing`.
- **F2. Готовые данные** — теги-смыслы (хвосты) + таблица характеристик топов со столбцом «Доминанта».
  id-якорь `blk-f2`.
- **F3. Принадлежность признаков топа (АВТО)** — новинка: % присутствия значений характеристик у топа,
  ≥30% = обязателен (порог гл. 13). Считается по `card.json` (прокси Wildbox, без кабинета). id-якорь `blk-f3`.
- **G. Ваша карточка против ниши** — гэпы своей карточки. **С новой страницы в PDF** (`pgbreak`).
- **G2. Воронка [2]** — наш vs конкуренты; фото+артикул(ссылка)+бренд; планка (медиана); строка
  «Отставание Δ» пастельно-красным; вороночные гэпы в план.
- **H. План доработки** — гэпы + цели ниши + «Ручные задачи». Пункты с авто-данными помечены
  кликабельными ✅-чипами-якорями (→ F2/F3/Листинг). «Полки/доска» и «ДЖЕМ-конверсии» удалены.

## Что изменилось (эта сессия)
- **F3 «Принадлежность %» — авто.** Новый блок: `belonging(cards)` раскладывает товар на признаки по
  характеристикам топ-карточек (`_chars` из `card.json`), считает долю присутствия токенов, ≥30% =
  обязателен. Прокинут в `build_report`/`build_html` параметром `belong`. Шум почищен: стоп-слова +
  выброс токенов-эха имени признака (стем первых 5 символов слов из названия).
- **План H — связка с авто-данными.** Пункты «Смыслы/листинг», «Характеристики», «Принадлежность %»
  получили кликабельные ✅-чипы (`.jump`), ведущие к секциям `#blk-f2`/`#blk-f3`/`#blk-listing`
  (id-якоря + подсветка `:target`). «Полки/доска» убрана совсем (нет источника данных).
- **PDF под печать A4 — переработан:**
  - **Все картинки видны:** `inline_images()` вшивает basket-слайды как `data:URI` (компактный вариант
    `c246x328` вместо `big`), не завися от сетевых таймаутов Chromium; снимаем `loading=lazy` для печати;
    `--headless=new` + `--run-all-compositor-stages-before-draw`. 68/68 картинок, PDF ~10 МБ.
  - **Компактность:** секции рвутся по границам «атомов» (карточки/строки таблиц/слайды), а не целиком
    → без крупных пустот; ужаты отступы/паддинги/футер. Заполнение 93–96% на контентных страницах.
  - «Доминирующие цвета» и «Ваша карточка против ниши» — с новой страницы (`section.pgbreak`).
- **Fix таблицы характеристик:** столбец «Доминанта» был `position:sticky;right:0` и в PDF налезал на
  соседний столбец. Заменён на обычный последний столбец: `table-layout:fixed; width:100%` (таблица
  вписана по ширине, «Доминанта» видна без прокрутки), зелёная подсветка + левая граница, заданы ширины
  первого столбца (14%) и «Доминанты» (15%), значения переносятся, заголовки — целыми словами.

## Что пробовали и НЕ сработало (важно, не повторять)
- **Картинки в PDF через сеть Chromium** — из 75 `<img>` в PDF попадало только 13: basket-CDN картинки
  с `loading="lazy"` «ниже сгиба» не догружались при печати. Полумеры (`--virtual-time-budget`) ненадёжны
  через прокси. РЕШЕНИЕ: вшивать картинки как `data:URI` (см. `inline_images`).
- **Вшивание full-res `big`-картинок** → PDF раздулся до **95 МБ**. Локального ресайза нет (нет ImageMagick/
  Pillow). РЕШЕНИЕ: качать компактный вариант basket `c246x328` (тот же CDN) — PDF ~10 МБ, качество для
  печати достаточное.
- **`section{break-inside:avoid}` в print** — целая высокая секция прыгала на новую страницу, оставляя
  большие пустоты. РЕШЕНИЕ: `break-inside:auto` на секции + `break-inside:avoid` только на «атомах»
  (`.lcard`, `tr`, `.callout`, `figure.slide`, `.crow`), `thead{display:table-header-group}`.
- **Столбец «Доминанта» через `position:sticky;right:0`** — в PDF (`overflow:visible`) пинился к краю
  страницы и накрывал последний столбец топа, оставляя пустой слот. sticky для печати бессмыслен.
  РЕШЕНИЕ: `table-layout:fixed;width:100%` — «Доминанта» становится обычным видимым последним столбцом.
- **`overflow-wrap:anywhere` на заголовках** таблицы характеристик рвал «ХАРАКТЕРИСТИКА» посреди слова.
  Ограничили перенос только значениями (`td`), заголовки — целыми словами, первому столбцу дана ширина.
- **Ранее (прошлые сессии, всё ещё актуально):** natural-breaks сегменты (→ 1 огромный + хвосты по 1 арт,
  вердикт цеплялся за выброс) → равные квантильные + порог ≥2 арт; сегменты по витринной цене → по цене
  продажи (`sale_price_of`); `wb_basket_host` обрывался на vol 5189 → экстраполяция + перебор соседей;
  hover-зум на `transform:scale` обрезался контейнером → floating JS-превью; период off-by-one → фикс
  date-math + явный `--period-label`; `AskUserQuestion` рвался («stream closed») → развилки текстом.

## Открытые вопросы (нужно решение пользователя)
Крупных открытых развилок нет — отчёт по структуре пройден полностью и согласован поблочно.
Мелочи «на усмотрение» (можно поднять, если пользователь захочет ещё доводки):
- **Блок C «широкая сотня».** Сегменты сейчас по ОТФИЛЬТРОВАННОМУ срезу [1]. Можно опционально считать
  по более широкой, менее отфильтрованной сотне (вся выдача по фразе без групп/exclude). Не критично.
- **Блок B: бренд vs артикул** как «конкурент» (сейчас агрегат по бренду, у большинства SKU=1).
- **Размер PDF ~10 МБ** из-за вшитых картинок — приемлемо для печати; при желании можно качать ещё более
  мелкий вариант basket (`tm`) для облегчения, но потеряется чёткость слайдов.
