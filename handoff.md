# Handoff — конкурентный анализ WB через MPStats + PDF-отчёты

## Цель
Проводить конкурентный анализ товаров/продавцов на Wildberries по данным **MPStats API** и оформлять
результат в **красивые многостраничные PDF** (сводка + разбор карточек + конкуренты + логистика +
потенциал + ниша + дорожная карта). Всё оформлено переиспользуемыми скриптами в репозитории.

## Текущее состояние
Работает end-to-end, всё закоммичено. Ветка `claude/wildberries-competitor-analysis-u4ftu1`,
открыт **PR #11** (https://github.com/SolexVK/wb-headless/pull/11). Два пайплайна:
- **Ниша/артикулы:** `collect.py` → `build.py` (обложка + карточки + ниша).
- **Продавец (расширенный):** `collect_seller.py` → `build_seller.py` — **9-страничный** разбор:
  сводка · 3 целевые карточки · ТОП-конкуренты · **логистика складов** · **потенциал + план
  распределения стока** · ниша · авто-дорожная карта.

Последний разбор — продавец **4289467 = ИП Комиренко Т А**, ниша детского постельного (12 nmId).
Отчёт v4 доставлен. Корневая причина низких продаж (подтверждена данными): товар на региональных
складах, ~нет на центральных хабах (Коледино/Электросталь/Тула-Алексин/Казань/СПб/Екб) — у
конкурентов там в среднем 4 хаба и ~50% стока. Плюс мало отзывов (×50 разрыв), 12 дроблёных
карточек, нет бренда. Цена (2 697 ₽) — выше медианы комплектов, т.е. НЕ причина.

## Файлы, над которыми работали (всё закоммичено в reports-generator/)
- `build.py` — рендер PDF ниши; `WH_NAMES` теперь грузится из `wb_warehouses.json` (баг исправлен).
- `collect.py` — сбор ниши/артикулов; тоже читает `wb_warehouses.json`.
- `collect_seller.py` — сбор по продавцу (nmId → seller_data.json): карточки, конкуренты сегмента,
  склады продавец-vs-конкуренты, **потенциал (привязан к доле центр. спроса)**, распределение стока,
  авто-дорожная карта.
- `build_seller.py` — 9-страничный PDF из seller_data.json (импортит CSS/хелперы из build.py).
- `wb_warehouses.json` — справочник складов WB (id→имя, только isWb, ~179). Заменил ошибочный хардкод.
- `wb_region_demand.json` — оценочные доли спроса по макрорегионам (для расчёта потенциала; редактируемо).
- `README.md` — документация обоих пайплайнов.
- `handoff.md` — этот файл.

## Что пробовали и НЕ сработало (важно — читать перед доработками)
- **Ассортимент продавца по id/имени/бренду в MPStats — НЕ работает надёжно.** `/wb/get/seller?path=имя`
  → total 0; `/wb/get/seller/{id}` → 405; `/wb/get/brand?path=бренд` → карточки ДРУГИХ продавцов
  (бренд-сквоттинг). WB catalog/card API за антиботом (429/404, WBAAS). **Обход:** список nmId от
  пользователя → item/* и category работают.
- **Имя/бренд продавца:** WB `static-basket-01.wbbasket.ru/vol0/data/supplier-by-id/{id}.json`.
- **Справочник складов:** WB `static-basket-01.wbbasket.ru/vol0/data/stores-data.json` (~14.5 МБ, 77k;
  isWb=фулфилмент WB). Внимание: WB-Тула = **Алексин (206348)**; «Склад продавца Тула» — это FBS
  (isWb=false), не фулфилмент.
- **`/wb/get/warehouses?path=` → 500** (нет распределения продаж по складам); footprint считаем из
  `item/{sku}` `sizeandstores.s` = {склад_id: кол-во}.
- **Категорийный `purchase` (выкуп)** — величина уровня подкатегории (одинакова для всех), не
  по-товарная; в таблице конкурентов заменено на «возраст карточки».
- **Дерево категорий:** `/wb/get/categories` (GET, ~12 МБ) — искать точный путь ниши.
- **Замусоренность подкатегории:** «Постельное для детей» включает подушки/одеяла/простыни →
  фильтр на комплекты (`--comparable "постельное бель" кпб "комплект бель"`), иначе цена/медиана врут.
- **Пагинация category:** `endRow=5000` — предел страницы; изредка пустой ответ → перезапуск.
- **Грабли:** `sizeandstores[*].s` бывает пустым list; `%,d` в Python-% не работает; случайный «但».

## Команды для проверки
Нужны `MPSTATS_TOKEN` и Chromium (`/opt/pw-browsers/chromium-1194/chrome-linux/chrome`).
```bash
# импорт (без сети)
python3 -c "import sys; sys.path.insert(0,'reports-generator'); import build, collect, collect_seller, build_seller; print('OK')"
python3 -c "import sys; sys.path.insert(0,'reports-generator'); import build; print(build.wh_label('130744'), build.wh_label('206348'))"  # Краснодар Алексин

# разбор продавца (пример — детское постельное, ИП Комиренко)
MPSTATS_TOKEN=*** python3 reports-generator/collect_seller.py \
  --sku 707011618 529697243 707008613 529730106 529741719 836321729 975082784 975072971 975082781 975077991 975077990 707013054 \
  --category "Дом/Детская/Постельные принадлежности/Для детей/Постельное белье" \
  --niche-name "детское постельное бельё" --comparable "постельное бель" кпб "комплект бель" \
  --seller-name "ИП Комиренко Т А" --seller-id 4289467 --detailed 3 \
  --d1 2026-06-08 --d2 2026-07-07 --out reports-output/seller_data.json
CHROME=/opt/pw-browsers/chromium-1194/chrome-linux/chrome \
python3 reports-generator/build_seller.py reports-output/seller_data.json --pdf reports-output/seller_report.pdf

python3 -c "d=open('reports-output/seller_report.pdf','rb').read();print('pages',d.count(b'/Type /Page')-d.count(b'/Type /Pages'))"  # 9
```
**Ожидаемое состояние (зелёное):** формальных тестов нет. `import` печатает OK; `wh_label` возвращает
«Краснодар»/«Алексин»; `collect_seller.py` пишет `seller_data.json` (ниша 8 704 SKU, сегмент ~5 736);
`build_seller.py` даёт **9-страничный** PDF; ссылок ~55. КРАСНОЕ: пусто в MPStats (токен/429), пустой
ответ category (перезапуск), Chromium не найден (`$CHROME`). На момент хендоффа всё зелёное, v4 доставлен.
Выходы в `reports-output/` (gitignored) — при новой сессии пересобрать командами выше.
