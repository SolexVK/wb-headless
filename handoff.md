# Handoff — Telegram-бот WB-скиллов

Ветка: **`claude/telegram-bot-skills-81540d`**. Разработка бота идёт здесь.

## Цель
Собрать Telegram-бота, который по требованию пользователя подтягивает нужный WB-скилл,
через диалог/кнопки собирает у пользователя входные данные, выполняет скилл и возвращает
готовый отчёт в чат в выбранном формате (HTML/PDF/XLSX). Скиллы добавляются постепенно —
**добавить скилл = добавить манифест**, без переписывания ядра. Есть умный кэш дорогих
вытяжек (лимиты MPStats / WB, правило 72 ч на отчёты кабинета) и реюз по склейке (imtID).

## Текущее состояние
Пройдены этапы 1, 2, 3a, 3b (см. `docs/telegram-bot/ARCHITECTURE.md` §10). Работает:
- **БД v3** (SQLite, `lib/db.js`): миграции v2 (слой бота) + v3 (сессии) + хелперы.
- **Реестр манифестов** (`bot/core/registry.js`) + первый манифест `wb-top-keywords`.
- **grammY-бот** (`bot/index.js`): меню → сбор формы (обязательные + ⚙ доп.) →
  подтверждение → **реальное выполнение** через очередь → выдача (текстовая сводка
  ТОП-конкурентов + JSON-контракт файлом). Персональная выдача владельцу задачи.
- **Очередь** (`bot/core/queue.js`) с лимитом конкурентности и дорожками-семафорами.
- **Исполнитель** (`bot/core/executor.js`): spawn `npm run <script>`, чтение JSON.
- Бот запускался живым (@solexvk_wb_tools_bot); при возобновлении, вероятно, остановлен
  (эфемерный контейнер) — перезапустить `npm run bot`.

Проверено на реальных данных MPStats (фраза «рубашка в полоску женская»: выдача 99 → 10
конкурентов). Токены MPSTATS_TOKEN и Wildberries_API есть в окружении.

**НЕ сделано:** этап 3c (mid-flow пикер конкурентов + выбор формата HTML/PDF/XLSX +
рендер/выдача), этап 4 (интеграция кэша `source_cache` в исполнитель), остальные скиллы
(cards-compare с правилом 72 ч, brand-sales, competitor-analysis), инженерный режим,
шаблоны форматов (`bot/render/`).

## Что пробовали и НЕ сработало
- **`git merge` ветки БД — НЕЛЬЗЯ.** У веток `telegram-bot-skills-81540d` и
  `origin/claude/database-branch-bx2f5u` **нет общего предка** (`git merge-base` пуст).
  Ветка БД отведена ДО появления скиллов: 18 файлов против 51, её `package.json` без всех
  скилл-скриптов и без `xlsx`. Merge (даже `--allow-unrelated-histories`) затянул бы старые
  версии 12 пересекающихся файлов и снёс рабочий код. Решение: взяли ЦЕЛИКОМ 3 DB-only файла
  (`lib/db.js`, `db-cli.js`, `data/wb.db`), а `package.json`/`.gitignore`/`.env.example`
  пропатчили аддитивно. Их версии из ветки БД удаляли критичное (`.secrets/` игнор,
  `Wildberries_API`, python-игнор) — их НЕ брать.
- **`withDefaults` пред-заполнял ОБЯЗАТЕЛЬНЫЕ поля** (period/top имеют default) → диалог их
  проскакивал, screenFor возвращал ask без field → падение. Исправлено: дефолты только для
  НЕобязательных полей; обязательные всегда спрашиваются у пользователя.
- **`pgrep -f "bot/index.js"` даёт ложное «жив»** — паттерн совпадает со строкой в самой
  bash-команде. Проверять живость через `ps aux | grep -F bot/index.js | grep -v grep` или
  по task-notification, НЕ pgrep из команды, содержащей этот путь.
- **Живой бот пачкал закоммиченную `data/wb.db`** (писал сессии) → стоп-хук на грязное
  дерево. Обошли: `DB_PATH=data/wb-runtime.db` (gitignored) для бота.
- **Импорт в дым-тестах из scratchpad**: относительный путь не резолвился — использовать
  АБСОЛЮТНЫЙ путь `/home/user/wb-headless/...` в import.
