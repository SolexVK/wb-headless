# Handoff — инструменты для Wildberries

Ветка: **`claude/wildberries-tools`** (каноническая). Продолжаем разработку здесь.
Веб-сессия может стартовать на авто-ветке `claude/resume-*` — скилл `/resume` (шаг 0)
теперь сам переключает на каноническую ветку из этой строки. Если оказался на авто-ветке —
перенеси работу в `claude/wildberries-tools` fast-forward’ом и продолжай в ней.

## Цель
Каскад инструментов для WB: **[1] ТОП по фразе → [2] Сравнение карточек → [3] Конкурентный
анализ**. Инструменты сцепляются общим JSON-контрактом (ключ `nmId`). Архитектура и
контракты — в `docs/pipeline/README.md`. Правило: наш артикул ВСЕГДА спрашиваем у
пользователя; конкурентов даёт [1] или пользователь вручную.

## Текущее состояние
- **[1] ТОП по ключевой фразе (MPStats) — ГОТОВ, зафиксирован как СКИЛЛ, обкатан вживую.**
  Скилл `.claude/skills/wb-top-keywords/`. Работает и отдельно, и в каскаде. Эндпоинт
  залочен, двухуровневая фильтрация согласована с пользователем и проверена на двух
  ассортиментах («муслиновая» → 48, «в полоску» → 56). HTML-отчёт с фото+цветом,
  авто-имя файла `<фраза>_<дата>.html`.
- **[2] Сравнение карточек — ГОТОВ** (кабинет WB, headless-браузер). `lib/wbCardsCompare.js`
  + скилл `wb-cards-compare`. DRY-RUN / `--submit` (тратит 1 лимит) / `--export-existing`
  (бесплатно). Экстрактор XLSX→JSON: `lib/wbCardsCompareParse.js` (контракт cards-compare).
- **[3] Конкурентный анализ + оркестратор — ЧЕРНОВИК, ТРЕБУЕТ ПЕРЕСМОТРА.**
  `lib/wbCompetitiveAnalysis.js` + `scripts/wb-competitive-analysis.mjs` и
  `scripts/wb-pipeline.mjs` написаны ДО переработки [1]. Логика [3] на фикстурах рабочая,
  но: (а) оркестратор зовёт [1] в СТАРОЙ форме `filters` (нет deep-групп/периода/пресетов);
  (б) саму суть [3] пользователь ещё не проговаривал — надо обсудить перед доводкой.
- **База WB API**: `lib/wbClient.js` (лимиты, token-bucket, ретраи), `lib/wbToken.js`
  (`npm run token:check`), снимки доки `docs/wb-api/*`, скилл `wb-docs`. Джем-отчёты API:
  `lib/wbJemReports.js`.
- **Токены (env, есть в этой сессии):** `MPSTATS_TOKEN` (заголовок `X-Mpstats-TOKEN`, для [1]),
  `Wildberries_API` (WB API), `WB_COOKIES` + `WB_LOCALSTORAGE` (сессия кабинета для [2]).

## Что изменилось (по сути)
- **[1] переосмыслен под финальную спеку пользователя:**

  - фильтр по НАЗВАНИЮ: **`exclude` — жёсткий гейт**; **группы соединяются ИЛИ**

    (ни одного ключа групп) добирается исключением, если выручка ≥ ТОП-`exceptionRank`

- **Матчинг — подстрока в нижнем регистре ⇒ ключи задаём СТЕМАМИ** (`прям`, а не `прямой`).
- **Ветка:** вся работа перенесена с авто-ветки `claude/resume-5kyfdp` на

## Что пробовали и НЕ сработало (важно, не повторять)
- **Старый эндпоинт `/wb/get/search`** — оказался HTML-заглушкой (HTTP 200, `text/html`,
  пустое тело). Тупик. РАБОЧИЙ — `POST https://mpstats.io/api/analytics/v1/wb/search/items`
  (новый versioned API, Laravel 422-валидация). Слово — query-параметр **`path`** (не `query`);
  период `d1`/`d2`, причём **`d2` строго РАНЬШЕ сегодня** (иначе 422); тело ag-grid
  `{startRow,endRow}`; ответ `{total,data:[{position,id,...}]}`, `id`=nmId. Проверка «эндпоинт
  реальный»: несуществующий `/wb/get/zzz` даёт то же `500 "Не корректные условия фильтра"`,
  что и `/wb/get/keywords` — т.е. это generic-заглушка, не признак живого метода.
- **Потолок выдачи `search/items` = ~100 товаров на фразу** (проверено на 3 запросах:
  `total`≤100, страница 100–200 пустая). **Топ-200/500 через этот эндпоинт недостижим** —
  для более глубокой выдачи нужен ДРУГОЙ метод (пользователь сказал «дам другой механизм»).
- **Строгий «И» между группами** — слишком жёсткий: терял лидеров с частичным описанием
  (в заголовке крой есть, воротника нет → не «полное совпадение» и не «безхвостый» → выпадал).
  На «муслиновой» оставалось 2 из ~70. Заменили на **ИЛИ** (Вариант 2, exclude-гейт) — стало 48.
- **Порог «безхвостых» по всему пулу** — исключённые товары (напр. «парео») задирали планку
  выручки, потом сами выкидывались → 0 результатов. Фикс: порог считаем **по пулу без
  exclude-хитов**.
- **`final_price` (витринная) ≠ средняя цена продажи.** Средняя цена продажи =
  `final_price_average` (проверено: = `revenue/sales`). Используем именно её в ценовом коридоре.
- **Подстрока без стема** — `прямой` не ловит «прямого» (разные окончания). Ключи — стемы.
- **`exclude` со словом `без`** — слишком широкая подстрока (ловит «без карманов» и т.п.).
  Задавать конкретнее, напр. `без ворот`.
- **[3]/оркестратор написаны до переработки [1]** — оркестратор передаёт [1] старую форму
  `filters`; не падает, но глубокие фильтры/период туда не прокинуты. Переделать при возврате.
