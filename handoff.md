# Handoff — планировщик производства одежды (planner/)

## Цель
SPA для планирования производства одежды под маркетплейс WB. Репозиторий `solexvk/wb-headless`,
рабочая ветка `claude/production-plan-twv8ki`. Владелец разворачивает сам на Mac mini, порт **8477**.
Ядро готово (план продаж → партии → расписание по цехам с Гантом, неттинг остатков, экономная
раскладка JIT, юнит-экономика, ранг сезонности). **Текущий фокус: страница «Отчёты»** — Excel/PDF
отчёты в красивом оформлении, включая сводный отчёт для собственника с диаграммами. Набираем отчёты
дальше по запросу владельца.

## Текущее состояние
Всё задеплоено и подтверждено владельцем («отчёт для собственника увидел, всё хорошо»). Последняя
правка — сомы под долларами на диаграмме закупки — запушена, ждём подтверждения после обновления.
Текущая сборка: **`reports-owner-som-labels-2026-08-27`** (APP_BUILD в `public/app.js` == BACKEND_BUILD
в `server.js` — держим РАВНЫМИ, бампаем на каждое изменение).

Работает:
- **Отчёты** (вкладка): выпадающий список отчётов + «Получить отчёт»; шапка с датой/временем; сохранение
  в архив ТОЛЬКО по кнопке «Сохранить отчёт»; отдельная вкладка «Архив» (просмотр/Excel/PDF/удаление).
  Отчёты:
  - **r3 «Сводка для собственника»** (НОВЫЙ, первый в списке): KPI-карточки (изделий всего, метраж
    ткани, стоимость ткани $/сом/₽, число заказов); блок «Пошив помесячно» — накопительная столбчатая
    диаграмма по цехам + матрица месяц×цех; блок «Расход ткани помесячно» — столбчатая диаграмма +
    таблица; блок «Закупка по периодам» — диаграмма стоимости ($ и сом над столбцами) + таблица
    (метраж/$/сом, итоги). Инлайн-SVG (`svgStacked`/`svgBars`, `svgBars` поддерживает 2-ю строку
    подписи `fmt2` и `padT`). Excel r3 — 3 листа. PDF/печать работают (SVG инлайн).
  - **r1** производство помесячно (цех×артикул×штук), **r2a** ткань помесячно, **r2b** консолидация
    закупки ткани.
- **Курсы валют** (`lib/currency.js`): официальные курсы НБ КР (nbkr.kg/XML/daily.xml), пары
  сом/$/₽, кэш в БД (`meta`), эндпоинты GET/POST `/api/currency`, шапка отчётов + «Обновить курс».
- **Закупка ткани** (r2b и данные для r3): Китай — за МЕСЯЦ до старта пошива (`CHINA_LEAD_DAYS=30`),
  Мадина (Бишкек) — за НЕДЕЛЮ (`BISHKEK_LEAD_DAYS=7`, +$0.40/м, для пошива в авг/сен), лето — в ДВА
  этапа (ранний по первому пошиву + начало января). Китайский НГ: февраль закрыт → заказы из мёртвой
  зоны (`cnyClamp`) сдвигаются на 5 января и объединяются (отдельно деми/лето). Excel: Бишкек/деми/лето
  на разных листах, столбец «Сумма, сом».
- **Проверка полноты** (панель, свёрнута по умолчанию `<details>`): сверяет план (партии) с
  произведённым (циклы), помечает missing/partial/noplan с причиной — чтобы находить «пропавшие»
  артикулы (напр. 002/003 без плана).
- Гант, матрица «кто шьёт» (жёсткая), JIT — как в прошлой сессии (см. ниже, без изменений сегодня).

Не доделано: ранги сезонности/план продаж в отчёты не выведены; 2 отложенные фичи Ганта (см. TODO).

## Что пробовали и НЕ сработало (грабли — читать обязательно)
- **Тест на demo-данных песочницы ≠ данные владельца.** Локальная `planner/data/planner.db` содержит
  демо (цеха Чоро/Ала/Нарын/…, ~5 артикулов). У владельца ДРУГИЕ данные (цеха М.Ж./Цех1..6, 20+
  артикулов, планшеты, летние). Дважды в прошлом рапортовал «работает» на демо — ошибка. Проверять по
  МЕХАНИКЕ кода и аккуратно формулировать «проверено».
- **Внутренние функции reports.js не экспортируются** — для смоук-теста r3 временно добавлял
  `export { report3Html as __r3h, report3Excel as __r3x }` в конец файла, гонял mjs-харнесс, ПОТОМ
  восстанавливал файл из бэкапа (`scratchpad/reports.bak*.js`) и `node --check`. Не забыть убрать
  временный экспорт перед коммитом (проверял tail файла).
- **Русская запятая в десятичных** (прошлая сессия, актуально): `+"5,5"`=NaN → откат к дефолту.
  Клиентский парс — `parseDec` (запятая/пробелы/точка). Сервер сохраняет верно.
- **Матрица «кто шьёт» — жёсткий потолок** (scheduler.applyPin): пин honorится только в пределах
  allowedWorkshops; drag-в-новый-цех работает через предрасширение allowedWorkshops в `/api/pin`.
  Из-за этого «пропавшие» артикулы — это чаще `noplan` (нет плана), а не unscheduled; панель полноты
  показывает причину.
- **JIT двигаем только аддитивным `jitStart` (пол), НЕ пинами дат кроя** — пины ломают непрерывность
  (параллель+разрывы). Экономная раскладка ограничивает НАБОР цехов (`stateReduced`), планировщик сам
  держит непрерывность через freeDate.
- **8-значный hex для прозрачности** (`${accent}12` и т.п.) в KPI-карточках — валидно в браузерах,
  в SVG/HTML работает. Не переусложнять rgba.
