# Handoff — инструменты для Wildberries

Ветка: **`claude/wildberries-tools`** (каноническая). Продолжаем разработку здесь.
Веб-сессия может стартовать на авто-ветке `claude/resume-*` — скилл `/resume` (шаг 0)
сам переключает на каноническую. Если оказался на авто-ветке — перенеси работу в
`claude/wildberries-tools` fast-forward’ом и продолжай в ней.

## Цель
Каскад инструментов для WB: **[1] ТОП по фразе → [2] Сравнение карточек → [3] Конкурентный
анализ**. Сцепляются общим JSON-контрактом (ключ `nmId`). Правило: наш артикул ВСЕГДА
спрашиваем у пользователя; конкурентов даёт [1] или пользователь вручную. Итог [3] —
многоблочный отчёт (A–H + воронка) + план доработки карточки. Архитектура и контракты —
`docs/pipeline/README.md`.

## Текущее состояние
- **[1] ТОП по фразе (MPStats) — ГОТОВ, СКИЛЛ, обкатан.** `.claude/skills/wb-top-keywords/`,
  `lib/wbTopKeywords.js` (+ `formatPickTable`), `scripts/wb-top-keywords.mjs`. Двухуровневый
  фильтр, HTML-отчёт, `--pick` (таблица-пикер для ручного выбора конкурентов в [2]).
- **[2] Сравнение карточек — ГОТОВ.** `lib/wbCardsCompare.js` + скилл `wb-cards-compare`.
  DRY-RUN / `--submit` (тратит 1 лимит) / `--export-existing` (бесплатно). JSON-контракт
  воронки `cards-compare.json`.
- **[3] Конкурентный анализ — РАБОТАЕТ в каскадном режиме, идёт поблочная доводка.**
  Python-движок `.claude/skills/wb-competitor-analysis/wb_analyze.py` (~1770 строк). Собирает
  markdown+HTML+PDF+JSON. Каскадный режим: `--items-json` (ниша из [1]) + `--funnel-json`
  (воронка из [2]) + `--seasonality-delta` + `--cost`. Блоки **A–H + G2 (воронка)**.
- **Оркестратор `scripts/wb-pipeline.mjs` — ГОТОВ, двухфазный.** Фаза 1 (discovery): [1] +
  сезонность (2 агрегата MPStats по половинам периода) + пикер. Фаза 2 (analysis): [2] → [3].
- **База WB API:** `lib/wbClient.js`, `lib/wbToken.js`, `lib/mpstats.js` (эндпоинт поиска
  залочен), `lib/wbCabinet.js` (headless-браузер), снимки доки `docs/wb-api/*`.
- **Токены (env этой сессии):** `MPSTATS_TOKEN` (заголовок `X-Mpstats-TOKEN`), `Wildberries_API`,
  `WB_COOKIES` + `WB_LOCALSTORAGE` (сессия кабинета для [2]).

**Поблочная доводка [3] (эта сессия) — сделано и согласовано с пользователем:**
- **A. Ёмкость** — шапка: отдельно «Ниша» (имя из фразы, `derive_niche`: «Рубашки женские»)
  и «Ключевая фраза». Период человекочитаемо (`derive_period_label`: «за последние 30 дней» /
  «август 2025 года» / «за последний год»). Формулировки: «Артикулов в срезе (после фильтров)»,
  «Совокупная выручка среза за период», «Динамика спроса (2-я половина к 1-й) — сезонный тренд».
- **B. ТОП-10** — расчёты по всему срезу, в таблицу ТОП-10; первые столбцы = **фото первого
  слайда + артикул со ссылкой**; строка **«Медиана ТОП-10»** (выручка/продажи/ср.цена);
  **hover-зум фото ×4** (floating-превью, JS). `first_slide_url`, `.bthumb`, зум в `JS_REPORT`.
- **C. Юнит-экономика** — коридор маржи/ДРР **зелёный+жирный**; сегменты по **цене продажи**
  (`avgSalePrice`, хелпер `sale_price_of`), выборка **топ-100**, равные по числу артикулов,
  колонка **«Медиана цены»**; безубыточность **с рекламой** (ДРР 8% = 1051 ₽); «продажи»=заказы
  ×выкуп 36%; целевой сегмент ≥2 артикулов (не выброс). Прибыль = операционная после всех расходов.
- **D. Цвета** (ранее) — схлопывание к базовому цвету (`BASE_COLOR_RULES`, `base_color`),
  выборка ~весь пул, доля/артикулы/совокупная выручка (до 10 цветов).
- **G2. Воронка** (ранее) — таблица наш vs конкуренты + планка (медиана) + строка «Отставание Δ»
  (п.п. и абсолют); вороночные гэпы в план.
- **F2. Характеристики** (ранее) — колонки подписаны брендом (доминанта по разным брендам).

## Что изменилось
- **[3] перевели с Node-черновика на Python-движок** `wb_analyze.py` (перенесён с ветки
  `wb-competitor-analysis`) и **перепровели источники на каскад**: ниша из [1] (`--items-json`,
  вместо MPStats-категории), воронка из [2] (`--funnel-json`). Контент (фото/видео/описание/слайды/
  характеристики) движок добирает по nmId из публичного API WB (`basket.wbbasket.ru`) — без квоты MPStats.
- **Юнит-экономика:** модель прежняя (P покупателя с СПП, S=P/0.96, комиссия от S; эквайринг/налог/
  ДРР от P; брак от себестоимости). Сегменты переведены на цену продажи, выборка топ-100.
- **Оформление отчёта:** видимая горизонтальная прокрутка таблиц (HTML), альбомный PDF без обрезки,
  hover-зум фото, зелёный коридор маржи.

## Что пробовали и НЕ сработало (важно, не повторять)
- **Блок D цвета «по склейкам ТОП-игроков»** (первая версия) — показывал сырые склейки
  («голубой, синий; небесно-голубой…») и долю по продавцам. Неверно. Переписали: схлопывать к
  **базовому цвету по первому токену** склейки и агрегировать выручку по базовому цвету.
- **Блок C сегменты «по наибольшим разрывам цен» (natural breaks)** — на скошенном распределении
  дал **1 огромный сегмент (35 арт) + мелкие хвосты из 1–2 арт**, вердикт цеплялся за одиночный
  выброс (сегмент из 1 арт с макс. прогнозом). ТУПИК. Вернулись к **равным по числу артикулов
  (квантильным) сегментам** — они ровные (по 7–8 арт) и это устраивает пользователя. Плюс порог
  ≥2 артикулов для целевого сегмента.
- **Сегменты по витринной цене (`final_price`)** — неверно: экономику надо считать по **средней
  цене продажи** (`avgSalePrice` = revenue/sales, что реально платит покупатель). Ввели
  `sale_price_of` и проносим `sale_price` в item из [1].
- **`wb_basket_host` — таблица хостов обрывалась на vol 5189** → свежие артикулы (высокий nmId,
  напр. наш 841324733, vol 8413) НЕ обогащались (фото/видео пустые). Фикс: экстраполяция
  `28 + (vol-5190)//250` + перебор соседних хостов ±3, потолок 60. Наш артикул: 15 фото, видео есть.
- **CSS hover-зум фото чисто на `transform:scale`** обрезался бы контейнером таблицы
  (`overflow-x:auto`). Сделали **floating-превью на JS** (`position:fixed`, вне контейнера).
- **PDF и «горизонтальная прокрутка»** — в PDF прокрутки не бывает (статичный формат). Для PDF
  вместо прокрутки: **альбомная ориентация + перенос текста в ячейках** (`@media print`), чтобы
  широкие таблицы вписывались. Скроллбары — только для HTML.
- **`AskUserQuestion` дважды рвался** («Tool permission stream closed») — задавал развилки текстом.
- **Период `--period 30` давал «за 31 дней»** (в [1]/оркестраторе d1 считался как now-(days+1)).
  Фикс в оркестраторе: d1=now-days*day + оркестратор передаёт точную подпись `--period-label`.
- **content_benchmark падал бы на отсутствующих контент-полях** в каскаде (search_words_count,
  негатив% недоступны) — сделали пропуск метрик без данных.
- **`__pycache__/*.pyc` случайно закоммитили** — убрали, добавили в `.gitignore`.

```bash
  --group "крой=оверс,прям" --exclude "притал,стойк,волан" --price-min 1800
# Фаза 2 — analysis ([2]→[3]); --export-existing переиспользует готовое сравнение бесплатно:

  --rivals 297675127,494807116,435980977,342248350 --cost 536 --export-existing

# Прямой прогон движка [3] на готовых JSON (быстрее, без кабинета):

  --items-json reports-output/<id>/top-rivals.json \
  --funnel-json reports-output/<id>/cards-compare.json \
  --cost 536 --seasonality-delta -28 --period-label "за последние 30 дней" \
  --html-out r.html --pdf-out r.pdf --json-out r.json
```
**Ожидаемое «зелёное» (конец сессии):** синтаксис JS+Python чист; `--selftest` exit 0;
`token:check --ping`=OK; каскад собирает отчёт со всеми блоками A–H+воронка на реальных данных
(проверено на фразе «рубашка женская в полоску», наш `841324733`, run-id `fresh-demo`). Формальных
unit-тестов нет; проверка — `--check` / `py_compile` / `--selftest` / живой прогон. Обогащение по nmId
и PDF (Chromium) идут ~1.5 мин — при прогоне ждать завершения (артефакты в `reports-output/<id>/`).

## Открытые вопросы (нужно решение пользователя)
- **Блок C, «выборка топ-100».** Сейчас в [3] приходит ОТФИЛЬТРОВАННЫЙ срез [1] (в примере 45 арт
  после deep-фильтров). «Топ-100» = весь срез (до 100). Пользователь спрашивал про топ-100 — надо
  ли считать сегменты по БОЛЕЕ ШИРОКОЙ, менее отфильтрованной сотне (вся выдача по фразе без
  групп/exclude)? Это отдельная про-водка данных из [1]. **ЖДУ решения** (предложил как опцию).

  брендов 1 артикул → «SKU=1». Предлагал вариант «конкурент = карточка (артикул)». **На усмотрение.**
- **Столбец «Упущено» в блоке B** = 0 (MPStats не отдал lost_profit в выдаче [1]). Убрать или оставить.
