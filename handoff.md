# Handoff

## Цель
Инструмент планирования производства одежды под план продаж WB (папка `planner/`):
Гант, партии по цехам, заказ ткани, юнит-экономика, RBAC. Идёт чек-ап и доработка:
чиним «мёртвые»/неверные механики и наращиваем «Производство 2.0» — непрерывный
конвейер вместо помесячной привязки, с автоочередью, приоритетом своего цеха,
контролем сроков и переносом объёма. Работаем на ветке `claude/production-plan-twv8ki`,
разворачивается на Mac mini (launchd-служба `com.wbheadless.planner`).

## Что изменилось
- Ткань: заказ теперь консолидируется по поставщику и «планшет+цвет», окнами по режиму
  поставщика; последний заказ по ткани = остаток (излишки вычитаются, без мёртвого
  остатка). Метраж считается в разрезе цвета из `planMatrix`.
- Планировщик: **ушли от месяцев**. Все партии сезона — один пул; событийная очередь
  назначает по «кто раньше освободился», приоритет своему цеху, порядок EDF с
  чередованием артикулов; закреплённые (с заданным цехом) партии не трогаются; каждая
  партия идёт в один цех целиком (дробление — Фаза 3). Дедлайн = крайний срок.
- Гант: общий вид — единый блок; детали по двойному клику; сброс ручного сдвига переехал
  в модалку.

## Что пробовали и НЕ сработало
- **«Бесконечные» партии на Ганте (важно!).** После Фазы 1 у пользователя часть партий
  растянулась на годы (готовность 2033, опоздание 2400+ дн). Сначала подозревали баг в
  движке/анкоре/накоплении freeDate — **это НЕ так**. Причина: у части цехов мощность
  **пошива была задана = 1 шт/день** (в данных пользователя реально стояла 1). Нормализация
  `Math.max(1, +v||1)` превращает пустое/0/битое в 1, и непрерывный конвейер (без
  месячного капа) честно растягивает партию на годы. Старый помесячный движок это ПРЯТАЛ
  (упирался в месяц + overflow). Воспроизведено: sew=110 → готовность 23 дня; sew=1 →
  2033 год. Обошли: (а) диагностика в scheduler — если партия шьётся >90 раб. дней,
  ошибка с именем цеха и его мощностью; (б) кламп правого края Ганта горизонтом
  «последний дедлайн + 60 дн», чтобы монстр не растягивал всю шкалу. Пользователь
  исправил мощность → всё встало ровно. **Мораль: при странных датах сначала проверь
  мощности цехов, а не логику движка.**
- **`fmt` в gantt.js не показывает год** — из-за этого «готовность 21 ноя» вводило в
  заблуждение (на деле 2031). Учитывать при отладке дат.
- **RBAC-политика молча теряла новые top-level поля.** `applyWritePolicy` переносит из
  `incoming` только явно перечисленные секции. Добавили `suppliers` в блок `cap.data`,
  иначе не-админ с правом «Данные» не мог править поставщиков. При добавлении новых
  top-level полей в state — не забывать про `permissions.js`.
- **Селектор `input[data-art]` не ловит `<select>`** — выпадающий список поставщика у
  артикула не сохранялся, пока не расширили на `input[data-art],select[data-art]`.
  Чекбокс «свой» цеха тоже потребовал ветку `'own' in dataset` (иначе `w[undefined]="on"`).

# поднять сервер локально (без пароля) и дёрнуть расчёт

`launchctl kickstart -k gui/$(id -u)/com.wbheadless.planner`.
