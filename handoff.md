## 1. Цель

Строить полезные инструменты для работы с Wildberries на базе **энциклопедии**, собранной из
видео-уроков. Текущий фокус — **инструмент конкурентного анализа**: по нише (и, опционально, своему
артикулу + себестоимости) он выдаёт многоблочный отчёт и **план доработки карточки** — деньги
(топ-конкуренты), **маржинальный ценовой коридор** (юнит-экономика), принадлежность (цвета), контент-
бенчмарк, конкуренты по ключевым запросам и готовые данные по топам (смыслы/слайды/характеристики).
Экспорт в HTML и **кликабельный PDF**. Параллельно заведён рабочий цикл `/handoff` ↔ `/resume`.

## 4. Что изменилось (по сути)

- **Юнит-экономика** — ядро (`unit_calc`, `price_buyer_for_margin`, `price_segments`,
  `compute_economics`, `ECON_DEFAULTS`); блок C = маржинальный коридор + сегменты × маржа/прибыль +
  вердикт. «Зона объёма» показана отдельно как не-цель.
- **HTML-отчёт** (`--html-out`) + **кликабельный PDF** (`--pdf-out`, headless Chromium).
- **Фаза 3** — блок D: реальные цвета по склейкам ТОП-игроков, 8 цветов + широта.
- **Фаза 2** — слой публичных API WB (`wb_search`, `wb_basket_card`, `wb_slide_urls`,
  `wb_characteristics`), ретраи/кэш; **не тратит квоту MPStats**.
- **Фаза 4** — `--keywords`: блок B2, конкуренты из выдачи WB, метка 🆕 (нет в ТОП категории).
- **Фаза 5** — блок F2: смыслы (хвосты запросов), слайды листинга топов (миниатюры в HTML/PDF),
  таблица характеристик топов с доминантой.
- **Разрешены конфликты с `main`** — влит `origin/main` (модуль stock-report) объединением.
- **Команды `/handoff` + `/resume`** — фиксируют ежедневный цикл (вечером фиксируем, утром поднимаем).

### Параметры юнит-экономики (дефолты, общие; себестоимость спрашивать `--cost` каждый раз)
Комиссия до СПП 35,7% · СПП 4% · эквайринг 4,7% · налог 2% (от цены с СПП) · ДРР запуск/выход 30%/8% ·
брак 2,5% (от себестоимости) · выкуп 36% (только объём) · логистика/хранение 0 · целевая маржа 25–30%.
Модель: маржа от цены без СПП `S=P/(1−СПП)`; комиссия от `S`; эквайринг/налог/ДРР от цены с СПП `P`.
Проверка C=536: безубыток ≈ 1051 ₽, коридор 25–30% ≈ **2094–2613 ₽** (сходится вручную).

## 5. Что пробовали и НЕ сработало (грабли)

- **MPStats квота 429** — боевой прогон не сделан. Движок распознаёт конверт `{code,message}` и выводит
  понятную ошибку (не «нет данных»). Ждём сброса.
- **Дата контейнера опережает горизонт MPStats** → «будущие» даты дают пустой срез (`{data:[],total:0}`)
  — не ошибка. Для теста брать прошлые периоды.
- **WB search** отдаёт `products` в **корне** JSON (не под `data`) — было 0 результатов, исправлено;
  обязательны `curl --compressed` + `User-Agent`.
- **WB basket CDN** — 429 при пачках; добавлены ретраи на правильный хост + задержка 0.4 c + кэш;
  обогащение best-effort (в сессии грузилось 1/4–2/5 из-за тестовых бёрстов; на одиночном прогоне полнее).
- **`card.wb.ru/cards/v2/detail`** периодически 0/404 — **не используем**; характеристики берём из
  `basket .../info/ru/card.json` (полный `options`) — надёжно.
- **Merge-конфликты с `main`** — возникли из-за того, что `main` ушёл вперёд (добавили stock-report),
  а мы правили те же `.gitignore`/`package.json`/`server.js`. Решено merge’ем + union-разрешением
  (rebase не делали, чтобы не переписывать историю/не force-push’ить).
- **Инструменты харнеса `Artifact` и `AskUserQuestion`** несколько раз падали с «permission stream
  closed» — демо отдавали через `SendUserFile`, вопросы задавали текстом.
- **Конверсии в корзину/заказ по запросу** — только **ДЖЕМ** (подписка есть), программно не дёрнуть;
  нужен импорт выгрузки (см. §7.1).
- **Переименование чата** к конфликтам/недоступности команд отношения не имеет — совпадение.

## 6. Команды для проверки

Формальных unit-тестов нет; работоспособность проверяется так:

```
# self-test движка (без сети, синтетика) — собирает весь отчёт
python3 .claude/skills/wb-competitor-analysis/wb_analyze.py --selftest
# + HTML и кликабельный PDF
python3 .claude/skills/wb-competitor-analysis/wb_analyze.py --selftest --html-out /tmp/r.html --pdf-out /tmp/r.pdf
# синтаксис
python3 -m py_compile .claude/skills/wb-competitor-analysis/wb_analyze.py
node --check server.js && node --check report-stock.js
# публичный API WB (без квоты MPStats): живой тест выдачи
python3 -c "import sys;sys.path.insert(0,'.claude/skills/wb-competitor-analysis');import wb_analyze as W;print(len(W.wb_search('рубашка',5)))"
# ветка сливается с main чисто?
git fetch origin && git merge --no-commit --no-ff origin/main; git merge --abort
# полный боевой прогон (нужна квота MPStats + себестоимость)
python3 .claude/skills/wb-competitor-analysis/wb_analyze.py --gender women --item рубашка \
  --pattern полоска --my-sku <арт> --cost <руб> --keywords "..." --html-out /tmp/wb.html --pdf-out /tmp/wb.pdf
```

**Ожидаемое состояние (на момент записи):** `--selftest` завершается строкой `[selftest] OK`;
`py_compile` и оба `node --check` проходят; проверка merge печатает `Already up to date` / без
`CONFLICT` (ветка сливается с `main` чисто). Единственное «красное» — **боевой прогон MPStats падает
на квоте 429** (ожидаемо, не поломка). `wb_search` вживую иногда отдаёт меньше карточек из-за 429 WB —
норма, деградирует мягко.
