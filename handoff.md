# Handoff — Анализ ниши Wildberries

## Цель
Инструмент оценки ниши/категории WB по данным MPStats: ёмкость, сезонность, тренд, конкуренция,
насыщенность → скоринг 0–100 и вердикт «заходить/осторожно/не заходить» с заключением на цифрах.
Плюс: реализация остатка (метод Овчинникова), экономика/маржа, выкуп, планка входа, отбор
уточняющих фраз из выгрузки «Оракул запросов» (Wildbox), PDF-отчёт. Цель — запускать на ЛЮБОЙ нише.

## Файлы, над которыми работали
- `lib/mpstats.js` — клиент MPStats: apiRequest (GET/POST), fetchCategory (POST, ключ `sort`),
  fetchCategoryTrends/Sellers/Brands/PriceSegmentation, fetchSearchResults, fetchCategories;
  нормализация товара (avgStock из stocks_graph, выкуп, контент, реклама, возраст, оборачиваемость).
- `lib/nicheReport.js` — базовый агрегатор категории (ёмкость/продавцы/монополизация) + CSV.
- `lib/nicheAnalysis.js` — движок: 5 блоков, скоринг, реализация остатка (sellThrough, нормировка на
  30 дн), экономика (unitEconomics), выкуп/возраст/сегмент/планка, риск-флаги, заключение, фаза 2.
- `lib/oraclePhrases.js` — свой ридер xlsx/csv + фильтр фраз (плюс/минус, `@цвета` через expandKeys).
- `lib/nicheReportHtml.js` — HTML-отчёт (инлайн-CSS+SVG, рус. термины, без повторов).
- `lib/renderPdf.js` — печать HTML→PDF headless-хромиумом (без npm-зависимостей).
- `report-niche.js` — CLI: аргументы + env (NICHE_ORACLE/PLUS/MINUS/COST/QUERY/FREQ/SUPPLY), запись pdf/html/csv/json.
- `server.js` — `GET /reports/niche` (query/freq/supply/cost).
- `scripts/wb-category.mjs` — резолвер пути категории по словам (учитывает пол).
- `scripts/oracle-phrases.mjs` — предпросмотр отбора фраз из Оракула.
- `config/niche-thresholds.json` — пороги скоринга (калибруются, env NICHE_THRESHOLDS).
- `.claude/skills/wb-niche-analysis/` — SKILL.md + references/{scoring,mpstats}.md.
- `docs/niche-analysis-methodology.md`, `NICHE.md`, `.env.example`, `.github/workflows/niche-report.yml`.

## Что изменилось
- Реализация остатка (Овчинников) заменила прежний ошибочный сигнал «частотность/карточки»; считается
  по СРЕДНЕМУ остатку периода (stocks_graph), нормирована на месяц (порог 1.5× валиден на любом периоде).
- Ёмкость/насыщенность берутся из ценовых сегментов (вся ниша), а не из усечённой выборки top-N.
- Тренд — год-к-году (trends отдаёт ~6 лет помесячно и ИГНОРИРУЕТ d1/d2), сезонность доступна всегда.
- Добавлены экономика единицы (модель сверена с эталоном), выкуп, возраст топа, перспективный
  ценовой сегмент, планка входа, жёсткие риск-флаги, заключение с рекомендацией.
- Ингест Оракула + плюс/минус-ключи по корню слова + `@цвета` (список цветовых корней).
- Отчёт переведён на русские термины, без дублей; добавлен PDF с цветными SVG-графиками.

## Что пробовали и НЕ сработало
- **Частотность из API MPStats.** Эндпоинт `/wb/get/keywords` СУЩЕСТВУЕТ (не 405, а осмысленные 500),
  требует query-параметр `path`=категория, но на ЛЮБОМ теле фильтра отвечает «Не корректные условия
  фильтра». Перебрал: `filterModel:{}`, `filterModel:null`, `sortModel:[]`, `sort:[{colId:...}]`,
  GET без тела, `fbs`, `filters:{}`. Не подобрал контракт — публично не документирован. Обход:
  частотность берём из выгрузки Оракула вручную. Подключить можно, если добыть полную API-доку MPStats.
- **Под-пути keyword-эндпоинтов** (`/wb/get/keywords/expanding|check|serp|group`, `/wb/get/subject/keywords`)
  — все дают generic 405 «Must be one of: OPTIONS» = НЕ существуют. Реальный только `/wb/get/keywords`.
- **`/wb/get/search`** — html-заглушка (пустой 200), тупик. Рабочий поиск — `POST /analytics/v1/wb/search/items`
  (залочен живым токеном), но он режет выдачу на ~100 карточек: `total` ≤ 100 — это ТОП-выдача, НЕ
  полное «предложение». Поэтому кол-во карточек для спрос:предложение берём из Оракула, не из API.
- **`category/trends` игнорирует d1/d2** — всегда ~77 месячных точек за ~6 лет. Из-за этого «половина vs
  половина» давала 6-летний рост (604%!) — переделали тренд на year-over-year (12 vs 12 мес).
- **Реализация по снимку `balance`** (на сегодня) смещала исторические периоды — перешли на средний
  остаток из `stocks_graph`. На длинном периоде raw-ratio рос линейно → нормировали на 30 дней.
- **Путь категории угадыванием** (`Женщинам/Одежда/Платья`) даёт `total=0` — путь НАДО резолвить из
  `wb/get/categories` (реальные пути другие, напр. `Женщинам/Платья и сарафаны`). Отсюда `scripts/wb-category.mjs`.
  Внимание: слова пола не совпадают с деревом («женские»≠«Женщинам») — в резолвере есть маппинг пола.
- **`unzip` CLI для xlsx** — ненадёжно; сделали свой ридер ZIP (central directory + zlib.inflateRawSync).
- **Скриншот HTML хромиумом по имени файла с кириллицей** — трактуется как URL (DNS-ошибка). Нужен
  префикс `file://$(pwd)/<файл>`. Сам PDF рендерится корректно (htmlToPdf уже использует file://).
- **Минус-ключ «любые упоминания цвета»** — не литеральное слово; keyMatches его не ловит. Встроили
  список цветовых корней и токен `@цвета` (expandKeys).

```bash
  scripts/wb-category.mjs scripts/oracle-phrases.mjs; do node --check "$f"; done

node scripts/wb-category.mjs женские рубашки
NICHE_COST=536 node report-niche.js "Женщинам/Блузки и рубашки/Рубашка" 2025-08-01 2025-08-30
# Полный с фразами: NICHE_ORACLE=oracle.xlsx NICHE_PLUS=... NICHE_MINUS=...,@цвета ... node report-niche.js "<путь>" d1 d2

# Экономика — сверка с эталоном (себест.536 → безубыток ~1051, коридор ~2094-2613):
node --input-type=module -e "import('./lib/nicheAnalysis.js').then(m=>console.log(m.unitEconomics(536,2000)))"
```
**Ожидаемое состояние (зелёное сейчас):** `node --check` всех файлов — OK; 5 smoke-наборов —
PASSED; экономика воспроизводит эталон; живые прогоны отрабатывают и рендерят PDF. Формальных
unit-тестов в репо нет — проверка через `node --check` + smoke-скрипты (в scratchpad, эфемерны) +
живой прогон. CI (GitHub Actions) — только `.github/workflows/niche-report.yml` (ручной запуск отчёта),
автотестов в CI нет.
