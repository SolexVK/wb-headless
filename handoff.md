# Handoff — Производственный план (planner)

## Цель
Рабочий веб-инструмент для планирования отшива рубашек: план продаж (с детализацией
размер×цвет) → этапы/партии → распределение по цехам → интерактивная диаграмма Ганта →
дашборд, план по размерам, план продаж, заказ ткани. Развёрнут на Mac mini пользователя,
доступ через браузер по Tailscale. Ветка: `claude/production-plan-twv8ki`.

## Текущее состояние
- **Инструмент работает**, развёрнут на Mac mini как служба launchd (автозапуск,
  переживает перезагрузку). Доступ по Tailscale: `http://100.108.217.93:8477`
  (порт 8477, т.к. 8090 занят OpenClaw). Логин `admin` + пароль (env `PLANNER_PASSWORD`).
- **6 вкладок**: Диаграмма Ганта, План по размерам, План продаж, Заказ ткани, Дашборд, Данные.
- Данные пока сид-пример (5 артикулов, 6 цехов). Реальные мощности/расход ещё не внесены.
- Всё, что просил пользователь за сессию, реализовано и проверено (см. «Что изменилось»).
- **ВАЖНО про деплой:** пользователь несколько раз не видел изменения, потому что на
  Mac mini не проходил `git pull` / не перезапускалась служба. После каждого пуша нужно
  напоминать полную последовательность обновления (см. «Команды»).

## Файлы, над которыми работали
- `planner/lib/model.js` — модель/сид/нормализация: матрица размер×цвет, комментарий
  артикула, fabricInfo{цвет:{image,plansheet,colorNo}}, flowOffsets по цехам,
  compareArticleId (автосортировка артикулов), buildMatrix/sumMatrixStage/stageUnits.
- `planner/lib/scheduler.js` — планировщик: дробление (мин. цехов, пропорц. мощности),
  предпочтительный цех (ручной выбор), resolveFlowOffsets (per-цех сдвиги операций),
  ткань, логистика, вехи.
- `planner/server.js` — Express + REST + Basic-auth + bind HOST/PORT (не менялся в этой сессии).
- `planner/public/index.html` — вкладки, секции, ранняя установка темы, легенда Ганта.
- `planner/public/app.js` — весь фронтенд: рендеры вкладок, матрица, план продаж (мини-карточки
  с цехом/комментарием/образцом), заказ ткани, тема, сворачиваемые блоки, сортировка, образцы.
- `planner/public/gantt.js` — SVG-Гант: дорожки операций, drag, период закупа ткани пунктиром,
  цвета через CSS-переменные темы.
- `planner/public/styles.css` — светлая/тёмная темы, матрица, мини-карточки, swatch, сворачивание.
- `planner/deploy/*`, `planner/DEPLOY.md`, `planner/README.md` — деплой на Mac mini.

## Что изменилось (по сути, хронологически за сессию)
1. **Матрица размер×цвет** — источник истины плана; вкладка «План по размерам» (ввод),
   суммы этапа выводятся из матрицы.
2. **Вкладка «План продаж»** — детальные мини-карточки по партиям и артикулам (цвета-колонки,
   размеры-строки, ВСЕГО, итог), фильтры по партиям/артикулам/цехам.
3. **Светлая тема** + переключатель 🌙/☀️ (по умолчанию светлая, выбор в localStorage).
4. **Фильтр по цехам + строка цеха** в мини-карточках (при дроблении — все цеха с объёмами).
5. **Дробление переписано**: цельная партия в 1 цех; иначе — минимум цехов (обычно 2:
   основной+вспом., 3-й лишь при нехватке) пропорционально мощности, без мелких хвостов.
6. **Смещения операций внутри цикла (flowOffsets) per-цех** — сдвиг пошива/утюжки/ОТК в раб.
   днях, 3 колонки в Данные→Цеха; пусто = авто по мощности. (Первая версия была неверной —
   межцикловый сдвиг cycleOffsetDays — переделана после уточнения пользователя.)
7. **Ручной выбор цеха** для артикул-этапа в «План по размерам» → мгновенный пересчёт.
8. **Период закупа ткани на Ганте** — пунктирная линия (кружок=заказ → ромб=склад цеха).
9. **Вкладка «Заказ ткани»** — консолидированный заказ на партию, дата = самая ранняя;
   расход м/шт, образец, № планшета, № цвета; блок «Консолидировано».
10. **Сворачиваемые блоки** во всех листах (шеврон ▾/▸, состояние в сессии).
11. **Комментарий к артикулу** (Данные, показывается в мини-карточках Плана продаж).
12. **Образцы ткани по цветам** — ввод ОДИН РАЗ в Данных (образец 80×40 + № планшета +
    № цвета), автопоказ в «План по размерам», «План продаж», «Заказ ткани» (там только показ).
13. **Автосортировка артикулов по номеру** (числовая, 004<026): сервер при save/load;
    список в «План по размерам»; блоки в «Заказ ткани».
14. **Кнопка «вверх»** (появляется при прокрутке >300px) на всех листах.
15. **Липкое верхнее меню** (sticky) — остаётся видимым при прокрутке.
16. **Стоимость ткани ($/м)** — поле в Данные→Артикулы; в «Заказ ткани» расчёт
    стоимости: колонка по цвету, итог по артикулу, KPI «Стоимость ткани на партию»,
    стоимость в консолидированном блоке (расход и цена берутся из «Данных», в
    «Заказе ткани» только показ; убран редактируемый расход data-fab-per).

## Что пробовали и НЕ сработало (грабли — важно!)
- **Развёртывание на Mac mini: `npm install` намертво зависал.** Долго грешили на puppeteer
  (качает Chromium). Не помогло: `PUPPETEER_SKIP_DOWNLOAD/SKIP_CHROMIUM_DOWNLOAD`,
  `--ignore-scripts` (дал `ENOTEMPTY rename puppeteer-core` из-за битого node_modules),
  `rm -rf node_modules`, `--offline` (`ENOTCACHED`). **Настоящая причина** (нашли через
  `npm install --verbose`): в конфиге npm прописан сломанный ПРОКСИ (вероятно OpenClaw) —
  каждый запрос `ECONNREFUSED`, потом ~70с и отдача из кэша. `curl` до реестра работал (он
  прокси игнорирует). **Решение:** `npm config delete proxy` + `https-proxy` (user и global) +
  `npm config set registry https://registry.npmjs.org/`, затем ставить ТОЛЬКО express в
  изолированной подпапке: `cd planner && npm install --prefer-offline --ignore-scripts` (68
  пакетов за ~0.6с). Отсюда `planner/package.json` (только express, без puppeteer).
- **Порт 8090 занят OpenClaw** → перешли на 8477.
- **Доступ по Tailscale с Windows давал 502 Bad Gateway** — браузер на Windows тоже гонит
  через прокси OpenClaw. Сам сервер доступен (`curl 100.108.217.93:8477/api/health`→401).
  У пользователя настроен `tailscale serve` (OpenClaw) на 127.0.0.1:18789 — НЕ трогали.
  Рабочий доступ — с другого компьютера (без прокси).
- **Basic-auth падал с `ERR_INVALID_CHAR`** из-за кириллицы в заголовке `WWW-Authenticate`
  (realm) → realm заменён на ASCII `"Planner"`.
- **Смещение цикла** — сначала сделали межцикловый сдвиг (неверно понял), пользователь
  уточнил: нужны перекрытия операций ВНУТРИ цикла per-цех → переделали в flowOffsets.
- **SVG-заливки через `var(--cut)`** в presentation-атрибутах в Chromium РАБОТАЮТ (проверено),
  поэтому смена темы перекрашивает Гант автоматически.
- Пользователь несколько раз не видел новые вкладки → код на сервере был старый (`git pull`
  не проходил). Проверка: `curl -s localhost:8477/ | grep -c 'data-tab="salesplan"'` → 1.
- **`position: sticky` для верхнего меню НЕ работал** — меню уезжало вверх (замер
  `topbar.getBoundingClientRect().top` = -276 при прокрутке). Причина: `html, body
  { height: 100% }` в styles.css ломает sticky. **Фикс:** убрать `height: 100%`,
  заменить на `body { min-height: 100vh }`. После — top:0 при прокрутке (липкое).
  Важно: скриншоты puppeteer снимаются от начала ДОКУМЕНТА, а не вьюпорта, поэтому
  проверять липкость надо замером getBoundingClientRect().top, а не скриншотом.

## Команды для проверки
Локально (dev-контейнер; зависимости в корне уже стоят от прошлых сессий):
```bash
# синтаксис
node --check planner/server.js && node --check planner/lib/scheduler.js \
  && node --check planner/lib/model.js && node --check planner/public/app.js \
  && node --check planner/public/gantt.js

# прогон планировщика на сиде (ожидаем: cycles 20 warnings 0)
node -e 'import("./planner/lib/model.js").then(async({defaultState})=>{const{buildSchedule}=await import("./planner/lib/scheduler.js");const s=buildSchedule(defaultState());console.log("cycles",s.cycles.length,"warnings",s.warnings.length)})'

# цена ткани в сиде (ожидаем: у 004 fabricPricePerMeter = 3.6)
node -e 'import("./planner/lib/model.js").then(({defaultState,normalizeState})=>{const a=normalizeState(defaultState()).articles.find(x=>x.id==="004");console.log("004 цена $/м:",a.fabricPricePerMeter)})'

# сортировка артикулов (ожидаем: 004 → 026 → 027 → 031 → 035)
node -e 'import("./planner/lib/model.js").then(({defaultState,normalizeState})=>{console.log(normalizeState(defaultState()).articles.map(a=>a.id).join(" → "))})'

# поднять локально (порт по умолчанию 8090; браузерные проверки делали puppeteer'ом)
PLANNER_PORT=8090 node planner/server.js
```
Браузерные smoke-тесты в сессии писались как одноразовые `_*.mjs` в корне (puppeteer,
Chromium в ./chrome) и удалялись после. Формальных unit-тестов НЕТ.

**Ожидаемое зелёное сейчас:** все `node --check` проходят; планировщик даёт `cycles 20
warnings 0`; сортировка даёт `004 → 026 → 027 → 031 → 035`; сервер стартует; вкладки/матрица/
план продаж/заказ ткани/дашборд рендерятся без ошибок в консоли (единственная безвредная —
404 favicon). Прод (Mac mini): `curl -s -o /dev/null -w "%{http_code}" localhost:8477/api/health`
→ 401 (сервер жив, требует пароль).

## Обновление прода (Mac mini) — давать пользователю после каждого пуша
```bash
cd ~/wb-headless && git pull origin claude/production-plan-twv8ki
git log --oneline -1        # сверить с последним коммитом
cd planner && npm install --prefer-offline --ignore-scripts --no-audit --no-fund && cd ..
launchctl unload ~/Library/LaunchAgents/com.wbheadless.planner.plist
launchctl load   ~/Library/LaunchAgents/com.wbheadless.planner.plist
```
Затем в браузере жёсткое обновление `Cmd+Shift+R`.
