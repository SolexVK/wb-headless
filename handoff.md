# Handoff

## Цель
Инструмент планирования производства одежды под план продаж WB (папка `planner/`):
Гант, партии по цехам, заказ ткани, юнит-экономика, RBAC, контроль сроков. Идёт
большая линия «Производство 2.0» — непрерывный конвейер + «тихий контроль» + спасатель
сроков + правила настила, с прицелом на живую сеть ввода данных (Telegram) и стресс-
устойчивый авто-план. Ветка `claude/production-plan-twv8ki`, деплой на Mac mini (служба
launchd `com.wbheadless.planner`).

## Файлы, над которыми работали (эта сессия)
- `planner/lib/db.js` — таблицы `prod_events`, `responsibles` + помощники (eventAdd,
  eventsForPartia, responsibleList/Set).
- `planner/lib/model.js` — партия: statusDates/expectedReady/snoozeUntil/progress;
  PARTIA_ROLES/OP_ROLE; settings: planningDate, delayThresholdDays, transferDays,
  nesting{minSizeQty,minColorQty}.
- `planner/lib/scheduler.js` — «тихий» контроль отставания (по статусу+датам),
  валидация настила (warnings kind:'nesting'), todayISO/порог.
- `planner/lib/rescue.js` — НОВЫЙ. findRescues: переназначение целиком (заморозка) →
  настил-дробление (splitPartia) → эскалация. Проверочный прогон через buildSchedule.
- `planner/lib/nesting.js` — НОВЫЙ. validateMatrix, splitPartia (цвета→размеры), matrixTotal.
- `planner/lib/permissions.js` — вкладка 'timing' в TABS и в праве записи партий.
- `planner/server.js` — applyProductionEvents (диф партий → авто-штамп статуса +
  события); API /api/responsibles (GET роли+юзеры, PUT), /api/rescue.
- `planner/public/app.js` — вкладка «Контроль сроков» (список внимания + карточка
  спасения), ответственные в «Данные», настройки контроля/настила, кнопка «Разделить
  партию» + предупреждения настила в «План по размерам», клиентские хелперы настила.
- `planner/public/gantt.js` — значок «⏱+Nд» на блоке, ввод факта операций в детальном
  окне (опционально), onProgress.
- `planner/public/index.html` — вкладка «Контроль сроков».

## Что изменилось (смысл)
- Контроль сроков развёрнут на «тишина=ок, система спрашивает по исключениям».
  Сигнал — статус партии (авто-дата) + ручная «ожидаемая дата». Партии в статусе
  «план», просрочившие дедлайн, тоже попадают в «Требует внимания» (там кнопка спасения).
- Спасатель: переиспользует движок расписания как встроенный проверочный прогон —
  принимает вариант, только если помощник успевает И не создаётся новых срывов.
- Настил: 20/400 — мягкие ориентиры; дробление всегда старается быть валидным.
- База: движение — событиями (масштаб под живую сеть), конфиг/план — JSON-блобом.

## Что пробовали и НЕ сработало (грабли — читать!)
- **Пооперационный ручной журнал (первый заход 3a) — тупик.** Сделали ввод дат по
  крой/пошив/утюжка/ОТК на каждую партию. Пользователь верно сказал: это мёртвая
  система, никто вручную вести не будет. Развернули на «тихий контроль» (статус+даты
  авто). Пооперационный ввод остался опциональным «разбором» в окне Ганта. МОРАЛЬ:
  минимизируй ручной ввод, опирайся на то, что уже делается (статус) и на события.
- **Спасатель: «перетасовка» с разморозкой авто-назначений давала «затронуто 16
  партий»** — это по сути полный перепланинг, а не точечное спасение (артефакт: авто-
  партии при повторном прогоне назначаются иначе). Убрали. Оставили ТОЛЬКО чистое
  переназначение с заморозкой (двигаются лишь даты у помощника) + настил-дробление +
  эскалацию. МОРАЛЬ: «минимум возмущения» важнее «оптимальности»; замораживай план.
- **Спасатель редко находит whole-reassign на Aug-1 дедлайне** — это НЕ баг: тесный
  дедлайн, все конкурируют, любой перенос двигает чужую stage1-партию за срок →
  честная эскалация. На дедлайнах с запасом (окт/дек/фев) переназначение находится легко.
- Ветку настил-дробления в спасателе трудно спровоцировать: whole-reassign покрывает
  почти всё; дробление — редкий фолбэк. Это свойство домена, не дефект.
- **Определённость движка**: `Date.now()`/`new Date()` в ядре расписания использовать
  осторожно (для «сегодня» — ок, но помни про недетерминизм в тестах — передавай
  planningDate явно).
- (из прошлых сессий, всё ещё актуально) «бесконечные» партии = мощность пошива цеха
  задана 1 (нормализация Math.max(1,...)); при странных датах сначала проверь мощности.
  `fmt` в gantt.js не показывает год. Новые top-level поля state — не забывать в
  permissions.js applyWritePolicy.
