# Handoff

## Цель
Сделать мост **Telegram ↔ Claude Agent**: пользователь пишет задачи по проекту прямо из
Telegram-чата, бот выполняет их в репозитории через Claude Agent SDK (движок Claude Code —
доступ к файлам, git, командам) и присылает результат обратно в чат. По сути — «Claude Code,
которым управляешь из Telegram».

## Текущее состояние
Реализованы **все четыре тира** плана доработок (Tier 0–3). Код написан, проверен на
синтаксис, покрыт юнит-тестами (13 тестов, все зелёные). План зафиксирован в `ROADMAP.md`,
все пункты отмечены `[x]`.

**Важно:** бот **ни разу не запускался вживую** — в этой среде нет токена Telegram, ключа
Anthropic и выхода к Telegram API. Первый реальный прогон — за пользователем (по `TELEGRAM.md`).

Ветка: `claude/telegram-chat-o45oqz`. Всё запушено. Pull request **не создавался** (ждёт
решения пользователя).

## Что изменилось
- **Tier 0 (надёжность):** опрос Telegram и выполнение задач расцеплены (очередь + воркер);
  встроенная загрузка `.env`; таймаут задачи через `AbortController`; graceful shutdown
  (SIGINT/SIGTERM); персистентная сессия в `.bot-state.json`; обработка 409 Conflict.
- **Tier 1 (UX):** прогресс в реальном времени (события `tool_use` → строки `🔧 …`); `/stop`;
  `/status`; HTML-форматирование ответов с откатом в текст; дневной лимит расходов
  (`DAILY_COST_LIMIT` из `total_cost_usd`); `/model` и `/mode`.
- **Tier 2 (фичи):** подтверждение опасных действий кнопками (`canUseTool` + `callback_query`);
  git-шорткаты `/diff` `/commit` `/push`; приём файлов (document → проект) и `/send <путь>`;
  несколько проектов `/project` (`BOT_PROJECTS`); несколько пользователей
  (`TELEGRAM_ALLOWED_CHATS`) с отдельной сессией на чат; голосовые → текст через
  OpenAI-совместимый STT.
- **Tier 3 (эксплуатация):** always-on (systemd/Docker/pm2); режим webhook
  (`BOT_MODE=webhook` + монтаж в `server.js`); логирование в файл (`BOT_LOG_FILE`, ротация по
  размеру); тесты `node --test`.
- Модуль сделан импортируемым: `main()` под гейтом `IS_MAIN`, чистые функции экспортируются
  (`toHtml`, `chunk`, `summarizeTool`, `loadDotenv`, `parseProjects`, `parseAllowed`) — для тестов
  и для встраивания webhook в server.js.

## Что пробовали и НЕ сработало
- **Изначально неверно поняли задачу.** Первая версия делала Telegram-бота для отчётов MPStats
  (по проекту). Пользователь уточнил: нужен мост, чтобы писать *мне* задачи из Telegram. Урок:
  на «Telegram чат» без контекста — сначала уточнять цель (что и сделали через AskUserQuestion).
- **Claude API (Messages) vs Claude Agent SDK.** Скилл `claude-api` явно НЕ генерирует код Agent
  SDK и покрывает только Messages API/Managed Agents. Messages API умеет только «болтать», не
  править код. Правильный инструмент для «работать над проектом» — **`@anthropic-ai/claude-agent-sdk`**
  (Claude Code как библиотека, `query()` с встроенными Read/Write/Edit/Bash). Не путать с
  Tool Runner из обычного SDK.
- **Версия пакета.** Сначала поставили `^0.1.0` наугад — неверно. Проверили `npm view` →
  актуальная `0.3.205`, зафиксировали `^0.3.205`. Вывод: версии SDK всегда проверять через npm.
- **Формы сообщений SDK — только по типам, не по памяти.** Все шейпы сверяли по
  `sdk.d.ts` из распакованного tarball (`npm pack` → tar): `system/init` → `session_id`;
  `result/success` → `result: string` (у `result/error` поля `result` НЕТ, есть `errors[]`);
  `assistant.message.content[]` с блоками `tool_use` (`name`, `input`); отмена — через
  `options.abortController` (не `signal`); `bypassPermissions` требует
  `allowDangerouslySkipPermissions: true`, иначе ошибка; `canUseTool` возвращает
  `{behavior:'allow'}` или `{behavior:'deny', message}`.
- **`.env` через `node --env-file`.** Отказались: флаг только с Node 20.6+, а `engines` требует
  `>=18`, и падает если файла нет. Сделали свой мини-парсер `.env` без зависимостей.
- **Telegram HTML + разбивка длинных сообщений.** Резать HTML по лимиту 4096 опасно (рвутся
  теги). Решение: форматировать HTML только если ответ влезает в один кусок; иначе/при ошибке
  парсинга — откат в простой текст с безопасной разбивкой по `\n`.
- **Блокирующий цикл (было в первой версии Tier 0).** `await handleMessage` внутри цикла
  `getUpdates` блокировал приём сообщений на время задачи → `/stop` и очередь были невозможны.
  Исправлено расцеплением на два независимых цикла `poll()` и `worker()` через `Promise.all`.
- **Голос (STT).** Claude API аудио не транскрибирует. Настоящий STT требует внешнего сервиса,
  которого в среде нет. Сделали подключаемо: OpenAI-совместимый эндпоинт (`STT_API_URL/KEY/MODEL`);
  если не задан — бот честно пишет, что распознавание не настроено.
- **Webhook в server.js.** Чтобы не рисковать рабочим `server.js` (puppeteer/отчёты), не стали
  переносить логику. Экспортировали `registerExpressWebhook(app)` и добавили в server.js
  маленький опциональный блок под флагом `TELEGRAM_WEBHOOK_IN_SERVER=1`. Проверка окружения там
  НЕ фатальная (не роняет сервер) — в отличие от standalone-запуска.
