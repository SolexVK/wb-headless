# Handoff — Производственный план (planner)

## Цель
Веб-инструмент планирования отшива рубашек: план продаж (детализация размер×цвет) →
партии по цехам → Гант → факт производства → заказ ткани → мультисезон. Развёрнут на
Mac mini пользователя (Tailscale). Ветка: `claude/production-plan-twv8ki`.

## Текущее состояние
- **Работает**, развёрнут на Mac mini как служба launchd. Доступ по Tailscale:
  `http://100.108.217.93:8477` (порт 8477; логин `admin` + пароль из env `PLANNER_PASSWORD`).
- **7 вкладок**: Гант, План по размерам, План продаж, Факт, Заказ ткани, Дашборд, Данные.
- Данные — сид-пример (5 артикулов, 6 цехов, 1 сезон). Реальные цифры пользователь не вносил.
- Всё из запросов пользователя реализовано и проверено (см. «Что изменилось»).
- **Модель перестроена на ПАРТИИ** — это ядро. Старые сохранения мигрируют автоматически.
- **ВАЖНО про деплой:** после каждого пуша давать пользователю полную команду обновления
  (git pull + npm install в planner/ + launchctl unload/load + Cmd+Shift+R). Раньше он не
  видел изменения из-за незапущенного pull.

## Файлы, над которыми работали
- `planner/lib/model.js` — сезоны+этапы+партии; ensurePartias (миграция matrix→partias),
  assignPartiaNumbers (нумерация ПО ЦЕХАМ), нормализация сезонов, цена ткани, seed.
- `planner/lib/scheduler.js` — задания из партий; предпочтительный цех = partia.workshopId;
  cycle несёт partiaNo/status/wbUnits(факт); удалён импорт stageUnits.
- `planner/public/app.js` — весь фронт: партии (renderMatrix), Факт (каскадные фильтры),
  План продаж (карточки по партиям), Заказ ткани (стоимость), сезоны, вставка из буфера,
  экспорт/импорт TSV-шаблона, сортировка, тема, сворачивание, scroll-top.
- `planner/public/gantt.js` — № партии в подписях, отметка выполненных (✓/📦), период
  ткани пунктиром, частые даты на оси (шаг по зуму, вс красным), фильтр по сезону.
- `planner/public/index.html` — вкладки Факт; селектор сезона в шапке; кнопка scroll-top.
- `planner/public/styles.css` — темы, партии/статусы, swatch, matrix-io, season-pick и др.

## Что изменилось (по сути, за сессию)
1. **Переименование цвета** сохраняет количества (во всех партиях) и образец/планшет/№цвета.
2. **Кнопка «Сохранить план»** на «План по размерам».
3. **МОДЕЛЬ ПАРТИЙ** (крупный рефакторинг): `state.partias`
   `{id,no,articleId,stageId,workshopId,planMatrix,factMatrix,status,historical}` —
   источник истины по количествам вместо `article.matrix` (удаляется при нормализации).
   В одном этапе у артикула может быть НЕСКОЛЬКО партий (разные цеха).
4. **Нумерация партий — своя у каждого цеха** (Чоро П1,П2; Ала П1…); авто-партии — отдельная
   группа. Пересчитывается на клиенте (recomputePartiaNumbers) и сервере (assignPartiaNumbers).
5. **Лист «Факт»** — фактические количества по партиям; на WB уезжает факт (cycle.wbUnits),
   производство планируется по плану. Статус+«прошлый период» тут (убраны с «План по размерам»).
6. **Каскадные перекрёстные фильтры на «Факт»**: Этап/Артикул/Цех/Партия зависят друг от
   друга; показываются только партии со сформированным планом (сумма>0); невалидные сбрасываются.
7. **Гант**: № партии в подписях, выполненные партии зелёной рамкой+✓/📦, тултип со статусом
   и «На WB (факт/план)»; более частые даты на оси (шаг зависит от зума, вс красным).
8. **Мультисезон**: `state.seasons` + `stage.seasonId`; селектор сезона в шапке фильтрует ВСЕ
   листы; в Данные — панель «Сезоны» + колонка сезона в этапах; «+ Сезон» добавляет 4 этапа,
   продолжающих календарь (бесшовно).
9. **Ввод плана**: вставка из буфера (Ctrl+V на ячейке) + экспорт/импорт TSV-шаблона
   (ARTICLE/STAGE-блоки, «этот артикул»/«все»).
10. Ранее в сессии: цена ткани ($/м) в Данные → стоимость в Заказе ткани; кнопка «вверх»;
    липкое верхнее меню.

## Что пробовали и НЕ сработало (грабли — важно!)
- **`position:sticky` для верхнего меню НЕ работал** (уезжало вверх, top=-276). Причина:
  `html,body{height:100%}` ломает sticky. Фикс: убрать height, поставить `body{min-height:100vh}`.
  Проверять липкость только замером `getBoundingClientRect().top`, НЕ скриншотом puppeteer
  (он снимает от начала документа, а не вьюпорта — вид обманчив).
- **Проверка фильтра сезона на Ганте дала ложный «не фильтрует»** — измеряли `#gantt .g-cycle`
  на НЕАКТИВНОЙ вкладке (Данные), DOM Ганта был устаревший. Правильно: переключиться на
  вкладку Гант, потом менять фильтр и мерить. После этого — 20 циклов (сезон1) / 0 (пустой сезон2).
- **AskUserQuestion падает** в этой сессии (`AbortError: permission stream closed`) — задавать
  развилки текстом в чате.
- **Ранее (деплой на Mac mini):** `npm install` в корне висел из-за сломанного ПРОКСИ в конфиге
  npm (OpenClaw), не из-за puppeteer. Фикс: `npm config delete proxy/https-proxy` (+global),
  ставить только express в `planner/` (`npm install --prefer-offline --ignore-scripts`).
  Порт 8090 занят OpenClaw → 8477. Доступ по Tailscale с Windows давал 502 (прокси браузера) —
  работать с другого устройства. Кириллица в WWW-Authenticate роняла auth → realm ASCII.
- **SVG fill через `var(--…)`** в Chromium РАБОТАЕТ (тема перекрашивает Гант автоматически).

## Команды для проверки
Локально (dev-контейнер, зависимости в корне стоят):
```bash
node --check planner/server.js && node --check planner/lib/scheduler.js \
  && node --check planner/lib/model.js && node --check planner/public/app.js \
  && node --check planner/public/gantt.js

# планировщик на сиде (ожидаем: cycles 20 warnings 0)
node -e 'import("./planner/lib/model.js").then(async({defaultState})=>{const{buildSchedule}=await import("./planner/lib/scheduler.js");const s=buildSchedule(defaultState());console.log("cycles",s.cycles.length,"warnings",s.warnings.length)})'

# партии: миграция + нумерация по цехам (ожидаем 20 партий, matrix удалён)
node -e 'import("./planner/lib/model.js").then((M)=>{const s=M.normalizeState(M.defaultState());console.log("партий",s.partias.length,"matrix удалён",s.articles.every(a=>!a.matrix),"сезонов",s.seasons.length)})'

# сортировка артикулов (ожидаем 004 → 026 → 027 → 031 → 035)
node -e 'import("./planner/lib/model.js").then(({defaultState,normalizeState})=>{console.log(normalizeState(defaultState()).articles.map(a=>a.id).join(" → "))})'

# поднять локально (браузерные проверки — одноразовыми _*.mjs через puppeteer, chrome в ./chrome)
PLANNER_PORT=8090 node planner/server.js
```
Формальных unit-тестов НЕТ. Браузерные smoke-тесты пишутся как временные `_*.mjs` в корне и удаляются.

**Ожидаемое зелёное сейчас:** все `node --check` проходят; планировщик `cycles 20 warnings 0`;
партий 20, matrix удалён, сезонов 1; сортировка `004 → 026 → 027 → 031 → 035`; все вкладки
рендерятся без ошибок консоли (единственная безвредная — 404 favicon). Прод: `curl -s -o
/dev/null -w "%{http_code}" localhost:8477/api/health` → 401.

## Обновление прода (Mac mini) — давать после каждого пуша
```bash

cd planner && npm install --prefer-offline --ignore-scripts --no-audit --no-fund && cd ..
```

## Открытые вопросы (нужно решение пользователя)
1. **Реальные данные — ЖДУ:** мощности цехов (крой/пошив/утюжка/ОТК шт/день, осн/вспом),
   расход ткани м/шт и цена $/м по артикулам — заменить сид.
2. **«Единый план для всех этапов»?** Пользователь обмолвился, что «на этапе формирования
   плана количества по размерам единые для всех этапов». Сейчас модель хранит ОТДЕЛЬНУЮ
   план-матрицу на каждый этап (как в исходной Google-таблице: 1403→1413→1711→1978). Если
   он имел в виду ОДНУ матрицу на артикул для всех этапов — это другая структура. Я оставил
   по-этапно и предупредил его; он не возражал. Держать в поле зрения.
3. **Импорт партий при нескольких партиях на артикул+этап:** сейчас шаблон грузит в ПЕРВУЮ
   партию (или создаёт). Мульти-партийный импорт (несколько цехов в одном блоке) — не сделан.
4. **Хранение образцов ткани** в state.json (лимит ~1 МБ/файл) — при десятках распухнет.
   На будущее вынести в отдельное хранилище. Не срочно.
