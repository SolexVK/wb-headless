### «Размеры и цвета» — что готово (ЭТА СЕССИЯ)
Блоки показываются в просмотре сохранённого плана («Ранг сезонности» → Часть 2), считаются при
построении плана.

**РАЗМЕРЫ (`sizeAnalysis`) — из ОФИЦИАЛЬНОГО API MPStats.**
- Метод (найден в офиц. репо `github.com/mpstats-io/claude-code-skills`, подтверждён вживую):
  `GET https://mpstats.io/api/analytics/v1/wb/items/{sku}/sales/sizes?d1&d2` → `[{size_name,
  size_origin, sales}]` — продажи по размерам за период. Один вызов = кривая спроса карточки.
- Экономия квоты (у токена ВСЕГО ~150 вызовов!): строгий **ТОП-10** конкурентов (`plan.sizeTopN`),
  кэш `mp_size_sales` в БД **TTL 7 дней** (повторные пересборки = 0 вызовов), **квота-гард**
  (перед батчем `GET user/report_api_limit`; при нехватке раздел не строится, `reason:low-quota`),
  429→ждём `Retry-After` (1 повтор), 4xx не ретраим, интервал 300мс. Окно спроса — свежие 90 дней.
- Движок `computeSizeCurveFromSales`: доля спроса = продажи размера ÷ всех; покрытие = доля
  карточек ТОПа. **Сведение диапазонов**: конкуренты продают то диапазонами («44-46»), то
  одиночными («44»). Одиночные вливаются в накрывающий диапазон (канон ниши) → одна шкала, доли
  =100%. Крайние (низкое покрытие) — в сноску. ONE SIZE — вне сплита.
- Файл `planner/lib/season/mpstatsSizes.js` (клиент + fetchApiLimit + fetchSalesSizesBatch с
  кэшем/квотой), `sizeCurve.js` (движок). Фикстура офлайн: `SIZESALES_FIXTURE_FILE`.

**ЦВЕТА (`colorAnalysis`) — БАЗА = СУММАРНЫЙ ОБЪЁМ продаж цвета.**
- Доли/лидер/количество считаются по **суммарному объёму** (`units`) — реальный спрос. Лидер =
  цвет с макс. объёмом (у пользователя = белый). НЕ по Ср/арт (средняя-на-карточку задиралась у
  цветов с малым числом карточек → ложный лидер «жёлтый»).
- Кол-во: лидер = «Выкупы (прогноз)» (объём одного лучшего цвета, не итог!); остальные =
  прогноз × (units_i / units_best). Общий тираж = сумма (больше прогноза).
- Ассортимент: минимум `seasonColorMinCount` (по умолч. 5) расцветок — сперва надёжные
  (≥3 карточек), затем **⚑ добор** из малоданных. Порог силы `seasonColorMinRel` (40%) расширяет
  сверх минимума. Слабые — «доп.» в сноске. Флаг **▲ эфф** = Ср/арт цвета выше лидера
  (недооценённая ниша). Оба поля живые (без пересборки).
- **Пул цветов — РАСШИРЕННЫЙ**: доли считаются на всём релевантном наборе ДО обрезки лимитом
  группы (для serp — вся выдача `g.items`, кроме исключённых), а не на ТОП-N плана. Бесплатно
  (цвет+продажи уже в выдаче). `colorAnalysis.poolSize/planSize/serpTotal` — охват.
- Файлы: `colorSize.js` (`computeColorShares` + `colorQuantities`), фронт-зеркало
  `seasonColorQuantities` в `app.js` (та же формула, сверяется в node).

### «Ранг сезонности» (кратко — закрыто в прошлых сессиях)
serp-v2 MPStats (1–3 запроса/прогон, кэш `wb_serp`, офлайн `SERP_FIXTURE_FILE`). Отбор
конкурентов (нишевый ключ, минус-стемы, пол, approved/excludedIds). Два режима `articleType`:
`seasonal` / `allseason` (год вперёд + мини-сезоны). Объём «Выкупов» прибит к факту ТОП-1/ТОП-3
(allseason — помесячно), проекция роста cohort/market/none + ручной. Цена = **медиана по ШТУКАМ**
(priceMed), без авто-дрейфа, ручной `priceMultiplier`. Ценовые сегменты (квартили) + целевое окно
от себестоимости через СПП. ТОП-15 с чекбоксами исключения и авто-пересборкой.

## Файлы, над которыми работали (эта сессия)
- `planner/lib/season/mpstatsSizes.js` — НОВЫЙ. Клиент analytics/v1 sales/sizes: fetchSalesSizes,
  fetchApiLimit (остаток квоты), fetchSalesSizesBatch (cache-first, 429/Retry-After, throttle).
- `planner/lib/season/sizeCurve.js` — движок кривой размеров из sales/sizes + сведение
  одиночных размеров в диапазоны + extremeSummary (крайние в сноску).
- `planner/lib/season/colorSize.js` — `colorQuantities` переписан на базу «суммарный объём»
  (units), добор ассортимента из малоданных, флаг efficient.

  (расширенный пул до обрезки лимитом) в collectSerpAll/collectFromCategory/sliceSerpWindow,
  computeColorShares на colorPool + poolSize/planSize/serpTotal.
- `planner/lib/db.js` — таблица `mp_size_sales` + mpSizeSalesLoad/Save (кэш размеров TTL 7д).
  (Осталась и `wb_size_snap` от снятого подхода — не используется, безвредна.)
- `planner/public/app.js` — блоки «Размерная сетка и спрос» и «Цвета: доли спроса и кол-во»
  (колонки Продажи/Доля объёма/Ср/арт/Кол-во, лидер подсвечен, поля «цветов в ассортименте» и
  «порог силы»). `APP_BUILD='season-colors-volume-2026-08-01k'`.
- `planner/server.js` — кэш-бастинг: index.html отдаётся с `app.js?v=<mtime>`, `styles.css?v=`.
- УДАЛЁН `planner/lib/season/wbSizeStock.js` (публичный card.wb.ru-скрапинг — снят, см. грабли).

## Что изменилось (смысл)
Добавлен мини-инструмент раскладки: размеры — из платного, но экономного MPStats analytics/v1
(ТОП-10 + кэш 7д + квота-гард); цвета — доли по суммарному объёму на расширенном пуле артикулов,

## Что пробовали и НЕ сработало (грабли — читать ОБЯЗАТЕЛЬНО!)

- **`node --check` НЕ ловит runtime-ошибки.** Необъявленная `seasonColorMinCount` (использовалась,

- **Кэш браузера держал старый app.js** несмотря на `no-cache` (диск = сборка i, UI = сборка f).
