# Handoff — FBS-аналитика (мульти-тенант веб-сервис для Wildberries)

Ветка: `claude/fbs-fullfilment-branch-cfvgir` · последний коммит: `c5f73e4`.

## Цель
Мульти-тенантный веб-сервис аналитики FBS (Fulfillment by Seller) для Wildberries.
Крутится на Mac Mini, доступен через Tailscale+Caddy по адресу
`https://mac-mini-vital.tail13d29e.ts.net/fbs/` (сейчас — ПРИВАТНО, только внутри
tailnet; см. открытые вопросы). Каждый продавец подключает свой кабинет (WB
API-токен), сервис считает отчёты по его FBS-фулфилментам. Весь UI и ответы — на
русском. Код сервиса — в `service/`, пайплайны/скрипты отчётов — в `scripts/`.

Отчётов **5**: Подсорт, Остатки, Движение заказов, География, Логистика.
Вкладки: Остатки → «Текущие / Динамика»; Логистика → «Сборка / Доставка / Путь
возврата»; География → «Регионы / По ФФ отгрузки».

Известных багов нет. Тесты все зелёные.

## Файлы, над которыми работали (эта сессия — «Динамика»)
- `service/models.js` — `ReportRuns.stockSeries(cabinetId,{days})`: по дням берёт
  последний снимок остатков → ряд {dates, warehouses[{name,values}], grand}
  (+ query `runsDataByReport`).
- `scripts/lib/agg/stock.mjs` — НОВЫЙ. `stockMetrics(series)`: текущий/дельта/

  stockMetrics. Также карточка «Остатки» на витрине упоминает «Динамику».
- `scripts/lib/report-interactive.mjs` — рефактор тултипов в `attachTips(root)`;
  новый блок для `.dyn[data-dyn]`: клиентская перерисовка SVG с пересчётом
  масштаба, чипы `data-li`, `data-dyn-all` (показать все), `data-dyn-none`
  (скрыть все). CSS чипов (`.dyn-chip`).
- `scripts/fbs-stock-dynamics-dashboard.mjs` — НОВЫЙ. HTML/PDF-дашборд динамики
  (dashboard-kit `lineChart`); книжная ориентация (`@page portrait` override),
  плашки ФФ + дни до 0, таблица.
- `service/reports.js` — маршрут страницы отдаёт `series` при `tab=dynamics`;
  новый маршрут `/reports/stock/dynamics/download/{html,pdf,json}` (404 при <2
  снимках); импорт `buildStockDynamicsHtml`.
- `service/reports-runner.js` — `buildStockDynamicsHtml(cabinet, series)` через
  genArtifact + новый dashboard-скрипт.
- `service/smoke-agg.mjs` — юнит-тесты `stockMetrics` (тренд, дни до 0, вырос/
  просел, риск; 10 проверок с ручным счётом).
- `service/smoke-reports.mjs` — e2e динамики: подсказка при <2 снимках, «состаривание»
  снимка на день назад (прямой SQL через `node:sqlite`) → реальный график,
  чипы/«Показать все»/«Сбросить все», колонка «Дней до 0», выгрузки, отсутствие
  старых пустых плашек.

## Что пробовали и НЕ сработало (грабли — читать обязательно)
1. **«Ничего не открывается» = НЕ сервер, а клиент (Tailscale).** Диагностика
   показала: Mac и все сервисы живы (FBS `:9110/healthz=200`, Caddy `:9000/fbs=200`,
   `tailscale serve` цел). Причина — на Windows-машине `tailscale status` = «Logged
   out»: узел вышел из tailnet → браузер не достаёт `*.ts.net`. Лечится `tailscale
   up` (перелогин) на Windows. Прокси был НЕ виноват — исключение
   `ProxyOverride=…;100.*;*.ts.net` на месте. Метод: сначала curl с самой Mac по
   localhost (минуя сеть) — если 200, сервер жив, значит клиент/сеть. Прошлая
   грабля (Windows system-proxy рубит не-443) в этот раз ни при чём.
   ВАЖНО про природу адреса: `tailscale serve` = «tailnet only» (в выводе так и
   написано) — это ПРИВАТНЫЙ доступ только для устройств в твоём tailnet, НЕ
   публичный. Чтобы открыть всему интернету — нужен `tailscale funnel` (см. откр.
   вопросы). Чтобы Windows не выкидывало — в админке Tailscale отключить key expiry.
2. **PDF-зависание ~55с (регресс из P2c, исправлен).** Свежий `--user-data-dir`
   в headless Chrome на macOS/launchd → запрос доступа к Keychain висит до
   таймаута. Не задавать свой user-data-dir; используем профиль по умолчанию +
   `--use-mock-keychain`. `--landscape`/`--portrait` во флагах html-to-pdf.mjs
   ИГНОРИРУЮТСЯ (он фильтрует `--`-аргументы) — ориентацию PDF задаёт ТОЛЬКО
   `@page` в CSS страницы. Поэтому книжную ориентацию динамики сделали через
   `<style>@page{size:A4 portrait}</style>` в body дашборда (переопределяет
   landscape из dashboard-kit). Проверять ориентацию по `MediaBox` в PDF
   (portrait ≈ `[0 0 595 842]`, landscape ≈ `[0 0 842 595]`).
3. **cwd в `service/` после `cd service`** ломает `node --check scripts/...` и
   `git add scripts/...` (MODULE_NOT_FOUND / pathspec). Всегда возвращаться в
   `/home/user/wb-headless` (или абсолютные пути).
4. **`node --check` не проверяет встроенный клиентский JS.** `INTERACTIVE_JS` —
   это строка внутри модуля; чтобы проверить её синтаксис, пишу строку в .js файл
   и `node --check` его. Внутри строки нельзя backtick/`${` (там template literal
   модуля) — только конкатенация и одинарные/двойные кавычки; backslash в regex
   экранировать как `\\`.
5. **Тест «динамики» требует ≥2 снимков в РАЗНЫЕ дни.** Два refresh в один
   UTC-день схлопываются в 1 точку (byDay). В smoke «состариваю» один снимок на
   день назад прямым SQL (`node:sqlite` к `process.env.DB_PATH`), не трогая
   API моделей.
6. **Разные графики — разные классы.** Страница использует `mvChart`
   (class `mv-chart`, в views), PDF-дашборд — `lineChart` (class `linechart`, в
   dashboard-kit). При проверках/ассертах не путать.
7. **`diff -q` по несуществующему файлу = «отличается»** (ложная тревога по
   `xl/sharedStrings.xml` — openpyxl его не создаёт). Авторитетна `diff -rq` по
   распакованным .xlsx; расхождение только в `docProps/core.xml` = таймстемп.
8. **smoke-reports проверяет вхождение строк** — при смене заголовков/подписей
   синхронизировать ассерты (ловили при переименовании h1 логистики и удалении
   плашек «период/снимков» в динамике).

## Открытые вопросы (нужно решение пользователя)
- **Публичный доступ (funnel) vs приватный (serve).** Сейчас сервис ПРИВАТЕН —
  `tailscale serve`, только устройства в tailnet. Пользователь решил: внешних
  пока НЕ пускаем; при переезде на виртуальный сервер настроим публично там. То
  есть funnel сейчас НЕ включаем — решение принято, вопрос закрыт до переезда.
- **Days-to-OOS — грубая оценка.** «Дни до нуля» считаются линейно по тренду
  периода (first→last), не учитывают всплески/дозаказы. Если понадобится точнее —
  можно взять скорость только по убыванию или скользящее среднее. Не блокер,
  помечено как «≈» в UI. Улучшать только по запросу.
- Прочие развилки прошлых итераций (P3a двойной рендер, P3c легаси-CLI) — решены
  «оставить как есть».
