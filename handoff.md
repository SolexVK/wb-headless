### «Ранг сезонности» (serp-v2) — что готово
Раздел строит по конкурентам: ранг сезонности + прогноз продаж (объём, цена, поставки) на
будущий период, копит планы (Часть 2). Всё на MPStats **serp-v2** (1–3 запроса/прогон, кэш в БД,
офлайн-тесты через `SERP_FIXTURE_FILE`). Лимит MPStats 150/день — жёстко экономим.

**Отбор конкурентов:** нишевый ключ (4-символьный корень); минус-слова по стему; фильтр по полу;
«Предв. выбор» (approvedIds) и исключение из ТОП-15 чекбоксами (excludedIds, авто-подтягивание
следующего + пересборка из кэша).

**Два режима товара (`plan.articleType`):**
- `seasonal` — разгон-с-нуля → сезон → распродажа в ноль (лёгкий муслин/марлёвка).
- `allseason` — круглогодичный (полоска/клетка): год вперёд, сезонный пик → мягкий спад →
  межсезонная база (склад не обнуляется); мини-сезоны (НГ, 14/23фев, 8мар); ровный помесячный
  подсорт. Авто-подсказка типа по амплитуде рельефа (`seasonalityHint`).

**Объём «Выкупов»:**
- Форма кривой — синтетическая; ИТОГ прибит к факту: продажи ТОП-1/ТОП-3 за аналогичный период.
- `allseason` — ПОМЕСЯЧНО: у каждого месяца свой топ-3 (лидеры меняются) → сумма 12 целей.
- Проекция роста: `growthMode` `cohort` (по умолч. для allseason — рост карточки, без новичков) |
  `market` (агрессивно) | `none`; ручной коэффициент `growthManual`. Зажат [0.5, 2.0]/ручн.[0.5,3.0].
- Уровень ТОП-3/ТОП-1 = скорость лидеров по выручке ÷ активные дни за год.

**Цена (важно, много итераций):**
- Цена продажи конкурента = **медиана, взвешенная по ШТУКАМ** (цена, ниже которой продано 50%
  годовых штук) — не по дням (медиана по дням занижала сильных продавцов, проверено на AIDEMIKO:
  1549 по дням vs 2321 по штукам). Это ЦЕНА ПОКУПАТЕЛЯ (с СПП), как отдаёт MPStats.
- Цена в плане по дням = якорь (медиана выборки) × сезонный профиль × **ручной `priceMultiplier`**
  (по умолч. 1.0). Авто-дрейф год-к-году (priceAdj) к цене НЕ применяется (год-к-году цены не
  коррелируют с ростом) — показан подсказкой. `priceUndercut` — подрезать под медиану (0 по умолч.).

**Ценовые сегменты + себестоимость (связка с юнитом):**
- Выборка бьётся на 4 квартиля по priceMed (Дешёвый/Средний/Высокий/Премиум) — карта рынка.
- **Целевое окно подбора конкурентов:** приоритет — ЯВНО выбранный сегмент; иначе «от
  себестоимости»: `себест × наценка(×от..×до) = бухгалтерская цена`, `× (1−СПП%) = цена
  покупателя` → фильтр конкурентов в этом окне → на них весь расчёт. «Авто» сегмент → окно от
  себестоимости.
- Модель цен WB: базовая − скидка_продавца = БУХГАЛТЕРСКАЯ (от неё юнит) − СПП = ЦЕНА ПОКУПАТЕЛЯ
  (MPStats). Сегменты — по цене покупателя; выгодность — по нашей бухгалтерской = покуп/(1−СПП).
- Себестоимость (`cost`) + наценка (`markupMin/Max`) + `spp` — все поля вручную. В карте сегментов:
  цена покупателя, наша расчётная, наценка, viable ok/thin/loss, целевое окно помечено 🎯.

**ТОП-15 конкурентов:** фото, метрики за год, оборачиваемость, разброс цены мин–макс, чекбоксы
исключения с авто-пересборкой.

## Файлы, над которыми работали (весь блок сезонности)
- `planner/lib/season/wbSerp.js` — serp-v2 клиент (фикстура-first).
- `planner/lib/season/seasonPlanReport.js` — ядро: gatherSerp (медиана по штукам priceMed +
  priceLo/Hi), collectSerpAll (approvedIds/excludedIds), computePriceSegments (сегменты+СПП+
  наценка+viable), целевое окно (сегмент/себестоимость), seasonTargets (объём помесячно+рост).
- `planner/lib/season/forecast.js` — buildEngineeredSeason (сезон), buildAllSeasonYear
  (круглогодичный+мини-сезоны), priceMultiplier (авто-дрейф убран), seasonalityHint.
- `planner/lib/seasonApi.js` — проброс всех cfg → plan (articleType, growthMode/Manual,
  priceSegment, cost, markupMin/Max, spp, priceUndercut, priceMultiplier, approved/excludedIds).
- `planner/public/app.js` — конструктор (все поля), карта сегментов, ТОП-15 с чекбоксами и
  разбросом, подписи «Выкупы»/«Цена», авто-пересборка исключений. `APP_BUILD='season-price-2026-08-01c'`.
- `planner/public/styles.css` — стили сегментов/чекбоксов.

## Что изменилось (смысл)
Сезонность доведена до продакшена: точная привязка объёма к факту лидеров + рост когорты;
цена — по реальной цене продажи (медиана по штукам), без авто-дрейфа, с ручным множителем;
ценовые сегменты и целевое окно от себестоимости через СПП (связка с юнит-экономикой);
интерактивный отбор конкурентов (исключение из ТОП-15 с пересборкой). Круглогодичный режим
рядом с сезонным.

## Что пробовали и НЕ сработало (грабли — читать!)
- **Жгли лимит MPStats тест-скриптами** — НИКОГДА при разработке. Только офлайн через
  `SERP_FIXTURE_FILE=<scratchpad>/srt.json` (реальная выдача муслина, 200 тов × 730 дн).
- **AskUserQuestion дважды перебил пользователя** — для развилок в этой теме вопросы ТЕКСТОМ.
- **Ценовой фильтр/undercut: 0 ≠ «нет».** priceUndercut/spp=0 трактуются как «без скидки»; в
  тестах не передавай 0 как «нет ограничения» цены (режет всё) — используй null.
- **Медиана цены ПО ДНЯМ занижала сильных продавцов** (много малообъёмных скидочных дней) →
  перешли на медиану ПО ШТУКАМ. Медиана устойчива к сливам (пока <50% объёма).
- **priceAdj (авто-дрейф цен) завышал** прогнозные цены (× сезонный профиль). Убрали из цены,
  заменили ручным множителем.
- **Приоритет сегмента vs себестоимости:** окно от себестоимости молча перекрывало ручной выбор
  сегмента → смена сегмента «не работала». Исправлено: явный сегмент > себестоимость > авто.
- **«36361» сезонного из ранних тестов** — артефакт устаревшего кэша `wb_serp`; на актуальных
  данных сезонный муслин = 17088 (рост когорты по отобранным ~1.2, а не «рынок 1.79»).
- **Деплой Mac mini:** planner на порту **8477** (не 8090 из шаблона plist — порт в plist на
  машине). Funnel держать `tailscale funnel --bg 8477`; после pull — `launchctl kickstart`;
  автологин обязателен (агент пользователя).
