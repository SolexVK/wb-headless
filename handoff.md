## Цель
Каскад инструментов для WB: **[1] ТОП по фразе → [2] Сравнение карточек → [3] Конкурентный
анализ**. Сцепляются общим JSON-контрактом (ключ `nmId`). Правило: наш артикул ВСЕГДА
спрашиваем у пользователя; конкурентов даёт [1] или пользователь вручную. Итог [3] —
многоблочный отчёт (A–H + воронка + авто-принадлежность F3) + план доработки карточки.
Архитектура и контракты — `docs/pipeline/README.md`.

  выкупы=заказы×36%. Колонки: цена продажи / медиан.цена / артикулов / доля выручки / выкупов-SKU /
  рейтинг / маржинальность / опер.прибыль-SKU / прогноз опер.прибыль-SKU.
- **D. Доминирующие цвета (базовые)** — по всей базе MPStats (`allItems`), схлопывание к базовому
  цвету (`base_color`/`BASE_COLOR_RULES`); ряд: [цвет | диаграмма 50% | метрики 30%: доля·артикулы·
  сумма заказов ₽]. **С новой страницы в PDF** (класс `pgbreak`).
- **E. Контент-бенчмарк** (по 20 SKU) — медиана топа + лидер (только значение) + «Ваше»; метрики

- **Листинг топов (слайды)** — по 10 слайдов на карточку с подписью-номером; шапка 2 строки

- **F2. Готовые данные** — теги-смыслы (хвосты) + таблица характеристик топов со столбцом «Доминанта».

- **F3. Принадлежность признаков топа (АВТО)** — новинка: % присутствия значений характеристик у топа,

- **G. Ваша карточка против ниши** — гэпы своей карточки. **С новой страницы в PDF** (`pgbreak`).
- **G2. Воронка [2]** — наш vs конкуренты; фото+артикул(ссылка)+бренд; планка (медиана); строка
  «Отставание Δ» пастельно-красным; вороночные гэпы в план.
- **H. План доработки** — гэпы + цели ниши + «Ручные задачи». Пункты с авто-данными помечены
  кликабельными ✅-чипами-якорями (→ F2/F3/Листинг). «Полки/доска» и «ДЖЕМ-конверсии» удалены.

## Что изменилось (эта сессия)
- **[4] Юнит-калькулятор — новый инструмент.** По запросу «ЮНИТ КАЛЬКУЛЯТОР» вынес подтверждённую
  модель юнит-экономики (первоисточник — `references/analysis-workflow.md`, раздел «Юнит-экономика»;
  то же ядро, что в блоке C движка [3]) в самостоятельный модуль `lib/wbUnitCalc.js` + CLI. Модель:
  `S` — цена продавца без СПП, `P` — витрина с СПП (`P=S·(1−СПП)`); комиссия 35,7% от S; эквайринг
  4,7%, налог 2%, ДРР 30%/8% от P; брак 2,5% от себестоимости; логистика+хранение 0 (индивид.).
  Маржа = опер. прибыль/S. Выдаёт: раскладку на единицу, ценовой коридор под маржу, точку
  безубыточности (рабочую + в запуске), обратный расчёт (цена под маржу/прибыль), таблицы
  чувствительности (цена/ДРР), прогноз за период. Совпало с эталоном из БЗ (C=536 → безубыт. 1051 ₽,
  коридор 2094–2613 ₽). HTML/PDF-отчёт через `lib/htmlToPdf.js`.
- **Telegram-бот для интерактивного ввода.** По запросу «вводные через интерактивные сообщения в
  Телеграме». Отдельный процесс на long-polling (публичный URL не нужен, работает через исходящий
  HTTPS-прокси). Пошаговый диалог себестоимость→цена→ДРР, быстрый ввод «536 2400 8» и key=value
  (рус. синонимы), inline-кнопки (цена под маржу / ДРР / PDF / новый расчёт), PDF-отчёт документом.
  Логика диалога — чистый reducer `lib/wbUnitBot.js`, покрыт офлайн-сценариями (без токена).
- **Комиссия отображается с десятой (35,7%, не 36%)** — `fmtPct1` в местах, где ставка выводится.

## Что пробовали и НЕ сработало (важно, не повторять)
**Эта сессия ([4] + бот):**
- **`AskUserQuestion` снова рвётся («Tool permission stream closed before response received»)** — как и
  прошлые сессии. Развилки задавал текстом, пользователь отвечал свободной строкой. Не полагаться на этот
  инструмент в этом окружении.
- **Скрипт-скриншотер в `scratchpad/`** не видит `node_modules` проекта (`ERR_MODULE_NOT_FOUND: playwright`)
  — резолвинг модулей идёт от каталога скрипта. РЕШЕНИЕ: класть временный `.mjs` в корень репозитория
  (там `node_modules`) и удалять после прогона.
- **PDF (`--pdf`) на свежем контейнере падает** — `playwright` не установлен (`Cannot find package
  'playwright'`). Ожидаемо: нужен `npm install`. CLI это ловит и подсказывает; после install PDF ~78 КБ, ОК.
- **Живьём Telegram-бот НЕ проверен** — в сессии нет `TELEGRAM_BOT_TOKEN`, соединение с `api.telegram.org`
  не гонял. Проверен только reducer офлайн (6 сценариев). При возобновлении — поднять с реальным токеном.

**Прошлые сессии ([3]):**
- **Картинки в PDF через сеть Chromium** — из 75 `<img>` в PDF попадало только 13: basket-CDN картинки
  с `loading="lazy"` «ниже сгиба» не догружались при печати. Полумеры (`--virtual-time-budget`) ненадёжны
  через прокси. РЕШЕНИЕ: вшивать картинки как `data:URI` (см. `inline_images`).
- **Вшивание full-res `big`-картинок** → PDF раздулся до **95 МБ**. Локального ресайза нет (нет ImageMagick/
  Pillow). РЕШЕНИЕ: качать компактный вариант basket `c246x328` (тот же CDN) — PDF ~10 МБ, качество для
  печати достаточное.
- **`section{break-inside:avoid}` в print** — целая высокая секция прыгала на новую страницу, оставляя
  большие пустоты. РЕШЕНИЕ: `break-inside:auto` на секции + `break-inside:avoid` только на «атомах»
  (`.lcard`, `tr`, `.callout`, `figure.slide`, `.crow`), `thead{display:table-header-group}`.
- **Столбец «Доминанта» через `position:sticky;right:0`** — в PDF (`overflow:visible`) пинился к краю
  страницы и накрывал последний столбец топа, оставляя пустой слот. sticky для печати бессмыслен.
  РЕШЕНИЕ: `table-layout:fixed;width:100%` — «Доминанта» становится обычным видимым последним столбцом.
- **`overflow-wrap:anywhere` на заголовках** таблицы характеристик рвал «ХАРАКТЕРИСТИКА» посреди слова.
  Ограничили перенос только значениями (`td`), заголовки — целыми словами, первому столбцу дана ширина.
- **Ранее (прошлые сессии, всё ещё актуально):** natural-breaks сегменты (→ 1 огромный + хвосты по 1 арт,
  вердикт цеплялся за выброс) → равные квантильные + порог ≥2 арт; сегменты по витринной цене → по цене
  продажи (`sale_price_of`); `wb_basket_host` обрывался на vol 5189 → экстраполяция + перебор соседей;
  hover-зум на `transform:scale` обрезался контейнером → floating JS-превью; период off-by-one → фикс
  date-math + явный `--period-label`; `AskUserQuestion` рвался («stream closed») → развилки текстом.
