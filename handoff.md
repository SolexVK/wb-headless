# Handoff — Производственный план (Этап 3)

## Цель
Инструмент планирования производства одежды. Связка: **Ранг сезонности (прогноз спроса)
→ План по размерам (матрицы цвет×размер по довозам) → Диаграмма Ганта (расписание по цехам)**.
Ключевая идея Этапа 3: динамические довозы (партии-поставки по датам прихода на WB) вместо
фиксированных этапов; объёмы/тайминг производства вытекают из кривой сезонности; сезонный подбор
цветов по месяцам; и учёт уже существующего товара (остатки/в пути/производство) через неттинг.

Приложение: vanilla-JS ES-module SPA (`planner/public/app.js`) + Node/Express бэкенд
(`--experimental-sqlite`). Крутится на Mac mini пользователя, порт **8477** (`PLANNER_PORT=8477`),
наружу через Tailscale Funnel. Ветка: `claude/production-plan-twv8ki`.

## Текущее состояние
Всё задеплоено и работает. За эту сессию сделано (по порядку):
1. **Помесячный анализ цветов** на «Плане по размерам» (из дневных графиков конкурентов, поле
   `report.colorAnalysisByMonth`). Полосы-тиры (зелёная ≥5% / жёлтая 3–5% / красная <3%), только %,
   сортировка по убыванию, опережение (окно продаж), умное сопоставление рынок↔мои цвета
   (джинса↔синий, хаки↔зелёный), все цвета артикула, коллизии канонов помечены.
2. **Сезонные цвета по довозам** (ранее в сессии): чипы вкл/выкл, тираж делится между включёнными
   довозами; выключенный цвет исчезает из таблицы размеров.
3. **Авто-подбор цветов по месяцам** — кнопка: по окну продаж каждого довоза выключает цвета <3%,
   сохраняет свои нишевые. Окно = все месяцы, которые довоз закрывает (partiaCoverage).
4. **Перекомпоновка «Плана по размерам»** + блок «🎨 Подбор цветов для довоза» (селектор довоза +
   жирная строка «Шить … → Продажи с … <месяцы>»; даты пошива обратным счётом по мощности цеха).
5. **Безопасный повторный перенос из прогноза** + значок синхронизации («✓ синхронизировано» /
   «⚠ прогноз пересобран — обнови перенос»). Замена только forecast-партий, ручные не трогаются.
6. **НЕТТИНГ (Фаза 1)** — новое: `state.supplies` (остатки/в пути/склад/производство), модуль
   `lib/supply.js`, живой слой в планировщике (к производству = план − покрытое), вкладка «Остатки
   и поставки» (CSV/Google-CSV/шаблон), маркеры прихода на Ганте.

Текущие билды (после деплоя должны совпасть):

## Что изменилось (по сути)
- **Помесячные цвета:** из уже собранных дневных графиков конкурентов (0 доп. сети) считаются доли по
  цвету за каждый календарный месяц. На «Плане по размерам» окно продаж довоза = от его прихода на WB
  до прихода следующего довоза (последний — хвост 2 мес). Ключуемся от даты прихода (= старт продаж),
  поэтому «шьём раньше — продаём позже» учтено само.
- **Неттинг (Фаза 1):** `supplies` = записи предложения (source: wb|transit|prod_stock|in_production,
  matrix цвет×размер, availableOn). `computeSupplyNetting` хронологически гасит довозы предложением,
  доступным к их дате (пул переходит вперёд), к производству = план − покрытое (Хэмилтон),
  `planMatrix` не трогаем. Цвета предложения сводятся к цветам артикула канон-нормализацией;
  несопоставленные → `unmatched`. Планировщик и заказ ткани работают на нетто.
- **Ввод остатков:** вкладка «Остатки и поставки» — CSV-вставка, шаблон CSV (все артикулы×цвета×
  размеры), импорт Google-CSV по ссылке (бэкенд-прокси). Импорт заменяет прежние записи того же
  (артикул+статус). Дата пустая → авто-дефолт по лид-таймам.
- **Гант:** производство уменьшено неттингом; вверху маркеры прихода (цвет по источнику, `+объём`,
  подсказка). Гант рисуется по ЦЕХАМ (не по артикулам) — поэтому предложение показано маркерами на
  шкале, а не отдельной строкой-артикулом.

## Что пробовали и НЕ сработало (грабли — читать перед работой!)
- **«Живучесть» сервера на 8477 (ГЛАВНЫЕ грабли).** На Mac mini сервер под супервизором
  (launchd/pm2/nodemon). Деплой бэкенда: `git pull` → `lsof -ti tcp:8477 | xargs kill -9` → супервизор
  сам поднимет НОВЫЙ код за пару секунд. Ручной `node server.js` НЕ запускать (словит EADDRINUSE — это
  норма). **Диагностировать ТОЛЬКО по `backendBuild` в `/api/health`**, не по тексту ошибки.
- **Циркулярный вес при сезонных цветах:** нельзя брать вес довоза из текущего объёма партии на лету
  (выключил цвет → объём упал → вес поплыл). Решение — стабильный `partia.deliveryShare`, зафиксирован
  лениво из объёма ДО правок цветов.
- **Коллизия канонов цвета:** «джинса» и «синий» оба → канон «синий»; старый `Map`-подход молча терял
  один. Решение — блок цветов пере-ориентирован на цвета артикула; коллизии помечаются «рынок общий».
- **normColor уже умнее, чем казалось:** джинс→синий, хаки→зелёный, шоколад→коричневый уже в словаре
  `public/colorNorm.js`. Не дублировать.
- **Новое поле отчёта требует пересборки плана:** `colorAnalysisByMonth` появляется только после
  «Построить план» заново; для старых планов панель показывает подсказку о пересборке. Кэши на фронте
  (`matrixColorMonthly`, `matrixForecastStamp`) сбрасываются при пересборке.
- **Гант по цехам, а не по артикулам:** нельзя нарисовать предложение как «строку артикула» — сделаны
  маркеры на шкале. Если в Фазе-доработке захотят отдельную строку прихода — это заметная переделка
  layout gantt.js.
- **zsh + многострочная вставка с кавычками/эмодзи** (`dquote>`): пользователю давать ОДНОСТРОЧНЫЕ
  команды без двойных кавычек и эмодзи.
