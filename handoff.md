## Цель
Довести до ума раздел **«Ранг сезонности»** планировщика: по предмету WB собрать
конкурентов-аналоги, точно отфильтровать релевантные (плюс-/минус-слова, строгий ключ,
ручная дочистка «неопределённых»), построить ранг сезонности и прогноз плана продаж.
Ключевая боль пользователя: фильтр **сильно резал и оставлял нерелевантное** — надо, чтобы
плюс-слова **уточняли** нужные артикулы, а минус-слова **убирали** ненужные, без ложных
срабатываний. (Публичный доступ + Telegram-авторизация + RBAC + мобильная адаптивность —
предыдущие блоки, ЗАКРЫТЫ и подтверждены.)

## Текущее состояние
Работает и запушено:
- **Пословный (whole-word, по стему) матч фильтра** вместо подстрочного. «лен» больше не
  ловит «ма**лен**ький/зе**лён**ый». Плюс-слова = «любое из» (уточняют + дают `_relevance`),
  минус = «любой исключает», при конфликте форм одного стема плюс имеет приоритет.
- **Русский стеммер** дополнен окончаниями прилагательных `ых/их/ым/им`, чтобы
  `длинный/длинным/длинных` сходились к стему `длинн`.
- **Полная выдача предмета** (не топ-180): `collectFromCategory` тянет все страницы
  (`endRow=5000`, `maxPages≤8`), обогащает до `MAX_ENRICH=1200` карточек WB.
- **Словарь признаков** (`buildFeatureDict`): гармошка +/− по группам характеристик WB.
- **«Неопределённые»** (без плюс/минус) — ручная дочистка с превью/зумом/чекбоксами,
  форс-включение через `includeWb`.
- **Расширенный лог** всех этапов + кнопка выгрузки `.txt`, комментарии-статусы под блоками.
- Обогащение карточек — из **бесплатного** `card.json` WB CDN (title+описание+характеристики),
  без расхода квоты MPStats; кэш на диске 30 дней (`data/wb-cache/cardinfo/`).

Проверки зелёные (см. ниже). На Mac mini нужен рестарт службы + жёсткое обновление страницы,
чтобы подтянулся билд `…-24j`. **Реального прогона на живой выдаче после этого фикса ещё не
было** — пользователь должен прислать новый `seasonlog.txt` для сверки, стал ли фильтр
отсекать меньше и релевантнее.

## Что изменилось (по сути)
1. Матч фильтра: **подстрока → целые слова по стему**. Устранены ложные срабатывания на
   коротких словах внутри других слов.
2. Разделение зон матча: **минус/строгий ключ — только по характеристикам** (`cardCharText`,
   без описания, чтобы не переисключать), **плюс/релевантность — по полному тексту**
   (`cardMatchText`: title+subj+описание+характеристики).
3. Плюс-приоритет: `exclVals = valueStemList(exclude).filter(vs => !plusKey.has(vs.join(' ')))`
   — если тот же стем есть и в плюсах, минус его не режет.
4. Стеммер собирает словоформы прилагательных вместе (ых/их/ым/им) — раньше формы
   рассыпались между плюс- и минус-списками.
5. Сбор — **вся выдача предмета** + обогащение до 1200 карточек (было 180), поэтому фильтр
   видит не только топ по выручке.

## Что пробовали и НЕ сработало (важно!)
- **Подстрочный матч (`text.includes(stem)`)** давал ложные срабатывания: «лен» → «маленький»,
  «зелёный»; «хлопок» ловил части чужих слов. → Перешли на `wordStemSet`: бьём текст на слова
  `split(/[^a-zа-я0-9]+/)`, стемим каждое, сравниваем множества стемов. Матч только по ЦЕЛОМУ слову.
- **Стеммер ронял конфликт форм.** `stem('длинным')` возвращал `длинным` (в `RU_ENDINGS` не было
  `ым`), а `stem('длинный')` → `длинн`. Плюс-приоритет по точному стему не срабатывал, товар
  ошибочно исключался (падал тест wordmatch #5). → Добавили `ых/их/ым/им` в `RU_ENDINGS`
  (2-символьные, после 3-символьных, т.к. матч по первому подходящему). Теперь формы сходятся.
- **Минус по полному описанию переисключал.** Раньше exclude матчился по `cardMatchText`
  (с описанием) — длинные маркетинговые описания случайно содержали минус-слова, выборка
  схлопывалась в 0. → Минус и строгий ключ считаем по `cardCharText` (title+характеристики).
- **Строгий ключ жёстко ронял товары без карточки.** Если card.json не подтянулся — товар
  выпадал даже будучи релевантным. → Фолбэк на имя товара; если ВСЕ карточки не пришли —
  фолбэк на старый матч по имени (не оставляем пользователя с пустой выборкой).
- **enrichCap=180** — фильтровали только топ-180 по выручке из 76 795 в предмете (в сегменте
  ~3 722), поэтому «принято 10–76» — не баг фильтра, а недосбор. → `MAX_ENRICH=1200`,
  тянем все страницы, убрали ранний deep early-stop.
- **NLP-библиотеки для стемминга/лемматизации не берём** — на Mac mini лишняя сборка/трение.
  Свой лёгкий `stem()` + группировка по характеристикам WB достаточны.
- **Grale деплоя (в силе):** обновления не видно на Mac mini ⇒ (1) браузер кэшировал app.js/css —
  анти-кэш + Cmd+Shift+R и сверить `APP_BUILD` в консоли (`…-24j`); (2) служба Node не
  перезапущена — ОБЯЗАТЕЛЬНО `launchctl kickstart -k gui/$(id -u)/com.wbheadless.planner`
  после git pull (держит lib/*.js в памяти); (3) сохранённые планы держат старый forecastDaily —
  кнопка пересборки.
- **`cd planner` у пользователя часто падает** — он УЖЕ внутри `planner/`. Команды давать без `cd planner`.
- **`ERR_TUNNEL_CONNECTION_FAILED`** у пользователя был клиентский (VPN/прокси), не сервер:
  `curl` Funnel с Mac mini отдавал 200. Проверять с телефона/мобильного интернета.
