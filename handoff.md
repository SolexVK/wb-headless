# Handoff — Анализ ниши Wildberries

## Цель
Инструмент оценки ниши/категории WB по данным MPStats: ёмкость, сезонность, тренд, конкуренция,
насыщенность → скоринг 0–100 и вердикт «заходить/осторожно/не заходить» с заключением на цифрах.
Плюс: реализация остатка (метод Овчинникова), экономика/маржа, выкуп, планка входа, отбор
уточняющих фраз из выгрузки «Оракул запросов» (Wildbox), цветной PDF-отчёт. Цель — запускать на
ЛЮБОЙ нише (скрипт + скилл). Сейчас идёт этап доработки самого PDF-отчёта по замечаниям пользователя.

Все 9 исходных доработок отчёта + 5 последующих правок ВНЕДРЕНЫ и проверены на рендере:
1. 5 измерений — рядом с баллом реальные цифры (шрифт крупный, 11.5px, тёмный).
2. Реализация остатка — временнáя диаграмма по месяцам (зелёные ↑ = благоприятные окна), под
   столбцами нужный остаток на карточку под целевые продажи сегмента.
3. Экономика при марже 30% — объём/выручка/прибыль по ТОП 1-3 карточкам целевого сегмента.
4. Перспективные сегменты — два лучших, ОБА подсвечены на диаграмме (бэйджи 1/2); выручка/продажи
   по ТОП 1-3 (мы стремимся в ТОП, значит целимся в их результат).
5. Сезонность — рекомендации по торговле вне сезона.
6. Топ-продавцы — выручка ₽/мес, бренд, ссылка на витрину.
7. Планка входа — без CPM; экспресс-ориентиры топ-50 (цель объёма, фото/видео, отзывы, размеры, описание).
8. Уточняющие фразы — реализация мини-баром, стрелки ↑/↓ в «спрос:предл.».
9. Заключение — реализация с направлением (спрос выше/ниже предложения); вердикт понижается стопами.

## Что изменилось
- Отчёт из «абстрактных баллов» стал «на реальных цифрах»: 5 измерений, ТОП 1-3 в экономике и
  сегментах, помесячная реализация с планом остатка, вне-сезон, топ-продавцы с витриной.
- Реализация остатка: одиночный датчик заменён на ВРЕМЕННУЮ диаграмму по месяцам (агрегация дневных
  sales_graph/stocks_graph → месяц). Под столбцами — нужный остаток = целевые продажи / коэф. месяца.
- Экономика/сегменты считают выручку по ТОП 1-3 карточкам диапазона (`topInBand`), а не по средней
  карточке сегмента — потому что цель входа = выйти в ТОП.
- Вердикт: жёсткие стопы (затоварка <0.8×, монополизация ≥40%, барьер отзывов, убыточность) теперь
  понижают «Заходить»→«Заходить осторожно» СРАЗУ на верхнем уровне (score.verdict), а цвет бейджа
  берётся по тексту вердикта — шапка и заключение больше не расходятся.

## Что пробовали и НЕ сработало
- **Плюс-ключ «мужская» в мужской категории** — совпадает почти с каждой фразой Оракула (194→105),
  т.е. отбирает всю категорию, а не нишу «в клетку». Обход: убрать «мужская» из плюс-ключей —
  тогда 19 фраз по атрибутам (клетка/длинный рукав/демисезон/осень/отложной воротник). ВЫВОД:
  для узкой ниши плюс-ключ, совпадающий с полом/категорией, бесполезен — фильтровать по атрибуту.
- **Поле `revenuePerCard`** (без Month) в buildConclusion после переименования на `revenuePerCardMonth`
  давало «NaN тыс ₽» в заключении. Выявлено ТОЛЬКО на живом прогоне (в smoke не всплыло). Исправлено.
- **score.verdict без учёта стопов** — понижение вердикта делал только buildConclusion локально, а
  большой бейдж в шапке оставался «Заходить» зелёным при затоварке. Рассинхрон всплыл на нише, где
  ЕСТЬ жёсткий стоп (мужские рубашки 0.66×); у женских рубашек стопов не было, поэтому раньше не
  проявлялось. Урок: тестовые данные без стоп-флагов не покрывают ветку понижения.
- **Крупный шрифт реальных значений в 5 измерениях** сначала налезал на бар (левая колонка узкая).
  Обход: расширил левую колонку (barX 214→250, barW 246→198) и сократил строки значений.
- **Подсветка обоих рекомендуемых сегментов в демо** не срабатывала — границы сегментов в тестовом
  массиве не совпадали с from/to возможностей (matching по точному равенству minPrice/maxPrice).
  В реальных данных совпадают (opps приходят ИЗ segments). В демо — выровнял границы.
- **pdftoppm / imagemagick для рендера PDF→PNG** — не установлены. Проверка визуала: скриншот HTML
  headless-хромиумом `--screenshot` c префиксом `file://` (кириллица в пути = трактуется как URL).
- Ранее (прошлые сессии, всё ещё актуально): `/wb/get/keywords` даёт «Не корректные условия фильтра»
  на любом теле → частотность из Оракула; `category/trends` игнорирует d1/d2 (тренд год-к-году);
  `search/items` режет выдачу на ~100 → предложение из Оракула; реализация нормируется на 30 дней.
