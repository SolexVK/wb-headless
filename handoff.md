# Handoff — FBS-сервис (Wildberries фулфилмент-аналитика)

## Цель
Мультитенантный веб-сервис аналитики FBS по Wildberries: организации/участники,
подключение WB-кабинета (токен AES-256-GCM), отчёты по фулфилмент-складам.
Хостится на Mac Mini, наружу — через **Tailscale serve + Caddy**:
**https://mac-mini-vital.tail13d29e.ts.net/fbs/**. Код в `service/`, ветка
`claude/fbs-fullfilment-branch-cfvgir`. Пайплайны — `scripts/fbs-*.mjs`.

## Текущее состояние
Работает и развёрнуто на Mac Mini (последний деплой — коммит `818ddcd`). **5 отчётов:**
Подсорт, Остатки, Движение, География, Логистика — у каждого KPI+инсайты+графики+
сортируемые таблицы, выгрузки Excel/JSON/HTML-дашборд/PDF, общий архив (90 дн),
свет/тёмная тема. Все smoke-тесты (4 набора) зелёные.

**За эту сессию сделано:** (1) новый отчёт «Логистика» (сборка+доставка по ФФ);
(2) фикс — список складов тянется ЖИВЫМ запросом WB (новые ФФ подхватываются сами);
(3) юнит-тест резолвера складов; (4) **полный критический аудит всей ветки тремя
агентами** — найдено ~10 реальных багов + крупное дублирование; составлен план (см.
«Открытые вопросы»). **ВАЖНО: по аудиту ещё НИЧЕГО не исправлено — только план.**

## Что пробовали и НЕ сработало (грабли — читать перед деплоем/доступом)
1. **ГЛАВНАЯ ловушка сессии — доступ к сайту через браузер.** Долго грешили на Chrome/QUIC,
   потом на OpenClaw. **Настоящая причина: системный ПРОКСИ на Windows** (`200.10.39.195:8000`,
   для WB/BIFIT) пропускает только `:443`, а нестандартные порты (`:8443/:8444/:10000`) режет →
   ошибка браузера **`ERR_TUNNEL_CONNECTION_FAILED`**. `curl` прокси не использует → работал на всех
   портах, браузер — нет. **Фикс:** в Windows `inetcpl.cpl` → Подключения → Настройка сети →
   Дополнительно → «Не использовать прокси для…» дописать **`*.ts.net;100.*`**. После этого открылось всё.
   Урок: `ERR_TUNNEL_CONNECTION_FAILED` = прокси; сверять РАЗМЕР/ТЕЛО ответа (FBS healthz=71 байт vs
   оболочка OpenClaw=10316), а не только код; проверять в РАЗНЫХ браузерах (Яндекс открывал то, что Chrome — нет).
2. **OpenClaw стирал tailscale-маршруты** при рестарте (`gateway.tailscale.resetOnExit: true`) — делал
   `serve reset` и ставил только свой `/`. Поставили `resetOnExit false`, НО оно **требует рестарта
   гейтвея OpenClaw, чтобы вступить в силу** (ещё не сделано — см. «Открытые вопросы»). Если маршруты
   слетят после апдейта OpenClaw — повторить `tailscale serve --bg …` (команды в git-истории/этом файле).
3. **Планировщик (`8477`, ветка production-plan)** — Telegram-авторизация; `/` → 302 `/login`; виджет
   Telegram проверяет домен → «Bot domain invalid» при заходе по голому IP; по hostname `…ts.net` ок.
   `/admin` — это админ-страница ПЛАНИРОВЩИКА, не FBS. Отдан на `:8444 → 8477`.
4. **Ложный ход в аудите доступа:** curl отдавал `200` — приняли за здоровый FBS, а это была
   HTML-оболочка OpenClaw (перехват `/fbs`). Всегда сверять размер/тело.
5. **PowerShell-команда (`curl.exe`, `` `n ``) в Mac zsh** → zsh завис на `dquote bquote>`. Выход — Ctrl+C.
