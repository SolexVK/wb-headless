# Handoff — wb-headless (ветка `claude/niche-analysis-q6jw7e`)

## Цель
Инструментарий WB-аналитики (MPStats + публичные API WB) и построение товарных отчётов «от модели»:
рынок ниши за год + топ-10 + разбор 3 артикулов (деньги, характеристики, ключевые запросы, отзывы,
диагональное сканирование, график выручка+остаток по месяцам), книжный PDF + интерактивный HTML.
Всё упаковано в скилл `wb-product-report`.

## Что изменилось (по сути)
- Женская ниша больше не ловит мужские/школьные рубашки (раньше в «полоску» лезли Oh my man!, MIXERS
  MAN, BYKEN школьная) — gender-фильтр + excludeBrand + MINUS=школьн,мужск.
- Отбор топ-3 артикулов: сначала строим отчёт → берём реальных ГОДОВЫХ лидеров из `data.market.top10`
  → визуально проверяем монтажом → пересобираем. 3-мес. лидер ≠ годовой (напр. Neman 9.9М за 3мес,
  но 3.1М за год — заменён на С девяти до пяти/Vashbrend/Divastore 10–12М/год).
- Сводный анализ: рейтинг привлекательности (денежность карточки 30% / упущ.спрос 25% /
  раздробленность 20% / чек 15% / насыщенность 10%). Победитель — жабо гипюр (65).

## Что пробовали и НЕ сработало
- **Скриншот книжного HTML через `file://$(pwd)/...` в цикле** → ERR_FILE_NOT_FOUND (chromium).
  Обход: абсолютный путь строкой `file://$F` с предварительным `test -f`. PDF всё равно
  генерится независимо (htmlToPdf рендерит из строки в памяти), файлы .pdf на месте.
- **Чтение загруженных PDF (Read с pages)** → `pdftoppm is not installed` (poppler нет в окружении).
  PDF-страницы отрендерить нельзя. Обход: это МОИ отчёты → брал данные из локальных JSON в
  `reports-output/shirts-analysis-*.json` (они авторитетнее и богаче PDF).
- **Первый прогон «полоски»**: топ-10 содержал мужские/школьные (Oh my man! 12.7М, BYKEN школьная
  12.6М, MIXERS MAN). Причина: фраза «рубашка в полоску приталенная» тащит мужское/детское.
  Решение: gender-фильтр в shirtsMarket + excludeBrand + MINUS.
- **Первый отбор «однотонных/асимметричных» из 3-мес. выдачи** дал слабых по году лидеров.
  Решение: пересобрал из годового топ-10 с визуальной проверкой (см. выше).
- **PIL/sharp для кропа скриншотов** — не установлены. Обходился высокими окнами chromium.
- Напоминание: у MPStats СУТОЧНЫЙ лимит (429 «за ДАТУ»); search.wb.ru — ПОМИНУТНЫЙ 429 (лечится
  ретраем с backoff, встроено). Сегодня лимиты не мешали.

## Команды для проверки
```bash
# синтаксис всех модулей
for f in lib/*.js report-*.js build-summary.js; do node --check "$f" || echo "FAIL $f"; done

# пересборка сводного отчёта (без сети)
node build-summary.js   # → reports-output/summary-women-shirts.html

# пример пересборки одного отчёта (нужен токен и сеть; СУТОЧНЫЙ лимит MPStats!)
MPSTATS_TOKEN=<из env> \
SHIRTS_CATEGORY="Женщинам/Блузки и рубашки/Рубашка" \
SHIRTS_NICHE_QUERIES="рубашка на запах в полоску|рубашка в полоску на завязке|блузка на запах в полоску|рубашка в полоску приталенная" \
SHIRTS_MINUS="тепл,тёпл,флис,детск,девочк,мужск,коротк,без рукав,безрукав,летн,школьн" \
SHIRTS_REFINE='{"longSleeve":true,"include":"полоск","exclude":"летн|пляж|детск|школьн","excludeBrand":"mixers|oh my man|man!","scan":140}' \
SHIRTS_D1=2025-08-22 SHIRTS_D2=2026-08-21 \
node report-shirts.js 694695755 770842529 327957543

# PDF генерится chromium --print-to-pdf (poppler/pdftoppm в окружении НЕТ)
```
Ожидаемое состояние: `node --check` по всем файлам — ЗЕЛЕНО. `node build-summary.js` — пишет HTML без
ошибок. Формальных unit-тестов в проекте нет; корректность отчётов проверяется рендером в PNG
(chromium --screenshot) и просмотром + сверкой JSON (фото 3/3 и 10/10, размеры не пусты, топ-10 без
мусора). Красных проверок нет.
