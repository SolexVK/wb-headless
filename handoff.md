# Handoff

## Цель
Сделать по выгрузке остатков WB («Остатки по дням») интерактивный Excel-дашборд,
на котором видно динамику остатков по артикулам/складам по дням. Инструмент —
воспроизводимый генератор `analytics/inventory-dashboard/build_dashboard.py`,
который из сырой выгрузки собирает готовую книгу с фильтрами, KPI и графиками.

## Текущее состояние
Работает, задача выполнена в актуальной постановке.
- Генератор собирает книгу с листами: **Дашборд** (2 фильтра — Артикул/Склад, живые
  `SUMIFS`, KPI, график), **По артикулам**, **По складам**, **Данные** (+ скрытый
  «Списки» для выпадающих списков).
- Актуальная логика обработки: **консолидация размеров** (сумма по Артикул×Склад,
  размерность «Размер» убрана) и **отсев нулевых складов** (строки Артикул×Склад,
  нулевые за весь период, отбрасываются).
- На последней выгрузке (32 дня, 06.07–06.08): 20 368 сырых строк → 2 809 после
  консолидации и отсева; 28 складов с реальным остатком из 161. Глобальные суточные
  итоги при отсеве не меняются (46 348 → 30 562) — удаляются только нули. Проверено.
- Готовые файлы отправлены пользователю через SendUserFile (в репозиторий не
  коммитятся — это его коммерческие данные).
- Ветка: `claude/inventory-dashboard-5j5lif`. Запушено. PR не создавался.

  первая версия: 3 измерения (Артикул×Размер×Склад), листы включая «По размерам».
- Переработка под уточнённую постановку (коммит `8f15790`): размеры консолидированы,

- Фильтр «ВСЕ» реализован без wildcard: критерий `SUMIFS` = `"<>"` (совпадает с любой

- Сводные листы содержат ПРЕДрассчитанные значения (из pandas), а не тысячи живых
  `SUMIF`; интерактивным на формулах остаётся только лист «Дашборд».
- У книги выставлен `fullCalcOnLoad=True` — формулы пересчитываются при открытии.

## Что пробовали и НЕ сработало
- **Пересчёт формул через headless LibreOffice (`xlsx/scripts/recalc.py`) НЕ работает
  в этой среде.** Виснет и отваливается по таймауту даже на файле из 3 ячеек (пробовали
  80/100/280/300 с — всё timeout). Причина: `recalc.py` запускает `soffice` дважды
  (установка макроса в профиль + запуск), и каждый раз медленно бутстрапит свежий
  профиль в песочнице (AF_UNIX под LD_PRELOAD-шимом). Прямой `soffice --convert-to`
  стартует, но полноценный recalc-макрос не доходит. **Обход:** не полагаться на
  headless-recalc; поставить `wb.calculation.fullCalcOnLoad=True`, чтобы Excel/
  LibreOffice сами пересчитали при открытии, а числа независимо сверить через pandas.
  → При возобновлении НЕ тратить время на recalc.py, он тут не поедет.
- **Первая версия грузила ~2000+ живых `SUMIF` на сводных листах** (166+149+14 ключей
  × 7 дней) — книга становилась неподъёмной для любого пересчёта. Отсюда решение
  считать сводные листы значениями в Python, оставив живые формулы только на дашборде.
- **Грабли со смещением столбцов при верификации:** на сводных листах дни начинаются
  с колонки **C** (ключ в B), а не с D. Первый проверочный скрипт читал с D и дал
  ложное «не сходится». Правильно: дни в колонках C..(C+NDAY-1), Изм. и % — следом.
- `openpyxl`/`pandas` в системном python отсутствовали — ставили через `pip install`
  (не в venv, среда эфемерная — при новой сессии поставить заново).

## Команды для проверки
Формальных тестов у модуля нет; проверка = прогон генератора и верификация чисел.
```bash
pip install openpyxl pandas            # среда эфемерная, ставить заново
python -c "import ast; ast.parse(open('analytics/inventory-dashboard/build_dashboard.py').read())"  # синтаксис
# сборка из сырой выгрузки:
python analytics/inventory-dashboard/build_dashboard.py <input.xlsx> /tmp/out.xlsx --sheet "Остатки по дням"
```
Верификация (то, что делали в сессии): открыть /tmp/out.xlsx через openpyxl и сверить,
что суммы по дням на листах «По артикулам»/«По складам» равны глобальным суточным
итогам сырой выгрузки, а на «Данные» нет складов с нулевым остатком за период.
**Ожидаемое состояние сейчас:** генератор проходит `ast.parse` (зелёный) и успешно
собирает книгу на обеих выгрузках пользователя; recalc через LibreOffice — заведомо
КРАСНЫЙ (см. «Что не сработало»), это ожидаемо и не блокер. Excel открывает файл и
пересчитывает формулы штатно.
