# Handoff — Производственный план (planner)

## Цель
Рабочий веб-инструмент для планирования отшива рубашек: план продаж → этапы →
распределение по цехам → интерактивная диаграмма Ганта → дашборд с вехами,
тканью и логистикой до склада WB. Ветка: `claude/production-plan-twv8ki`.
Инструмент разворачивается на Mac mini пользователя и доступен через браузер
по Tailscale.

## Текущее состояние
- **Инструмент собран и работает** (проверено headless-браузером и вручную).
  MVP: движок планировщика, Гант с drag&drop, дашборд, формы ввода, персист.
- **Развёрнут на Mac mini пользователя**, работает как служба launchd
  (автозапуск, переживает перезагрузку). Доступ по Tailscale:
  `http://100.108.217.93:8477` (порт 8477, т.к. 8090 занят OpenClaw).
  Проверено — открывается с другого компьютера.
- Пока показывает **сид-данные** (пример на 5 артикулах). Реальные данные
  пользователь ещё не вносил.
- Не реализовано (заложено на будущее): матрица размер×цвет по этапам,
  мультисезон, буферы под форс-мажоры как отдельные блоки.

## Файлы, над которыми работали
- `planner/lib/calendar.js` — рабочий календарь (6-дневка, вс — выходной).
- `planner/lib/model.js` — схема состояния, дефолты, сид (артикулы 026/027/031/035/004, 6 цехов).
- `planner/lib/scheduler.js` — авторасчёт: распределение по цехам, дробление, поток крой→пошив→утюжка→ОТК, ткань, логистика.
- `planner/server.js` — Express: статика + REST API (`/api/state`, `/api/schedule`, `/api/override`), опц. Basic-auth, bind на HOST/PORT.
- `planner/public/index.html`, `styles.css` — оболочка SPA + стили.
- `planner/public/app.js` — вкладки, дашборд, формы ввода, сохранение, override.
- `planner/public/gantt.js` — SVG-Гант с перетаскиванием блоков.
- `planner/package.json` — изолированные зависимости (только express, без puppeteer).
- `planner/deploy/start.sh`, `com.wbheadless.planner.plist` — автозапуск macOS.
- `planner/DEPLOY.md`, `README.md` — инструкции.
- `package.json` (корень) — добавлен скрипт `planner`.
- `.gitignore` — добавлен `planner/data/`.

## Что изменилось
- Реализована модель: артикул (цвета, размерный ряд, расход ткани, план по
  этапам в штуках), цех (роль main/aux, мощности крой/пошив/утюжка/ОТК шт/день),
  этап (2 месяца продаж → 1 календарный месяц отшива, дедлайн WB).
- Планировщик балансирует цеха по времени завершения (все загружены + сроки),
  дробит партию между цехами пропорционально мощности пошива при нехватке,
  считает поток с перекрытием, заказ ткани (лид-тайм 3 нед + буфер), логистику
  (недельный карго + 10–15 дн), подсвечивает срывы дедлайнов.
- Гант: 4 дорожки операций «лесенкой», перетаскивание блока = сдвиг старта кроя
  с мгновенным пересчётом; двойной клик — сброс.
- Добавлена опц. защита паролем (`PLANNER_PASSWORD`) и деплой-обвязка.

## Что пробовали и НЕ сработало (важно!)
- **`npm install` в корне намертво зависал на Mac mini.** Долго думали, что дело
  в puppeteer (качает Chromium). Пробовали:
  - `PUPPETEER_SKIP_DOWNLOAD=true` + `PUPPETEER_SKIP_CHROMIUM_DOWNLOAD=true` — не помогло, всё равно виснет.
  - `--ignore-scripts` — выдало ошибку `ENOTEMPTY rename puppeteer-core` (битый node_modules от прерванных install).
  - `rm -rf node_modules` + повтор — снова зависание.
- **Настоящая причина** нашлась через `npm install --verbose`: каждый запрос к
  реестру падал с `ECONNREFUSED`, потом через ~70 сек отдавался из кэша
  (`200 cache stale`). Значит npm ходил через **сломанный прокси**, прописанный
  в его конфиге (скорее всего OpenClaw/Hermes). При этом `curl` до реестра
  работал (200 за 0.26с — curl прокси игнорирует), а `env | grep proxy` был пуст
  (прокси был в npm-конфиге, не в env).
- `npm install --offline` — не прошёл (`ENOTCACHED`, не все пакеты в кэше).
- **Что сработало:** удалить прокси из npm-конфига и поставить только express в
  изолированной подпапке:
  ```
  npm config delete proxy; npm config delete https-proxy
  npm config delete proxy --location=global; npm config delete https-proxy --location=global
  npm config set registry https://registry.npmjs.org/
  cd planner && npm install --prefer-offline --ignore-scripts --no-audit --no-fund
  ```
  Установка прошла за 596мс (68 пакетов). Отсюда родился `planner/package.json`
  (только express) — чтобы не тянуть puppeteer на сервер.
- **Порт 8090 занят** приложением OpenClaw (открывалось чужое приложение) —
  перешли на **8477**.
- **Доступ с Windows-десктопа по Tailscale давал `502 Bad Gateway`** — потому
  что браузер на Windows тоже гонит трафик через прокси OpenClaw. Сам сервер
  доступен (`curl http://100.108.217.93:8477/api/health` → 401). Также у
  пользователя настроен `tailscale serve` (OpenClaw) на `127.0.0.1:18789` — его
  НЕ трогали, чтобы не сломать OpenClaw. Рабочий доступ — с другого компьютера
  (без этого прокси) — заработал.
- Мелочь: кириллица в HTTP-заголовке `WWW-Authenticate` (realm) роняла Basic-auth
  с `ERR_INVALID_CHAR` → заменили realm на ASCII `"Planner"`.

## Команды для проверки
Локально в этом репозитории (dev-окружение, зависимости в корне уже стоят):
```bash
# синтаксис-чек движка
node --check planner/server.js && node --check planner/lib/scheduler.js

# прогнать планировщик на сиде (ожидаем: 20 циклов, 0 предупреждений)
node -e 'import("./planner/lib/model.js").then(async({defaultState})=>{const{buildSchedule}=await import("./planner/lib/scheduler.js");const s=buildSchedule(defaultState());console.log("cycles",s.cycles.length,"warnings",s.warnings.length)})'

# поднять сервер локально
npm run planner   # http://localhost:8090  (или PLANNER_PORT=XXXX)
# с паролем:
PLANNER_PASSWORD=test npm run planner
```
Проверка API: `curl -s -o /dev/null -w "%{http_code}" localhost:8090/api/health` → 200 (без пароля) / 401 (с паролем без creds).

**Ожидаемое состояние (зелёное сейчас):** `node --check` проходит; прогон
планировщика даёт `cycles 20 warnings 0`; сервер стартует, `/api/schedule`
возвращает 20 циклов; Гант/дашборд/формы рендерятся без ошибок в консоли
(проверялось puppeteer'ом, единственная «ошибка» — 404 favicon, безвредна).
Формальных unit-тестов в проекте нет — проверка через self-run выше.

На проде (Mac mini): служба `launchctl list | grep planner`, здоровье
`curl -s -o /dev/null -w "%{http_code}" localhost:8477/api/health` → 401.

## Открытые вопросы (нужно решение пользователя)

   (а) матрица размер×цвет по этапам (детальный раскрой, ближе к Google-таблице

   данных и нужна для точного расчёта ткани по размерам.
2. **Реальные данные — ЖДУ:** нужны фактические мощности всех цехов

   м/шт по каждому артикулу — заменить ими сид.
3. **Многопользовательность:** сейчас одна общая учётка (admin + пароль). Если
   нужно несколько пользователей/ролей — это отдельная доработка. Пока не срочно.
