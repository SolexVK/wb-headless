# Handoff — planner / Этап 3+ (пины Ганта, авто-цеха, выгрузки, «Экономная раскладка»/JIT)

Ветка: `claude/production-plan-twv8ki` · репо `solexvk/wb-headless` · приложение в `planner/`.
Билд на конец сессии: **`jit-gender-deep-2026-08-27`** (APP_BUILD в `public/app.js`, BACKEND_BUILD в `server.js` —
держим РАВНЫМИ; бампаем вместе с каждой правкой). Деплой у пользователя: Mac mini, порт 8477, supervisor.

## Цель
SPA планирования пошива одежды под Wildberries. Прогноз спроса («Ранг сезонности», MPStats) → план по
цветам/размерам → довозы (партии-поставки со сроком WB) → вычет реальных остатков → раскладка нетто по
цехам → диаграмма Ганта → выгрузка листов в Excel для цеха. Цель — шить только нужное, вовремя, комфортными
партиями, ничего не теряя. **Главная задача этой сессии (не закрыта до конца): «Экономная раскладка» —
пересобрать график так, чтобы не морозить деньги (шить точно к сроку, а не заранее), при этом непрерывно
(без простоев), минимумом цехов, летние — к 15.04.**

## Текущее состояние
Всё нижеперечисленное задеплоено и подтверждено пользователем по ходу сессии (кроме, возможно, самого
последнего билда `jit-safe` — просил проверить завтра):
- **Пошив не раньше — на партию** (`partia.earliestStart`, поле на «Плане по размерам»). Планировщик берёт
  позднейшую из `earliestStart` и `article.sewNotBefore`. Аддитивно.
- **Гант: ручное перетаскивание блока одним движением** и на другой ЦЕХ (вертикаль), и на дату (горизонталь).
  Пер-батчевые пины `state.batchPins["partiaId#batchIndex"]={ws,cut}` (стабильный ключ). Пин-цех перекрывает
  `allowedWorkshops` (блок не «исчезает»). Кнопки: «🧲 Уплотнить», «↺ Сбросить раскладку» (чистит пины И
  `jitStart`). Пиновый блок помечен 📌.
- **Авто-синхронизация «Кто шьёт»**: перенос блока в новый цех ставит галочку этого цеха; уход последнего
  блока — снимает. Прочие батчи артикула «замораживаются» цех-пином, чтобы не было каскада.
- **Выгрузка «⤓ Слепок раскладки»** (кнопка на Ганте): Excel, строка = артикул×цвет×партия, все даты и
  запасы. Для анализа.
- **«💰 Экономная раскладка» (JIT)** — движок `lib/jitLayout.js`, кнопка на Ганте, эндпойнт
  `POST /api/jit-layout {apply|reset, opts}`. Текущая версия **`jit-ownlock`** (день 2). Итог правок дня 2:
  - Приоритет — **БАЛАНС: минимум цехов БЕЗ новых опозданий** (`balanceMinWorkshops`, галочка «⚖ Найти минимум
    цехов без опозданий», ВКЛ по умолчанию). Свип по числу доп.цехов, берём наименьшее с опозданиями ≤ базы.
  - **Летний потолок 15.04 → 30.04** (`summerFinishMMDD` деф. `04-30`). Летние «не раньше» — пользователь
    ставит `article.sewNotBefore` (поле «Пошив не раньше» на Плане; уже есть), движок соблюдает (`esOf`).
  - **СТРОГАЯ привязка к своему цеху**: артикул, у которого матрица «кто шьёт» разрешает own → шьётся ТОЛЬКО
    в own (при сокращении не перебрасывается). Остальные — свободно.
  - **Сокращение цехов — через ОГРАНИЧЕНИЕ набора цехов** (временная копия `allowedWorkshops`), НЕ жёсткая
    привязка «артикул в один цех» — планировщик сам дробит крупные довозы параллельно по разрешённым цехам
    (так база укладывалась в сроки). Применяется ws-пинами (матрицу пользователя не портим).
  - **Универсальная страховка сдвига**: сдвиг блоков не добавляет опозданий/разрывов сверх выбранного
    распределения — иначе откат. Изделия сохраняются (📦 в превью).
  - **ГЕНДЕР (`jit-gender-deep`)**: мужские модели `MENS_ARTICLE_IDS=['002','003','005','006','007']` — только
    в «мужские-способные» цеха (те, что шьют мужские в базе); женские — в любые. Применяется при сокращении
    (в `stateReduced`: мужской артикул → target ∩ mensCapable, иначе fallback mensCapable). Season и gender —
    независимые оси (005/006/007 и летние, и мужские).
  - **ГЛУБОКИЙ ПЕР-ДОВОЗНЫЙ сдвиг** (`deepShift`, галочка «🔬 Глубже давить заморозку»): каждый довоз стартует
    как можно позже под СВОЙ дедлайн (не по самому срочному в цехе) → заморозка падает СИЛЬНЕЕ (тест 4.7→1.8),
    но между довозами появляются ПАУЗЫ (0→14). Опоздания не растут (пер-довозная защита), изделия сохранены.
    Обычный (пер-цеховой) сдвиг — 0 пауз, но экономия скромнее. Пользователь выбирает галочкой.
- Ранее в сессии: точный % размера по цвету (`sizeTarget`), тумблер нетто/спрос пер-артикул, выгрузка рангов
  сезонности всех артикулов в .zip (ежедневно).

Не тестируется в контейнере: WB/MPStats API (нет сети/токена), реальные данные пользователя (в его БД на
Mac mini). Проверка — `node --check` + изолированные node-тесты на сид-модели и синтетике.

## Что изменилось
1. **Механика JIT — только через аддитивный пол `partia.jitStart`, НЕ через пины дат.** Планировщик сам
   сериализует поток (freeDate) ⇒ непрерывность и «одна модель за раз» гарантированы, сдвижки этапов
   соблюдаются. `jitStart` не трогает ручной `earliestStart`.
2. **`jit-safe` (текущий движок):**
   - **По умолчанию (без галочки) — БЕЗ регресса.** Цеха/порядок НЕ трогаем. Делаем только ЕДИНЫЙ сдвиг блока
     каждого цеха позже к его самому срочному дедлайну (заморозка вниз). Летние — потолок 15.04 в расчёте
     запаса. Финальная страховка: если опоздания/разрывы стали хуже базы — весь сдвиг откатывается (тождество).
   - **Галочка «Сократить число цехов» (`ignoreAllowedMatrix`, `maxExtraWorkshops`)** — только по явному
     включению: модели съезжают в свой+N цехов (игнор матрицы «кто шьёт»). Тогда возможны опоздания — честно
     показываем в превью.
   - **Замер сохранности**: в превью 📦 ИЗДЕЛИЙ (должно быть «=0», иначе красным) и 📅 дней производства
     (Σ длин полос; меньше = быстрее в мощном цехе, изделия те же). Заморозка split: несезон (экономим) / лето
     (неизбежна). Доказано: изделия строго сохраняются.
3. Пер-батчевые пины Ганта + авто-синхронизация «кто шьёт» + слепок в Excel (см. «Текущее состояние»).

## Что пробовали и НЕ сработало (грабли — читать перед правками движка!)
- **JIT v1 — пины ДАТ кроя (`state.batchPins.cut` как override).** Закреплённая дата ПЕРЕБИВАЕТ признак «цех
  занят» (freeDate) → на Ганте появились ПРОСТОИ и ПАРАЛЛЕЛЬНЫЕ модели в одном цехе. Замер: база 0 наложений/
  0 разрывов; пины — 3 наложения/6 разрывов/271 день простоя. **ВЫВОД: никогда не пиновать даты кроя для
  раскладки; только пол `jitStart`, а непрерывность отдаёт планировщик.**
- **JIT v2/v3 — распыление партий по срокам (jitStart на каждую/по волнам, лето-наполнитель).** Когда
  мощности больше потока, между партиями с разными дедлайнами неизбежны РАЗРЫВЫ. Пользователь (скрин)
  забраковал: «производство должно быть непрерывным». **Любое per-партийное прицеливание в дедлайн = разрывы.**
- **JIT v3 — критичный баг: условие «созревший несезон» было инвертировано** (`diffDays(startAt,T)<=0` вместо
  `>=0`) → весь несезон ставился на seasonStart (экономии ноль). Исправлено (в v4/5 логика заменена).
- **JIT v4 — авто-балансировка/концентрация по цехам БЕЗ защиты.** Молча перераспределял артикулы → РОСЛИ
  опоздания (30474→42096) и перестройки (34→38). Пользователь забраковал. **ВЫВОД: любое авто-перераспределение
  по цехам легко даёт регресс — делать только по явной галочке и с замером «не хуже базы».**
- **Сокращение до 3–4 цехов при «летние все к 15.04» — упирается в мощность.** Грубая оценка по слепку
  (~225 шт/д): пик готовности к апрелю-2027 требует ~6–7 цехов; в 4 цеха объём к срокам НЕ влезает → опоздания.
  Поэтому сейчас в 4 цеха = опоздания (движок показывает честно). Возможные развязки — ниже в «Открытых».
- **Ранние грабли сессии** (не JIT): sizeAdjust-как-множитель против sizeTarget-как-абсолют (сбили данные
  пользователя — откат `git revert`, урок: не менять семантику существующих полей, только новые поля);
  «бордовый»→«красный»; кириллица «ХL»→XL; слияние довозов (нетто>спрос) — отключено.

## День 2 — сделано (`jit-balance`)
Ответы пользователя: приоритет = **БАЛАНС (минимум цехов БЕЗ опозданий)**; летние можно дошивать **до 30.04.2027**.

  числу доп.цехов, берём наименьшее, где опозданий не больше базы; в превью строка «⚖ минимум цехов … : N».
  Ядро вынесено в `runOnce(maxExtra, reduce)` + `assignWs`/`latenessOf` для свипа. Поле «жёстко: свой+N
  (можно с опозданиями)» = `ignoreAllowedMatrix`. Дефолт (без галочек) = безопасная экономия без сокращения цехов.
