# 11. SEO-оптимизация карточки

> Как собрать наименование, характеристики, категории и текст так, чтобы карточка
> индексировалась только по **релевантным** запросам и не сливала рекламный бюджет.

## 1. Ключевой инсайт нового алгоритма

- Новый алгоритм WB = **ИИ определяет принадлежность ключа** к вашей нише. **Нерелевантные
  ключи не индексируются** в поиске и почти не попадают в рекламное SEO. Околорелевантный
  **«мусор»** в описании (для «расширения семантики») → **потеря рекламного бюджета**.
- Технология перенесена **из Яндекса**: директор по внедрению алгоритмов WB — бывший директор
  Яндекса по алгоритмам рекламы. Отсюда: запросы **не будут скрывать полностью** (как на Ozon) —
  логика Wordstat подразумевает показ, чтобы продавцы адаптировались.
- **Кластеры / идентификатор поисковой выдачи:** у главного запроса есть кластер из 10–30+
  запросов, где карточка стоит на **разных позициях**. ~7 месяцев назад WB **скрыл всё, кроме
  главного запроса** (в рекламе/Радаре); «средняя позиция» = усреднение по кластеру.
- Работает это уже **~1,5 года** — просто стало явно видно в новом интерфейсе рекламы.

## 2. Зоны индексации и правило дублей

Зоны (по силе): **Наименование (тайтл)** — одна из сильнейших · **Характеристики** (по ним WB
сверяет и подбирает релевантных конкурентов) · **Описание/Состав** (индексируется, анализ конкурентов).

**Правило дублей:**
- Внутри одной зоны слово **не должно повторяться** 3–4–5 раз — это спам.
- Между зонами слова **могут и должны пересекаться** — это НЕ спам; сильные слова лучше держать
  во всех ключевых зонах.

## 3. Наименование (title)

Формула: **предмет/категория (ВЧ) + «для чего / для кого» (применение) + усиливающее слово.**
- Пример товарка: «**Отпариватель ручной для одежды мощный**». Ватты/цифры — **не** в наименование
  (видно из фото/характеристик).
- Одежда: «**трусы хлопковые набор 9 штук**» / «трусы хлопковые слипы набор 9 штук».
  - **Пол не писать** (берётся из характеристик), не писать «женские», «качественные» (решает
    покупатель), страну — в характеристики.
- Структура из Amazon: категория + ВЧ/СЧ ключи + основные характеристики (≈4 слова:
  существительное + прилагательное + хвост).
- Проще всего — взять наименование **топового конкурента** (топ-6 по рейтингу из бота), если
  максимально под него подходите.

## 4. Характеристики

- Писать **только правду** про товар (время нагрева, мощность, вес, покрытие, тип управления,
  комплектация). Возврат из-за неправды → WB понижает (сверяет заявленное с тем, что клиент взял).
  От одного клиента ничего, от большой (сильной) аудитории — быстрое падение.
- **Состав + ткань** — важнейшая характеристика для одежды (через неё попадаешь в нужные полки/сегмент).
- **Цвета — только чистые** (чёрный/белый/синий/зелёный). «Чёрно-матовый / чёрно-асфальтный /
  чёрно-бежевый» = **спам цветов**.
- **Предмет — реже** в характеристиках: предмет берётся из категории; товар индексируется по
  предмету, даже если он нигде не прописан (проверено).
- Слова в характеристиках индексируются **и как категория, и как запрос** — релевантные, без
  повторений, **без ошибок**.
- Инструменты: «просмотр релевантных характеристик» в Пушка-боте (спарсенный закрытый бот
  «нравится/не нравится»); сильные характеристики топ-конкурентов — через **мониторинг карточки**
  (бот). Wildbox → «Мониторинг товаров» → создать список → добавить артикулы конкурентов → таблица
  общих характеристик (но «сильные» показывает только Пушка-бот).

## 5. Категории

Категории отвечают за: наполнение каталога, **буст запросов**, индексацию, авто-рекламу, **вход в
акции**.
- Механика акции: акция смотрит на **категории** → если категория есть и в ней есть запросы → при
  росте CTR/CR2 идёт **буст в запросах**. Если запрос есть, а **категории нет — «бот не заходит»**,
  буста нет (индексируешься слабо).
- Главная категория (одна) + **подкатегории** = слова в характеристике «назначение товара»: бег,
  ходьба, йога, пилатес, гимнастика, туризм; **большие размеры** (oversize / one size / 58+);
  будущая мама (для беременных / роддом); домашняя / повседневная.
- **Только релевантные** категории. Если поле принимает 3, а релевантна 1 — вписать **1**.
  Нерелевантную (нет больших размеров) — **не вписывать ни в коем случае** (тянет нерелевантный трафик).
- Где смотреть: **MPStat** (анализ характеристик SKU → категории) или **Wildbox** (анализ поиска →
  товар → шестерёнка → количество категорий; «анализ категорий»). Карточки до 2023 хранят пустые
  категории (релевантность сомнительна).
- Запросы, на которые отвечает категория, **тоже индексируются** → категорийные слова должны быть
  уникальны, ВЧ, хвосты.

## 6. SEO-текст (описание): два способа

### Способ A — от конкурентов (без Gem)
```
1) Wildbox → анализ артикула конкурента → блок запросов → «Скачать»
2) Бот → Keywords → загрузить таблицу → жёлтая зона
3) Отсортировать позиции 1..299  (раньше 1..399; сейчас 1..299 — заказы/выкуп идут с 1–3 стр.)
4) Wildbox → SEO → Группировка запросов → уникальные слова + частоты
5) Оставить ТОЛЬКО релевантные слова (см. §7)
6) ChatGPT составляет текст (§8)
```
Брать **топ-6** конкурентов сегмента (у топа больше запросов); часто хватает **1–2 сильных**.

### Способ B — через Gem
Для карточки, которая **уже поработала** (2–3 мес в рекламе, накопила статистику): Gem → поисковый
запрос → скачать запросы → группировка → слова. Одежде нужно **~100 слов** (макс. тариф), товарке
**~30**. Для **новой** карточки Gem картины не даёт — брать способ A.

> **Идентификатор поисковой выдачи** (слова «с прочерком») — запросы кластера, которые не
> индексируются/не рекламируются (маленькая аудитория), но участвуют в анализе релевантности. При
> группировке запросов **убираются**.

### Способ C — Wildbox (полный цикл из эфира эксперта)

Пошаговый сбор и чистка SEO в разрезе **кластеров** (новая механика):
```
1) Анализ топов поиска (запрос) → «Формировать список» → «Товары» → выделить все →
   «Добавить в мониторинг» (папка конкурентов)
2) SEO-блок, сбор ключей (несколько способов):
   • «Запросы у списков»: загрузить папку; фильтры — ПРЕДМЕТ (сразу режет нерелевант),
     базовая частотность (напр. от 300), «% присутствия в артикулах» (исключить брендовые),
     кол-во товаров в выдаче → «Показать ключи»
   • «Поисковые подсказки» (2 уровня): вставить главный запрос → собрать актуальные подсказки WB
   • «SEO AI» (нейросеть): вставить артикул → собирает топ-100 ПОХОЖИХ конкурентов, их ключи
     (ранжированы по «индексу важности»), а также СЛОВА НАЗВАНИЙ и ХАРАКТЕРИСТИКИ топов
   Все ключи → «Добавить в мониторинг» (папка ключей; дубли сервис удаляет сам)
3) Продвижение → «Кластеризатор»: загрузить папку ключей → отчёт (ключи группируются в кластеры)
   Чистка: нерелевантные кластеры удалять; проверка релевантности — скопировать название кластера /
   самый частотный ключ → в выдачу WB → если 3–4+ релевантных карточки, кластер оставить, иначе убрать.
   Чистить до ~50 релевантных кластеров на странице (после удаления подтягиваются новые — пройти все).
4) Взять ПО ОДНОМУ ключу из каждого кластера (узкое ядро!). Не нужно 2000 ключей — из одного ключа
   кластер «притягивает» тысячи. → SEO → «Группировка запросов» → слова-корни;
   мусорное слово → «Добавить группу в стоп-лист» (убирает слово и все запросы с ним разом).
5) SEO → «SEO тексты» → бот: промпт «напиши продающий текст для <товар> используя слова: <список>».
   Проверка: «Загрузить из мониторинга» (чистое ядро) → «Анализировать»: общая частотность, полное /
   частичное вхождение, «отсутствуют». Добить недостающие релевантные запросы вручную (замена в тексте).
```
Правила: не более **3 повторений** одного запроса в тексте (иначе спам); WB такие тексты не ругает.

**Анализ характеристик (Wildbox):** «Анализ характеристик» → загрузить мониторинг → «Сравнение
характеристик» + свой артикул → сервис сравнивает название/цвета/предмет/характеристики с топами и
подсвечивает пересечения. **Незаполненные характеристики** (WB выкатил обновление) сильно влияют на
видимость — заполнять все релевантные (клиент часто заходит через **фильтры**).

## 7. Что считать мусором (убираем)

- Общие слова: **одежда, бельё, товар, стиль/стильный, модный, образ, нижнее, вещь**.
- **Страны** (Турция, Финляндия — только в характеристики), **«купить»**, **«подарок»** (если не
  факт), **опечатки** («трусить», «трума»), нерелевантные запросы («трусы Олимпиады» — позиция 251,
  частота 0).
- **Правило:** релевантно = **растёт в органике**; околорелевантное (относится к товару, но не
  растёт) = **мусор** = слив бюджета.
- Проверка слова: забить запрос в WB → если продаётся «не то» — не брать. Если есть конкурент, но
  это реклама — зайти к нему, посмотреть **органику за 2 недели**; ниже 3-й страницы — не брать.
- Слово может быть релевантно по **насмотренности** (old money, 2K, корейский стиль): если у вас
  нет соответствующего визуала (модель/крой/рваность) — в этих «модных» запросах вы не нужны, не берите.

## 8. Промпт ChatGPT для SEO-текста

> «Ты аналитик SEO-оптимизации мирового уровня, работаешь с алгоритмами маркетплейсов. Ты составил
> описание [текст-эталон]. Проанализируй текст и построение, сделай так же со следующими словами:
> [слова]. Составь **как человек, без повторений слов**. Сделай сухую выжимку по концепции. Не
> используй слова, которые могут увеличить индексацию запросов и подключить новые запросы (слив
> бюджета в рекламе). Правильно склоняй слова.»

- **Одежда:** каждое слово **1 раз** (без повторений).
- **Товарка:** главное слово (фонарь/кружка/отпариватель) — **2 раза** (связующий элемент для
  красивого текста), остальные — 1 раз.
- Текст можно генерить **бесконечно уникальным** — для другой склейки те же слова, но другой текст
  (для ботов важна уникальность в рамках склейки; при склейке текст можно повторять, при
  **расклейке — индивидуальный**).

### Почему так (LCA / EAT)
WB перенёс из Google **LCA/EAT**: экспертность, авторитетность, надёжность; учитывает текст,
сезонность, актуальность, тех-особенности, «для кого / как применяется». Текст должен быть
**экспертным** и «литься красиво». Семантическое окружение (авто-добавление слов) WB **не взял** —
слишком нагружает дата-центры; контекст берёт из **смыслов инфографики и поведения покупателя**.
Текст покупатель почти не читает — он **для ботов**; покупателю нужны характеристики.

## 9. Прочие правила

- **Память рекламы/SEO ≈ 1,5 недели**: после смены SEO старые запросы висят, пока не заминусуешь и
  не упадёт трафик.
- Смена SEO у карточки, высоко стоящей в **органических полках**, позиций **не теряет** (остаёшься
  в тех же словах).
- **Нельзя** в одной склейке зимнее+летнее (лосины с начёсом/без) — разная аудитория, разделять.
- **Тайминг:** инфографику вносить **утром** (новый покупатель видит новую); запуск рекламы — в
  **утренние пиковые часы**.
- Вся оптимизация теперь собирается за **10–15 минут**.
- Реклама (превью 3-го модуля): нельзя отключить запрос до **100 показов на кластер**; убрали
  минус-фразы; **ставка → больше показов/запросов**; Радар минусует. Персонализация: показы
  сопряжены с конверсией/заказом/выкупом; в **полках** персонализация уже сильная, в запросах — пока слабая.

## 10. Связь с инструментами

Способ A по шагам почти готов к автоматизации через MPStats/наш прокси (выгрузка запросов →
фильтр 1–299 → группировка → фильтр мусора → генерация текста). ⚠️ Идентификатор поисковой выдачи,
«принадлежность» и точные позиции по кластеру — только Wildbox/Gem; MPStats их не отдаёт.
Категорийные слова частично доступны через MPStats (характеристики SKU).
