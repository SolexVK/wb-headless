# Правила проекта wb-headless (план продаж на сезон)

Документ обязателен к соблюдению. Методология — `docs/sales-plan-method.md`,
использование — `REPORTS.md`.

## ПРАВИЛО 1. Новый прогон начинается с уточняющих вопросов

Когда пользователь говорит «давай сделаем новый прогон» (или подобное) —
**НЕ запускать сбор данных сразу и НЕ переиспользовать данные прошлого прогона**
(только если пользователь явно не попросил взять прежние данные).

Сначала **задать уточняющие вопросы понятным человеческим языком** по параметрам:

- `--words` — какие слова должны быть в названии (любое из);
- `--all-words` — какие слова должны быть все сразу;
- `--exclude` — что исключить из выдачи;
- `--brands` / `--exclude-brands` — по брендам;
- `--price-min` / `--price-max` — ценовой коридор, ₽;
- `--min-sales` — минимум продаж (отсечь мёртвые карточки);
- `--limit` — сколько аналогов брать в группу;
- `--d1` / `--d2` — период истории (по умолчанию см. Правило 2).

Только **получив ответы**, приступать к сбору данных, анализу и построению
плана. Не додумывать за пользователя тип товара и фильтры.

## ПРАВИЛО 2. Горизонт истории — 2 года назад от текущей даты

- По умолчанию окно = **последние 2 года** (от текущей даты назад), а не любые
  два года.
- Учитывать **общее движение тренда** по категории и релевантному запросу.
- **Взвешивать по свежести:** данные ближайшего прошедшего года ближе к
  реальности, чем позапрошлого → недавний год имеет больший вес при построении
  сезонного профиля (`recencyWeight`).

## ПРАВИЛО 3. Уровень плана — блендинг 90% конкуренты / 10% свои

- Делаем срез по **своим товарам** (если есть статистика) и выборку по
  **конкурентам** (отфильтрованные аналоги).
- Уровень базы = **90% от конкурентов + 10% от своих** (`competitorWeight=0.9`).
- Причина: только свои данные могут быть неполными/искажёнными относительно
  рынка; отфильтрованные конкуренты дают более точную и неискажённую картину.
- Если своей статистики нет — 100% по конкурентам.

## ПРАВИЛО 4. Результат — два файла

1. **`.xlsx`** — таблица с продажами и ценами за каждый день запрошенного
   периода, с разбивкой на этапы: **вход; разгон; старт сезона; пик сезона;
   начало распродажи; конец распродажи**.
2. **HTML-артефакт** — визуальный отчёт с характерными цветами: кривая сезона,
   фазы, план заказов в штуках и цены по дням.
